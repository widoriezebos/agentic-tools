# Local invariants of the metasystem repository itself

These are THIS project's filled-in rules, moved out of the shipped template
when the comb found the template carrying our model names and incident
history into every adopted repository (2026-08-06). Shared defaults live in
`metasystem/metasystem.conf`; this file keeps the development-specific rules.

- Two rosters exist and must never be confused. **Development** of the metasystem and its kit uses, by the human's ruling of 2026-09-23 (R-122-m0, replacing the roster of 2026-09-21) and until further notice: Claude on Fable (`claude-fable-5-1`) for design authoring, Codex `gpt-6-sol` for design review, Claude on Opus (`claude-opus-5-5`) for building, and Codex `gpt-6-sol` for code review; Codex `gpt-6-astra` for the extra critique reads Wido asks for by name. A build spends far more tokens than a review of that build, so Codex reads and Claude writes; the author and the reviewer of any piece of work are always different models. Each seat names this roster in its own gitignored `metasystem/metasystem.conf.local`, which also keeps `claude-opus-5-5` in `runtime.claude.maximal-models` so that a design-bearing build does not escalate. A coordinator using a different model delegates design authoring through the design-mode roster. Correctness is still worth paying for. A **benchmark run** is the opposite: it measures the metasystem, repeats, and must stay cheap, so it hosts on Opus or Sonnet with `gpt-5.6-luna` delegates, configured in the spec's own manifest roster. Applying the benchmark's cost ceiling to development work cancelled three healthy jobs on 2026-08-05.
- Use focused canaries while changing code, then the shared testing contract in `metasystem/docs/project-rules.md` to select the required verification. Complete independent groups across every stage of the admitted selection and repair failures as a batch before another expensive run. Routine low-risk work does not require the full battery. Commit and landing consume matching successful proof without repeated tests or builds. Use the supported failure-stopping wrappers and actual structured results; never infer a verdict from a log tail or an unrelated earlier green.
- When a test fails, first check whether brittle assumptions about timing, execution order, shared state, paths, or external processes caused the failure. If they did, fix the underlying fixture or runner dependency before changing the test assertion. Preserve the behavior the test is meant to prove; retries, longer sleeps, and weaker assertions do not repair brittleness.
- Before claiming test concurrency works, verify every concurrency-capable suite runner through its real entrypoint, including nested runners. Record observed overlapping workers and successful results for each, and explain necessary serial execution. A configured worker count or a parallel peak in another part of the suite is not proof. Use existing runtime evidence; do not introduce a maintained runner inventory.
- On this development Mac, run suites with `METASYSTEM_TESTING_WORKERS=9`, as Wido requested on 2026-09-22 to shorten individual runs while accepting occasional overlapping suites. Keep the inherited `METASYSTEM_TEST_WORKERS` allowance intact. Other hosts retain their automatic or explicitly configured worker count.
- On the local `metasystem-debian` Linux VM, use six test workers with at least six allocated CPUs. Wido requested six workers and no CPU oversubscription on 2026-09-23; the VM currently has six CPUs and 16 GiB of RAM. Keep inherited worker limits intact.
- Run the normal suite on the current host by default. Run tests inside a VM only when Wido explicitly requests that run; a portability concern is a reason to recommend a VM check, not to start one automatically. Existing Linux cross-compilation checks still run on the current host and require no VM. Running the normal suite on a Linux host does not require a separate virtual machine. Do not add a platform inventory or classifier.
- Behavior tests stub or mock Git, including fixture setup; they must run with real Git unavailable. Wido explicitly requested this on 2026-09-23. Keep only narrowly named adapter integration tests whose actual Git interaction is the claim, with a concrete reason a stub cannot prove it. Use per-test dependency instances and existing injection seams; no global fake state, successful fallback to real Git, wholesale Git emulator, or maintained exception inventory.
- Committed implementation and test logic belongs in Go; Bash is for plumbing, as defined in `metasystem/docs/architecture.md`. Do not introduce other implementation or test languages into Git. Temporary local tooling is outside this restriction. The one exception, by human decision on 2026-09-21, is the browser interface's frontend: its React and TypeScript source, its npm build toolchain and development-time tests, all under `metasystem/`, and the built bundle committed inside the Go package that embeds it. The npm toolchain builds and is never part of the deployed runtime; the server and all application logic stay Go.
- A receipt is appended in the same commit as the work it describes. Bookkeeping-only commits hide the ratio of records to evidence, which is the retro's own inversion test (IL-19).
- `metasystem/metasystem.conf.local` contains secrets. Never read, echo, include in a diff, copy into an evidence bundle, or include its contents in a return. Use synthetic configuration files in isolated test fixtures when testing local overrides.
