## Decisions Reserved for the Human

All five were answered by the human on 2026-07-31: recommendations 1, 2, 3, and 5 accepted as stated; decision 4 confirmed (keep and document). Kept in full below as the record of what was decided.

1. **F4 mechanism.** Recommended: add `unresolved` as a sixth classification, defined disjointly from `no-progress` (critique round 2): `unresolved` is a valid measured result whose delta lies inside a declared noise floor; the run executed and produced an interpretable measurement that neither confirms nor refutes. Without a declared noise floor the classification is illegitimate, and a run that produces no interpretable measurement stays `no-progress`. Add an opt-in ledger line `- No-gain budget: N` that `assert-stop-loss.sh` enforces as "N trailing consecutive cycles without a `contract-improved`". The improve skill instructs writing `- No-gain budget: 3` and owns the mapping rule that reserves `contract-improved` for runs that pass `scripts/frontier.sh challenge` on the primary metric with every guard metric at or above its floor, so neither a guard-only improvement nor a guard-regressing gain can reset the count (critique rounds 2 and 3). Without a declared budget line, `unresolved` does not authorize another cycle on its own (human direction required, exactly as a single `no-progress` works today) and never counts toward the two-no-progress trigger. Alternative: a hard three-unresolved trigger for all ledgers, which would wrongly punish legitimate theory-killing runs in take-a-step-back.
2. **F6 approach.** Recommended: `check` tolerates a worktree whose only change is the baseline file itself, comparing porcelain paths against the `--file` value normalized to the repository root; a `--file` outside the repository is rejected by record and check alike, because dirt outside the toplevel is invisible to git; record's advice echoes the actual `--file` value (critique rounds 2 and 3). Alternative: reword only, which keeps a false block in the documented flow.
3. **F7 approach.** Recommended: keep the strict asset list in template mode (marker file present) and derive requirements from the skills present on disk in adopted mode: each present skill directory needs a valid SKILL.md, and runtime profile files are not required in adopted mode, because project-added skills never had them and core skills may drop them after registration. Note this deliberately loosens a shipped guarantee for adopted repos; the audit still validates whatever exists.
4. **F11 openai.yaml (resolved by evidence, veto only).** The removal recommendation is withdrawn: OpenAI's skill documentation defines `agents/openai.yaml` as invocation metadata consumed in place by OpenAI skill runtimes, which discover repository skills under `.agents/skills` including symlinks. Remaining work is documentation plus a `codex` registration target in `adopt.sh` (work items 12 and 14). Listed here so the human can veto keeping the files.
5. **F11 README.** Recommended: declare the README a second teaching exception (one sentence, as `docs/working-modes.md` has) and trim restated constants where a pointer is as clear. Alternative: aggressive thinning, which costs the README its pitch value.

3. **Close the classification gap (REM-3).** Add `unresolved` to `skills/take-a-step-back/SKILL.md` with decision 1's disjoint definition (a valid measurement inside a declared noise floor; illegitimate without one; uninterpretable runs stay `no-progress`). Record the decision in `development/source-analysis.md`.
4. **Add frontier direction (REM-4).** `record --direction max|min`, persisted as `direction=`, default `max` when absent so existing frontier files keep working. `record` resolves direction exactly like the noise floor (flag, environment variable, stored value, default), and a resolved direction that differs from the stored one is refused without `--force`, because a direction change re-baselines the frontier's meaning. `challenge` takes no direction input and ignores the environment: it compares using only the persisted direction, because a challenge-time reinterpretation has no `--force` recovery path (critique round 2). `status` prints the direction. Update `skills/improve/SKILL.md` and the improvement-evaluation line in `docs/project-rules.md` to declare direction with the evaluation, and give `docs/working-modes.md` a one-line touch so the teaching guide stops implying up-only improvement (non-material, cheap).
5. **Tighten proof-cell concreteness (REM-5).** `concrete()` requires a backticked token, a token containing a slash or file extension, or "Not applicable" followed by a reason containing at least one word character after the delimiter; bare "Not applicable" and the empty-delimiter "Not applicable:" both fail; delete the bare keyword whitelist. Owner cells pass only when they contain a backticked token, a token carrying a dot, slash, or double colon, or a CamelCase token; plain prose fails. Verify `docs/examples/design-obligation-matrix.md` still passes before committing. `development/metasystem-design.md` is a historical receipt the validator never gates; do not edit it to satisfy the new rule and do not treat it as a constraint.
6. **Fix the baseline first-run block (REM-6).** Per decision 2: `check` ignores dirt consisting solely of the baseline file, comparing porcelain paths against the `--file` value normalized to the repository root (via the git toplevel), so custom relative and in-repository absolute paths behave identically, and rejecting a `--file` outside the repository with a usage error, because git cannot see its dirt; record's closing line echoes the actual `--file` value: "commit <file> now or with the next checkpoint; check ignores this file's own dirt".
