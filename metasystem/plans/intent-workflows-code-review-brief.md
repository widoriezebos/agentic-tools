# Independent implementation review: complete tasks through intent

Round budget: three maximum, declared before round one; stop at the first round
with zero material findings. One correction round is the norm. This is diagnostic
review under the user's explicit machinery bypass, not an invented approved goal
box or governed certificate. Goal verbs-match-intent is tier3, risk3/2/3/2, queued.
Fable design chains used fixtures-as-arbiter, making this independent read mandatory.

Threat model: trusted human and agent operators, mistaken inputs, duplicate or
lost responses, concurrent work, process crashes/cancellation, failed/compacted
model outputs and ambiguous targets. Preserve real enrolled-human authority,
goal/branch/custody/budget invariants and evidence integrity. No hostile local
administrator/symlink-sandbox redesign, cryptographic redesign, extra platforms,
new provider integration or speculative future workflow is requested.

Scope: complete computed base-to-candidate change and all affected consumers.
Preserve every capability in intent-workflows-capabilities.md and unchanged
machine consumers. Root owns plans/rulings/receipts and the final certification;
Opus owns product/tests/public guidance. Existing expected help changes are
authorized; weakened assertions, coverage floors, fake delivery, and claimed
proof without actual owner execution are not. Other incoming main changes are
part of the base; do not attribute them to this implementation.

## Prepared immutable copy

The launch input review-subject.json names the exact physical/private checkout,
base commit, candidate commit, reviewedTree, full diff SHA256 and artifact paths.
Read that manifest and its actual computed diff FIRST. It includes committed,
uncommitted and formerly untracked unignored work; conf.local is never included.
Never replace it with a builder's file list or return. Do not edit the copy or
product. No new review chain, paid model, full test gate or push. Write findings
only to the declared external output paths. Root will run selected exact-candidate
acceptance and full coverage; this review does not mint those proofs.

## Materiality (apply verbatim)

> Would the change ship a defect, violate its brief, or damage what certifies it?

For each finding say whether the slice works and is safe without the fix, and
name the artifact that would change. Report demonstrated failures of the actual
first-use contract. Taste, optional consistency, theoretical hardening and proof
that first use does not need are non-material notes, never a fix-round demand.
Required named fixture absence/failure is material because design closure relies
on those fixtures. Root adjudicates every finding; critic never edits or disposes.

## Findings and return

Write both declared Markdown report and canonical return.json. JSON includes
reviewedTree, verdict, materialCount, unexamined and findings array with stable
id (ICR-1...), severity, boolean material, claim and evidence. Markdown includes
the corresponding table and concrete work/safety/artifact test for every material
item. Evidence names precise file lines and observed/reproduced failure or exact
control flow; a hypothetical word alone is insufficient.

Final response only the report path and VERDICT: land, or VERDICT: fix first
(N material findings). Zero material findings is advisory agreement; root retains
certification after its final immutable acceptance and runtime observations.
