On 2026-09-14 seat m1b's Bash tool ran a descendants walk that never ends under zsh; the tool's timeout moved it to the background and it burned 65 to 70 percent of a core for twelve hours (`records/misc/leaked-processes-diagnosis-2026-09-15.md:72-80`, class C). ## 2. Facts verified on this machine, 2026-09-16

**F1. A SessionStart hook's exports reach every Bash tool shell of the session.** Claude Code passes `$CLAUDE_ENV_FILE` to SessionStart hooks only; lines appended there are exported into later tool shells (installed hook reference, `~/.claude/plugins/marketplaces/claude-plugins-official/plugins/plugin-dev/skills/hook-development/SKILL.md:259-261,328`); the openai-codex plugin already writes there (`~/.claude/plugins/cache/openai-codex/codex/1.0.6/scripts/session-lifecycle-hook.mjs:35-40`). Live: this delegate's own tool shell (a headless `claude -p` session) is `/bin/zsh -c source ~/.claude/shell-snapshots/snapshot-zsh-<ms>-<tag>.sh 2>/dev/null || true && export CODEX_COMPANION_SESSION_ID='90addc77-...'<LF>...: && setopt ... && eval '<command, single quotes escaped as '"'"'>' < /dev/null && pwd -P >| /tmp/claude-<tag>-cwd`, and `env` there shows the three variables beside `CLAUDE_CODE_SESSION_ID` and `CLAUDE_PID`. The env file's text is thus in argv[2] and in the environment of every tool shell, both readable through `KernelProber.Probe` (`internal/identity/identity_darwin.go:86-102`).

**F2. The reaped-children CPU accumulator is readable, grows on the smallest child, and is the shell's own evidence of child work.** Measured with python3 ctypes: `proc_pid_rusage(pid, RUSAGE_INFO_V1, buf)`, 144 bytes, `ri_user_time` at offset 16, `ri_system_time` at 24, `ri_child_user_time` at 96, `ri_child_system_time` at 104, units mach absolute time at `hw.tbfrequency` 24000000:

| Case | Own CPU | Children CPU (reaped) |
| --- | --- | --- |
| a 1 s spin in the probe; `getrusage` says 0.956 s | 22934549 units = 0.956 s | 0 |
| the delegate's parent `claude` process, same user, no privilege | read ok | read ok |
| pid 1 (root) | refused, errno 1 | refused |
| zsh after `sleep 0; /usr/bin/true` five times, then idle | 0.0085 s | 360747 units = 0.015 s |
| zsh with a hot python child still running | 0.0030 s | 0 |
| the same after that child exited and was reaped | 0.0035 s | 12542721 units = 0.523 s |
| zsh whose child double-forked a hot grandchild | 0.0053 s | 18592 units = 0.0008 s (the subshell only) |
| zsh that `exec`ed its last command | 0.0083 s | 0 (reset by exec; no longer a shell) |
| the class C loop of the diagnosis record, over one second | 0.1645 s | 22901643 units = 0.954 s |

Same-user reads need no privilege; the accumulator grows when the shell reaps even `sleep 0`; a running child adds nothing until reaped; a double-forked grandchild never reaches the shell; exec resets it but leaves the shell shape. **The class C loop is not childless under this evidence**: every pass forks `pgrep`, `tr` and a subshell, reaped at about one CPU second per second. Section 11 escalates that.

## 3. Rules

Package: new `internal/busyshell`. Seams per R-104-m1e: `Clock`, `Sleeper`, `Prober` (`identity.Prober`, `identity.go:175-181`), `CPUReader`, `Table` (pid lister plus parent reader), `Custody`, `LockOwner`, `Signal` (`ref.go:129`), `Store` (registry, outbox, log, notices). Every witness runs on fakes with an injected clock; only P2 reads a real process, its own. Mutations: section 6.

- **P1 (shape).** The executable (`Exact.Exe`, `identity.go:42`) has base `zsh`, `bash` or `sh`; argv[1] is `-c`; argv[2] begins with `source ` and a path under `<home>/.claude/shell-snapshots/`; the environment is known and carries `CLAUDE_CODE_SESSION_ID`, a numeric `CLAUDE_PID`, `METASYSTEM_SHELL_OWNER` and `METASYSTEM_SHELL_OWNER_ROOT` (P3). Unknown argv, environment or executable never matches (`identity.go:46-52`). The parent is `CLAUDE_PID`, 1 or dead; any other live parent marks a subshell. Witness `TestToolShellShape`: the F1 argv matches; a foreign live parent, a `/bin/sh -c` hook, a python3 with the token, unknown-argv, unknown-environment and token-less rows do not.
- **P2 (CPU readers).** `identity.CPUTimes(pid) (own, children time.Duration, ok bool)`, cgo-free. Darwin: `SYS_proc_info` (336) call `PROC_INFO_CALL_PIDRUSAGE`, flavor `RUSAGE_INFO_V1`, the four F2 fields over `hw.tbfrequency` (as `enumerate_darwin.go:47` reads it); the builder confirms the call number with the F2 probe. Linux: `/proc/<pid>/stat` fields 14, 15 (own) and 16, 17 (children) (`identity_linux.go:140-146`), over `userHZ`. Any error: `ok=false`. Witnesses: `TestCPUTimesOfSelfAgreeWithRusage` (own pid against `Getrusage(RUSAGE_SELF)` at the same instant, within one second); `TestCPUTimesAreMonotoneAcrossASpin` (the spin ends on accrued CPU, never wall time); `TestCPUTimesOfAGonePidAreUnknown`; `TestCPUTimesDecodeTheChildFields` (a fake buffer with F2's `sleep 0` row decodes to 0.015 s of children).
- **P3 (custody, bound at creation).** *Record.* In the hook's start path, after arming (`supervision-hook.sh:1040-1050`) and before `session start` (`:1054`), the hook runs `metasystem steward shell-owner announce` with the root, the session, the main's pid and start, the start source and `--env-file "$CLAUDE_ENV_FILE"`. Under the lease registry lock (`internal/lease/verbs.go:275`) the verb reuses a record for the same session and main or mints `artifacts/agents/steward/shell-owners/<nonce>.json` `{nonce (random), runtimeSession, ownerRoot, mainPid, mainStartMicro, createdAt, source, digest}`, `digest` sha256 over the other fields, written atomically and refused when the file exists; then it appends `export METASYSTEM_SHELL_OWNER='<nonce>'` and `export METASYSTEM_SHELL_OWNER_ROOT='<ownerRoot>'` to the env file (F1), so every later tool shell inherits both at creation; a resume or compaction re-exports the existing nonce. A verb failure is a start notice; its shells are `unowned`. *Resolution.* The owner is read from `<acting root>/artifacts/agents/steward/shell-owners/<token>.json` and nowhere else; `ownerRoot` and `runtimeSession` come from the record, never from the acting root, the env root, an announcement or `CLAUDE_CODE_SESSION_ID`. Env root differs from the acting root: `foreign`, counted, never stored. No record: `custody-unknown`, a defect line. A record whose digest fails, whose `ownerRoot` is not the acting root, or whose `runtimeSession` or `mainPid` differ from the shell's environment: `custody-defect`, a defect line, never signalled (a nonce recorded in two checkouts, a copied or edited record and a foreign token all land here). A non-shell executable with the token: `token-non-shell`, a defect line. Otherwise the owner is written at the first sighting and never overwritten. The record survives the main's death: it lives outside `artifacts/agents/mains/`, where the census prunes announcements (`internal/census/run.go:654-685`); the pass retires it only when the main is dead, no live candidate carries the nonce, and it is older than 24 hours. Witness `TestCustodyBindsAtCreation`: main dead and announcement absent before the first sighting, owned and ended within the bound; the record copied verbatim into fixture checkout B, B reports `custody-defect` with zero signals while A acts; a token with no record; a python3 with the token; an edited `ownerRoot`. *Build prerequisite.* The hook edit (one call, about 12 lines) needs Wido's word before unit 2.
- **P4 (registry).** `artifacts/agents/steward/busy-shells.json`, read, reduced and replaced inside the tick under the arbitration lock (`internal/steward/tick.go:110-114`). Key: the full `identity.Ref` (`identity.go:25-31`). Fields: `ref`, `owner`, `commandSummary`, `commandDigest` (P9), `cwd`, `firstSeen`, `sightings[{at, own, children, childPids[], complete}]` (`complete` false when a read failed), `state` (`sighted`, `busy-forking`, `intended`, `ended`, `survived`, `gone`, the refusal states of P6 and P11), `refusal{kind, firstAt, lastAt, count}` (P10), `lastAction`. Reduce: append this tick's sighting, incomplete when a read failed; drop sightings older than twice the bound, never the newest; a Dead identity becomes `gone`, dropped once its outbox record is done (P7); an unreadable file becomes an empty registry with one log line, never a failed tick. Witnesses: `TestRegistryRetainsTheBaselineAcrossTicks`, `TestRegistryRecoversFromACorruptFile`, `TestRegistryKeysOnExactIdentity`, `TestRegistryRecordsIncompleteSightings`.
- **P5 (predicate: childless over the whole interval).** Busy when retained sightings i and n (n newest) exist with `at_n - at_i >= bound`, `own_n - own_i >= fraction × (at_n - at_i)`, and every sighting j in [i, n] is `complete`, lists no child, and has `children_j == children_i`. The childless interval therefore restarts wherever the accumulator grew, a child was listed or a read failed. `busy-forking`: the own-CPU condition holds over the bound but the accumulator grew; reported once per episode (P8), never signalled. Unseen by the evidence: a double-forked child is reparented to pid 1 and never reaps into the shell (F2); a shell that disowned its worker and then spins without forking is ended, the worker untouched (section 8). Witness `TestBusyPredicateOverSightings`: 31 minutes at 100 percent own, flat children, empty lists: busy; the critic's mixed row (30 percent own, a `go test` child reaped before the fourth sighting): not busy, and `busy-forking` when the lists are empty but the accumulator grew; 40 minutes at 0.5 percent beside a hot child, and 20 minutes at 100 percent: not busy; one incomplete sighting inside a qualifying hour: not busy until a full bound passes after it.
- **P6 (guard beside TERM and KILL, fail-closed).** Before TERM, and again before KILL after `TermGrace`, in order, each step refusing on its own state and never re-evaluating an old sighting in place of a failed fresh read: (a) identity by the guard's own probe: Dead is `gone`, Unknown or error `unknown-identity`; (b) a fresh `CPUTimes` reading: `ok=false` is `unknown-cpu`; the reading is appended and P5 re-evaluated with it; a grown accumulator is `kept-child-work`, a fallen own rate `kept-cpu-fell`; (c) the table: an `AllPids` error (`enumerate_darwin.go:25`) is `unknown-table`; a `ParentPid` false for a live pid (`:112-116`) is `unknown-parent`; a listed child is `kept-child-work`; (d) P11's states. Only a pass through all four sends; a refusal ends the action this tick, records the episode (P10), one log line and one notice per episode (P8). Witnesses, all seams fake, every row asserting zero signals: `TestGuardRefusesOnEveryUnknown` (one row per unknown and lock state); `TestGuardRefusesChildWork` (a child reaped since the last sighting; a child listed at the guard; the critic's mixed scenario with an empty final list); `TestGuardReprovesThePredicate`; `TestGuardRunsBeforeKillToo` (a KILL-side `unknown-cpu` leaves KILL unsent); `TestGuardNeverReusesAnOldSighting`.
- **P7 (action, durable intent first).** (1) Write `artifacts/agents/steward/busy-shells.outbox/<pid>-<startMicro>.json` (key, ref, owner, evidence, planned action, phase `intended`) atomically, before any signal; (2) TERM to the pid alone through `identity.SignalExact` (`ref.go:132-151`), phase `signalled`; poll `AliveRef` (`identity.go:191`) every `Poll` through `Sleeper` until `Clock` shows `TermGrace`; if Alive, the guard again, KILL, `KillGrace`; (3) outcome `ended`, `survived` (Alive after KILL, a defect) or `gone`, phase `outcome`; (4) append one JSON line to `artifacts/agents/steward/busy-shells.log` (key, entry, evidence, outcome), phase `logged`; (5) write the session notice (P8), phase `notified`; (6) remove the record and set the registry state. Every pass drains the outbox before reading candidates: `intended` with the shell Alive re-runs the guard and continues at (2), with the shell gone takes `gone` and continues at (4); every later phase continues at its next step. Idempotence: the append scans the log's tail for the key first; the notice write replaces by key. Witnesses: `TestActionCompletesFromEveryCrashPoint` (the fake store fails once after (1), (2), (4), (5) and on the notice write; later ticks with the shell Dead end with the record removed, exactly one log line and one notice); `TestActionSignalsByIdentity` (sequence intent, guard, TERM, poll, guard, KILL; exactly `TermGrace/Poll` sleeper calls).
- **P8 (notice, addressed to the session).** Every outcome and refusal episode writes `artifacts/agents/steward/session-notices/<runtimeSession>/<key>-<kind>.json` `{runtimeSession, key, kind, message, createdAt, surfacedAt}`, `runtimeSession` from the owner record. Reader: new verb `metasystem steward session-notices --repo <root> --session <session>` prints that session's unsurfaced notices and stamps `surfacedAt`; the Stop hook calls it beside the pending line that runs before every exit (`supervision-hook.sh:2507-2508`) with its own hygienic `$session` (`:1552-1566`), and the start path beside `:1054` for a resumed session. A headless session runs the same hook; no tmux. The checkout notifier stays as a secondary copy through `steward.QueueNotification(ownerRoot, ...)` (`internal/steward/intervene.go:336-350`, `notify.go:41-88`). Message: kind, time, pid, own CPU seconds over the span, `cwd`, `commandSummary`, `commandDigest`, and "match the digest against the command in your transcript; re-issue or abandon it by hand"; each kind has its own truthful wording; no resume from stored argv is promised. Witness `TestNoticeReachesOnlyItsSession`: sessions A and B share one fixture checkout; A's shell is ended; the verb with A's session prints the notice once, with B's never; the checkout copy exists once under `ownerRoot`.
- **P9 (redaction; no full command anywhere).** Registry, outbox, log, status, health, notices and the checkout copy carry only `commandSummary` and `commandDigest`. The digest is sha256 over the tool's command text: the text between the final `eval '` and the closing `' < /dev/null` of argv[2], `'"'"'` unescaped (F1), so the session matches it against the `command` of its own Bash call. The summary is that text after `busyshell.Redact`, then its first 200 characters. `Redact` replaces with `<redacted>`, case-insensitively: the value after `Authorization:` and after `Bearer `; the value in `(token|key|secret|password|passwd|pwd)\s*[=:]\s*\S+`; `user:pass@` in a URL; the value of every `NAME=value` and `export NAME=value`. Witness `TestRedactionHidesSecretShapes`: plant `curl -H 'Authorization: Bearer secret-value' https://u:p@host/x?token=abc`, run the pass through `ended` on fake seams, assert `secret-value`, `p@` and `abc` occur in no output text (the 64-hex digest masked first, since hex can contain `abc`) and that the digest equals sha256 of the planted command.
- **P10 (refusal episodes and the health role).** `refusal` starts at the first refusal of any P6 or P11 kind with `firstAt` = that tick's clock; later refusals update `lastAt`, `count` and the kind, never `firstAt`; it resets to null when a sighting evaluates P5 false or the entry ends. `busy-shells` joins `healthRoleOrder` and `KnownHealthRole` (`internal/steward/health.go:66-92`): dead when any entry is `survived` or has an episode with `firstAt` older than twice the bound; unknown when the registry is unreadable; alive otherwise. The `Reason` (`health.go:96-108`) lists entries acted on within retention, so the health line and the Stop report's per-role line (`internal/report/stoppresentation.go:1287-1291`) carry the event; the preview refuses unknown fields (`:275`), so the role lands in steward and hook together. Witness `TestBusyShellsHealthRole`, fake clock, bound 30: refused on every tick for ninety minutes, the role flips to dead exactly at the tick 60 minutes after `firstAt` (the seventh refusal), alive at the sixth; refused, then P5 false, then refused again: a new `firstAt`; `survived`: dead; an `ended` entry: alive with the event in the reason.
- **P11 (authority and the test-run lock, fail-closed).** A pass signals only an entry whose record's `ownerRoot` is the acting root; `foreign`, `unowned`, `custody-unknown` and `custody-defect` are counted, never signalled. `LockOwner` reads `/tmp/metasystem-testrun-lock`: directory absent, nothing protected; present with `owner` absent, unreadable or without a decimal token: `lock-indeterminate`, every signal refused this tick; a token naming a pid of Unknown liveness: `lock-owner-unknown`, every signal refused; a live pid protects itself and its descendants: a candidate that is one, or whose ancestor chain (`ParentPid` to 1, at most 64 hops, any false `unknown-parent`) contains one, is `kept-protected`; dead pids protect nothing. Witness `TestPassNeverSignalsAForeignOrProtectedShell`, zero signals in every row: a record naming checkout B, run from A; an owner file naming the candidate, then its parent; the lock directory with no owner file; an unreadable or malformed owner file; an owner pid of Unknown liveness; a parent read failing mid-walk.
- **P12 (wiring).** `RunTick` (`tick.go:104`) runs the pass after `ReapContinuations` (`tick.go:170`) and before the decision; the pass drains the outbox, enumerates the table as `census.EnumerateProcesses` does (`internal/census/production.go:45-50`), classifies, reduces, guards and acts; its error rides `TickResult.BusyShells` (`tick.go:45-58`), never `degradedTick` (`tick.go:323`). Witness `TestTickRunsTheBusyShellPassAndSurvivesItsFailure` (registry unwritable: the tick completes with the error in its result; a pending outbox record is drained first).
- **P13 (knobs and the fixture scale).** `metasystem.steward.busy-shell-minutes` (git config as `TickSeconds`, `internal/steward/runner.go:97-98`; default 30; 5 to 1440). In a fixture-enrolled checkout only (`EnrollmentFixture`, `internal/steward/identity.go:40`, as `notify.go:49` checks) the bound, `TermGrace` and `KillGrace` are scaled by `METASYSTEM_FIXTURE_CAP_SCALE_MILLI/1000`; a production root ignores it. Witnesses `TestBusyShellKnobsValidate`, `TestBusyShellScaleAppliesOnlyToFixtureRoots`.
- **P14 (status counts).** `steward status` (`cmd/metasystem/steward_verbs.go:800`) gains `busyShells{sighted, busyForking, intended, ended, survived, refused, foreign, unowned, custodyUnknown, custodyDefect, tokenNonShell}` from the registry and the pass result, plus the session notices. ## 11. Escalation: the incident's own shape

Item: the Intent's motivating case, "such a shell" of R-112-m1e decision 2, is the class C loop; the DONE reads "a seat shell that burns CPU with no child process for 30 minutes ... never ending a shell whose work is in its children". The class C loop is not childless under the reaped-children evidence (F2, last row): it forks `pgrep`, `tr` and a subshell every pass and reaps about one CPU second per second of children. Under any predicate that honours the DONE's second half, a fork-heavy busy loop is indistinguishable from a legitimate fork-heavy loop (an hour-long `gofmt` loop over many files shows the same own CPU, short reaped children and empty lists); the difference is that one never terminates, which no engine-readable evidence shows. This page therefore delivers the DONE's letter, reports the incident's shape as `busy-forking` to its session, and does not end it. That is not a narrowing of the DONE; it is a gap between the Intent's example and the DONE's text that only Wido can close.

- (a) Accept for this goal: fork-heavy busy shells are reported to their session, never ended. Cost: the exact incident recurs as a notice and a seat ends it by hand.
- (b) Extend R-112 decision 2: a seat tool shell whose own CPU stays at or above the fraction for the bound is ended even when it reaps short-lived children, provided no child was listed at two consecutive sightings. Rationale: a tool shell past the Bash tool's ceiling (600 s at most) is already backgrounded and unread. Cost: a legitimate fork-heavy loop over 30 minutes is ended and its session told to re-issue it; one more unit.

Recommendation: (a) now, so the DONE lands unchanged, with (b) as its own goal if Wido wants the incident's shape ended by the engine.
