## Material findings

### ER-C1: "closed-result reference" means an author-dispositioned chain; `test` cannot consume one

- **Different or wrong?** Wrong. **Works and safe without it?** No: step 1 fails at first use, or admits the builder into closure.
- **Design contract:** Result contract, "Examination reference: existing authenticated job, session, subject and closed-result reference, supplied by the review owner" (line 136); ER-1 rejects an "unclosed examination" (line 199); Roles, "no human approval step" (line 76).
- **Source fact:** `internal/readsubject/closure.go` `ReadClosedClosure` (lines 120-258) accepts a reference only when the root has `chainClosed`, a clean `findingRegister` and `findingRegisterRound` equal to the closure round and at least 1. `internal/dispatch/build.go:681` initialises every chain with an empty register at round 0; the round is set only by a fold (`finding_register.go:234`) and `chainClosed` only by `metasystem close` (`close.go:247`), which for a review chain requires the author's `--dispositions` (`intent_delivery.go:48,86`).
- **Failure:** `metasystem test --goal G` dispatches the examiner, the examiner completes, and the reference stays "unclosed" until a person or the builder runs `close --dispositions`. Either `test` reports in-progress forever (ER-5 "test follows the same assessment" fails) or the builder folds the register to close it, so construction sits inside the closure of its own examination (ER-1 "reject builder session" passes on session identity but the closure act is the builder's).
- **Smallest correction:** state that an evidence examination closes at the examiner job's own terminal `completed` return that binds the evidence subject: extend `ReturnBindsSubject` and closure for the evidence kind with a required empty register folded at round 1 by the review owner at collection time; the verifier reads decisions from the examiner's round return by job and session reference; `metasystem close --dispositions` plays no part and a register touched by any chain member other than the review owner refuses.

### ER-C2: "newer failure prevents acceptance" is undefined at component granularity, and the parent's own failure is the newest observation

- **Different or wrong?** Wrong in either direction. **Works and safe without it?** No: ER-4 is unreachable under one reading, ER-2 gives a silent false pass under the other.
- **Design contract:** ER-2 "newer failure or live producer prevents acceptance" (line 200); verifier checks "newer contradictions" (line 150); ER-4 "all obligations complete while old parent remains failed" (line 202).
- **Source fact:** `internal/proofrun/test_result.go` `newestReuseObservation` (420-511) ranks observations per group id and identity by `group.Status`; a section group has exactly one status from `parseSectionResult` (`test_section.go:10-57`, one `section<TAB>name<TAB>pass|fail|gated<TAB>exit` line, called from `test_build.go:2006`). No per-scenario record exists in custody today.
- **Failure:** In ER-4 the cited components come from attempt A1 whose `section/adoption-fixtures` status is `failed`, and A1 is the newest observation of that group at its identity. An implementer who keeps the existing group-level rule refuses every citation (ER-4 fails). An implementer who checks only component records misses a newer group-level failure written by an engine that emits no components (ER-2 fails silently: the composed result is sufficient while the seat holds a newer red for the same group).
- **Smallest correction:** define the contradiction rule once: for a cited component, refuse when any observation of that component id at the cited identity is newer than the cited one and not passed, when any observation of the parent group newer than the cited attempt carries no component records, or when any producer of the parent group is live; the citing attempt's own non-success terminal is not a contradiction of its completed components. Add to the section protocol a component line form and a parent status that is never `pass` for a partial run, so `parseSectionResult` can never read a residual scenario run as a group pass (the bed already prints "diagnostic selection, not the bed's gate result", `fixture-bed-scenarios.sh:307`).

### ER-C3: the step-1 coverage carry rule cannot fire on the motivating change because "coverage-producing source" is the whole execution root

- **Different or wrong?** Different, and ER-4's residual is wrong. **Works and safe without it?** It is safe but does not do the one thing step 1 promises: the native gate reruns after an audit-only correction.
- **Design contract:** Native coverage, "carry an existing complete coverage measurement only when its coverage-producing source, test inputs, embedded assets, dependency/toolchain, instrumentation flags, platform, package inventory and ratchet are unchanged. The examiner may establish applicability across other input changes, such as the shell audit expectation" (lines 171-174); ER-4 "examiner requires audit and failed scenario, rerun those and required current parent checks" (line 202).
- **Source fact:** `internal/proofrun/coverage.go` `reusableCoverageForAttempt` (218-262) requires `evidence.InputManifest == FullDigest(executionRoot)` and `evidence.EngineDigest == Digest(executionRoot)`. Any edit under `scripts/` changes the full digest. The audit-expectation fix in the motivating incident is under `scripts/`.
- **Failure:** With the existing predicate kept, the coverage component from the failed parent is never carriable for a scripts-only change, so the residual set must include the full coverage producer, which is the native gate; ER-4's stated residual is wrong and the goal's cost saving does not occur. The examiner clause cannot rescue it: the same paragraph forbids the examiner from carrying coverage across changed measurement inputs, and the only measurement-input identity that exists says they changed.
- **Smallest correction:** name a deterministic coverage-input digest for the component route (the engine projection paths already used by `engineProjectionTree` in `cmd/metasystem/test.go:1597`, plus test inputs and testdata, embedded assets, go.mod and go.sum, instrumentation flags, package inventory, ratchet, toolchain and platform), record it in the component at `CompleteCoverage`, and compare that digest instead of the full root digest. Remove examiner discretion from coverage carry: coverage is exact-identity only in step 1. The examiner then decides scenarios and the audit check, never coverage.

## Deferred suggestions and implementation obligations (not material)

These do not change step 1's shape; each is fixture-expressible and becomes an implementation obligation.

- **Native-success owner for the coverage component.** `CompleteCoverage` today has no native-success input; it relied on the parent's `TerminalSuccess`, which the component route drops. State that the Go native gate (`proof_run.go go-gate-tests`) retains expected and observed terminals in the component and that completion derives from them, never from a shell argument. Replacement predicates for the component route: evidence written under the mutation lock while the attempt was live and uncancelled (already checked at `coverage.go:115-117`), the attempt now has a terminal of any result, and every identity equality holds.
- **Examiner reader budget.** Both review kinds route through `reviewBriefFacts` (`intent_delivery.go:625,709`), which refuses without `--tool-calls` and without an approved goal budget with `ReviewRoundLimit >= 1`. `test` has no such flag and must not gain a caller knob. Name the bound's source (hazard-class configuration obligations or a fixed examiner budget in the testing contract). Review rounds are not decremented anywhere in dispatch, so attachment is not budget-limited.
- **Subject digest purity.** Attachment of repeated requests relies on subject equality. The evidence subject's "freshness context" must not include a per-invocation episode or timestamp, or every `test` pays a model call and ER-5's attach case fails.
- **Residual scenarios run through the parent runner's named selection**, so the process-group reaper (`fixture-bed-scenarios.sh:243-250`, rc 125) and cleanup apply; never the child environment path.
- **Citations resolve only inside the subject's original-observation set**; a citation to any other attempt refuses with the missing fact.
- **Examiner role.** `exactCriticRole` and `ReadClosedClosure` accept only code-critic, design-critic and warden. Say which role the examiner is dispatched under or extend the closed set in both places; the critic-only exemption in `validateHazardCompletion` (hazard.go:248) correctly means the examiner chain itself needs no further critic.
- **Schema bump is a fleet event.** `requireTestingWorkerCapabilities` demands exact schema equality with the trusted destination engine, so every seat installs the compatibility release before `metasystem test` runs again. Correct behaviour, but schedule it.
- **Smallest slice.** Step 1 remains the smallest thing that works. A deterministic-only slice (failed scenario plus changed-input scenarios) needs per-scenario input declarations, which the design correctly defers to `test-selection-improves-on-the-simple-rule`; the section group declares `scripts/**` as one input. `review evidence` adds no new path.
