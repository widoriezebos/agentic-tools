## Decisions the seat has taken (build on them; argue only with evidence)

- D1 The lane stays language-neutral. It decides only whether a proof is full or scoped, against which green tree, and it records what ran and why. It computes nothing language-specific and keeps the project's `landing.prove.command` as its one way to run tests; what it asks of that command is passed in the environment beside `LANDING_TREE` and `LANDING_COMMIT` (you name the variables and their contract). A project whose command ignores them gets today's behaviour: a full proof every time.
- D2 Which groups a change affects comes from machinery that already exists, never from a second selector and never from a hand-kept list: the testing contract's groups and their declared inputs (facts 4, 11), `metasystem test run`'s selection, retained reuse by execution identity and its record of selected, fresh and omitted groups with reasons (fact 6), and the language adapter seam (fact 7) for the module graph. You decide how the VM proof reaches that runner (run `metasystem test run` in the VM, or something smaller), and say why.
- D3 Step 1 (R-121) is the re-proof after a tip move, the livelock in the goal's evidence: when the lane must prove a tree that differs from a green tree of the same batch only by what main gained meanwhile, it proves the groups that difference affects and keeps the green for the rest. A batch's first proof stays the full suite in step 1, so code a batch brings is always fully proved. Scoping a batch's first proof, with its full-suite cadence (every batch that touches engine core, and at least hourly), is step 2; name what step 2 builds on.
- D4 The full suite still runs at least hourly: if main has no full green proof newer than one hour, the next proof is full. Say plainly how much step 1 loosens today's rule (whole tree at every push), for example which pushed trees were never proved as a whole and how long a missed dependency can stay on main.
- D5 Safe defaults, all to a full proof: a language with no adapter, an adapter error, an unreadable or invalid contract, a changed path that no group's inputs cover and no adapter unit owns, and `go.mod`/`go.sum` (fact 6). Each is recorded with its reason.
- D6 The ledger shortcut (fact 3) is removed in step 1: a ledger-only difference is the case where the changed paths select only the groups that declare ledger paths. Over-broad inputs such as `verb-ratchet`'s `metasystem/**` make that group run on every difference; say whether step 1 narrows it or accepts its cost (measure it from the proof logs, fact 5).
- D7 The binary-dependency miss (fact 8) must not recur in a scoped proof. Say how step 1 closes it in the neutral contract (for example a group that builds and runs a binary declares that binary's source among its inputs, checked by a test, or a main package's change selects every group that builds it), and how a Java adopter's equivalent (a test that runs another module's built artifact) is covered.
- D8 The hang rule is deferred, because the VM suite's 25-minute per-binary timeout now bounds a hang (fact 9) and `metasystem test run` has its stall supervisor (fact 6). Name the record field (per-group measured duration) the ten-times rule will build on.
- D9 `docs/project-rules.md:50` is amended by this work: say the new sentence.
