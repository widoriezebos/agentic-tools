## 2. Decisions

### D1. The capability vocabulary

Six names. Each is defined by a measurement that runs in the delegate's environment and can fail. The table lives in Go (`internal/sandboxcap/vocabulary.go`); a name outside it is refused wherever it appears. The measurement is one Go verb (D3); it execs the shell tools where the beds use shell tools and uses syscalls where the engine does.

| Capability | The measurement (all steps must pass) | Fails when |
| --- | --- | --- |
| `temp-isolation` | `mktemp -d` under the launched `TMPDIR` succeeds; the resolved path is outside the worktree and outside its git directory (`git rev-parse --absolute-git-dir`); the same holds for `GOTMPDIR`; inside it, with the environment the harness gives scenario children (D4), `git init`, one commit, `git clone --bare`, a clone of the bare copy, a `git push` from the clone to the bare copy and a `git fetch` back all succeed, and `git count-objects` in the scratch repository is greater than zero while the quarantine store's count is unchanged; a FIFO (`unix.Mkfifo`) under it can be created, opened both ends and written; an exclusive file lock (`unix.Flock`) under it can be taken and released; the directory can be removed | any step exits non-zero, a path is inside the worktree or its git directory, or the scratch objects landed elsewhere |
| `temp-exec` | a shell script written under `TMPDIR` and made executable runs, both by path and through a directory prepended to `PATH` | the script cannot be made executable or does not run |
| `own-process-inspection` | with a child the probe spawns (`bash -c 'exec -a metasystem-sandbox-probe-<nonce> sleep 30'`, so the nonce is its argv): `ps -p <self>,<child> -o pid=,ppid=,pgid=,command=` prints both rows with the nonce; `kill -0 <child>` succeeds | a command exits non-zero or a row is missing |
| `process-enumeration` | `ps -axo pid=,ppid=,pgid=,command=` exits zero and contains the child's row; `pgrep -f <nonce>` prints the child's pid | a command exits non-zero or the row is missing |
| `process-group` | in a non-interactive bash with `set -m`, a background `bash -c 'sleep 30 & wait'` is its own group leader (`[[ -o monitor ]]`); `kill -0 -- -<pid>` succeeds; `kill -TERM -- -<pid>` succeeds; within five seconds `kill -0 -- -<pid>` fails and the leader is reaped | monitor mode is refused, a group signal is refused, or the group survives |
| `detached-start` | a child started with its own session (`Setsid`) survives its parent's exit for one second and can be signalled by pid, then is killed | the child is gone after the parent exits, or the signal is refused |

Why these and nothing else: the hook bed needs only its own rows from `ps` (1.1), so own-process inspection is split from enumeration and a sandbox that permits the first and denies the second is not falsely incapable; the beds build executables under the temporary directory, so `noexec` is measured, not assumed; the engine below them uses a FIFO and file locks, so both are in the temporary-isolation steps; the land and supervision beds arm owners that outlive the arming command, so a detached start is measured. The beds need no network. Signalling one's own child by pid needs no capability any sandbox in the record denies. Wall-time reliability of a long scenario under a sandbox is not a capability and is not claimed; row 31 owns it. A future need is added to the Go table with its measurement, never to a bed.

### D2. How a bed declares itself

Every bed script carries three header lines at column zero within its first 40 lines, and a bed that has sandbox needs carries a fourth:

```text
# Bed: land-fixtures
# Section: land-fixtures
# Depends: scripts/agents/fixture-bed-scenarios.sh scripts/agents/fixture-budget.sh scripts/agents/fixture-assert.sh
# Sandbox-Needs: temp-isolation temp-exec own-process-inspection detached-start
```

`Bed:` is the script's own identity and must be unique across every registered file. `Section:` names the section id from the catalog (`validate-section-selector.sh:8-55`) that runs the script, or `none` for a script no section runs. `Depends:` lists repository-relative paths and globs the bed sources or executes beyond its own file, or `none`. `Sandbox-Needs:` is a space-separated list of D1 names; a bed without the line is `undeclared` for assignment and nothing else. The three mandatory lines are what makes the touched-bed closure (D5) complete: the registry, not `validate-metasystem.sh`, answers which scripts a section runs, and a headerless script cannot hide in a section.

### D3. How the probe measures, where it is recorded, when it goes stale, and what it can attest

The measurement is one Go verb, `metasystem adapter sandbox-measure --output FILE [--worktree DIR] [--needs LIST]` (`internal/sandboxcap/measure.go`). It runs the D1 measurements (all six, or the named ones) in the calling process's environment and writes the measurement file:

```json
{"schemaVersion": 1, "measuredAt": "...", "os": "<uname -sr>", "tmpdir": "...", "gotmpdir": "...",
 "worktreeGitDir": "...", "probeVersion": 1,
 "capabilities": {"temp-isolation": {"present": true, "detail": "..."},
                  "process-enumeration": {"present": false, "detail": "ps -axo: exit 1: Operation not permitted"}}}
```

It measures where the beds will run, so it runs inside a delegate: the seat verb `metasystem adapter sandbox-probe --runtime R` (`internal/adapter/sandboxprobe.go`) dispatches one implementer-role job under the workspace preset in a job worktree of a throwaway repository, the way the self-test dispatches its permission legs (`selftestrun.go:273-310`), through the adapter operation `sandbox-probe-launch` (a distinct name, so the seat verb and the adapter operation cannot be confused or recurse). The brief asks for exactly one command: `<enrolled engine> adapter sandbox-measure --output <scratch>/sandbox-probe.json --worktree <workspace>`. The verb reads that file and never the model's words. A missing or malformed file records every capability `present: false` with detail `probe result absent`.

What the probe can attest, said plainly. The model runs the command; a model with write access to the scratch root could write the file itself. No adapter can run a command under the runtime's sandbox without the model (section 1.2), so the probe is a forecast made under the delegate's envelope, not an observation the seat made. Two things bound the damage. The result is bound to the envelope class it was measured under, and the measurement of record is the bed's own preamble (below), so a wrong forecast costs at most the seconds of the preamble, a forged forecast cannot make a bed pass, and the seat's proof remains the recorded proof whatever the report says.

The record. The snapshot gains one optional member, `sandbox`, written through `adapter capability-snapshot --sandbox FILE` from the measurement file; its exact schema, which the writer validates and the reader depends on, is:

```json
{"sandbox": {"schemaVersion": 1, "measuredAt": "...", "os": "<uname -sr>", "probeVersion": 1,
             "envelopeClass": "sha256:...",
             "capabilities": {"temp-isolation": {"present": true, "detail": "..."}, "temp-exec": {"present": true, "detail": "..."},
                              "own-process-inspection": {"present": true, "detail": "..."}, "process-enumeration": {"present": false, "detail": "..."},
                              "process-group": {"present": true, "detail": "..."}, "detached-start": {"present": true, "detail": "..."}}}}
```

`capabilities` holds exactly the six D1 names, each with a boolean `present` and a string `detail`; `measuredAt`, `os` and `probeVersion` are copied from the measurement file; `tmpdir`, `gotmpdir` and `worktreeGitDir` are not copied, they describe the throwaway job. Stale means any of: the snapshot is older than `capability.snapshot-max-age-days`; `sandbox` is absent (unmeasured); `sandbox.os` differs from the current `uname -sr`; `sandbox.probeVersion` differs from the running engine's `sandboxcap.Version`; `sandbox.envelopeClass` differs from the job's. A stale or absent member does not refuse dispatch. It makes every bed a seat bed with reason `unmeasured` or `stale:<why>`, and dispatch prints one line naming `metasystem adapter sandbox-probe --runtime R`. The steward health row `capability-snapshots` (`internal/steward/health.go:61`) adds a warning per configured runtime whose newest snapshot has no fresh member. The adapter operation is added to `runtime-common.sh` and answered by `claude.sh`, `codex.sh`, `devin.sh` and `fake.sh`; the fake runs `sandbox-measure` in its own process (the host's truth) and accepts `--sandbox-profile <name>` to script absences for fixtures, like its `--profile` today (`fake.sh:362`).

The envelope class. The expanded envelope carries absolute roots, three of them under the repository's own git directory (section 1.2), so its digest can never match between a probe in a throwaway repository and a real chain. The class is therefore computed before expansion, by a function `dispatch.EnvelopeClass(presetPath, isWorktree, withScratch)` that hashes the unexpanded preset bytes (`permissions/workspace.json` as shipped) together with the ordered list of tokens for the roots the expansion would add without resolving any of them: `<worktree>` for the workspace, and for a worktree job `<worktree-gitdir>`, `<agent-refs>`, `<agent-reflog>` (the three roots of `envelope.go:139-155`) and `<scratch>` (D4). No path enters the hash. The probe job and every implementer round are worktree jobs under the workspace preset with the scratch root, so they have one class, whatever repository they sit in; a job under the critic preset has another. `TestEnvelopeClassAcrossRepositories` is written first (fixture first, unit 2b): a probe job in a throwaway repository and a real chain in another repository have one class, and the same preset without the worktree roots has a different one. Exact roots are still validated per job by the envelope expansion, as today; the class only says the policy is the same.

The preamble. `run_fixture_bed_scenarios` runs `sandbox-measure --needs <the bed's Sandbox-Needs>` at bed start in the bed's own environment and writes the result into the report (D6); when a declared need is absent at run time the harness writes `outcome: capability-absent` and exits 3 before any scenario, and review conformance reads that as `assignedTo: seat, reason: measured-absent-at-run` rather than refusing the return. A provider policy change after the probe is caught at the next bed run, whoever runs it.

### D4. Where the delegate's temporary directories live, and who owns them

The envelope for a worktree job gains one write root, the chain scratch root `<installation>/artifacts/agents/scratch/<root-job>/`. It is added in `ExpandPermissions` beside the git roots (`envelope.go:16`), so it is recorded in the job record's requested envelope, reaches Claude's `allowWrite` (`claude.go:34-36`) and reaches Codex as an extra root (`codex.go:80`). Ownership, one owner per moment. The dispatcher creates the root and its four subdirectories `tmp`, `go-tmp`, `bed-reports` and `package-runs` when it creates the job worktree, before `finalize_and_launch` (`dispatch.sh:2000`); before each round's launch it empties `bed-reports` and `package-runs`, so a report can only come from the round it is read for. The reaper, when it marks a round terminal, moves `bed-reports` and `package-runs` into `rounds/<n>/` by directory rename before it calls `job mirror` (`dispatch.sh:1186-1194`), so the mirror carries them and nothing reads a half-written report. The dispatcher removes the root when it removes the worktree.

The harness `fixture-bed-scenarios.sh` gains three things, each a no-op when the seat runs a bed: it strips the git steering family from every scenario child's environment (the names `gittree.ScrubbedEnviron` strips; `land-fixtures.sh:15` keeps its own unset); it records after `set -m` whether monitor mode took effect and, when it did not, reaps by pid instead of by group and says so once on stderr, and the report records `reapMode: pid`, which is not a cleanup guarantee for grandchildren and is not claimed as one; and it runs the preamble measurement and writes the report members of D6. ### D5. The assignment rule, the touched-bed closure, and its two moments

The rule is one Go function, `sandboxcap.Assign(registry, sandboxMember, touched)`. A bed is assigned to `delegate` when it is a harness bed, declares needs, and every need is `present` in the runtime's snapshot member. Otherwise it is assigned to `seat` with one reason: `undeclared`, `sequential`, `unmeasured`, `stale:<why>` or `missing:<capability>`.

Touched is one explicit closure, `sandboxcap.TouchedBeds(changedPaths, registry, plan)`, used by the packet, the return, conformance and the proof record alike. A bed is touched when a changed path is the bed script itself; or matches one of its `Depends:` entries; or `testpolicy.Select` selects the bed's declared section for the changed paths. The third clause is the proof's own selection, and because every script declares its section (D2) it names every script the section runs, including `runtime-hook-fixtures.sh` and `health-fixtures.sh`; the first two add the beds the selection misses (a harness edit touches every harness bed; a helper edit touches every bed that lists it); an orphan is touched by the first two only. Over-assignment costs delegate minutes, under-assignment costs a round.

Moment one, dispatch. ### D6. The evidence contract: reports, receipts, and what review conformance refuses

Bed evidence is a file the harness writes. The report's schema 1 is owned by the verification-loop program's first member (its D6): `bed`, `section`, `startedAt`, `endedAt`, `exitStatus`, `scenarios[]` with `leg`, `terminal` and `silentExit`, `failures[]`, `tails`. This goal adds schema 2 members: `treeId`, the snapshot of the worktree the bed ran on, computed at bed start by `metasystem test tree-id --worktree DIR`, one call to the same primitive conformance uses (`gittree.go:255-277`), so it equals `reviewedTree` when the worktree did not change; `engineDigest`, the sha256 of the resolved `METASYSTEM_BIN`, and `engineStamp`, the stamp it was built with (`go-build.sh:51-78`); `capabilities`, the preamble measurement of D3; and `outcome`, `ran` or `capability-absent`. What the report binds: the source tree, by identity; the engine, by record. Whether an engine built from the same tree by the seat has the same digest depends on `go-build.sh --out --trimpath` being reproducible on one toolchain, which is not established here; member 6 records both digests and the claim stays "bound to the source tree the bed ran on, with the engine it ran identified" until a fixture shows the digests equal.

Package evidence is a receipt the engine writes. `metasystem test package-run --package ./<pkg> [--package ...]` runs `go test -json` on the named packages with no selector, refuses `-run`, `-skip` and a `GOFLAGS` that carries either, and writes `<METASYSTEM_PACKAGE_RUN_DIR>/<pkg with slashes as dashes>.json`: `argv`, `cwd`, the `GOFLAGS` seen, `exitStatus`, `treeId`, `engineDigest`, and `tests[]`, the names that ran from the `go test -json` events. A delegate that ran `go test -run` by hand has no receipt, which is the same as not having run the package.

Review-stage conformance (`conformance.go:354`), which the seat runs before any read is paid, adds these checks after the boundary check; the program page's D1 gives them a typed outcome beside the string interface. Each is a registered refusal row (`internal/refusal/register.go:35`, shape `agent`) with a plain-English line that names the item. None reads `evidence[]` prose. The package rows are built today (member 5b); the bed rows wait for member 8.

| Code | Refused when |
| --- | --- |
| `PACKAGE_RUN_MISSING: <package>` | a Go package has a changed `.go` file in the diff and no receipt names it, or the receipt's `exitStatus` is non-zero and no `gaps` entry carries `package:<package>` |
| `PACKAGE_RUN_STALE: <package>` | the receipt's `treeId` differs from `reviewedTree` |
| `PACKAGE_RUN_ONLY_NEW_TESTS: <package> (TestA, TestB)` | the base tree's runnable set for the package is non-empty and the receipt's `tests[]` shares no name with it, so only tests this round added ran; reported instead of `PACKAGE_RUN_MISSING` so the delegate learns what it did |
| `BED_EVIDENCE_MISSING: <bed>` | the bed is in the delegate column, `delegateBedsRequired` is true, and `rounds/<n>/bed-reports/<bed>.json` is absent |
| `BED_REPORT_MALFORMED: <bed> (<why>)` | the report does not parse, its `bed` or `section` differs from the registry, a scenario name repeats, or a report exists for a bed not in the delegate column; fail-closed |
| `BED_EVIDENCE_STALE: <bed>` | the report's `treeId` differs from `reviewedTree` |
| `BED_RED_UNREPORTED: <bed> (exit N; failed: a, b)` | the report's `exitStatus` is non-zero, or a scenario is `silentExit`, and no `gaps` entry carries the exact token `bed:<bed>` |

The base tree's runnable set is what `go test` would run there, not what the source text says: conformance checks out the base tree with `NewDetachedWorktree` (`internal/gittree/detached.go:13-28`), runs `go test -list '^Test' ./<pkg>` in it with the same toolchain, platform and `GOFLAGS` the wrapper recorded (the form the gate already uses, `go-gate.sh:672`), and caches the list under `artifacts/agents/compare/base-tests/<tree>/<pkg>.json`. A package whose runnable base set is empty, because it had no tests or only tests behind a build constraint the platform does not satisfy, is never refused this way, because an honest unfiltered run of it can only run new tests. `TestReviewOnlyNewTestsUsesRunnableBase` is written first (fixture first, unit 5b): a base package whose only test is `//go:build linux`, checked on a non-Linux host, passes; the same package with one portable base test that the receipt did not run is refused.

A report with `outcome: capability-absent` refuses nothing: the bed moves to the seat column with reason `measured-absent-at-run` and the snapshot member is marked for re-probe. A red report or receipt named in `gaps` is an accepted return (section 7, question 3). The validator does not prove the delegate ran anything; the seat's proof still does, and the delegate's run is never a recorded attempt. What the validator makes mechanical is the requirement, so the seat no longer relays what the delegate could have seen.

The fake adapter writes scripted reports and receipts from brief markers (`FAKE:bed-report land-fixtures exit=0`, `FAKE:package-run ./internal/dispatch tests=TestNew,TestExisting`), so every refusal is proven without a sandbox.

## 4. Risks

- A delegate edits after running a bed or a package: `BED_EVIDENCE_STALE` or `PACKAGE_RUN_STALE` names it; the follow-up re-runs it.
- A delegate forges a report or a probe result: the seat's proof is still the recorded proof; a forged probe is corrected by the bed's preamble at the next run; a forged report only removes a failure from the delegate's own return, and the seat's proof puts it back into the record.
- The probe's git leg runs under the environment as launched; if the exported steering breaks scratch repositories, `temp-isolation` is absent and the beds that need it go to the seat until the launch environment is fixed. That is a measured fact, not a guess.
- Cost: one delegate turn per runtime per thirty days, or after a CLI, configuration, OS or preset change; the preamble's seconds per bed run; one `go test -list` per changed package per base tree, cached.
- The supervision section runs four scripts; the delegate would run the assigned bed scripts directly, and the seat's proof runs the section. Evidence is per bed, proof is per section; the assignment record names both.
- A scenario that leaks a process inside the sandbox: the harness reaps by group or, without monitor mode, by pid, which does not reach grandchildren; what survives the delegate session is the runtime's to end, and `process-group` says which case a runtime is in. Not a guarantee; recorded as such.
- Over-assignment: the touched closure includes every bed of a selected section; a wide surface can send a delegate to a bed the diff does not affect. It costs minutes, not rounds.
- A `Depends:` line that omits an executed helper that is not `source`d escapes `TestDependsCoversSourcedFiles`; each 4b unit's dependency-change leg edits one declared dependency and asserts the bed is touched, and the read's threat model names an executed path missing from `Depends:`.
