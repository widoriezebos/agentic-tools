## 2. Small ownership change

Add one small pure Go owner, `metasystem/internal/testpolicy`, for decoding the testing contract, validating its finite declarations, computing affected requirements, resolving mode, and judging evidence sufficiency. It accepts values; it does not read Git, spawn processes, reserve budget, write records, or signal a process. No existing owner presently makes this application-wide decision.

Keep surrounding responsibilities where they are:

1. `config` resolves the installation and committed contract location; `gittree` captures the actual change, trusted base, candidate, and before/after posture. `behaviorsurface` supplies path grammar and the existing engine/payload/coordination distinctions.
2. `cmd/metasystem/test.go` composes those inputs and `testpolicy`; it does not implement risk rules inline. Small Go adapter files in `internal/proofrun` translate native runner inputs and outputs. They are ordinary compiled adapters, not a plugin or runner framework.
3. `proofrun` admits one execution, owns all selected child commands through its existing launcher/watchdog, retains results and reusable components on its attempts, and preserves stop and retry behavior. `dispatch.ProjectBudget` remains the sole budget projection. A governed `run` wrapper remains the sole reservation when the existing authenticated join applies.
4. `landing` recomputes sufficient proof at the actual commit/push boundary. Its receipts remain projections of committed attempts. Existing lease, provenance, review-chain, source-parity, static, and coverage owners retain their invariants.
5. `gaterun`, the standing-validator custodian, and `steward` own broader cadence, detection, and recovery. No scheduler, daemon, build system, approval service, generalized workflow language, or parallel proof store is added.

All new or changed decision, assertion, report parsing, fixture-selection, and measurement logic is Go. Bash only starts named commands, passes paths/context, performs process plumbing, and propagates status. Move the touched shell policy to these owners in the same cutover; do not use this feature to translate every existing shell fixture.

## 3. Public interface and result semantics

The public interface and its implementation are Go. Bash is only command/process plumbing. Maven is an optional native command beneath the generic adapter, never the MetaSystem interface or a dependency. This records Wido's explicit clarification; no Maven-specific adapter or build-system implementation is authorized here.

The same installed binary exposes these commands in MetaSystem and every adopted repository:

```text
metasystem test list   --root INSTALLATION [--json]
metasystem test check  --root INSTALLATION [--json]
metasystem test plan   --root INSTALLATION [--goal ID] [--tree TREE]
                      [--mode auto|canary|standard|deep]
                      [--purpose delivery|diagnostic|cadence] [--json]
metasystem test run    --root INSTALLATION [--goal ID] [--tree TREE]
                      [--mode auto|canary|standard|deep]
                      [--purpose delivery|diagnostic|cadence]
                      [--groups ID,ID] [--cap-min N]
                      [--retry-decision PATH] [--result PATH]
metasystem test verify --root INSTALLATION [--goal ID] --tree TREE [--json]
```

`ROOT` always resolves an installation using existing installation resolution. Contract paths and `TREE` use the containing Git repository's **whole-project** path space, including application source outside a nested installation. `TREE` defaults to the real index tree; delivery requires the relevant index and working-tree inputs to agree, including relevant untracked/ignored files, symlinks, executable modes, and gitlink refusal. No caller-supplied changed-path list is trusted. `list` shows kinds, modes, groups, providers, obligations, applicability, native commands, and declared cost targets. `check` validates structure, path containment, nonempty providers, references, tool availability, and native discovery support; it does not run tests or declare delivery ready.

Default mode is `auto`, purpose `delivery`. An explicit `canary` defaults to `diagnostic`; `canary --purpose delivery` is refused with the missing-delivery-requirements explanation. `--groups` is diagnostic only and cannot alter the required set. An explicit standard delivery request for a deep-required change is refused **before launch**, with the required groups. The caller can still run a standard or canary diagnostic. Explicit deep selects the affected deep set; it does not mean every test in the repository. Cadence requires the existing authenticated standing obligation and uses its recorded catch-class set.

`plan` performs bounded metadata/discovery reads, never test execution. It emits the resolved group set and all reasons before admission. The runner recomputes the plan rather than accepting an editable plan file as authority. `verify` performs identity and evidence checks only: zero native test/build launches, no reservation, no automatic repair run. It returns 0 for sufficient proof, 1 for absent/failed/invalid/unavailable proof, 2 for malformed input. Missing proof names the exact `test run --mode auto` action and missing groups.

Cost comparison is a Go test/evidence helper for this feature under `internal/proofrun/test_cost.go`, not a new public command with a feature-specific profile. It reads the retained reports and applies section 9's scoped acceptance thresholds without launching any native work. No `--force` or `--no-reuse` execution flag is introduced.

`test run` keeps candidate `PROOF-RESULT` dispositions and statuses: newly executed successful commands 0, actual child failure its status, live duplicate 75, reusable success 76, diagnosed retry required 77, admission refusal 78, malformed input 2. `TEST-RESULT` explains whether proof is sufficient independently of command success. Diagnostic success is not a delivery verdict. A child itself exiting 75–78 remains `failed`, not a no-child disposition. Return the first failed command's status in deterministic stage/group order and retain every command's exact status. Delivery stops launching further commands after a decisive failed, invalid or unavailable required command; already-started owned work is joined and cleaned up. Diagnostic and cadence runs may collect the results of their already-planned independent groups, preserving the existing collect-and-report use case. No purpose adds groups on failure. Signals and launch failure are separately recorded; never invent an exit status for a command that did not start.

Automatic delivery execution has three ordered barriers: the applicable canary groups, the remaining required standard groups, and the remaining required deep groups. Add `always.canary` to executable/configuration/policy delivery requirements, rather than expecting each agent to request a separate preliminary run. Pure coordination or non-instruction prose retains its declared static-only path. Each barrier must be satisfied by completed valid or reusable evidence before any command in the next barrier starts. Contract/admission validation precedes every launch; avoid preparing expensive later-stage builds or private beds before their barrier is reached. On a decisive failure, retain every selected but unstarted group as `not-run` with reason `earlier-required-check-failed`, its blocking group id, and null execution times/status. It is missing evidence, never a pass or an unselected omission. `plan` and the final result expose these stages and barriers. This is fixed ordering in the existing sequential worker, not a configurable workflow language.

Add `landing test-receipt --mode auto|standard|deep` as compatibility plumbing to the same composition. With a version-1 testing contract it uses whole-project tree semantics and produces receipt schema 2. Legacy `--command` continues to produce only legacy evidence and cannot satisfy a migrated test contract. CLI help distinguishes the legacy subtree argument from the schema-2 whole-project argument; `--command` and `--mode` are mutually exclusive. `land.sh` changes its v2 tree capture to `git write-tree` without stripping the installation prefix.

Record every `exec.Start` at the common Go command boundary, including nested instrumented gate measurement/build commands, with command class and process record key. An `exec` handoff is one command launch, not an additional launch. These counters count commands actually started, not OS grandchildren guessed from a process scan or test cases printed by a runner. Existing process records continue to record exact launcher, child, and watchdog custody. Native test case counts come from the separate native inventory. A legacy uninstrumented nested command is explicitly `countsComplete=false` and cannot satisfy the launch-count acceptance tests.

Reports requested by `--result` are atomic projections of retained attempts and no-child decisions, not authority records. Failure output includes the named native log and report paths; preserve full output through the existing evidence collector. Public summaries expose hashes of environment values, not credentials.

## 4. Minimal committed configuration

Add one configuration key, `testing.contract=testing.json`, resolved relative to the installation. The contract is always committed, strictly parsed JSON version 1. Local or environment overrides may select diagnostic tools but cannot replace the delivery contract, lower risk, drop groups, or change its policy base. Tool/config differences remain proof inputs.

Required contract fields:

* `schemaVersion: 1`, `projectRisk`, `surfaces`, `groups`, `always`, `unknown`, `cadence`.
* `projectRisk`: `severity`, `exposure` in 1–3, `reversibility` in `revert|restore|irreversible`, `detection` in `immediate|delayed`, `recovery` in `bounded|unbounded`. These are project defaults; a surface may raise them and may declare `crossCutting` obligation ids. No surface lowers a project default.
* A surface has unique `id`, nonempty `paths`, `dependsOn` surface ids, `standard`, `deep` group ids, `critical` obligation ids, optional `crossCutting` obligation ids, and optional `risk` containing risk raises. `dependsOn` means this consumer uses that provider; select reverse-transitive consumers. Cycles are legal and handled as a set, not recursion without a visited set. Every critical/cross-cutting obligation must name at least one applicable group through that group's `obligations`; if several providers are declared, require their union, then normalize overlapping native executions.
* A group has unique `id`, `kind` (`unit|component|integration|e2e|performance|static|build`), `adapter`, `cwd`, `inputs`, `outputs`, `tools`, `obligations`, `platforms`, `targetMs`, and adapter-specific arguments. `outputs` is an explicit possibly empty list of repository-relative directories/files owned only within the private execution candidate. `tools` is an explicit possibly empty list of `{id, executable, versionArgs}` descriptors; names resolve through the captured effective PATH and absolute executables must be readable. The actual command executable is always implicit. Optional `externalInputs` contains `{id, path}` descriptors, with absolute paths or `${NAME}/suffix` locators resolved from the captured environment; absent declared files have an explicit absence marker and unset locator variables refuse delivery. Bind resolved file/tree contents; never silently omit an unreadable declared input. `platforms:["any"]` is normal; a narrower list requires the contract to declare the alternative provider for every required obligation. No automatic “skip because tool absent”. `targetMs` is an engineering target, never a kill timeout.
* `always` has `canary` and `standard` group lists. `unknown` is a nonempty bounded diagnostic group list. `cadence` contains the existing standing obligation's catch-class group ids; no timer or new cadence authority is introduced.

Path grammar is the existing behavior-surface grammar: exact repository-relative paths or directory prefixes ending `/**`, with `.` and `..` rejected inside declared paths. `cwd` is a canonical repository-relative directory (the single literal `.` means the project root). Reuse `behaviorsurface` matching; do not introduce arbitrary globs or regular-expression risk rules. Native Go test filters are anchored explicit test-name lists, not path patterns.

Group input closure defaults to the entire non-runtime project input manifest. A narrower `inputs` declaration is permitted only when it includes the executable/adapter, native build/configuration files, tests and fixtures, resources, provider/consumer dependencies, and every declared external input. The authoritative base declaration is the minimum when policy changes. Existing coordination/operational exclusions may remove irrelevant records; a group that reads one of those files must explicitly include it. Undeclared external inputs make delivery evidence non-reusable until bound or isolated. No ENGINE-only digest stands for application or full validation proof.

Mutable output ownership is checked against both trusted-base and candidate tracked trees. An output path may not contain or equal a tracked source, test, fixture, configuration, executable input, or another selected group's actual mutable directory. The same relative output name is lawful in distinct private candidates; declarations normalized to one native execution share that execution's one private output owner. Resolve symlinks and reject output escape from the assigned private candidate. A declared broad input directory may contain a declared output subtree only when that subtree contains no tracked or separately declared input. Start each group's output/report directories empty inside its own private candidate; copy no prior report/build/database output into them. The runner may pass their resolved paths to the native command through explicit environment bindings; fixed native directories work because the entire execution candidate is private. Reports must lie in declared outputs. Only these validated mutable paths are removed from that group's source key. Recompute all remaining inputs after execution; a test mutating an input produces invalid evidence even if it exits zero.

Whole-project source enumeration excludes `.git` and installation-owned runtime state at its resolved nested prefix, not arbitrary top-level names. A tracked application file under `bin` or `artifacts` remains an input. The installed MetaSystem executable is bound by its executable hash/build descriptor separately; its directory is not a blanket source exclusion. Existing partial evidence trees under the actual installation's runtime artifacts are runtime-owned and are not discovered as application packages. An application declaration cannot turn a tracked source into an output or runtime exclusion. These rules belong to the schema-2 project manifest owner in `proofrun`; retain `FullDigest`'s old exclusions only for explicit schema-1 legacy proof.

No empty contract, empty standard application test set, missing provider, unknown field/reference, duplicate id, no-test native result, or blanket success command can report a ready adopted application. Static/build-only groups cannot satisfy an application's testing obligation. `check` detects structural no-ops; native execution must additionally prove discovered tests actually ran. Semantic value of an assertion still requires review and the pruning fault probes; the schema does not claim to prove that arbitrary assertions are useful.

### Native adapter shape

The native command boundary is deliberately small. These adapters ship in this slice:

1. **Go:** fields `packages` (explicit module-relative package directories), `tests` (`all` or an explicit list of top-level test names), `race`, `coverage`, `env`. The Go owner expands local package membership and import edges, including test imports and embedded/testdata resources. Enumerate using Go's package metadata under the effective environment before measurement; failed/incomplete discovery becomes uncertainty, never an empty successful list. The argv is `go test -json -count=1`, optional `-race`, optional `-cover`, an anchored `-run` only for the explicit list, and exact packages. Keep the existing 30-minute non-race and 60-minute race package hang bounds, with the enclosing accepted deadline authoritative. Parse Go JSON and package inventory; require actual test start/terminal events for non-exempt packages. Coverage still goes through `audit.ParseCoverage`/`CheckCoverage` with exact inventory/floors; a targeted test-name subset cannot claim a whole-package floor.
2. **Section:** the existing MetaSystem section selector, for existing static and real-process fixture groups. The stable catalog and applicability decisions move to Go `testpolicy/metasystem.go`; `validate-section-selector.sh` becomes its thin compatibility entry point. Keep current section identifiers, dependencies, stage status semantics, and the production section bodies. A Go-owned selection launches each selected section once and validates its complete stage/progress output. Pure shell exit 0 without its expected section evidence is invalid. Selected sections never masquerade as the unselected canonical validator.
3. **Command:** the language-neutral escape from a fixed native roster, without an execution-policy escape. Fields are a nonempty `argv` array, `reports` (repository-relative directories), `format:"junit-xml"`, and `env`. It executes one native runner command without implicit shell interpolation and parses fresh JUnit XML with missing, zero-test, skipped-only, stale and failing-required-report refusals. Reports are produced only in this group's declared private outputs. Applications whose existing runner emits this format can adopt the interface without changing languages. A runner without structured output must first supply a reviewed project adapter that emits it; a bare exit-zero command is insufficient. The command executable, wrapper/configuration, report inventory, declared inputs, and environment are identity-bound exactly like the named adapters. Static/build commands can use `format:"exit-status"`, but cannot provide testing obligations. This is one direct process adapter, not a plugin loader or alternate proof owner.

## 5. Selection and risk, with no discretionary first-slice branch

For delivery, the trusted policy base is the destination remote-tracking commit already captured by the existing landing flow; its configured destination remains authoritative. Capture the implementation root's base commit too. Assess the accumulated change from their merge base to the candidate, not just changes since the latest local checkpoint. Initial direct fixes use their recorded root-job base. Missing/contradictory bases refuse delivery and still permit diagnostics. Record-only movement on the remote is excluded only through the authoritative behavior projection; actual upstream source movement recomputes affected consumers and identities.

Algorithm, in order:

1. Read base and candidate policies; classify both sides of additions, removals, renames, and mode changes. Compute changed surfaces and reverse-transitive consumers from the **union** of both dependency graphs. Add all associated standard groups, `always.standard`, and providers for their critical and cross-cutting obligations. Provider disappearance or unknown impact is explicit uncertainty.
2. Compute maximum severity/exposure from accepted goal risk and the project/affected surfaces. Executable/configuration changes require deep if severity or exposure is at least 2, goal novelty is at least 2, recovery is unbounded, reversibility is not `revert`, detection is delayed, or any critical authority/data/proof/lifecycle obligation is touched.
