# enrollment-proves-a-human-not-a-terminal

- State: queued
- Risk: severity=3 novelty=2 exposure=3 accumulation=2 basis="severity 3: the enrolled terminal is the only thing separating an agent from every human-reserved act in a checkout, including stop, arm, approve, set-budget, steal and resume, and today an agent can create one; novelty 2: a second factor and its storage are new to this system, though the enrollment record and its generation already exist; exposure 3: every checkout on every machine, and the whole point of the stop verb's classifier depends on it; accumulation 2: every act performed through an agent-made enrollment is a ledger line that says a human typed it, and those accumulate unreadably"
- Tier: 3
- Intent: Wido's word 2026-09-08, after directing m1b to enroll a terminal and approve a goal in his name while remote: 'We can secure the enrollment with a TOTP later, create a backlog item for this'. Today goal enroll-terminal proves only that the caller has a controlling terminal and can walk its ancestry to that terminal's session leader (internal/humanauthority/authority.go, Enroll), and requires no prior human proof, so 'has a terminal' stands in for 'is a human'. An agent can therefore start a tmux session, enrol it, and from then on pass every human-reserved gate in that checkout: approve, set-budget, set-priority, steal, resume, session stop, and metasystem stop and arm. m1b did exactly that at 10:40Z on 2026-09-08 under ruling R-88-m1b, at Wido's explicit direction and after raising the consequence, which is why this goal exists rather than a quiet fix. This is the same assumption the stop verb's classifier had to stop making: two of that chain's reads found ways an agent could clear a human stop, and both were treated as the class that matters most. DONE means enrolment carries a second factor that an agent in the checkout cannot produce: a time-based one-time code the human supplies at enrolment and again when the enrolment is renewed, verified against a secret the checkout does not store in the clear and that no agent-readable path can reach. The refusal a caller meets names what is missing without leaking the secret or the expected code. Enrolment generation still increments so an older enrolment cannot be replayed. A fixture proves that an agent-spawned terminal without the code is refused, that the human path with a valid code succeeds, that a stale or reused code is refused, and that an existing enrolment keeps working until it is renewed so no fleet is locked out by the change. Wido decides whether relayed authority returns alongside this, because a working second factor is the thing that could make a remote human act lawful again without an agent pretending to be him.
- Origin: main
- Next step: Read internal/humanauthority/authority.go around Enroll and ReadEnrollment, the callers that demand enrolled ancestry (the human-act gate in cmd/metasystem/goalsync_mutations.go and the classifier paths the stop verb fixed), and ruling R-88-m1b in memory/rulings.md. Design first, on the design lane: where the secret lives so an agent in the checkout cannot read it, how the code is presented and verified, what happens to the enrolments that already exist, and whether renewal is periodic or per-act. Canary before battery: the smallest proof is one enrolment attempt without a code refused and one with a valid code accepted, each a named test with a ceiling, before any bed runs. Note for whoever takes it: relayed approval was retired when the authority horizon passed on 2026-09-06, and this goal is what could replace it, so it is worth asking Wido about that in the same design round rather than after.
