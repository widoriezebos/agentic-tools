# human-proof-fits-the-act

- State: approved
- Priority: 3
- Sequence: 8
- Risk: severity=3 novelty=2 exposure=3 accumulation=1 basis="severity 3: the change moves the authority boundary itself, and a wrong grading would admit an agent to an act that grants authority, which is the one thing the walk exists to prevent; novelty 2: a grading table over proof classes that already exist (enrolled terminal, temporary word, channel word, fixture) plus a second enrolled terminal, no new mechanism; exposure 3: every human act on every machine and every seat's graceful stop; accumulation 1: each act is judged on its own and nothing compounds"
- Tier: 3
- Intent: Wido, 2026-09-07 morning, after an hour lost to it: 'this check if the process is from a terminal is starting to bug me' and 'if the terminal no longer lives then I can't ever stop this'. Human authority is proven by walking the invoking process's ancestry: it refuses any agent signature and must arrive at the exact terminal enrolled in that checkout (internal/humanauthority/authority.go; the enrollment record artifacts/agents/authority/human-terminal.json binds one terminal id, one terminal process and one session leader). The mechanism is right and must stay: an agent with a shell in the checkout would otherwise approve its own goals and raise its own budgets by typing --by. But its shape costs more than it should. Three defects, all seen this morning on m1d: (1) every human act demands the same proof, so stopping a session, which only halts work, is as hard as approving a budget, which grants authority; the seat's Stop hook refuses the turn end and the only graceful exit is an act that needs a live enrolled terminal, so a human away from that terminal can end the session only by killing the process; (2) enrollment binds ONE terminal line, so Wido enrolled at 07:48 on /dev/ttys010 and the very next command, typed in another tab, refused TERMINAL_NOT_REACHED; (3) the refusals name a missing file or an error code and never the repair, so neither 'human authority has no readable terminal enrollment' nor TERMINAL_NOT_REACHED tells the human to run goal enroll-terminal, and enrolling needs no prior enrollment, a fact nothing states. DONE means: the proof required is graded by what the act enables, so acts that only stop, park or release work are proven by a human at ANY terminal of that host (no agent signature anywhere in the ancestry, the walk reaching a terminal, the enrolled one or not), while acts that grant or widen authority (approve, set-budget, unapprove, accept-risk, set-obligation, resume, the classification sweep and enroll-terminal itself) keep the full enrolled-terminal walk unchanged; a human at any live terminal can always reach the stop path, so no seat can ever be wedged by a dead terminal; more than one terminal may hold an enrollment at once, or the refusal states that re-enrolling from any live terminal restores authority and that no prior enrollment is required; and every refusal in the authority layer prints one command that would have succeeded or says in words that none would.

Slice 2: the build behind fixtures that drive an agent shell refused for both an approve and a stop, a human shell at an unenrolled terminal allowed to stop and refused for an approve with the enroll command printed, that printed command running and then the approve succeeding, and a dead enrolled terminal recovered by one enroll from a fresh terminal. Receipt: the go gate plus the human-authority package and the goal CLI fixtures. Related: human-goal-verbs-forgiving carries the same refusal rule for the goal verbs and is parked one line from done; enroll-terminal-refuses-macos-terminal (done) fixed the walk for Terminal.app. FOURTH DEFECT, SEEN 2026-09-07 on m1d, about the relay rather than the human's own terminal: Wido was present in an agent session and told it, in his own words, to add a durable-stop requirement to the metasystem-stop-verb intent, and the session could record nothing. 'goal edit --intent' refused with 'the human approved this intent; unapprove the goal, edit it, then approve the new intent'; unapprove and approve are human-only, and passing --by refused TERMINAL_NOT_REACHED. The human's instruction, given directly to the machine, could only be handed back to him as a three-command script to type at his terminal. The one mechanism built for this, --temporary-human-word with --review-by, is retired in fact: since 2026-09-07 the horizon rule and the not-in-the-past rule are mutually unsatisfiable, so no relayed word binds at all (goal fixture-review-by-date-rolls-over carries that decision). The design should say what happens to a human word spoken to a seat: either a graded relay that records the word with its provenance stated and unverified, or an explicit statement that no such path exists and the human always types it, so the seat stops trying. Recording a word is not granting authority, and today it is graded as if it were.
