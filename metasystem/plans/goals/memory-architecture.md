# memory-architecture

- State: queued
- Intent: The metasystem gets a designed information architecture: {metasystem, app} × {documentation, memory} — four quadrants plus plans and records, each with its own place and laws; docs stays static documentation, memory is for memories, plans is for plans, and the app's documentation and memory remain separate from the metasystem's under the two-part update-safety law (Wido 2026-08-26, R-6/R-7/R-8)
- Origin: human
- Next step: Appetite: 4h for the design slice (broadened by R-8 from memory-only to the full information architecture), migration slices after. The design must deliver: (1) the QUADRANT MAP — {metasystem, app} × {documentation, memory}: metasystem docs (docs/, static), metasystem memory (rulings, known-issues, flake registry, drafts, receipts, retro learnings, journey, conclusions), APP documentation (the app's own design/readme content — app-owned), APP memory (the app's issues, its rulings, its drift records — a quadrant nobody has yet named a home for), plus plans (backlog, goals, designs in flight) and records (critique rounds, dispositions) as their own categories; machine-local agent memories distinguished as NOT metasystem memory. (2) the PLACES — per R-6 docs/ stays classical static documentation; per R-7 plans/ is scrutinized file-by-file (registers, critique transcripts, dispositions, landed rationale, and receipts are memories or records masquerading as plans); per R-8 the app quadrants live under the app-guardrail-program TWO-PART LAW: app-owned content is never overwritten by a metasystem update, at worst losslessly migrated — so app documentation and app memory homes must sit on the app side of that line (the covenant/doctrine precedent: docs/app-doctrine.md and covenant.json are already app-owned paths). (3) the LAWS per type — append-only vs editable, id grammars (KI-x, R-x), supersession chains, who writes, and how machinery reads them (residue-demands-a-token, counselor, actionable-metrics, the adoption/tailoring path which must place app quadrants correctly at inception). (4) MIGRATION without breaking consumers (fixtures grep these paths; validate and the battery reference them; adoption copies them). INTERIM: new dynamic metasystem memory beside the existing registers in plans/ as explicitly temporary (R-6/R-7); plans/rulings.md carries the standing rulings. Design goes to Wido as a draft before any file moves (R-2). Related: app-guardrail-program (the two-part law), app-doctrine, continuous-self-improvement, historical-residue-sweep. ADOPTED-REPO DEFAULT (R-9, Wido 2026-08-26): in an adopted repo the plans and docs trees belong to THE APP by default — the design must make the quadrant boundary visible in the tree itself (vendored/namespaced metasystem material vs app-owned trees) so adoption gives the app its quadrants BY CONSTRUCTION and a reader always knows whose file they hold; the metasystem dev checkout is the declared special case where the app being built is the metasystem itself. PRIORITY + ACCEPTANCE (R-10, Wido 2026-08-26): separation is the design's FIRST-ORDER requirement — mixed context makes upgrades hazardous and confuses metasystem, agents, and humans alike. Two mechanical acceptance tests bind the design: (a) the UPGRADE REHEARSAL — apply a metasystem update to an adopted repo carrying real app content; every app-quadrant byte is identical afterward (the two-part law, proven end to end, not asserted); (b) the OWNERSHIP ORACLE — any path's ownership is answerable mechanically (a verb or manifest an agent, human, or tool can ask: metasystem-generic or app-owned, no judgment call); a design that cannot pass both is not converged. This item queues HIGH. SIMPLICITY GUARDRAIL (R-11, Wido 2026-08-26): intuitive, easy to understand and maintain — no over-design, no over-engineering. The simplest structure that passes the upgrade rehearsal and the ownership oracle WINS; a layout that needs explaining fails; the critique rounds must attack complexity with the same teeth as gaps (a finding of over-design is material). Concretely: prefer a handful of plainly-named top-level places over deep taxonomies, prefer convention over manifest where convention alone can answer the ownership oracle, and let the two acceptance tests — not elegance — be the tiebreaker.
