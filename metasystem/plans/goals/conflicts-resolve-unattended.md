# conflicts-resolve-unattended

- State: claimed
- Priority: 1
- Sequence: 2
- Risk: severity=3 novelty=3 exposure=3 accumulation=2 basis="Decides how every seat's work reaches main when main moved; a wrong rule either stalls the fleet or lands unreviewed merges; it compounds across every future goal"
- Tier: 3
- Intent: When a goal's work conflicts with a newer main, the machinery resolves it without a person: in a seat with no landing lane, in the landing lane, and for a goal branch that must move onto a newer main (Wido 2026-10-03, on m1g's question 'resolve / replay / refuse': 'this is too simplistic. This needs a proper design and review round. The goal is unattended functionality'). Today: a goal branch cannot be brought onto a newer main (the branch reader refuses merge commits; work revise builds on the old base, so the same lines conflict again); a branch the lane returns for a conflict has no route back in (items 48, 57); the landing agent fixes small plain conflicts but its resolution is not reviewed, only proved. The design decides what is resolved by whom, how a resolution is reviewed and proved, when a conflict is genuinely the person's call (and then asked with its impact, R-143-m1e), and keeps one landing mechanism.
- Origin: main
- Next step: Tier-3 design: use cases from tonight's real conflicts (ui-shows-true-facts vs ui-reads-well-on-a-phone in ProjectPane.tsx and the bundle; fleet-panel-ux vs ui-reads-well; generated files such as testing.json and UI bundles), threat model, rabbit-hole risks with mitigations, options with pros and cons (resolve in place, replay onto main and re-review, regenerate generated files, refuse with paths); Astra critique tier 3; then build in slices. The seat found both remaining paths closed by the engine itself: a merge commit on the goal branch is refused by the one-parent rule (internal/goal/branch/range.go:272), and a rebase gives every unit commit a new id while each published read's Goal-Read trailer names the old 40-hex id, so every read is orphaned although the patches of three of four units are unchanged (the attestation already carries a PatchDigest the range check does not use). Decided by hand tonight: rebase, resolve, one read over the unit list, hand in again; about an hour of critic time for a conflict whose resolution the lane had already written out. The design must give the lane an act for a resolution it can name, and let an unchanged patch keep its read across a rebase. Use case added 2026-10-03 21:53 (m1e): the lane returned review-findings-read-as-decisions at 21:51 for a conflict only in generated files (internal/ui/web/bundle/bundle.json sourceDigest and dist/assets/index.css, index.js), the third such return today (fleet-panel-ux twice before). A generated file never needs a person: the resolution is to regenerate it from the merged sources with the project's own build (npm bundle for the web interface) and prove the result. The design must let the lane do that itself for files the project declares generated, and leave only source conflicts to a seat or a person. Use case added 2026-10-03 22:17 (m1e): fifth conflict return of the day. m1f handed in three reviewed typing units of one-folder-deployed-and-evolved from a goal branch 731 commits behind main; the lane found seven conflicting files under cmd/metasystem. The lane names the paths and stops; the seat rebases, resolves, re-reads and hands in again (about an hour). Two rules for the design: the seat path rebases a goal branch onto the latest main before every hand-in (and says so in the hand-in sentence), so the lane only ever sees conflicts that appeared in the last minutes; and a read survives a rebase whose patch digest is unchanged, so only the unit a conflict actually touched is read again. REQUIREMENT (Wido, 2026-10-03 22:22 CEST, binding, the critic's first question in every round): the mechanism is generic for any application adopted by the metasystem, in any language. Nothing about this repository is written into the mechanism; adopter specifics are declarations. Concretely: (1) which files are generated and the one command that regenerates them is a declaration in the adopter's project contract next to the testing contract; the lane regenerates whatever is declared and treats every undeclared conflict as a source conflict; (2) the seat path rebases a goal branch onto the latest main before every hand-in and says so in the hand-in sentence; (3) a read stays valid across a rebase when the unit's patch digest is unchanged, so only a unit a conflict touched is read again; (4) the lane never merges source conflicts itself: it returns them with the paths and the plain resolution it can name, and a seat with a builder and a critic resolves them; a conflict between peers that needs a judgement is a person's call, as the docs say. Design step 1 is at most 1,500 words with scope first; Astra critique asks first whether every rule holds for a Java adopter with no npm and no Go. Highest priority (sequence 1 of priority 1), pinned to m1h, which starts the design now while it watches its deploy step's first landings.
