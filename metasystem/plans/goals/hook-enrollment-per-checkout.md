# hook-enrollment-per-checkout

- State: queued
- Priority: 2
- Sequence: 7
- Intent: What: Every checkout has its pre-commit guard installed and verified, and a checkout without one is flagged loudly. Most of this exists: system setup, adopt, helm take and browser actions all install and verify the guard. What is left: the health check, system check, does not look for the guard, so a checkout that only commits and never runs a goal command can be without one and nobody notices. Why: In such a checkout every commit fence is silently off. Pros: A missing guard becomes visible, cheaply, since the verification already exists. Cons: One more line in the health report; small work.
- Origin: main
- Next step: Next: Add a guard check to system check's setup-drift list, so it names a missing or unverified pre-commit guard and says that system setup repairs it. Done when: on a checkout with an empty .git/hooks, metasystem system check reports the missing guard, and after system setup it no longer does.
