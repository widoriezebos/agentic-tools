# goal-abandoned-with-a-reason

- State: approved
- Risk: severity=2 novelty=3 exposure=3 accumulation=2 basis="severity 2: nothing wedges, but the only two moves available today are both dishonest, a false done that corrupts every count of completed work or a silent drop to the lowest rank that hides the problem; novelty 3: a new terminal state read by four consumers, a transition that must not reuse the claim-clearing path, a retention rule change and an ordered fleet rollout because the record grammar is closed; exposure 3: every reader of the live set, every completion count and every prune; accumulation 2: two specimens already, and one of them is reported as open work in every seat's end-of-turn scan"
- Tier: 3
- Intent: There is no way to record that a goal will never be worked and why. The states are queued, approved, claimed, parked and done; parked means resume later and is still live, still ranked, still counted against the one-claim quota. So a goal that cannot be pursued has to be forced through goal done with a conclusion explaining it was not done, which corrupts every count of completed work and makes readers parse prose to learn whether done meant done, or quietly dropped to the lowest priority band, which says nothing true and hides it. Two live specimens: account-provenance became permanently unresumable through a machinery defect, three verbs locked against each other, and its work is now carried by account-provenance-carried, so abandoning the record would be honest while the work continues; and the superseded metasystem-stop-design is reported as open work in every seat's end-of-turn scan. Wido's shape, 2026-09-08: move it out of the live set the way done goals move, keep it out of consideration for implementation, retain it with its reason rather than pruning it, because pruning loses the history. Codex was asked for a second opinion and argued against a marker on done, on the ground that anything which changes completion counts, dependency satisfaction, retention and reopening is a state whether or not it is named one; the code agrees. DONE means an explicit abandoned terminal state carrying its reason, excluded from goal next, the idle refusal, the ranked listing and the claim quota, satisfying no dependency, exempt from prune, reopenable by a human into queued, reachable for a breach-stopped goal, and proven by fixtures for each of those.
- Origin: main
- Next step: Design lane first, because the shape is settled but three mechanisms have to be decided together. Verified constraints, each checked in this checkout on 2026-09-09: (1) depState in internal/goal/verbs.go returns StateDone for EVERY archived id, so an archived-with-a-marker goal would satisfy dependency edges as if completed; only done may satisfy a dependency, and that reader has to be taught the difference. (2) clearClaimBinding in internal/goal/verbs.go refuses while StopFence is set and goal done calls it, so abandonment routed through the completion path cannot touch a breach-stopped goal, which is the main case; it needs its own transition that preserves the stop evidence and invalidates the execution authority rather than clearing the fence, and reopening must not become a way to erase a stop. (3) The record grammar is closed, see the unknown-field and unknown-key refusals in internal/goal/file.go, and internal/goal/validate.go requires archived records to be done and live records not to be, so a new state hard-fails older binaries and the rollout is ordered. (4) Prune retention is the closure of live goals plus the newest N done walked through blocked-by edges, so it must become that closure plus abandoned goals AND their prerequisites, abandoned goals must sit outside the newest-N allowance, and abandonment must tolerate its own unfinished prerequisites. (5) Abandoning refuses while a live goal is blocked by it unless the same act re-points that dependency to a successor, waives it with a recorded human reason, or abandons the dependent too; never silent edge removal, because the defect is an unsatisfiable requirement, not a dangling reference. (6) Reopen into queued needing fresh approval, rank not restored, and the abandonment event kept with reason, actor, time and revision. (7) Amend the drop rule in docs/backlog-mechanism.md, which today tells readers a goal that loses its justification concludes; separate the case where the want evaporated, where concluding is honest, from the case where the want survives but the pursuit stops. (8) Check separately whether the end-of-turn open-work scan reads the ledger or the design document itself, because if it reads the document then archiving the goal will not silence it.
