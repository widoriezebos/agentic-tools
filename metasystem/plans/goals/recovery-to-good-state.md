# recovery-to-good-state

- State: queued
- Priority: 2
- Sequence: 14
- Intent: What: From any half-broken state, one command brings a checkout back to healthy, or refuses with a next command a seat can actually run; and stop brings everything fully down with nothing left running, from any state. Starting and stopping the system with system start, stop and check, and restarting only when down, already exist; a designed repair for half-broken states does not. Why: In early September, getting the system working again meant hours of manual repair: leftover processes, identity mismatches, and refusals whose remedy only a person at a terminal could apply. Pros: Seats recover themselves, and the person no longer has to do hand surgery. Cons: Some acts must stay a person's decision, so the design has to keep those human while making all machine actions safe to repeat.
- Origin: main
- Next step: Next: Re-check the eight broken-state examples recorded on 2026-09-02 against today's Go-only engine (system start, stop and check, and restart only when down), keep only those that still happen, and write the design for those. Done when: A short record lists each example as still happening or fixed, with the command used to check it, and a design page exists for the ones that remain.
