# role-context-composition

- State: queued
- Priority: 2
- Sequence: 14
- Intent: What: Each kind of agent (builder, critic, coordinator, steward) sees only the memory and instructions meant for its role, not whatever its runtime happens to load on its own. Why: The instructions for each role are already assembled from fixed recipes. But the runtimes also load files by themselves (CLAUDE.md, MEMORY.md, wow.md). A critic that can read the builder's memory is no longer a fresh pair of eyes. Pros: Critics stay independent, and roles are not steered by memory meant for someone else. Cons: What a runtime loads by itself differs per runtime and may not be fully controllable; cutting it may also remove useful context.
- Origin: human
- Next step: Next: Design only the gap: list which files each launched role's runtime (Claude and Codex) loads automatically beyond its recipe, check whether a critic can see a builder's memory today, and propose how to switch that off per role; one critique round, then to Wido. Done when: the design page lists, per role and runtime, what is loaded today and what should be, and Wido has ruled on it.
