# fleet-channel-gateway

- State: queued
- Intent: One bot for the whole fleet, no lost messages (Wido's decision 2026-09-03, Design A): a single CHANNEL GATEWAY reads and posts on behalf of every machine. Telegram fixes one fact - a bot token has exactly one reader - so exactly one machine (the host m1, always on) holds the gateway under a LEASE that fails over if it dies; every inbound human message is written by the gateway into a shared git-synced INBOX on the transport, tagged with the ask id it answers; every machine reads its asks and replies from the inbox, never from the provider. Posting also routes through the gateway so a provider swap (Telegram to Slack) touches one machine and one config. DONE means: a machine with no provider token can raise an ask, get Wido's reply from the inbox, and post status through the gateway; the gateway lease fails over in a test; a cursor replay never duplicates an answer (keyed by message id); m0 and m0b no longer compete for one token.
- Origin: main
- Next step: INTENT: one bot, one git inbox, provider-agnostic fleet. READER STRATEGY (Wido's refinement 2026-09-03, supersedes the lease for Telegram): ALL machines poll getUpdates WITHOUT an offset, so every machine sees the same pending messages; whichever commits a message to the shared git inbox FIRST wins (idempotent by provider message id - the others find it already committed and skip); the offset is confirmed ONLY after that commit is durable on the transport (never confirm before commit - confirming consumes the message for everyone). No lease, no single point of failure for Telegram. The inbox remains the fleet contract; the reader strategy is PER PROVIDER: Slack delivers each event to one connection, so a Slack reader keeps the single-gateway shape. Telegram drops unconfirmed updates after ~24h - harmless once committed, so the post-commit confirm must actually run. CONSTRAINTS: identity check (per-provider user id + shared TOTP) runs on the committing machine; idempotent by message id; N destinations with a per-message-class routing policy; first valid answer wins per ask id. FREEDOMS: inbox format/location; whether posting also routes through one machine or each posts directly (Wido: parallel posting to several providers is wanted). Tier 3 ladder. Companion: answer-archive. Budget Wido's word at approval.
