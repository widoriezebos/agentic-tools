# goal-worktree-dispatch-uses-the-primary

- State: approved
- Priority: 1
- Sequence: 2
- Risk: severity=2 novelty=2 exposure=3 accumulation=2 basis="changes how every critic and builder is dispatched from a goal worktree, a path every seat uses many times a day; a wrong rule blocks reviews fleet-wide, a right one removes four of tonight's six person-needing refusals"
- Tier: 2
- Intent: Every dispatch made from a goal worktree (a critic read, a commit read, a builder round, a review close) runs with the seat's armed primary engine and the primary's runtime registry and settings; the worktree is only the tree under review, never the tool. A brief the build admitted is never refused at review, and a review of a frozen unit can take a corrected brief without a builder round. Generic: holds for any adopter checkout layout; nothing names this repository.

Smallest fix: when the root is a goal worktree of a seat, default the engine (and the registry and settings it implies) to the seat's primary installation instead of ROOT/bin; the hand route tonight is METASYSTEM_BIN=<primary>/bin/metasystem on the review command, used by m1l and m1k under R-145's hot-fix exception. Fourth face, 00:35 (m1h, conflicts-resolve-unattended unit 1 round 2, Codex gpt-6.1-sol): the unit builder launched through internal/launch/codex.go runs 'go build' inside the Codex sandbox without the delegate GOCACHE and without the cache directory as a writable root, so Go falls back to ~/Library/Caches/go-build and the sandbox denies it ('operation not permitted'); the dispatch adapter path (internal/adapter/codex.go, BuildCodexCommand with extraDirs as sandbox_workspace_write.writable_roots, supervisor/env.go setting GOCACHE and STATICCHECK_CACHE) gets both, which is why m1j's builds compile and m1h's cannot. m1f saw the sibling (no network for devgate static's tools), m1l saw Go-cache and process-scan denials in a builder round. Hand route tonight: the brief allows GOCACHE under the workspace for the stuck unit. Evidence 00:38: m1h's launch record (~/.metasystem/launch/20261003t220905-1a6d83aaf4-r2-s1/record.json) carries no GOCACHE in its environment; the exec log names GOCACHE only in the brief text. Fifth face (m1i, critic code-critic-2128897eb0d1f51e6de8e5e9 at the goal worktree, Codex): 'go: creating work dir … operation not permitted', the sandbox has no writable Go temp dir either, so the critic could not run go test, the engine filed a synthetic unproven finding, a retry is refused ('its findings are decided, not retried') and a person had to accept the placeholder. The environment contract therefore covers GOCACHE, GOTMPDIR, STATICCHECK_CACHE and the writable roots for all three, for every path that starts a Codex process (launcher, adapter, critic at a worktree); and a critic whose sandbox cannot run the tests reports that as its own failure, never as a finding against the unit (item U's rule). Item 55 read in code (m1f, 00:40): engineSkewPreflight (internal/delegation/infra.go) runs 'git log --ancestry-path <engine stamp>..HEAD' in the goal worktree, so once a goal branch sits on top of the main commit the seat's engine was built from, the goal's own unit commits count as engine skew whenever they touch engine code ('the engine is older than this checkout, and engine scripts changed'); every rebased goal branch hits it, and the only way past is to rebuild the primary at a main commit that is not an ancestor of the branch (m1k, m1l, m1f tonight, three rebuilds). Rule: the check compares the engine against main-side commits only (merge-base of the branch with main), never against the goal's own units; the goal's engine-code changes are the subject under review, not the tool. Sixth face (02:08, m1j's steward): the handoff continuation of a seat session was refused by the same brief-authority check ('the brief cites paths the delegate's tree does not hold: artifacts/agents/context/handoffs/<id>/state.json'), the path being the handoff's own state file, which lives under the seat's artifacts and not in the delegate's tree; the steward then started a fresh session without the continuation, so the successor lost the handoff's context and had to be briefed by the supervisor. ui's steward failed the same way at 21:47 and 22:25 for a different reason (install generation). Rule: the brief check admits paths under the seat's own artifacts and state directories (they are the brief's inputs, not the tree under review), and a refused continuation reports the path class so the steward can repair it instead of discarding the handoff. Seventh face (02:50, m1i, unit A of rosters-are-configuration-items): the Codex builder's sandbox refuses 'sysctl kern.proc.all', which the test harness's fixture exit scan needs, so no test under internal/launch, internal/delegation or cmd/metasystem can run inside a Codex build; the builder stopped after 14 minutes with a partial change and the round's own proof (outside the sandbox) showed 113 failing tests. A unit that migrates about a hundred such tests cannot be built blind. Decision tonight (hot-fix class): unit A builds on Claude Opus 5.5 with the critic on Codex Sol. Rule for the environment contract: the build runtime's sandbox either grants what the project's test harness declares it needs (network for declared tools, a writable Go cache and temp dir, process listing for the fixture scan) or the dispatch routes the unit to a runtime that can run the tests, and says so in the record; a builder that cannot run the tests reports that as its own limitation, not as a finding.
