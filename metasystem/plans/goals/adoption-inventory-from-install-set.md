# adoption-inventory-from-install-set

- State: queued
- Priority: 2
- Sequence: 8
- Intent: What: MetaSystem knows exactly which files it installed into a repository, because adoption writes that list down, instead of relying on a hand-kept list in the code. Why: The hand-kept list misses about eleven shipped documents. For those files the tools disagree about whether a file belongs to MetaSystem or to the application, so the wrong review rules can apply to a change. Pros: One complete source of truth; the path check, the critique waiver and the landing check agree for every installed file. Cons: Adopted repositories carry one more recorded file; older adoptions need today's list as a fallback until they are adopted again.
- Origin: main
- Next step: Next: In the Go adoption code (internal/adopt), write the installed file set into the adopted repository, and have the ownership lookup (stateroot shippedInventoryPath) read it, with today's list as the fallback. Done when: tests show a shipped docs file answers as MetaSystem's, an application docs file as the application's, and a folder of installed files as MetaSystem's.
