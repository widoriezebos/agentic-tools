- Intent: A pipeline's result must depend on what its commands did, never on how the kernel scheduled a pipe. The defect has two directions, both measured on 2026-09-14. A producer into a reader that STOPS EARLY: git archive piped into tar exits git=141 tar=0 under pipefail because bsdtar stops at the end-of-archive marker while git still writes, depending on the archive's trailing bytes against the pipe buffer (47,636,480 bytes passed while both a smaller and a larger archive failed); and printf piped into grep -Fq exits printf=141 grep=0 because grep exits at its first match while printf is still writing, a scheduling race that happens below the buffer size and grows likelier under load (m1b measured it on a 24 KB report, well under the 64 KiB macOS buffer). A producer into a reader that STARTS LATE: captureChannelOutput in cmd/metasystem/channel_verbs_test.go points stdout and stderr at pipe write ends, runs the command to completion and reads only afterwards, so any command printing past the 64 KiB buffer blocks forever; TestWaitSessionStartPrintsPendingRows hangs to the ten-minute Go timeout, and it already hung at its own landing commit 57ba0586, so it is not caused by later output growth. Sites: git archive into tar at scripts/agents/witness-gate.sh:144 and :147 (a real landing path, under set -o pipefail), five in scripts/agents/land-fixtures.sh and one at scripts/agents/supervision-fixtures.sh:2528; fourteen printf piped into grep -q in the supervision bed alone, one of which (3438-3440) makes stop-hook-monitor fail at every commit today; about ten os.Pipe capture helpers in cmd/metasystem tests. The same shape bit m1c twice on 2026-09-14 outside fixtures: git apply piped into head truncated a rebase and reported success, and a trailing grep turned a green verification into exit 1. DONE: every site uses a conforming form - a file or a here-string for an early-exiting reader, a draining reader that runs concurrently with the command for a late one; a gate check refuses a producer piped into an early-exiting reader (tar -x, head, grep -q, sed with q, awk exit) under pipefail regardless of output size, and refuses a swapped standard stream outside the shared draining helper; and fixtures force both failures deterministically - an archive padded past its end marker beyond the buffer, and a producer that writes a second chunk after a stall so the early reader has already exited.
