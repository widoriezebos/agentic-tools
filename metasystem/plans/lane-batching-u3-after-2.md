## U3-1 (high): a cached green hides a red when a test starts a child through helper code
internal/proofrun/test_go.go goTestChildLaunches (~490) scans only the package's *_test.go files for os/exec, os.StartProcess, syscall.Exec and two testutil helpers; a test calling a helper in its own non-test file or in another module package that starts a child is treated as "no child", gets cached, and a change read only by the child is never seen (reproduced by the critic: internal/rootaudit/load.go runs `go list` over its own testdata; 9 such packages exist in this repo). Fix: scan the package's non-test files AND every module package its test files import directly (one level), for the same launch markers; any package with a launch anywhere in that set is "spawns children" → never cached unless its declared inputs cover what the child reads (today: never cached). Whatever cross-package gap remains (a helper two imports away) is written into the design's threat model as an accepted risk with its impact in plain words — the coordinator carries it to Wido. Test: the critic's shape — the child in child/helper.go called from the test; the child's file changes → the group re-runs (mutation: scan test files only → cached green → test fails); a package whose test imports a module package that spawns → not cached.

## U3-2 (high): the changed-path list breaks proofs and can wedge the lane
internal/landing/plain/reuse.go ~45-62 copies the whole changed-path list once per go group (61 copies) into LANDING_PROOF_CHANGES; prove.go ~1134/1302 and repoproof/full.go ~404 put it into one environment variable or the single `bash -c` string for the VM; prove.go ~1229-1230 stores the map on every results.jsonl line. ~300 changed paths since the last full green exceed the macOS argument limit ("Argument list too long"); the Linux VM caps a string at 128 KiB (~35 paths); `--fresh` and `--trunk` build the same variable, so nothing can record the full green that would shrink the list. Fix: the lane computes the per-group answer itself (it already loads the contract in proofReuseChanges) and sends only the ids of the changed-or-unknown groups (a short list, or a file path if long); nothing copies the map into Result. Test: 400 changed paths → the proof starts and the variable stays small (mutation: send the paths → the test asserting the variable's size fails).
