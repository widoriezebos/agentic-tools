## 1. What the audit found

Five m1b attempts idled 1.8 to 26.8 hours after a section died with exit 141 and the launcher never emitted the end event; an m1e attempt (proof-mtvl0alu) stayed live 24.5 hours after its launcher died; 23 process records still said running; 16 attempts ended launcher-killed without a terminal (proof-attempts.md section 6). Nothing on the checkout reads the attempt records periodically: the launcher owns the one terminal commit, and a dead launcher commits nothing.

## 2. Design: three reconciliation paths in one reaper pass

`proofrun.ReconcileAttempts(root, prober, now, emit)` runs after every job reaper pass (cmd/metasystem/supervise_component.go, `setupReaper`). For each attempt without a terminal:

1. **Launcher dead.** `identity.AliveRef(prober, attempt.Launcher.Ref())` is Dead. Every process record the attempt published (`ProcessKeys`) is stopped through the identity-safe ladder `proofrun.Stop(record, options)` (suite group, watchdog, launcher; each signal preceded by proof of the recorded identity; already-gone is fine). If any component reads not-stopped, the attempt stays live and the pass says so: a reservation is released only after confirmed termination of every child, never on elapsed time. Otherwise the records are marked done and the attempt is finalized `failed`, exit status 1, reason `reconciled: launcher pid N started S is dead; K recorded processes confirmed ended; no terminal was committed`.
2. **Recorded suite process ended without a terminal, launcher alive.** Every recorded suite leader and watchdog of the attempt is dead while the launcher still lives, seen on two consecutive passes (the first observation is recorded beside the attempt; the pass after the window acts). The launcher is wedged on a child that no longer exists: a cancellation intent is recorded first (it serializes against process publication, the order `CancelStopProof` uses), the keys are read again, the launcher is stopped through the ladder, and the attempt is finalized `failed` with the reason `reconciled: recorded processes ended without a terminal; launcher pid N stopped`. This is not the audit's own hang shape, where the section died with exit 141 while the suite leader lived on, waiting on a pipe: that shape has a live suite process and is bounded by the consumption supervisor (c08fe2cb, zero CPU for its window) and by proof-groups-detect-hangs-by-progress-not-the-clock; the DONE clause "section process ended without an end event" is read as this path for the recorded processes and is otherwise slice 2 of that sibling goal.
3. **Supervisor verdict dead or stopped.** A closed stop fence routes live attempts through the stop batch (internal/dispatch/stop.go, `CancelStopProof`), which cancels rather than fails them; the reaper's pass and the stop batch never act on the same attempt twice because the terminal commit is one locked transition. A launcher whose liveness reads Unknown is left alone and named in the pass: doubt never authorizes a kill.

Confirmed termination means the three recorded identities (suite leader, watchdog, launcher) and every live member of the recorded suite process group (read from the process table by group id; a child the leader spawned is a child all the same). A process the launcher never recorded and that left the group is outside this proof, and the audit's leaked supervise trios from temp fixture repositories are of that kind: they are the census's, not the attempt's.

The pass is idempotent and lock-disciplined: stop ladder outside the mutation lock, then the mutation lock, a re-read, and the single terminal commit, the same shape `CancelStopProof` uses. A terminal attempt is never signalled; its process records that still say running are marked done once every process they name is dead (the audit's 23), and an observation marker a launcher's own commit left behind is cleared.

**Health role** `proof-attempts` (internal/steward/health.go): dead when a live attempt's launcher is provably dead (remedy: the reaper's next pass reconciles it; if the reaper is not running, `metasystem up --repo <checkout>` re-arms it); unknown when a record is unreadable or carries no launcher evidence; alive otherwise. It joins the stop verdict like every role, which is the steward-incident clause the goal absorbed. A reservation the reaper holds as custody-pending shows as a live attempt with a live child, which is the truth.

**Status**: the DONE sentence says `metasystem status`; the verbs are `metasystem supervise status --repo` (a `liveAttempts` list with attempt id, goal, launcher pid, launcher liveness and record count) and the steward's health, so "no live attempt whose launcher is dead" is a line an operator can read in both.

**The tick and the window.** The reaper runs every interval (60 s in production); the observation window defaults to 30 s, so "persists" means the next tick. The window is real time because the reaper's clock is; the tests inject it.
