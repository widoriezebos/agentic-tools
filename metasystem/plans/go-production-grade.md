## Verdict

The codebase is closer to production grade than the request implies. Formatting and vet are clean, staticcheck finds 12 issues in 36k lines (3 of them staged patience-stream fields), the full suite passes under the race detector, the import graph is a strict layered DAG with no dumping-ground packages, and the command layer is a clean table-driven verb router (all ran it, re-verified 2026-08-12). The distance to "fully adhering" is:

1. **It does not build on Linux.** One package (`internal/identity`) is Darwin-only and sits under everything. The port surface is small and specified in the portability ledger — and the critique surfaced two liveness-semantics defects (B1, B2) the port must correct rather than reproduce.
2. **A handful of oversized units.** One 1,472-line file whose sixty declarations all carry a disambiguating prefix (the language's signal that it wants to be its own package), and about twenty functions over 100 lines.
3. **Domain state rides in raw maps.** 699 `map[string]any` sites in non-test code (ran it, recount 2026-08-12); the design standard's own smell list names this. Fixing it is the largest and riskiest item, because the maps are also the on-disk JSON contract.
4. **Claims without enforcement.** Adoption can ship a stale, unverified binary (B3); several production paths run external commands with no bound (B4); the atomic-replace writers document or imply crash-durability they silently drop on directory-sync failure (B5); the durable-append owners never sync at all (B6); the shipped coverage ratchet cannot see a testless package and the gofmt gate is fail-open (B8); the new repository audit skips unreadable files silently (B7).
5. **Small naming and idiom debt.** Redundant file prefixes, two `util` files, two wrongly-named error variables, one grab-bag helper file, and roughly 400 unwrapped `fmt.Errorf` calls.

Three steps are explicitly behavior-changing and say so: Phase 0a (adoption gains the Go-toolchain prerequisite), Phase 1 (the B1/B2 liveness corrections), and Phase 4 (production hardening, B4/B5). Everything else preserves behavior under the acceptance discipline below.

## Findings

Numbered so phases can reference them. File:line evidence is as of 2026-08-11.

### Defects surfaced by the critique loop (B)

Behavior corrections, not refactors. Each is a place where the code contradicts its own documented invariant; fixing them changes a verdict or an error path some caller can observe, so each is listed in the reserved-decisions section.

- **B1 — Unreadable argv becomes a false `Dead`.** The identity contract says an argv read failure must not downgrade liveness (`identity_darwin.go:53-59`, read it), but `Custodian` compares the tag against the joined argv after a successful probe (`custodian.go`, re-verified 2026-08-12) — an unreadable (empty) argv fails the tag check and returns `Dead`, which authorizes `process-lost`. **The 2026-08-12 reaper ruling raises the stakes**: the standing reaper now records in its own contract that it "never records a death it has not proven" and that "an unreadable custodian defers" (`supervise/reaper.go`, commit c0f6f47, read it) — but `Custodian` mislabels the unreadable-argv case as proven death, so the reaper still acts on exactly the unproven verdict the ruling forbids. B1 is now a direct contradiction of a recorded human ruling, not just of a package doc. Phase 1 carries the correction, with the full verdict table specified there.
- **B2 — Restricted procfs turns `Unknown` into `Dead` on Linux.** The ledger's Linux mapping reads stat `ENOENT` as definitive death, and notes `hidepid` makes a live foreign process indistinguishable from a dead one — but only says "consider detecting" (`linux-portability.md:88`). `Dead` authorizes lock takeover (`lock/lock.go:90,120`). Phase 1 carries the detection contract and the arming refusal.
- **B3 — Adoption can ship a stale, unverified binary.** `scripts/adopt.sh:237-245` (read it) builds only when `bin/metasystem` is missing, copies whatever executable exists with no check of OS, architecture, source freshness, or link mode, and its fallback build omits the commit stamp (whose default `dev` then enters operational artifacts, `supervise/disk.go:129-133`) and any CGO pin. No verb prints the stamp, so verification is not even implementable today (ran it — grep). Phase 0 resolves this by always rebuilding.
- **B4 — Unbounded external execution in production paths.** Contract preflight runs a network `git fetch` with no timeout (`mission/contract.go:1243`, anchor refreshed 2026-08-12), fingerprint execution is unbounded (`contract.go:1420`), and missionrunner's generic runner uses `exec.Command` without context (`missionrunner/launch.go:37`) — against the house standard's explicit timeout/cancellation requirement (`design-principles.md:44-51`). The gate command itself already runs under `CommandContext` (`contract.go:887`), so the pattern exists in-repo. Phase 4 owns this.
- **B5 — Documented crash-durability is silently dropped.** `atomicWriteText`'s comment promises the record "survives a crash exactly as written or not at all" (`dispatch/record.go:328-330`, read it), but the directory sync that makes the rename durable discards its error (`record.go:356`); `mission/ledger.go:493` does the same and skips the sync entirely when the directory fails to open. Eight atomic-replace writers known at the round-7 sweep (the six from round 3 plus `cmd/metasystem/supervise_arming.go` `writeIdentityJSON` and the adapter snapshot's `exclusiveWriteJSON`); the count is whatever Phase 4's audit finds, not this list. Phase 4 owns this with B4.
- **B6 — The durable-append owners never sync at all** (round 7, verified). `registry.LockedAppend`'s contract says "this owns durability and framing" (`registry/append.go:8-12`, read it) and its supervise caller treats an error as "not durably written" — but `AppendFrame` writes and returns with no file or directory sync anywhere in the package (ran it — grep). `receipt.appendLine` likewise reports success after `WriteString`/`Close`, unsynced. Where B5's writers sync and drop the error, these owners claim durability and never attempt it. Phase 4 owns this: the B5 inventory is redefined from "writers discarding a sync call" to **every contractually durable state mutation**, and the two append families get their own design (file/directory creation, partial-write exposure, post-write sync failure, lock-holder concurrency, the same committed-with-doubt semantics, fault-injection tests).
- **B7 — The repository audit fails open** (round 7, verified). The new `internal/audit` scan silently skips `Stat`, walk, and read failures (`audit/metasystem.go:185-211`, read it), and its test asserts that a forbidden reference inside an unreadable file produces no hit *and no error* — so the full suite's audit gate (`validate-metasystem.sh`) can pass while unable to read the very files it polices. Phase 4 owns this as a behavior-changing hardening unit: in-scope policy files must be readable, walk/read failures refuse the audit, and only explicitly optional absent roots stay skippable; the fail-open test is replaced by failure assertions.
- **B8 — Two gate checks cannot fail the way they claim** (round 7, verified). The gofmt "hard gate" discards stderr and status (`go-gate.sh:57` — `gofmt -l ... 2>/dev/null || true`), so a missing or crashing gofmt passes silently. And the shipped coverage ratchet's join is exhaustive only over *measured* packages: `ParseCoverage` keeps only lines carrying a numeric `coverage:` value (`audit/coverage.go:46-53`), and `go test` prints no such value for a package with no test files — so a brand-new testless package is invisible to the ratchet (confirmed by a live run: an unregistered `[no test files]` package exits 0). Phase 0 owns both: capture gofmt's status and refuse non-zero (negative test via a failing shim), and join the ratchet against an independent `go list ./internal/...` inventory with an end-to-end testless-package refusal test.

### Portability (P)

- **P1 — Darwin-only identity.** `internal/identity` implements `KernelProber` only under `//go:build darwin`; `CGO_ENABLED=0 GOOS=linux go build ./...` fails there and 13 packages fail behind it (ran it). Port surface, semantics tables, and traps: `plans/linux-portability.md`, as corrected by B1/B2.
- **P2 — CGO not pinned.** `scripts/adopt.sh:240` and the `go build` in `scripts/agents/go-gate.sh` use the environment default (read it). Static-binary portability across Linux distributions is currently accidental.
- **P3 — No Linux signal in the gate.** Nothing cross-compiles for Linux, so a Darwin-only regression is invisible until someone tries (ran it — the current failure proves it).
- **P4 — Over-narrow build tag.** `internal/census/ancestor_production.go` is Darwin-gated but contains nothing Darwin-specific (read it; detailed in the portability ledger).
- **P5 — Two syscall dialects.** Eight files import legacy `syscall` while the rest of the module uses `golang.org/x/sys/unix` (ran it). Every symbol used (`SIGTERM`, `Kill`, `Flock`, `SysProcAttr`, `Wait4`/`WNOHANG`, `ENOTEMPTY`, `EEXIST`) exists on both platforms, so this is consistency debt, not a port blocker.
- **P6 — `ps` runs under two different owner contracts.** `internal/dispatch/mission.go:81` and `internal/mission/contract.go:1384` (anchor refreshed 2026-08-12) exec the same `ps -p <pid> -o command=` line, but the surrounding contracts differ materially (read it, verified in round 1): dispatch consults its fixture (`METASYSTEM_FAKE_PROCESS_IDENTITY_FILE`) only after ps failure, restricted to a sole-fake-runtime checkout, and separately requires PGID agreement (`dispatch/mission.go:63-88`); contract preflight layers `unix.Kill` + `census.Alive` + ps with its own fixture (`METASYSTEM_MISSION_PROCESS_IDENTITY_FILE`) matching start+tag (`mission/contract.go:1322-1350`). The shell suite arms both fixtures independently. Routing these through the identity owner is a contract-preserving owner move with its own gated unit in Phase 2½.
- **P7 — Filename convention hazard.** `identity_darwin.go` is deliberate, but Go silently build-gates *any* file ending in a GOOS/GOARCH name. The `adapter_<vendor>.go` pattern would silently drop an adapter for a vendor named `js`, `wasm`, or `plan9`. No current file is affected (ran it — full scan). Fixed as a side effect of S5.

## Supported platforms

Round 1 (R1-F9) separated two claims the portability ledger blends. **Link portability**: with `CGO_ENABLED=0` the binary itself runs on any Linux with a compatible kernel and architecture — true, and worth pinning. **Operational support**: the system also execs `git` (`mission/anchor.go:22`), `bash` (`mission/contract.go:858`), repository scripts (`contract.go:1371`), and `ps`; it reads standard procfs semantics (B2). A `scratch` or distroless container is therefore *not* a supported operational target, whatever the binary's link mode.

Claims follow evidence (R2-F8), so the profile has two tiers:

- **Verified**: macOS on arm64 (the development host, where the full suite runs today), plus the single Linux host that runs Phase 1's acceptance suite — distribution and architecture chosen by the human (reserved decision 8) and recorded here when it passes.
- **Expected-compatible, unverified**: other mainstream Linux distributions (Debian/Ubuntu/RHEL-family; Alpine with the packages below) on arm64/amd64, with a standard `/proc` mount (no `hidepid`). A platform moves to the verified tier only when a full suite run passes on it; the plan claims nothing it has not run.
- **The command inventory is a contract, not "a POSIX userland"** (R7-F5): the shell layer additionally requires `shasum` (`dispatch.sh:75`, `supervision-hook.sh:181` — a Perl tool present on macOS but only via the `perl` package on most Linux, where the native tool is `sha256sum`), `pgrep` (`supervision-hook.sh:80,95` — package `procps`), and `mktemp` (coreutils). Phase 1 derives the complete production command inventory (a grep over `scripts/` for exec'd binaries), publishes it in this profile with the Linux package that supplies each non-POSIX command, and adds a preflight to arming/adoption that names anything missing. Where the Go binary already owns the capability (it hashes with `crypto/sha256` today), moving the shell caller onto `metasystem` beats documenting a dependency — decided per command in Phase 1, recorded here.

## Acceptance discipline

Every phase runs under `skills/refactor/SKILL.md`:

- **Acceptance gate:** `scripts/validate-metasystem.sh` (the full local suite, which sources `go-gate.sh` ahead of the shell fixtures). Per KI-10, the local suite is the gate; no hosted runner is assumed.
- **Baseline:** before the first edit, `scripts/refactor-baseline.sh record --gate "scripts/validate-metasystem.sh"` on a green run — which also refreshes every "ran it" claim above with current command evidence (R1-F16); implementation trusts the fresh run, not this document's history. Re-record at each phase acceptance.
- **Checkpoints:** each lettered step below is one commit that can be replayed alone; a phase is one cluster accepted by the full gate. Behavior-risk units are never batched with mechanical ones (R1-F11): they gate immediately, alone.
- **Obligation matrices:** any step that moves an owner or a package boundary (Phase 2½ both units, Phase 3a) tracks the full matrix per `docs/design/design-obligation-gate.md` in this plan before implementation.
- **Tests before restructuring:** any unit whose material behavior lacks focused tests gets coverage hardening as its first checkpoint (binds hardest in missionrunner, 54.4%).
- **Error text is contract** (E1): any change touching an error string greps `scripts/` for a matching fixture assertion first.
- **On-disk bytes are contract** (D1): no phase may change the JSON written to or read from `artifacts/`, `plans/`, or the registry, except where a step explicitly proves byte-compatibility differentially (Phase 5).

Ordered so standing guards land first, known defects (B1/B2 in Phase 1, B4/B5 in Phase 4) land before the typed-documents phase (R3-F8: not before every restructuring — Phases 2–3 precede Phase 4 in number and may in time), and the riskiest change (typed documents) lands last behind its own design gate. Phases 2, 2½, and 3 are independent of each other; Phase 5 wants both Phase 3 (extractions shrink the surface the typing touches) and Phase 4 first (hardening stabilizes the error text its golden corpus captures).

### Phase 4 — Production hardening: bounded execution and durable writes (behavior-changing)

The B4 and B5 work, moved ahead of the typed-documents phase because it fixes known defects, depends on nothing after Phase 0, and stabilizes error text before Phase 5 captures its golden corpus (R2-F13). Explicitly not behavior-preserving, so it stands alone and says so.

- **Bounded execution (B4)**: a per-surface design table agreed before implementation (R2-F12) — for each surface: the bound, the bound's owner (a `metasystem.conf` key with its default, so operators can tune it), the failure category per the standard (timeout vs dependency failure), the observable error text, and process-group termination semantics. Initial surfaces: contract preflight's network `git fetch` (`contract.go:1194`), fingerprint execution (`contract.go:1371`), missionrunner's command runner (`launch.go:33`) — plus an audit pass for peers. Focused hang tests per surface (a stub that never returns), and fixture-suite confirmation that no asserted error text changed without a matching fixture update.
- **Durable writes (B5 + B6)**: the inventory is **every contractually durable state mutation**, not just writers with a discarded sync call (R7-F3 — a sync-call grep cannot find the append owners that never call `Sync` at all). Known at the round-7 sweep: eight atomic-replace writers discarding the directory sync (`dispatch/record.go:356`, `mission/ledger.go:493`, `missionrunner/engine.go:186`, `host/host.go:64`, `adapter/adapter.go:104`, `lease/lease.go:171`, `cmd/metasystem/supervise_arming.go` `writeIdentityJSON`, the adapter snapshot's `exclusiveWriteJSON`), plus the two unsynced append families (B6): `registry.LockedAppend`/`AppendFrame` and `receipt.appendLine`. The phase opens by deriving the full inventory from the durability *contracts* (comments, caller expectations) as well as the write patterns, records each mutation's actual guarantee, and dispositions every site; the audit joins the B5/B6 checklist so a new writer cannot be missed silently. The append families get their own short design under the same outcome model: creation, partial-write exposure, post-write sync failure, lock-holder concurrency, committed-with-doubt semantics, fault-injection tests.
- **Audit integrity (B7)**: the repository audit must refuse what it cannot read (R7-F4): in-scope policy files that exist but fail `Stat`/read/walk refuse the audit run with a named error; only explicitly optional absent roots and deliberately pruned runtime paths stay skippable; the current fail-open test (unreadable forbidden reference → no hit, no error) is replaced by failure assertions.
  The fix is **not** naive error propagation (R3-F6): the directory sync happens *after* the rename has published the file, so by the time it fails the record transition is already visible — `RecordCAS` has applied it, the CLI would map the error to exit 1 (`cmd/metasystem/dispatch_verbs.go:recordExit`), and the shell emits lifecycle events only on exit 0 (`scripts/agents/dispatch.sh record_cas`), leaving committed state with a reported failure and a suppressed event.
  **The B5 outcome model, decided here** (R4-F1, transport and retry semantics fixed per R5-F1/F2 — this table is what reserved decision 4 approves; implementation follows it, not a fresh judgment call):
  - **Pre-publication failure** (directory establishment, temp-file create/write/fsync/close, or the rename itself): unchanged semantics — no new bytes at the target and the prior content unchanged; the writer returns the error, the verb exits non-zero, no event is emitted.
  - **Directory creation is part of the write and is made durable pre-publication, idempotently** (R6-F1, retry hole closed per R7-F1): all the writers `MkdirAll` first, and a new directory's own entry lives in its *parent* — syncing only the target directory says nothing about whether the directory itself survives a crash. Conditioning the chain sync on "did this call create something" has a retry hole: a failed chain sync leaves the directories visible, so the retry sees them pre-existing, skips the chain, and could report `durable=true` on an unproven chain. So the rule is **unconditional and inclusive of the durable anchor** (R8-F1 — an exclusive bound never syncs the directory holding the first created entry, and the range is empty when the target *is* the root): each writer names a durable anchor that is guaranteed pre-existing — the repository checkout for in-repo writers; for `~/.metasystem`, which may itself be created, the anchor is its parent (`$HOME`) — and every invocation syncs each directory from the target up to and **including** the anchor, *before* writing the temp file. Idempotent, no created-tracking, a few extra fsyncs on low-frequency writers. Failures there are pre-publication failures with plain-error semantics, keeping the post-publication doubt surface to exactly one operation: the target-directory sync after the rename. The fault-injection matrix carries a **two-call test**: first call fails the chain sync (plain error, nothing published); the retry must re-sync the chain before publication and may not return `durable=true` otherwise — with a variant where the writer's own directory tree, including the case of a freshly created `~/.metasystem`, is new.
  - **Committed-but-durability-unknown** (the directory sync after a successful rename, including the ledger's failed-directory-open case): **no retry** — after a failed fsync the kernel may clear the error state, so a subsequent success proves nothing (the documented fsync error-reporting trap); any post-publication sync failure is terminal doubt. The transition **stays committed and is reported as success with the doubt attached**: a committed transition is never converted into a reported failure (the F6 divergence this model exists to prevent), and there is no fail-then-succeed branch to mis-handle.
  - **A third outcome exists for the append families only** (R8-F2 — a failed append can leave a torn frame visible, which is neither "no new bytes" nor "committed"): **visible-but-uncommitted fragment**. The writer returns a plain error (the append is *not* committed, no event, no success exit); the torn tail is the *reader's* contract to detect and survive — the registry already frames records and surfaces `CorruptionError`, and the receipt log's line-oriented readers treat a torn final line the same way; repair truncates or skips the torn tail under the same lock on the next write or read; durability is claimed only after the post-write fsync succeeds. Fault tests inject a mid-frame failure and assert both the error return and reader-side recovery. Remaining append mechanics (exact repair timing, per-family reader rules) belong to Phase 4's gated design — the outcomes, invariants, and transports are decided here; the plan bounds that design, it does not replace it.
  - **The warning transport is the writer's signature** (R5-F1): each writer in the inventory changes from `error` to `(durable bool, err error)` — `err` non-nil only for pre-publication failures; `durable=false` with nil `err` is the committed-with-doubt outcome. The compiler then enumerates every caller, and the B5 checklist maps each one to its reporter: CLI verbs print the warning to stderr and exit with their success code; background components (supervision owner, mission runner) record it through their existing narration/log channel. No global state, no special error value a legacy `if err != nil` would misread as failure.
  - **Uniform across the full inventory** (atomic-replace writers on the two-outcome model, append families on the three) — the per-writer table in the B5/B6 checklist confirms each mutation against its rule, and any writer needing a different outcome is a recorded exception the human approves, not a local choice.
  - **Fault-injection tests per writer** (a test seam wraps the directory-sync step): post-publication injection asserts the file is visible with the new content, the return is `(false, nil)`, and the event/exit behavior matches the clean path — asserted on the returned values, not on captured stderr; pre-publication injection asserts no visible change and a non-nil error. Assertions cover both the returned outcome *and* the visible state.
  Comments are aligned with the guarantee actually delivered.

### Phase 5 — Typed domain documents (design-gated; the only phase that may touch bytes)

The D1 work, on the corrected premise (672 non-test sites; missionrunner 152, mission 124, adapter 95, dispatch 78). **Not started until its design passes `docs/design/design-obligation-gate.md`** — the on-disk records are named API surfaces under the project's reserved-decision rules.

What the design must specify (rewritten per R1-F3/F4 and R2-F9/F10/F11):

- **A lossless wire-document owner per family**: typed known fields *plus* a preserved raw remainder. Because `encoding/json` emits struct fields in declaration order, **structs are never marshaled directly onto the wire**: the canonical writer renders typed fields into a map, overlays the remainder, and encodes the merged map — sorted keys, `json.Number` spellings, two-space indent, no HTML escaping, and the trailing newline preserved by construction (R2-F9). `registry.ParseRecord` is the precedent for typed parsing, **not** for preservation.
- **A frozen accepted-input grammar** (R2-F10, completed per R3-F4): before conversion, tests capture what the current readers accept — duplicate keys (last wins under `encoding/json`), previously tolerated ill-typed known fields, null-vs-absent distinctions, **and trailing data after the top-level value** (the dispatch reader performs a single `Decode` with no EOF check, `record.go:291`, so trailing bytes and second top-level values are currently tolerated) — and the new readers must match them, per family. Narrowing the grammar is a behavior change this phase does not carry.
- **The differential oracle, captured first** (R2-F11): checkpoint 1 of each family drives the *current* writers through existing tests and fixtures to produce a committed golden corpus (inputs and byte-exact outputs, including CAS transitions, metadata updates, protocol errors, the mirror's normalized semantic-record hash, and state advancement, over the hard cases: unknown nested keys, number spellings, null-vs-absent, HTML characters, terminal records). Conversion checkpoints then diff the new writers against the corpus — the old implementation no longer needs to exist to be the oracle.
- **Exact CAS merge semantics**: `RecordCAS` today accepts arbitrary keys and values under its immutable/status rules (`record.go:232-251`); the typed layer must state which keys are typed, what happens to unknown patches, and how the permissive wire contract and the validated domain projection relate.

Staging, highest value first: dispatch job records, then missionrunner turn+state, then host results. Leaves stay maps where typing adds nothing — stated per family in the design.
