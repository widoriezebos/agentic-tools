Verdict: 11 material findings. No tests were run; evidence is from code reads and read-only transcript inspection.

1. **HIGH — The ownership split violates the current binding ruling.** The proposed shell ladder makes ordering, fall-through, provenance, and repair eligibility in-shell policy. The repository now records that all four belong to one `adapter devin-collect` engine verb; only process invocation stays in shell. Implementing r1 literally would already be wrong. [Current plan ruling](</Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/plans/delegate-delivery-design.md:6>)

2. **HIGH — “First qualifying bytes” discards valid lower-priority returns before validation.** Nonempty junk or a wrong-job schema-perfect object on stdout blocks a valid named file; any parseable named file blocks a valid transcript return. Full validation happens only after selection, and the downstream normalizer is never given the skipped named file. Candidate priority must be “first candidate that passes the canonical validator,” not “first nonempty/parseable candidate.” [Current collection](</Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/scripts/agents/adapters/devin.sh:352>) [Downstream adjudication](</Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/scripts/agents/adapters/runtime-common.sh:328>)

3. **HIGH — A matching `jobId` does not authenticate a transcript return.** The job identifier, round, and complete schema are disclosed in the prompt. Transcripts and delegate output are explicitly untrusted. Mining arbitrary intermediate write-call arguments lets poisoned repository content or the delegate manufacture a schema-valid object that passes every proposed guard. The design checks neither that the call targeted a return path nor that its observation recorded success; stored ATIF evidence shows denied writes still retain full arguments. This broadens “return” from an intentional final reply to any convenient intermediate tool argument. [Trust contract](</Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/docs/orchestration.md:128>) [Example denied write transcript](</Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/artifacts/agents/devin-selftest-20260808t121536z-42515-permissions-write/rounds/1/transcript.atif.json>)

4. **HIGH — The transcript predicate has no attempt boundary.** I verified that a stored round-two ATIF export contains every round-one step byte-for-byte. Legitimate cross-round duplicate job identifiers are currently prevented by record reservation and follow-up naming, but repair runs reuse the same job identifier and round, so those fields cannot distinguish the initial attempt from repair. “Last matching write” can therefore recover pre-repair material and falsely report the repair as its source. Recovery needs an engine-established step watermark or transcript-delta boundary. [Cumulative round-two transcript](</Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/artifacts/agents/devin-selftest-20260808t121536z-42515-main/rounds/2/transcript.atif.json>) [Job collision guard](</Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/internal/dispatch/record.go:153>)

5. **HIGH — A file-only repair cannot succeed through the existing repair contract.** `runtime_repair_turn` returns failure unless stdout is nonempty, while `after-repair` rejects any nonzero repair result before examining a candidate. It also passes only `repair-1.out`, not the repair transcript, into validation. Rewalking the ladder therefore requires a changed interface that reports provider exit status separately from delivery status; otherwise the exact repair shape being added is classified as failure. [Devin repair contract](</Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/scripts/agents/adapters/devin.sh:194>) [Shared repair path](</Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/scripts/agents/adapters/runtime-common.sh:364>) [Engine adjudication](</Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/internal/adapter/adjudicate.go:120>)

6. **HIGH — A separate empty-return repair path would bypass or duplicate the existing state machine.** Empty replies currently terminate through `empty-reply`; malformed replies alone enter `complete_from_cli`, which owns the repair count, cumulative-usage recomputation, repaired-session settlement, protocol-error mapping, and terminal compare-and-swap. Also, the malformed-repair prompt is authored in Go, contrary to the design’s claim that it is a neighboring shell heredoc. Empty and malformed delivery must converge in the engine-owned adjudication state machine, not become parallel shell flows. [Empty path](</Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/scripts/agents/adapters/devin.sh:363>) [Repair state machine](</Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/scripts/agents/adapters/runtime-common.sh:328>) [Prompt owner](</Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/internal/adapter/adjudicate.go:60>)

7. **HIGH — “Exactly one repair” is not durably enforced.** The in-memory counter is set immediately before the provider call, but `returnRepairs` is written only after that call returns, and failure of that compare-and-swap is ignored. A crash, kill, or re-entry during repair leaves durable state saying no repair occurred, permitting another paid repair. Claim the repair atomically before launch and make an already-claimed attempt terminally non-repeatable. [Repair ordering](</Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/scripts/agents/adapters/runtime-common.sh:364>) [Ignored recording failure](</Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/scripts/agents/adapters/runtime-common.sh:407>)

8. **HIGH — Transcript recovery is unbounded and then duplicated downstream.** Stored two-turn transcripts already reach roughly 200–345 KB and grow cumulatively. The proposed verb would parse the entire untrusted document, after which unchanged normalization parses it again and attempts a JSON decode from every opening brace. No byte, step, memory, or time ceiling applies after the CLI wait ends, so a delegate can wedge a running record with a large write argument. “Costs nothing at runtime” is false. Recovery needs bounded input and must prevent the downstream normalizer from remining an already-selected transcript. [Transcript normalization](</Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/internal/adapter/return.go:32>) [Per-brace decoding](</Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/internal/adapter/return.go:132>)

9. **HIGH — Torn-transcript and nonzero-exit precedence are unspecified and conflict with current behavior.** Devin session settlement runs before delivery collection; an unreadable transcript therefore fails `session_identity_disagreement` even when stdout or the named file is valid. Conversely, the design’s “when the CLI exits, walk channels” wording could promote output from a nonzero provider call, which current code deliberately forbids. Exit 1 versus exit 3 from recovery also has no terminal/fall-through mapping. Specify an outcome table covering CLI status, transcript settlement, channel results, and repair eligibility. [Current ordering](</Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/scripts/agents/adapters/devin.sh:333>)

10. **HIGH — The named file is neither per-attempt nor snapshotted safely.** It is not cleared before launch, repair reuses the same pathname, and the current parse-then-`cp` sequence reads it twice. A repair can overwrite the first malformed/torn artifact, contradicting the existing promise to retain the first reply; a background writer can also change bytes between validation and copying. Use distinct initial and repair paths, read each once into a bounded immutable snapshot, validate that snapshot, and preserve both attempts. [Named-file preparation](</Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/scripts/agents/adapters/devin.sh:236>) [Check/copy race](</Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/scripts/agents/adapters/devin.sh:352>)

11. **MEDIUM — Scope and observability claims are incomplete.** The Devin mission host uses the same schema-in-prompt mechanism, reads stdout only, and invokes `devin-prompt` without a return path, so the evidenced model bias remains live there. Separately, a single `repair` provenance token erases whether repair delivered through stdout, file, or transcript and is not bound to the accepted bytes. Provenance needs separate attempt/channel fields plus a digest, stamped only after canonical validation; host exclusion needs evidence or inclusion. The proof plan also lacks poisoned/denied writes, invalid higher-rung plus valid lower-rung, cumulative-attempt boundaries, repair-crash durability, large transcripts, nonzero exits, and actual host behavior. [Devin host](</Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/scripts/agents/hosts/devin.sh:44>)

REVISE: Candidate selection is neither validity-aware nor attempt-authenticated, and the proposed repair integration cannot preserve the existing one-shot adjudication, durability, and evidence invariants.
