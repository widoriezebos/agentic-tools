Tests never read a live ledger or install.

## Build
1. `internal/landing/plain/steward.go` (new). `type Intervention struct{At, Row, Subject, What, Why, How, Outcome string}` appended to `artifacts/agents/landing/interventions.jsonl` under the install lock (one line per act, the shape of the human steward's log). `func StewardStep(home string, now time.Time, seams ProveSeams) (StewardRun, error)`: read the status with its health, take `Health.Rows()`, and for each fired row that has an act below, act once and record it. Bounds (each a test): one act per (row, subject) per 60 minutes, read from the interventions file; no act while a person's proof runs (`RunningProof.Person != nil`), while a person's stop is open, or while the agent is mid-step (the agent step record younger than 2 minutes); never an act that ends a person's process, pushes code, or refuses a person's verb. A fired row without an act, or a bounded one, is reported, not acted.
2. The acts, each through the existing path the verb uses (find it; never a shell): `stale-question` → `WithdrawStaleLaneQuestion` then the trunk proof launch that `landing prove --trunk` performs (search `Trunk: true` in `cmd/metasystem/intent_landing.go` and move or expose the plain function); `unproven-incidents` → the same trunk proof launch when no proof runs; `stale-engine` → the deploy object's `now` through `internal/deploy` (`deployProject.runner`), outcome recorded; `silent-agent` → end the landing agent's session the way `landing stop` settles it (`settleLandingAgent`), without recording a person's stop, then the keeper's wake; `flake-under-load` → the trunk proof launch (lane-batching U5's repeat runs inside it). `batch-of-one`, `proof-drift`, `abandoned-resolution`, `overdue-goal`, `paused`, `question-open` report only.
3. Wiring: in `cmd/metasystem/landing_agent.go`, the keeper step the steward ticks (`newLandingAgentKeeper(...).Run`) runs `plain.StewardStep` after `Run()` when the run launched nothing (idle, held, paused, barren); its line is appended to the keeper's line. One tick, one steward step; the step itself is cheap (status read).
4. Status and health: `Health` gains `Interventions []Intervention` (the last five) and `Line()` appends `; steward: <last act> <minutes> min ago` when there is one; `landing health` prints the interventions group.

## Tests
Fixture installs with an injected clock and fake seams for every act (the fakes record the call; nothing launches): (a) stale question → withdraw called, trunk proof launched, one intervention line with Row=stale-question; a second step within the hour → nothing called, the run says "bounded"; after 61 minutes → acts again; (b) unproven incidents with no running proof → trunk proof; with a running proof → nothing; (c) stale engine → deploy now called once; (d) silent agent → settle + wake called; agent step 1 minute old → nothing; (e) a person's proof running → no act for any row; (f) report-only rows never call a seam; (g) the interventions file is appended under the lock and read back in `Health`; (h) the keeper wrapper calls the step only on non-launch outcomes. Mutation each: drop the bound, drop the person check, act on a report-only row → a test fails.
