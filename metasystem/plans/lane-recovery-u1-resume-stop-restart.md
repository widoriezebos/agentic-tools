## Build
1. `internal/landing/plain/resume.go` (new): `Resume(home string, person ActProvenance, now time.Time, seams ProveSeams) (ResumeRun, error)` runs, under the lane's locks and only when each condition holds, in this order: (a) a pending merge in the lane checkout that the lane's own status calls stale (the fix record abandoned, or "main moved: code change; rebuild") is aborted (`git merge --abort` through the seams' git) and the fix record closed; a merge the lane calls current is left alone and reported; (b) a barren hold is lifted by recording the person's selection of every admissible waiting goal, oldest first (the record `landing run --goals` writes; reuse that path: `PersonSelection`); (c) a sealed batch whose base is behind main by a code commit is restarted on the current main (the `landing restart` path); an open batch admits the admissible waiting goals (the `batch reopen` path); (d) main is proved when it is owed: open incidents and no trunk proof of the current main (the `landing prove --trunk` launch); (e) a stopped or paused lane is resumed and the agent started as `landing run` does. Each step appends one line to the run ("aborted the stale merge of G", "recorded the selection a, b", "restarted the batch on main 1234567", "proving main", "started the agent"); a healthy running lane yields "nothing to resume: the lane is running batch X" and changes no record (R-129). It never cancels a proof a person started and never touches a merge the lane calls current.
2. `cmd/metasystem/intent_landing_resume.go` (new): `landing resume [--by NAME] [--json]`, a person's act at the lane (prove the terminal as `landing start` does), registered like `landing restart` (intent row, idempotency row, declared check, coverage example, help text). `landing start` keeps its meaning; its refusal text and the barren-hold status line (lane/agent.go `barrenHold` reason) name `metasystem landing resume` as the remedy.
3. `landing stop` (intent_landing.go `stopLane`): after pausing admission and stopping regeneration it ends the landing agent's session through `settleLandingAgent` (the existing settle path), so a stopped lane has no live agent; the stop line says "the landing agent's session ended" or "no landing agent was running".
4. `landing restart` (batch_verbs.go): records the person's selection (the same record as `landing run --goals` for the reopened batch's members) so a restart alone lifts a barren hold (finding 200).
