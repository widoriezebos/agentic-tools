# Unit u8: a detached proof reads its own report

Working Mode: Implement. Goal lane-first-run-fixes (design brief `plans/lane-first-run-fixes-design-brief.md`, unit 8). Hot-fix class: the landing lane's engine, worktree branch off origin/main 5dfaf4fdc. Change only what this brief names; leave fixes uncommitted.

## The defect (measured on the real lane, 2026-10-11)

`artifacts/agents/landing/results.jsonl` of the landing install holds 155 real results; none carries `failed` and none `counted-full`. Every red was `unclassified` (so the landing agent asked a person instead of running the goal's fix round) and every full green never counted (so every batch reads "full proof overdue since …" and runs a full proof). Reproduction (a child started through `gaterun.LaunchDetached`, which opens the log `O_WRONLY|O_CREATE|O_APPEND` and makes it the child's stdout/stderr, Setsid): inside the child `os.Stdout.Name()` is `/dev/stdout`, and `os.Open("/dev/stdout")` fails with `permission denied` because the descriptor is write-only. `(*proofOutput).readLog` (internal/landing/plain/scope.go ~302-326) re-opens the log by `file.Name()`, so it returns before `readReport`: no report, no environment fingerprint, no package timings. The detached prover is `metasystem landing prove --wait --attempt ID` (prove.go ~497, launched at ~528); its cmd layer keeps `output := os.Stdout` for an `--attempt` run (cmd/metasystem/intent_landing_prove.go ~330). After the result, the same cmd layer renders "landing prove: …", "✗ … is proven red …" and "→ metasystem landing status …" into that stdout, i.e. appended to the proof log after `LANDING-CHECKED`.

## Decisions

- D1 `runCheck` (prove.go ~1090-1120) and `readLog` read the log by its known path, never by re-opening the output descriptor's name: `running.Log` when set, else the output file's `Name()` (a person's `--wait` creates the file itself). `readLog(path string, offset int64)`. A path that is missing or not a regular file leaves the environment unknown, as today.
- D2 `offset` is the log's size at the start of `runCheck` (Stat of the path), not `Seek(0, io.SeekCurrent)`: an `O_APPEND` descriptor reports position 0 before its first write, and the detached engine may already have written a preamble.
- D3 `readReport` (report.go ~44) accepts trailing lines after the final `LANDING-CHECKED` line when none of them begins with `LANDING-` (the engine's own render); a tail without a `LANDING-CHECKED` line stays incomplete, and a `LANDING-` line after it stays incomplete. Nothing else loosens. Check that `landing prove --classify ATTEMPT` and `plain.FailedChecks` (cmd/metasystem/intent_work.go ~622, the incident reader) go through this parser so a saved log with the render lines classifies.
- D4 Real-shape test in internal/landing/plain: the test binary re-launches itself through `gaterun.LaunchDetached` (Argv `os.Args[0] -test.run ^TestXxxChild$`, Env marking the child and a diagnostics path, Log a temp file); the child runs the real `runCheck` or, at least, the real `readLog` after a `/bin/sh -c printf` shell that writes `landing planned 1`, `LANDING-FAILED\tp/q\tTestA TestB`, `LANDING-CHECKED\t1` to its stdout, and writes `kind`, the failed units and the open error to the diagnostics file; the parent (bounded 20 s) asserts kind `complete`, one failed unit `p/q` with tests `TestA TestB`, no open error. Mutation: with D1 reverted the test must fail with `open /dev/stdout: permission denied`. Plus table tests for D3.
