## What it delivers

This is small: **one unit, one usable step**. The explicit commands `goal claim`, `metasystem internal goal next`, `session start` and `metasystem up` obtain their own fresh accepted snapshot before deciding. The session-start hook keeps today's offline ledger read. A slow ledger leaves session preparation visibly partial, with adoption pending and a command that resumes it. No manual `goal list --fetch` prerequisite remains.

U1 uses the existing projection, transport, publication and session owners. Build against main's restamp callback (`cmd/metasystem/up.go:113-165`) and claim as they are; U1 does not depend on `person-claims` landing first. This page changes explicit-command decision freshness, preserving current ownership and accounting rules. Records refs, batching and engine stamps remain deferred to the findings plan; their future consumers can use the observation in the existing command result. There is no daemon, freshness cache, new durable record or new public verb.

## Not in this goal

`person-claims` owns reservations, all-claim adoption and automatic claim preparation. It will consume `FreshProjection` for the post-preparation reread: reclassify the original caller, reread holder/epoch and refresh before selecting or publishing. It also owns per-claim pending preservation, including confirmed effects before a later timeout. The ownership-change and multiple-claim test assertions move there with those behaviors; this unit supplies the pinned projection/observation and the existing callback's typed pending result that they will consume.

The session-start hook retains its offline read; it needs no new budget constant. Hook-wide deadline propagation and publication-deadline plumbing are outside this goal; publication retains its current transaction checks, budgets and journal/recovery behavior.

## Decision 1: one observed tip per decision (U1)

**Sites.** `internal/goal/project.go:126` owns `Project`, `:137` reads the mutable accepted ref, and `:178` can return on a timer while its fetch goroutine continues. `internal/goal/fetchbounded.go:24` exposes bounded transport; `internal/goal/fetchadvance.go:20` returns `AdvanceResult.Tip`. `cmd/metasystem/intent_planning.go:1084` selects before actor handling at `:1246`; `cmd/metasystem/goal.go:295` and `:428` make next's fetch optional. The display reader is `cmd/metasystem/intent_goals.go:27`.

Add `goal.FreshProjection`, accepting the caller's cancellation/deadline and injected clock. It calls the existing bounded acceptance owner, then a private pinned-tip projection loader extracted from `Project`, using the returned tip rather than rereading the accepted ref. Return the projection with a small observation value: tip, observed-at, outcome and cause. It lives in the existing command/component result, never a file. Compute the approval horizon at successful observation, not before transport; an unchanged old commit can be freshly observed. Keep commit-age information separate from freshness. Local mode captures the current local ledger without network transport and retains sync-mode, identity and tree validation.

Prove/classify the actor before selecting. Claim refreshes before named-goal lookup, fallback, quota or held-work answers; internal `metasystem internal goal next` refreshes before ranking (`--fetch` stays compatible). Pass that same immutable projection to downstream readers. Display-only `Project` remains offline-capable.

Other decision inputs keep their owners: actor proof and live lease are read at the act; claim's lane view is read for that decision against the captured tip (`cmd/metasystem/landing_plain.go:38`), with unreadable membership retaining the standing quota for agents; presence in internal next remains advisory. A ledger observation promises no atomic snapshot across these owners. Every mutation still captures and validates the transaction's current tip and ownership through `internal/goal/txn.go:662`; a fresh preflight never replaces that race check.

## Decision 2: one bounded read on explicit commands; the hook stays offline (U1)

**Sites.** All three callers set the same callback: `cmd/metasystem/hook_entry.go:356`, `cmd/metasystem/up.go:239`, `cmd/metasystem/intent_process.go:682`. Main's `cmd/metasystem/up.go:113-165` reads offline before restamping one claim. `internal/hooks/runtime_hook_start.go:625` calls `ops.Up` synchronously. Repository-root `.claude/settings.json:30` grants SessionStart 15 seconds; brain preparation defaults to eight seconds (`internal/hooks/runtime_hook_start.go:599-605`: `brainDeadlineMS` 5000, `brainWait` five seconds plus three seconds), and that budget also covers supervision arming (`internal/up/up.go:833-845`) and wait recovery (`internal/hooks/runtime_hook_start.go:645`). `internal/goal/project.go:46` already defines the four-second `defaultFreshProjectionTimeout`; its comment concerns the different Stop hook. `internal/boundedexec/boundedexec.go:38` adds a five-second kill grace today.

Select the projection reader at the existing callback wiring: explicit `session start` and `metasystem up` use `FreshProjection`; the session-start hook retains `Project(endpoint, false, now)`. Keep main's single-claim restamp behavior. Do not put an unconditional fresh read in the shared callback, or make the hook's internal wait-recovery call inherit the explicit session command's fresh read. No hook budget constant or enclosing hook deadline plumbing is needed. The scheduler's `up --recover-only --if-down` selects recovery before ordinary arming (`internal/up/up.go:964`), never reaches the restamp and is unaffected.

Explicit claim, internal next, session start and up make **one bounded fresh-read attempt**, using the existing four-second `defaultFreshProjectionTimeout`, shortened by caller cancellation or any enclosing deadline. There is no in-command retry for transport, validation or identity failure. Report the cause and the same command as the remedy after repair; no stop record is needed because there is no retry loop. Mechanism 3's environment retry governs launched steps keyed by launch id; an inline command read is not one, so that retry does not apply. An environment failure consumes no build/correction attempt. Existing publication budgets remain independent; publication's necessary capture is not a second preflight attempt.

`FreshProjection` owns completion of that allowance, including validation, projection loading, transport cancellation, process exit and temporary-ref cleanup. Allocate up to three seconds to transport and reserve up to one second within the allowance for finishing/cleanup; shorten both for a shortened allowance. Extend the existing bounded execution owner with a per-call total deadline so its five-second default grace cannot be added outside this allowance. Thread that bound through the acceptance owner's local Git operations and cleanup too; injected repositories must obey cancellation rather than bypass it. No detached fetch or late accepted-ref advance after timeout. Cleanup failure is an explicit failure naming the temporary ref, never fresh success.

**Use of the wait.** No speculative work runs during ledger transport: selection and adoption depend on its result, while parallel preparation would complicate the deadline and ownership sequence. One transport is in flight per decision.

## Decision 3: pending survives every renderer; people retain their acts (U1)

**Sites.** `internal/up/up.go:160` produces a deferred component, but `:851` can still return aggregate `armed`. `internal/hooks/runtime_hook_start.go:631` examines only the aggregate/exit status. `cmd/metasystem/up.go:86` renders the JSON envelope; `cmd/metasystem/intent_process.go:688` maps the session result to an intent outcome.

Extend the existing restamp/component result with typed adoption status and observation/cause, carried into `up.Result`, its data/lines, the session intent and the hook notice. Adoption pending is a typed adoption field: when supervision succeeds, up's `Outcome` stays `armed`, its exit code stays 0 and its JSON envelope stays confirmed; the session intent maps pending adoption to `partial` (`intentPartial`, `cmd/metasystem/intent.go:787`, at the session mapping in `cmd/metasystem/intent_process.go:688`). The machine callers are unaffected: mission launch (`internal/missionrunner/launch.go:228`, `requireArmed` at `:544`) and landed rearm (`internal/testrun/rearm.go:428`) consume up's outcome through its envelope, while session isolation (`cmd/metasystem/session_isolate.go:82`) consumes its successful exit. On explicit commands, unknown freshness means **adoption pending**, including when supervision itself succeeded. For explicit commands, render partial preparation, its transport/deadline cause and the same command as the remedy: **`metasystem session start`** for session start, **`metasystem up`** for up. The hook keeps its offline read; its existing adoption failures still carry their cause and **`metasystem session start`** remedy. Do not hide the typed adoption state behind `armed`, `no-claimed-goal`, a rebuild notice or an empty frontier. Hook notices remain advisory to the runtime session; partial state does not terminate a person's session.

On explicit commands, agents cannot select, claim or adopt from unavailable freshness. A proved person's internal next may show the last readable accepted snapshot, explicitly stale and non-authoritative. A person's named claim bypasses a failed freshness preflight and goes to the normal safe publication transaction; stale existence/quota/area advice cannot veto that act. With transport still down, that transaction fails at publication's `CaptureTip` as an environment failure; the message says the remote ledger could not be reached during publication and names the same claim command after transport repair. Bypassing preflight does not promise offline publication. An unnamed claim cannot invent a candidate: show available stale information and invite a name. A person's session start can prepare supervision and the real discovered session while backlog/adoption remains unavailable; no runtime ancestor means no synthetic session. Helm possession never proves person authority and no freshness remedy clears it.

Transport remedies are the same command after repair, with no fetch-first ritual. Corruption, foreign identity and unknown ownership report their actual source and existing safe repair; they cannot authorize invalid shared mutation even for a person. Unreadable advisory banners, presence or policy never refuse a proved person's act. Unknown authority grants no agent permission and never relabels the caller as a person.

## Public-verb test and mutations (U1)

Drive real command/hook owners with injected clocks, transport and process boundaries and synthetic configuration. Behavior tests keep real Git unavailable. The narrowly scoped cancellation/temporary-ref cleanup adapter proof uses **real Git available**: a stub cannot prove process exit or actual Git ref cleanup. Do not stub the callback or publication effect being proved. These are required implementation tests, not evidence already run.

1. Begin with a stale local accepted tip and a newer remote claim. Run claim, `internal goal next`, session start and up through their real entries. Observe the remote state without a preceding list/fetch. Advance the accepted ref after fetch to prove projection remains pinned; return an unchanged old commit to prove observation freshness; expire approval during transport to prove the horizon uses observation time. **Mutations:** restore any explicit caller's offline read, reload the accepted ref or use the pre-fetch clock; each must fail its state assertion. Post-preparation ownership-change assertions belong to person-claims.
2. Through the real explicit session start and up entries, hang transport. Assert exactly one preflight attempt, cancellation, process exit and temporary-ref cleanup within the four-second allowance, and visible **adoption pending**, transport cause and the same command as the remedy. With supervision successful and adoption pending, assert the typed adoption field, up's `Outcome: armed`, exit 0 and confirmed envelope, and session intent `partial`; pass that actual up result through mission launch's `requireArmed` and the rearm envelope reader and assert both still accept it. Inject a shorter caller deadline and exercise the real-Git cleanup adapter proof. Repair transport, execute the printed command through its real owner, and observe adoption with unchanged ownership, budgets and accounting; replay must be idempotent. Separately drive `internal hook claude start` with unavailable remote transport: assert its ledger projection stays offline, starts zero freshness preflights (including through wait recovery), and preserves its preparation, supervision and wait-recovery behavior. This does not claim to bound existing hook publication. **Mutations:** retry an explicit read, ignore cancellation, add the default kill grace outside the allowance, leave a temporary ref, discard pending behind successful supervision, flip up's `Outcome` from `armed` to `partial` while adoption is pending, or wire the hook to FreshProjection; each must turn the test red. Per-claim preservation assertions belong to person-claims.
3. Exercise local mode, foreign/corrupt ledger, unreadable authority and agent transport failure; assert one explicit-command attempt and its cause/remedy, without a retry or stop record. For a proved person, test stale next, unnamed versus named claim, unreadable advisory inputs and session preparation with unavailable ledger or absent runtime ancestor. A named claim with transport down must reach publication's `CaptureTip`, fail there as an environment failure and say so; repaired transport must let the same command succeed. Follow the printed repaired-command remedy without clearing helm/ownership gates. **Mutations:** infer person authority from a name, use stale agent selection, veto a named person claim on advisory freshness, hide the CaptureTip environment cause, manufacture a session, or report unknown as an empty frontier; each must fail.

## Decided by m1e for Wido

- **Reversible:** the session-start hook keeps today's offline ledger read; only the explicit commands (`goal claim`, `metasystem internal goal next`, `session start`, `metasystem up`) read the ledger fresh. The stale-view friction of 2026-10-06 came through the explicit commands. The hook read's only beneficiary on main is remote reservations, which person-claims builds. Its 15-second budget is shared with brain preparation (eight seconds by default: `brainDeadlineMS` 5000, `brainWait` five seconds plus three seconds, `internal/hooks/runtime_hook_start.go:599-605`), supervision arming (`internal/up/up.go:833-845`) and wait recovery (`internal/hooks/runtime_hook_start.go:645`); a fresh read there risks the hook's main job. This removes round-1 finding 2 and the need for a hook budget constant or publication-deadline plumbing.
- Adoption pending is a typed adoption field; when supervision succeeds, up's `Outcome` stays `armed`, exit 0 and its envelope confirmed, while the session intent maps pending adoption to `partial` (`cmd/metasystem/intent.go:787`). Mission launch (`internal/missionrunner/launch.go:228`, `requireArmed` at `:544`), landed rearm (`internal/testrun/rearm.go:428`) and session isolation (`cmd/metasystem/session_isolate.go:82`) are unaffected; test 2 proves the first two through `requireArmed` and the rearm envelope, with a mutation that flips `Outcome`.
- Keep one unit on existing owners, with invocation-local observations and pending results. Explicit commands get one bounded four-second fresh-read attempt using `defaultFreshProjectionTimeout` (`internal/goal/project.go:46`), report the cause and name the same command as the remedy. There is no retry loop, so no stop record is needed; no new retry register or service is built here.
- Keep advisory failure distinct from unsafe shared mutation. A person can still act by name; an agent never guesses from stale data. Mechanism 1 supplies the authority rule.
- Build against main's restamp callback and claim as they are. Person-claims will consume `FreshProjection` and owns the post-preparation reread, per-claim pending preservation and their test assertions; leave reservations, eligibility, accounting, records refs and engine comparisons with their existing designs.
