## Intent

A person who knows that a red comes from one host's environment can keep it on that host with one act. Hand-ins on every other host then land. A code red still holds every host. The register records where each red was seen, who scoped it, why, and the impact statement that person read. The machine never sets or changes a scope. A host red closes on one green full check of current main on that host.

What changed from revision 2: the checkpoint reads each checkout's supervision state and waits out old detached proofs (D9); the scope act's flags reach the goal owner through the shared parser (D6, U2); a hand-in whose incident was scoped away is admitted (D10); the tests stub Git, ledger included (Tests); the scope act has no recovery case (D6).

## Problem

**What happened.** The MacBook lane (`landing-m1f`, Intel darwin/amd64) ran its first batch proof (attempt `20261106T123014`, main `e015235817`) while Little Snitch blocked Go's downloads (finding 550) and XProtect slowed every file write (551 correction). At 19:43 CET (`opened` 18:43:17Z in `plans/goals/trunk-red.json`) it recorded nine trunk reds on main: `red:fast-static-build-6` and eight `cmd/metasystem` tests. Every sighting's opid ends in `-landing-m1f-41ad7d6c`. Every owner machine is empty. This Mac's lane had proved the same main green (552). The ui seat's `work land` was refused for 1.8 h ("main has an open incident (red:fast-static-build)"). Wido closed all nine by hand between 21:27:50 and 21:28:48 CET. A tenth (`...ImpactPlanGitAdapter-2`) opened at 23:05 CET and Wido closed it at 00:02 CET. The week review ranks this class first: 26.0 seat-hours (section 2, rank 1).

**Why it spreads.**

- A sighting has no host field (`internal/goal/trunkred.go:82-101`). The host is only inside the opid string. Both lanes write the same log path, so the path cannot tell hosts apart. The recorder never passes `OwnerMachine` (`cmd/metasystem/intent_landing_incident.go:43`).
- A second host's sighting of an open trunk red is dropped. `repeated` treats any open trunk-red entry of the same identity as already applied (`trunkred.go:652-656`). So the register cannot show that two hosts saw one red, which is the best evidence that it is code.
- Every open trunk red holds every hand-in on every host. `openIncidents` keeps every unclosed entry of class trunk-red (`internal/landing/plain/hold.go:77-93`). `TrunkDecision` refuses while any is open (`hold.go:151-174`; the words at `:173`). Every lane hold path reads the register through `seams.incidents` (`hold.go:53-58`), which calls `ReadIncidents` (`hold.go:32-51`) unless a seam overrides it. Callers include the batch reopen (`batch_verbs.go:59-60`), the queue (`queue.go:367`, `:568`), status (`status.go:354`, `:379`, `:493`, `:538`, `:643`), drain (`drain.go:283`), resume (`resume.go:158`), the policy question (`policy_question.go:156`, `:193`), push (`cmd/metasystem/intent_landing_push.go:400`) and the seat's hand-in (`cmd/metasystem/landing_plain.go:144`, through `TrunkInputs`, `hold.go:244-253`). A seat with no lane reads `goal.LandingIncident` (`internal/goal/landing_hold.go:7-22`; words from `IncidentReason`, `landing_plain.go:162`).
- A person has no act between "hold everyone" and "close it". `incident close` and `incident claim` are the only incident acts (`cmd/metasystem/intent_planning.go:441-462`). Closing loses the hold on the host that is still red.
- A green full check on any host closes every open `red:` trunk entry (`intent_landing_incident.go:113-118`). Closure sets one `Closed` per entry (`trunkred.go:898-906`); there is no per-host closure.
- Flake sightings travel a second writer: `landingFlakeRecorder` (`cmd/metasystem/intent_landing_flake.go:112-139`), `FlakeRecordArgs` (`internal/goal/recordflake.go:15-24`), and the conversion to `TrunkRedRecordArgs` (`recordflake.go:120-122`). Today its only caller is the lane (`intent_landing_prove.go:145`). The seat's unit check writes main reds through `landingIncidentRecorder` (`cmd/metasystem/intent_work.go:684-694`).
- A hand-in with a person's exception is published only if the bound incident set equals the current one (`internal/landing/plain/queue.go:371`, `slices.Equal`). The hold owner already accepts a shrinking set: `exceptionCovers` asks only that every currently open incident was covered (`hold.go:116-134`, the loop at `:128-133`). So an incident that closes or is scoped away between binding and publication refuses a hand-in that nothing holds any more (Astra ENV2-03).

**Today's two MacBook entries are flakes.** `flake:5ee5869e...` and `flake:7db9c3a8...` (opid `...-landing-m1f-41ad7d6c`): `git worktree add` of 8079 files ran past the 300 s local bound (`internal/boundedexec/boundedexec.go:35-39`) and was green on repeat in 11 to 21 s. A flake holds no hand-in (`hold.go:80`). The register at `17acb13cb2` has 10 open entries, all flakes, none trunk red.

**What the evidence cannot show.** On one host, a red the host causes and a red the code causes look the same. Both complete, both reproduce on the repeat, and the failure reasons are empty (`"reason": ""` in both flake entries). A host's lane history is not a cause either: a code fault first seen on a new host has the same history as the 11-06 reds (Astra ENV-01). Greens on other hosts do not exclude a platform-specific code fault (Astra round 2). The cause is something a person knows (Little Snitch, XProtect) and records. What the machine can give that person is where the red was seen, and one act to keep it there.

## Decisions

**D1. Every sighting names its host.** `TrunkRedSighting` gains `Host` (`trunkred.go:82-101`). The host is the machine name of the lane registered on this computer: `lane.Read(home)` (`internal/landing/lane/lane.go:133`) and that checkout's `metasystem.goal.machine` through `owners.machine` (`cmd/metasystem/intent_landing.go:55`; `goal.ResolveMachineWithConfig`, `internal/goal/actor.go:30-37`). So the lane and a seat on one computer write the same host (`landing` here, `landing-m1f` on the MacBook). No lane, or an unreadable lane record or name, writes no host: a sighting is evidence, not a gate. Both writers carry it: `landingIncidentRecorder` (lane and seat unit check) and `landingFlakeRecorder` through `FlakeRecordArgs` and `recordflake.go:120` (Astra ENV-07). When a-red-is-classified-once U2 makes the seat call `landingFlakeRecorder`, it gets the host from the same function. Rejected: the actor's machine (`r.Actor.Machine`); a seat's unit check would write `m1f` and the lane `landing-m1f` for one computer. Rejected: parsing the opid; it names the actor, not the host.

**D2. A second host's sighting is kept.** A trunk-red sighting whose host no sighting of the open entry names is appended, and nothing else on the entry changes (no class, failures, holds or scope change). The same host again is already applied, as today (`trunkred.go:652-656`). A sighting with no host is treated as today. Effect: `movedIncidentMain` reads the newest sighting's base (`internal/landing/plain/trunk_recovery.go:18-21`); a later sighting on another host moves that base forward, which is true. A second-host sighting is evidence, not a failed recovery (decision 12): it is shown, and no question is raised (Astra round 2, question 2). Rejected: appending through the red-twice path (`trunkred.go:725-735`); it also rewrites failures and adds the other host's batch to `Holds`.

**D3. A scope is a person's decision, stored apart from the sightings.** `TrunkRedEntry` gains `Scope *TrunkRedScope`: `Host`, `By`, `At`, `Why`, `Impact`, `Opid`. Absent means fleet, as today; every existing entry keeps today's behaviour. Present means a person decided: `Host` empty is "this is code, hold every host"; `Host` set is "this is that host's environment, hold only there". One host per scope. The machine never writes, widens or removes it (R-142-m1e). A sighting on another host after a person's host scope is appended (D2) and shown, and the scope stays (Astra RULING-R-142, ENV-03). Only class trunk-red carries a scope; flakes hold nothing already. `Opened` stays the incident's first observation on any host; no word claims it is the scoped host's first observation. Rejected: deriving held hosts from all sightings (revision 1); a later sighting would change the effect of a person's decision.

**D4. No automatic scope in this delivery.** The recorder writes no scope. Revision 1's rule ("an unproven host's red stays on that host") is withdrawn. It decides by history, not cause. A code fault first seen on a new host would hold no other host, while other hosts' impact proofs may not run the failing group (`proofScope` reaches `impactScope` against the batch base, `internal/landing/plain/proof_admission.go:75-84`). That exposure needs Wido's word (R-36-m3), see Decisions for Wido. This delivery meets the week review's independence objective once a person scopes the incident, not before. Folds Astra ENV-01; this also removes the history read Astra ENV-08 found unsafe (`plain.Results` skips undecodable lines, `queue.go:159-165`).

**D5. The hold reads the scope in one place.** `ReadIncidents` (`hold.go:32-51`) reads the checkout's machine name with the injected git (`config --get metasystem.goal.machine`) and drops open trunk-red entries whose `Scope.Host` is set and differs. Every lane hold path, the exception binding (`hold.go:116-134`, `queue.go:367-373`) and the policy question (`policy_question.go:193`) then see one set per host. If the name cannot be read, nothing is dropped (fail closed). A seat with no lane (`goal.LandingIncident`, `landing_hold.go:11`) skips host-scoped entries: a host scope names a lane, and this computer has none. The refusal owner is `TrunkDecision` (`hold.go:173`), not `IncidentReason` (Astra ENV-08). On the scoped host it reads: "main is red on this host (landing-m1f): incident X, first seen 19:43; a person kept it here: <why>. Other hosts land." The time is `Opened`, the incident's first observation on any host (Astra round 2). Rejected: a host parameter on `openIncidents` and its callers. Same result, more changed lines, and a caller that forgets it holds the fleet.

**D6. The person's act, with its impact first and recorded.** Proposed words: `metasystem incident scope I --host NAME --reason TEXT` and `metasystem incident scope I --fleet --reason TEXT` (the name is Wido's call). Person only, as `CloseTrunkRed` (`trunkred.go:1043-1048`). The reason is the cause ("Little Snitch blocks Go downloads on the MacBook"). The goal owner builds the impact statement from the entry, so both the verb and the owner use one text (R-143-m1e). The verb prints it before it publishes, as `goal allow` does (`cmd/metasystem/intent_goal_permission.go:44-45`), and passes it to the owner. The owner rebuilds it from the entry at the ledger tip; if they differ, it refuses ("the incident changed; read the new impact and repeat"). Recording a newly built text after printing a different one would record what the person did not see (R-143-m1e; Astra ENV2-02). The scope records it in `Impact`, as a unit drop does (`intent_unit_drop.go:154-158`). The statement for `--host landing-m1f` says:

- what it lets through: "Hand-ins on every host except landing-m1f land while main fails X.";
- the risk: "If this is a code fault, other hosts land on a red main, and their impact proofs may not run X.";
- later work: "landing-m1f holds until a green full check of current main there closes X. A sighting on another host is shown, and the scope stays.";
- undo: "metasystem incident scope X --fleet --reason TEXT".

When no sighting names the host, it adds: "No sighting of X names landing-m1f." That is a warning, not a refusal (R-142-m1e). `--fleet` says every host holds until X closes, and names the `--host` undo. Refused: an agent, a closed entry, a class other than trunk-red, both or neither of `--host` and `--fleet`. A scope equal to the person's recorded one is success with nothing recorded (R-129-ui). `--fleet` on an entry with no scope records the person's decision (Astra RULING-R-142: only an already recorded equal decision is a no-op). Rejected: a `--host` flag on `incident close`; the act must keep the entry open.

Transport. The verb forwards to `runGoalTrunkRedWithDependencies` (`goalsync_mutations.go:2139-2164`; called from `intent_planning.go:2561`), whose sub-commands parse through `runSyncOnlyWithDependencies` (`:2077-2079`), `parseSyncFlags` (`goalsync_owner_report.go:43-50`) and `parseSyncFlagValuesWithOutput` (`goalsync_mutations.go:1043`). `syncFlags` (`:980-995`) has `why` but no host, fleet or impact. U2 adds `host` and `impact` strings and a `fleet` switch, registers them only for `trunk-red scope`, and refuses them on every other verb, as `--goal`, `--branch` and `--to` are refused outside `trunk-red own` (`:1156-1161`). The parser also refuses `trunk-red scope` with both or neither of `--host` and `--fleet`, or without `--why` or `--impact`. Folds Astra ENV2-02.

Recovery. The scope act gets no recovery case. `completeFromIntent` refuses to replay a journaled person's act (`internal/goal/recover.go:201-215`): a stored name is not authority. `trunk-red-close` has no case either (`recover.go:387-404` holds `trunk-red-record` and `trunk-red-own`). An interrupted, unpublished scope act is repeated by the person; a published one follows the existing confirmation recovery. Folds Astra ENV2-05.

**D7. A host red closes on its host's green, with its cause recorded.** `clearLandingIncidents` (`intent_landing_incident.go:83-131`) skips an entry whose `Scope.Host` is set and is not this lane's machine. If the machine name cannot be read, it skips every host-scoped entry. A host-scoped entry always carries a person's cause (`Scope.Why`) and closes on one green full check of current main on its host (the existing gate at `:84`). That is decision 2's evidence closure: the cause recorded and one green run on current main (Astra RULING-DECISION-2). One host per scope means one host's green never releases another host's red (Astra ENV-03). Fleet entries close as today. Flakes keep the three-pass rule (`countFlakePass`, `trunkred.go:909-930`; `plans/designs/red-names-what-failed.md` D3). R-35-m3 still asks that load-sensitive machinery be repaired.

**D8. The recovery on the red host is named in full.** After the host is fixed, on that host: `metasystem landing start` if the lane is paused, then `metasystem landing prove --trunk --fresh`. `--trunk` sets the subject to main (`cmd/metasystem/intent_landing_prove.go:231-232`); `--fresh` asks for a full check (`proof_admission.go:69-70`). The verb starts the check detached through `seams.Launch` (`intent_landing_prove.go:133-135`, `internal/landing/plain/prove.go:688`); the detached command runs `plain.Run` (`intent_landing_prove.go:384-394`) and a green trunk result reaches the closure (`:411-414`). The scoped hold words name this command. No new scheduler: the keeper's own clock launches fresh trunk proofs through the same `Start` (`internal/landing/plain/keeper_clock.go:176-192`: fresh trunk seams, then `Start`), whose detached command reaches the same closure (Astra round 2). Folds Astra ENV-06.

**D9. Readers first, read from the running engines.** The parser rejects unknown fields (`trunkred.go:203-207`). An engine without U1 cannot read a register with `host` or `scope`, and then every hold path fails closed on every host. So U1 adds the fields and the readers and writes nothing new. U2 and U3 land only after the checkpoint passes on every checkout that reads the register: m1e's seat, ui's seat, m1f's seat, this Mac's lane and the MacBook lane.

The checkpoint, per checkout, reads that checkout's supervision state, `metasystem/artifacts/agents/supervision/state.json` (`internal/supervise/disk.go:50-60`). Its owner writes `owner` (pid, start time, tag), `generation` and `engineBuild`, the stamp linked into the running binary (`disk.go:243-258`, `BuildStamp` at `:145-149`; reader `EngineBuild`, `:189-205`). A checkout passes when (a) the named owner is live: its pid runs with the recorded start time, the rule `armedIdentityAlive` applies (`internal/supervise/verifyarmed.go:32-44`); and (b) `engineBuild` names U1's commit or a later one (stamps are source-linked, `internal/enginebuild/stamp.go:1-8`; a `-dirty` stamp does not pass). On each lane there is one more condition: (c) no proof that started before the owner's `startedAt` still runs. A replaced supervisor does not replace a detached proof that the old binary started; that proof still parses the register with the old reader. `metasystem landing status` shows the running proof and its `since` (`internal/landing/plain/status.go:867`; `Running.Since`, `prove.go:70`). Rejected: the fleet line. `runnerContext` copies the installed enrollment's `EngineBuild` (`internal/steward/runner.go:129-139`), not the running binary's stamp (Astra ENV2-01). Rejected: a new stamp mechanism; the supervision state already carries one. No verb prints (a) to (c) today (no caller of `EngineBuild` or `InspectArmed` outside `internal/supervise`), so the steward reads the file and the process table on each host. Order: U1, checkpoint, U2 (the escape hatch), then U3.

**D10. Publication admits a hand-in whose incident left.** At `queue.go:371` the exact equality becomes the rule `exceptionCovers` already applies (`hold.go:128-133`): every incident open now must be in the bound set. One helper holds the rule and both call it. The identity, destination and unreadable-state checks around it (`queue.go:356-370`) stay. So an incident scoped away or closed between binding and publication no longer refuses the hand-in; an incident that opened after binding still asks for a renewed exception ("an incident opened after the exception; repeat it for the current incidents"). `openIncidents` keys on identity, opened and first sighting (`hold.go:67-71`, `:77-93`), so a scope added to a still-held incident does not change its key. Folds Astra ENV2-03.

## Decisions for Wido

Answered in his name with the rejected alternative; he overrules.

- **Automatic host scope: not now.** This delivery gives the person the act and the evidence. Rejected: revision 1's lane-history rule. It would have kept the 11-06 reds on the MacBook, but it would also keep a real code fault on a new host, with nobody deciding (Astra ENV-01).
- **The deferred follow-up is named, not built.** Proposed goal `a-host-red-is-proposed-for-scope`: collect attributable host events (blocked downloads, scanner slowdowns) and same-code recovery evidence on the red host; measure how often its proposal agrees with people's scope acts; then propose the scope act to a person in a question. Automatic action needs Wido's explicit policy word (R-36-m3), and nothing overrides a person's recorded scope (R-142-m1e). This page adds no writer for it.
- **The verb's name.** Proposed: `metasystem incident scope I --host NAME|--fleet --reason TEXT`. Rejected: `incident close --host`; closing ends the hold everywhere.
