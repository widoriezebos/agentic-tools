## What exists after step 1

A person edits the existing member file, applies it, sees a real split parent and linked unapproved children through `goal show`, and can reverse it before child work starts. The source is neither concluded nor permanently retired. The existing parser already accepts intent, next step, blockers and labels (`internal/goal/split.go:24`, `:63`, `:158`); the existing command reads that file (`cmd/metasystem/intent_planning.go:293`, `:2039`; `goalsync_mutations.go:3135`). Today's harm is in the effect: children become an arc (`split.go:282`), the parent becomes done and is archived (`:315–327`), and its id is retired (`:359`; `internal/goal/root.go:348`). Replace those effects directly in the existing transaction.

The first usable delivery is the five units below integrated as one goal. State readers precede the writer; reversal and notification ship with it. There is no intervening release advertised as a working split feature. This is useful before any browser or proposal database exists.

**A source block is a real hold.** `internal/goal/project.go:817` requires blockers to be done; changing that rule to treat split as done would violate this decision. After approving and supplying the child's ordinary risk/budget information, a person deliberately releases that hold with the already available `metasystem goal unblock CHILD --on G` (`cmd/metasystem/intent_planning.go:247`; `internal/goal/verbs.go:3335`, `:3374`). Approval alone does not release it. The command's impact explains this and names the unblock act; sibling and external prerequisites remain. Existing dependents of G continue waiting for G; after the children finish, concluding G remains the person's existing `goal done` act. Neither child completion nor splitting auto-concludes G.

Threat model: trusted people and agents make mistakes; concurrent goal acts, stale reads and interrupted publication occur. Existing goal transactions, actor authentication and channel delivery own those boundaries. No new service, paid planner, scheduler or dependency is introduced.

## Decisions with code sites read on origin/main

### S1 — Represent a split without concluding its parent

Extend the existing goal record (`internal/goal/file.go:25`, `:524`, parse/render beside `:1336`/`:1860`) with `StateSplit`, a parent's `Split` value containing child ids, the split transaction identity and prior state/park information needed for reversal, and each child's `SplitFrom` parent id; use existing history for actor/time and retain the existing ratification digest, without a separate proposal record. Validate reciprocal links and prohibit a live claim on a split source in the current goal validator (`internal/goal/validate.go:229`, `:323`); split stays in the live directory, never in done or the permanent `Decomposed` register. Move the state and lineage readers together: goal projection/show, `internal/project/goals.go:68`'s live/concluded classification, selection (`internal/goal/project.go:798–825`), claim/completion and the existing board/UI goal projection (`internal/ui/project/project.go:200`). Split is visible unfinished responsibility, unclaimable, and never a satisfied dependency; a person's existing conclusion remains explicit, while resume/reopen names the reverse command instead of reviving split work. Preserve previously retired parents as historical records without automatically migrating or reviving them. This unit admits the new representation and its readers; S2 is its sole new writer and all units land together.

### S2 — Apply the plain file through the current split transaction

Change `goal.Split`/`splitRequest` (`internal/goal/split.go:202`, `:210`) and its existing CLI adapter (`cmd/metasystem/goalsync_mutations.go:3122`) so the authenticated person's `goal split G --plan FILE` retains its shown impact and canonical member digest, rereads the accepted parent/children/dependency graph at the publication tip, and publishes parent StateSplit, reciprocal lineage and all children through `goal.Publish` (`internal/goal/txn.go:684`). Keep the parent's intent, budget, spending, approval evidence, prerequisites and outstanding obligations; release its claim without restoring a lease later, saving only prior state/park data needed by S4. Create children queued with no approval or inherited spending allowance, blockers equal to source plus parent's prerequisites plus the file's child edges, and no new claim-sharing arc; preserve existing group membership on the parent. Retire the new-split call to `raiseSplitOldArcDebt` (`split.go:486`), whose archived-parent lookup would otherwise fail after confirmation; legacy transaction recovery keeps its old interpretation. Leave existing dependents pointing at G, replacing the old dependent rewrite at `split.go:290` and removing archival/retirement at `:315–359`; validate the resulting graph for cycles and collisions before any publication. Reuse Markdown parsing and digest binding; show/edit are ordinary file acts, not verbs. Use the current revision lock and active/reserved-work evidence (`goalsync_mutations.go:3197–3217`, `split.go:254–268`), allowing completed design/critique spending without the old zero-attempt requirement while retaining its accounting; started implementation reconciliation remains deferred and no live work is discarded; a person's advisory override uses existing authority/impact, never loses live work or fabricates a completed physical effect. Full decomposition of a person's goal requires current person authority; R-148 authorizes only the future committed-stop follow-up, not a broad agent bypass based on OriginMain or `--by`. S5 is the post-confirmation approval-notification caller. Repeat/conflict and uncertain publication use the existing transaction outcomes and `goal sync --recover`, comparing current split/digest rather than child ids alone; no proposal operation-id API is added.

### S4 — Reverse before child work starts

Add the person's `metasystem goal split G --reverse --reason TEXT`, mutually exclusive with `--plan`, to the existing intent grammar and actor boundary (`cmd/metasystem/intent_planning.go:293`, `:2039`); this flag spelling avoids introducing a second nested parser solely for reverse. The split owner publishes a compensating goal transaction that restores the parent's recorded pre-split state/park, retains current intent/obligations/budget/history, clears the active split status, and parks the named children with a retained reversal reason, invalidating their execution approval while retaining ids, lineage, briefs and history. A previously claimed parent returns approved only if its ordinary approval is still valid, otherwise queued; never recreate its old claim. Existing dependents still reference G and need no inverse graph rewrite. Under the current goal transaction and work-reservation boundaries, “not started” means no child has ever acquired a claim, reservation, attempt or landed work, including a claim subsequently released; approval or editing a brief alone does not count as started. Read durable evidence for every child and recheck at publication; unknown evidence is pending, not zero. Retain the person's impact and desired reversal before advisory reads; if work has started, retain that decision and identify the work requiring reconciliation without claiming this bounded compensation undid it—the broader effect is explicitly in the automation/started-work brief. Missing original FILE does not prevent reversal because the committed goal contains the required state. Repeating an already confirmed reverse reports that effect; a stale/different split cannot be silently reversed. Ordinary person goal acts can subsequently reuse parked child records; no record, code or spending is deleted.

### S5 — Immediately request each child's approval

After S2's goal publication is confirmed, invoke a split-approval adapter in the existing channel owner, using its configured provider, destination and persisted once-per-key delivery/retry behavior (`internal/channel/phase/phase.go:193–218`; the landing-notice pattern is existing machinery, not a license to label this a landing). Key each notice by the committed split transaction and child id; pending approval is read from the authoritative child and links, never inferred from a posted message. The notice says which work came from G, that the child is unapproved and held by G, and names `metasystem goal approve CHILD`; details name the person's subsequent `goal unblock CHILD --on G` and the remaining prerequisites. The confirming command and existing recovery path both reconcile undelivered notices from that same committed result; lost responses never open duplicate children or intentionally repost a confirmed delivery. Failed delivery remains visible and uses the channel's existing bounded retry; it never rolls back the split or grants approval, and absent channel configuration reports “not sent” alongside the approve action. Reread before retry so a reversed or already-approved child does not receive an obsolete approval request. No new transport, timer or notification store is introduced; reuse or narrowly extend the current channel notice owner. A later R-148 convergence opener calls this same adapter after its own confirmed open.

## Readers, authority and integration

The four recurring defects are covered by each unit's scenario: **a remedy that cannot succeed** (follow open/unblock/reverse/recovery); **confused person/agent power** (current proof, separate approval, no automatic early unblock); **old state hiding current state** (transaction tip, durable started history, fresh retry state); **a seam hiding production behavior** (real verbs and persistence, fake external transport only). A proposal file is input, never executable instructions or proof of approval.

The cap declarations, `CheckDesignSize` and gate remain owned by review-drops. This design does not declare those keys twice or change its warning/appeal contract. R-148's agent follow-up path and the approximately 70-line convergence adapter remain in the automation brief: it must keep an accepted remainder source live, open its child blocked/unapproved, and invoke S5. It must not call full split and thereby stop the remainder. Existing `OriginMain` alone does not prove permission over a goal opened by a person; the inspected goal history itself contains human open/approve acts despite that origin value.

Each child obtains its own accepted design, budget approval and whole-goal landing through existing owners. Split lineage is not execution grouping, budget inheritance or exemption from outstanding findings. Plan-derived budgets belong to their follow-up and single calculation owner. The existing Partner may edit the file and relay a person's decision through its current grant; neither chat nor a file labelled “person” supplies authority. Semantic overlap remains owned by goal-intake-detects-overlapping-work, with no invented dependency on an unimplemented detector.

**Use of the wait.** While awaiting child approval, existing status readers may show the current split, children and exact next actions. No extra worker or paid author starts; there is no lock held while a person decides. Changes to approval, split state or dependencies invalidate prior displays. Delivery retry uses the channel's current bounded owner; this goal adds no timer or speculative work.
