### 2. Extend the shipped flake record rather than build another register

**Read.** `internal/goal/recordflake.go:29` already publishes flake sightings and routes a fix; `:85` constructs the package key `flaky:<unit>`, and `:135` reuses one fix goal per unit. `internal/goal/trunkred.go:137` is the durable entry, with sightings, evidence, owner, fix and closure. `:565` distinguishes candidate `pending-flake` from main `known-flake`; the latter also requires a separately authorized allowance. `cmd/metasystem/intent_landing_flake.go:94` currently recognizes only package-keyed pending entries. Treat existing allowanced incidents as existing contracts, not authority to manufacture a person's approval.

**Record and identity.** Reuse `TrunkRedEntry` and the existing locked/replayed publication. Add the ordinary observed `flake` class, independent of the legacy allowance classes. Its identity is `flake:` followed by the lowercase SHA-256 of the JSON array `[test unit, exact test name]`; store the two original strings too. Subtest names are not truncated. One entry stores both candidate and main observations, with the existing sighting's subject tree/commit and `Where` distinguishing candidate from main. A sighting has original and repeat attempt identities, both output paths and digests, observer, time and result. It is not a generic retry permission. The transient `plain.FlakeRecord` carries the subject location from its `Running` admission; never infer main from a branch name after execution.

`RecordFlake` creates or joins all tests in one failed unit in one publication, with one operation identity. Replaying that operation does not increment sightings. Reuse the existing per-unit fix-goal relationship once per publication; do not open one goal per test, change approval, or finish a fix goal. A flake entry is open until the existing proved-fix closure or a person's explicit close; its green repeat records intermittence and does not clear the defect. Candidate observations do not become main incidents merely because their records are published through main.

**Compatibility.** Existing package-keyed and allowanced entries remain readable and retain their identifiers, owners, histories and allowance semantics. One `FlakeFacts` reader expands their explicit failure names into test identities and joins them with new per-test entries. It deduplicates by sighting operation/attempt, preserves every evidence reference, and applies explicit closures and later sightings in order. A newer per-test observation cannot be hidden by an older package row; a closed fact cannot be reopened merely by rereading its old package history. Unnamed failures remain unknown and cannot confer repeat permission. New ordinary writes use only the test key. This is a read adapter for retained data, not an eager destructive migration or a second register.

U2 includes the enum validators, replay decoder, closure predicate and current admission/incident readers necessary for the new class to be lawful on its first use. This includes goal 2's `runner.KnownFlake` production caller of `landingFlakeJudge`, read at `cmd/metasystem/intent_work.go:486` in `/Users/wido/LocalStorage/GitHub/agentic-tools-m1e-review-chain-stops-and-records/metasystem`. It reads the retained launch's `exec.log`, requires named failures, and accepts a known flake only when every failed unit is known and unaffected. U2 routes the judge through `FlakeFacts` for both landing and unit checks, preserving that contract for legacy and new entries: missing tests or judge uncertainty returns not-known and falls through to ordinary base attribution; unreadable retained launch evidence remains an error. It neither grants another repeat nor consumes a work round for an environment failure. The new class neither grants a legacy time allowance nor blocks a candidate's unrelated work by itself. A main failure still enters the ordinary main-red path if its repeat is red; the flake label cannot hide that current failure. U4 adds the fuller public presentation, not a delayed safety fix.

### 3. Record one repeat and the failing test's actual output

**Read.** `internal/landing/plain/replay.go:55` already judges known, unaffected failures and `:76` starts their repeat; `:97` runs each failed unit. `internal/landing/plain/report.go:82` requires confirmed recording before reporting green. `cmd/metasystem/intent_landing_flake.go:117` wires the real publisher but currently forwards the enclosing log. `cmd/metasystem/intent_landing_incident.go:47` reads and hashes evidence for main failures. `internal/repoproof/full.go:91` runs the declared Go proof with JSON events; `:167` retains those raw events in stdout while decoding failure identities, and `:180` maps import paths to the unit paths the lane uses. Reuse these effect boundaries and the existing retained attempt history. `continueRed` already sets `Result.Repeat="started"` and writes it through `recordProofStop` under the lane lock at `replay.go:76–87`. `ProveSeams.checkBound` (`prove.go:320`) refuses a second automatic proof unless the retained tree result has `Repeat=="allowed"`; `proof_admission.go:112` preserves a separate explicit person override. No re-entry path buying a second repeat has been established; the design extends this existing guard rather than replacing it.

**Eligibility.** Read fresh flake facts for the captured subject. Every failing test must be an open registered fact, the testing contract must prove the changed candidate does not affect its surface, and the original report must be complete. Otherwise retain ordinary attribution; never infer “flake” from a failure name alone. The existing candidate surface check remains conservative on unknown input.

**Repeat accounting.** Extend the existing tree-keyed `Result` and `recordProofStop` record with original/repeat attempt links, failed-test evidence references and publication completion. Keep `Repeat="started"` as the durable admission under the existing lane lock, before execution. There is **no separate repeat-claim key or registry**: the attempt and failed test set describe the existing result; they do not establish a fresh allowance. Re-entry, restart, record-only commits and repeated commands consult that result and cannot reset its spent repeat. Run the existing declared unit selection once with the original proof environment and deadline, preserving the surrounding successful proof. This may execute the containing unit at the declared granularity; it never launches a second full suite merely to repeat one test. A repeat that did not run, timed out, lost its process, lacks a complete report or remains red does not authorize green. Hold with its observed cause; automatic continuation cannot spend a third execution. A person's explicit new proof uses the existing admission boundary and records its override and distinct attempt without rewriting this history.

**Goal 2's unit-check consumer — decided by m1e for Wido, 2026-10-08, reversible.** Goal 2 lands first; U3 then connects its unit-check repeats to the same `repoproof.TestEvidence` extraction and `goal.RecordFlake` publication used by landing. In that branch, `internal/launch/unit_attribution.go:47–52` saves `step.FlakeRepeat=true` before `advanceStep` repeats the retained command. Extend the owning retained step with original/repeated launch identities, frozen tree/test set and publication references. `step.FlakeRepeat` remains the one admission count for that unit-check attempt; the sighting records that execution and does not grant or count a second repeat. Landing likewise keeps `Result.Repeat` as its sole admission owner. These are distinct execution attempts, not two counters for one repeat; do not add a generic retry owner or run a lane repeat to record a unit repeat.

After the unit repeat completes, feed both retained launch logs through `TestEvidence`, then the existing `RecordFlake` publisher with a stable operation identity derived from the retained attempt. A passing repeat becomes a recorded candidate sighting only with complete per-test evidence and confirmed publication. Red, incomplete or missing output and evidence/publication failures preserve the spent step and a non-green result; base attribution remains goal 2's owner for affected/unknown failures. Resume repairs evidence/publication from retained launches without `advanceStep` executing again. This keeps one repeat with its sightings and output evidence on both production paths, while retaining goal 2's work-round and failure-attribution contracts.

**Evidence.** Retain the original full log and the repeated unit's log. Add `repoproof.TestEvidence`, called by the real lane recorder and the unit-check completion recorder on their complete retained logs, to read the existing JSON `Action`, `Package`, `Test` and `Output` events using the same package-to-unit mapping as `packageSuite`. Preserve the exact ordered output bytes for each failing test, including its full subtest name; retain them in an immutable attempt-owned evidence file with a digest. Validate the identity against the complete failed-test report, read the full log rather than its 64 KiB summary tail, and distinguish an observed test with empty output from missing events. Do not substitute the final `LANDING-FAILED` summary or another test's output. For a declared runner that cannot attribute output to a test, retain the raw log, report evidence unavailable and keep the result unresolved; do not invent attribution. The parser consumes the existing runner output contract, not a Go command guessed by the lane. No new runner command or output protocol is required for the shipped Go consumer.

Extend the transient record and existing sighting/repeat evidence fields as needed; the original red, repeated result and test-output artifact remain linked to one frozen subject. A publication or evidence write failure leaves the attempt non-green. Recovery retries publication from retained evidence without reexecuting the test. Failure after one durable write preserves that write; operation identity makes recovery idempotent. No tick commits and no competing flake retry counter outside the attempt owner.

**Use of the wait.** While the repeated test runs, its owner retains the original result and prepared publication inputs. It launches no additional work: there is no independent useful action here beyond the ordinary supervisor, and another proof would consume the same capacity. A moved subject invalidates use of the result for the new subject, not the retained evidence for the old one.

### 4. Put the fact in the views people already use

**Read.** `cmd/metasystem/intent_planning.go:2354` implements incident listing and currently puts every non-red class in its tracked section. `cmd/metasystem/incident_list_view.go:15` renders it. `cmd/metasystem/intent_table.go:513` routes `test status`; `cmd/metasystem/test.go:1172` requires a tree and preserves retained-proof verification. No new bare `test status` grammar is necessary.

`test status --tree TREE` adds the flake facts observed for that tree, with test name, original/repeat outcome, evidence and fix ownership, in text and JSON. It remains a read: flake metadata cannot satisfy missing proof, change proof's exit code or launch a test. Metadata read failure reports “flake information unavailable” separately from the proof verdict; unknown metadata is never a green flake fact.

`incident list` shows ordinary flakes only when they have a main observation; candidate-only facts appear through `test status`. The original main-red record, if any, keeps its own identity and blocking semantics. Existing explicitly allowanced main flakes remain visible with their allowance. `incident claim` and `incident close --reason` resolve the existing entry id and use their existing authority owners. Claiming a main flake links its fix without giving permission to return unrelated candidate work. The lane's result/status shows both attempts and the reason for a hold; it does not say that a repeat “fixed” the test.

## The four recurring defect classes

1. **A remedy cannot succeed, or undoes the gate.** U3 follows the actual emitted person-proof command with the repeat still spent; publication recovery must not rerun tests. U4 follows claim/close with the incident still open.
2. **An agent receives a person's power, or a person is treated as an agent.** Observing a flake grants neither a legacy allowance nor approval for its fix. Existing direct person proof/close remains available without clearing advisory policy.
3. **An older record hides current state.** U2 joins legacy and test-keyed evidence without letting older package history override a later sighting/closure. U3 retains the existing tree-keyed result and unit-check step as admission owners; a record-only commit or publication retry cannot clear either spent repeat.
4. **A test seam hides production behavior.** U1 uses actual registration, marker checks, owner proof and removal; the defect was reproduced through those functions. U2–U4 call public verbs and real state owners with boundary injection, never a fake publication standing in for proof of the write.
