## 1. Intent (verbatim)

Wido, 2026-09-29: "If the intent is to close the goal, we need a simple way for the human to close the goal, and even force it, if that is necessary, to just make it happen. So, an additional force flag that can be proposed if closing fails for whatever reason is maybe a solution. What do you think?" — and, on the proposal: "and force would only work at the helm not for an agent". Binding from slice 1: "Once at the helm, I don't want any magic flags or anything else"; and "build the smallest thing possible that works. We're not building a nuclear reactor here."

## 2. How it feels

**Return, with an open read item on the goal.** Wido types `metasystem helm return` at his terminal. After the readback it asks `Conclude goal g1-s76 with these commits? [y/N]` y, `Conclusion [Enter: landed at the helm by wido: 2 commits 7c8ba19, 6f7393d]` Enter. The conclusion refuses: `goal done g1-s76: refused: GOAL_DONE_READ_ITEMS_OPEN: goal g1-s76 has open read items R1; close each with one of: …`, then `Conclude anyway and record what was overridden? [y/N]` y: `goal done g1-s76: confirmed`. The archive's conclusion reads `landed at the helm by wido: 2 commits 7c8ba19, 6f7393d — overridden by wido at the helm: read items R1`; R1 is `accepted` with the reference `overridden by wido at the helm`. Return ends `the machinery is at the helm again`, exit 0. Answering n keeps the goal open and prints the forced command.

**The person typing it.** At the helm, at his terminal: `metasystem goal done g1-s76 --reason "landed by hand"` says `metasystem goal done: goal g1-s76 has open review obligation finding=F chain=C test=T; at the helm you may conclude anyway and record what was overridden: metasystem goal done g1-s76 --reason 'landed by hand' --force`. He adds `--force`: `goal done g1-s76: confirmed`, the conclusion names the obligation. Outside the helm the same refusal stops after `test=T`, as today.

**The agent beside him types the same with `--force`.** At the helm: `metasystem goal done: goal done --force is the person's own act: this shell was not proven at the enrolled terminal (admitted by the helm); run it yourself at the terminal you took the helm at`, exit 1, no conclusion written; the one person-proof yield slice 2 records when it grants the helm proof stays (HF-03). Outside the helm, from its own session: `metasystem goal done: goal done --force works only at the helm: take it first (metasystem helm take --reason TEXT), or close what blocks the conclusion`; with no session named, today's `cannot tell who runs metasystem goal done: …` (`cmd/metasystem/intent_goals.go:163-167`).

## 3. Step 4: what exists and works after slice 4

**Behavior.** `goal done G --reason TEXT --force` concludes despite the four goal-state refusals of the done request (`internal/goal/verbs.go:2572-2680`): open read items (`:2600`, `readitems.go:323-335`), an open review obligation (`:2603-2607`), an open carry word (`:2608`; `doneCarryRefusalFor`, `:5384-5398`: a `work land --exception` reservation not yet consumed at the code tip, `:5069-5100`) and a blocked dependency not done (`:2634-2638`). Everything else about the conclusion is today's.

**D-admit: the check, in one place.** The owner's `case "done":` (`cmd/metasystem/goalsync_mutations.go:1922-1960`), before `goal.Done`, when `--force` was passed: `forceAdmission(state helm.State, proof *humanauthority.Proof, root string) error`, with `state := dependencies.helm(f.root)` and `proof := req.Authority`. Three answers, in this order: (1) `!state.Active`: refused, "works only at the helm" (the text of §2). (2) `proof == nil || proof.Helm != nil || proof.FixtureOnly || !proof.TerminalValidFor(root)`: refused, "the person's own act … not proven at the enrolled terminal", with `(admitted by the helm)` when `Helm != nil` and `(no person proof)` otherwise. (3) admitted: `req.ForceBy = req.Actor.Human`. Why this works: the proof is the one the owner already built — with `--by` (typed, or filled by the intent layer's own walk, `intent_goals.go:156-190`) the done request proves through `dependencies.proveHuman` = `humanauthority.Prove` (`:1813-1822`, `:512`, `:628-633`, `:565`) and carries it as `Authority` (`:710`); with a session lineage only, `Authority` is nil. `Prove` (s2 `internal/humanauthority/authority.go:857-872`) returns `Helm == nil` only when `walkToEnrollment` reached the enrolled terminal with no agent in the chain (`:912-935`); the agent beside the person gets `HelmProof` (`:891-905`, `Helm != nil`), and so does a person at a terminal that is not the enrolled one — the take enrolls the terminal it is run at (s2 `cmd/metasystem/intent_helm.go:150-159`), so "the terminal you took the helm at" is the remedy. `TerminalValidFor` (`:218-222`) is the grade the done rows already ask (`verbs.go:320-346`, `:2613-2632`). `state` comes from a new owner seam `syncRequestDependencies.helm func(root string) helm.State` (`:526-532`), default `helm.Active` (`internal/helm/helm.go:109-128`), read on `f.root`, the act's authority root: the seat whose ledger is written (slice 2's HB-02 root). Agents never force: outside the helm answer (1) refuses them, at the helm answer (2); no class, checkout or ancestry question is asked, the proof kind decides.

**D-force: what force overrides and records.** `goal.VerbRequest` gains `ForceBy string` (`verbs.go:212-249`); `doneRequest` puts `"force": r.ForceBy` in the intent Args beside `conclusion` (`:2575-2577`) so recovery rebuilds the same request (`recover.go:302-330`, `:516`), and in `Mutate` each of the four sites refuses when `ForceBy == ""` and otherwise records and goes on: every open read item is closed as `ReadItemAccepted` with `ClosingReference = "overridden by <by> at the helm"` and `ChangedAt` (the fields the close verb sets, `readitems.go:298-300`), so `Done` lists them as accepted read items (`:2256-2264`); an open obligation becomes `discharged`, the only closed state the file admits (`file.go:710`); the carry word is named and left as it is (a word is consumed or expires, `:5069-5100`); only the positively identified open-carry-word refusal is passed over, and every other error from `doneCarryRefusalFor` (an inspection failure such as a trailer read, `:5054`, `:5390`) still refuses under force (revision 2, HF-02: the site returns both, so `doneCarryRefusalFor` returns the open word as a typed value beside its error and force skips only that). An unfinished blocker is removed from `Blocked` in the same transaction and named in the conclusion (revision 2, HF-01: validation rejects a done goal with an unfinished blocker, `validate.go:382-390`, before publication, `txn.go:795`; validation stays as it is). The conclusion written at `:2644` becomes `<reason> — overridden by <by> at the helm: read items R1, R2; review obligation F/C; carry word OPID; blocked by X`; the History line is today's (`actor=human:<by>`, `:2658`).

**What force never overrides.** Not live (`:2598`), already done or abandoned (`:2584-2595`), the residue check in `Done` (`:2209-2223`), the human rows (`:2613-2632`; a forced act carries a terminal-grade real proof, which meets them), ledger build, validation and publish failures (`internal/goal/txn.go:781-800`), and the follow-ups after the publish (`:2228-2273`). **The branch needs no rule:** `Done` sweeps after the publish through `SweepBranch` (`:2252-2253`; wired at `goalsync_mutations.go:1926-1959`), the sweep refuses a branch tip with unlanded commits (`checkSweepTipWith`, `internal/goal/branch/sweep.go:255-282`, code `:11`), and `Done` returns the landed conclusion with that refusal (`:2266-2273`), which the intent layer reports as a partial result naming the kept branch (`intent.go:876`, `:912-940`). Forced or not, nothing is lost.

**D-propose: the refusal proposes the force, only at the helm.** `Publish` flattens a `Mutate` error into a rejected result whose `Detail` is the message (`txn.go:925-930`), and the owner's message is that detail (`intent.go:797-810`, `:902`). In the same done case, after `goal.Done` returns a rejected result and `--force` was not passed: when `dependencies.helm(f.root).Active` and `goal.ConclusionOverridable(res.Detail)`, `res.Detail` gains `; at the helm you may conclude anyway and record what was overridden: metasystem goal done G --reason <reason> --force` before `dependencies.publish`. `ConclusionOverridable` sits beside the four sites and recognises their fixed shapes (the `GOAL_DONE_READ_ITEMS_OPEN:` prefix, `readitems.go:314-321`; `has open review obligation`; `has open carry word`; `is blocked by … which is not done`); the precedent is `carryAskFromRejectedDetail` re-deriving a typed ask from a rejected detail (`verbs.go:4841-4847`), and a test pins each site's text to it. Outside the helm the message is unchanged, byte for byte.

**D-return: the extra question.** In slice 3's `helmAnswers` (design §4.2-3): after "yes, conclude", when the `done` seam's result is refused and `ConclusionOverridable(result.Summary)`, return prints that reason and asks `Conclude anyway and record what was overridden? [y/N]`; y calls the seam again with `force`. The forced in-process call adds `--force` to the owner's argument vector and sets two dependencies on its copy of the invocation (as slice 3 sets `proveHuman`): `helm` answering the removed record as active, `helm.State{Active: true, Record: record, Since: since}` — return's own knowledge, decided cleanly: the signature is gone, the record it decoded is the helm that was held; and `proveHuman` answering return's own real walk, `humanauthority.Prove(root, owners.pid(), owners.reader, owners.now())`, taken after the removal (with the signature gone `AtHelm` grants nothing, s2 `cmd/metasystem/helm_admits.go:91-99`, so this proof is real or absent). The plain conclusion runs with the production readers, so its refusal carries no proposal; return's question is the proposal. When return's own walk is not a real proof (return typed from an agent's shell, which `helm return` allows), the question is not asked: return prints the reason and `to conclude anyway, take the helm again at your terminal and run: metasystem goal done G --reason … --force`. Without a terminal: nothing asked, the goal open, slice 3's plain command plus the forced one, marked `if the conclusion refuses for an open read item, review obligation, carry word or blocked dependency`. Return removes the signature first and exits 0 whatever any step said (s2 `intent_helm.go:254-282`).

**Seams.** `syncFlags.force bool` with `fs.BoolVar` (`goalsync_mutations.go:1014-1030`, as `claim` at `:1142`); `syncRequestDependencies.helm`; `goal.VerbRequest.ForceBy`; `goal.ConclusionOverridable`; the done command gains the switch `{name: "force", usage: "at the helm: conclude despite open read items, review obligations, a carry word or a blocked dependency; each is recorded as overridden"}` and the usage `metasystem goal done G --reason TEXT [--force]` (`intent.go:249-260`; a switch is a flag without `value`, `:93`); `runIntentDone` forwards it (`intent_goals.go:804-828`; `forward` passes a switch as `--force`, `:110-127`); slice 3's `helmOwners.done` gains `force bool`. `cmd/metasystem` already imports `internal/helm` (s2 `helm_admits.go:11`); `internal/goal` imports nothing new.

## 5. Later, when it hurts

- A helm yield for a forced conclusion, so return's readback lists it beside the admitted acts.
- The same flag for `goal abandon`, whose obligation check has the same shape (`internal/goal/abandon.go:129`).
- A steward completion of a conclusion deferred until the item closes (slice 3's deferred list).
- The agent beside the person asking the force question in the browser instead of refusing.
