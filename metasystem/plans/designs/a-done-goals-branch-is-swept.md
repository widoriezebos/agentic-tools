## Problem

A done goal's branch should disappear with the goal. Today the sweep runs once, inside the first `goal done`, and only when that run reaches it (`cmd/metasystem/goalsync_mutations.go:1937-1975`, `internal/goal/verbs.go:2458-2478`). Three things defeat it:

1. The repeat of a landed act confirms from its idempotency row and never runs its follow-ups: the verb prints "Repeat goal done if cleanup is pending" (`cmd/metasystem/intent.go:1298-1327` reports the incomplete follow-up) but the repeat cannot do what it advertises.
2. The sweep's landed test (`internal/goal/branch/sweep.go:255-282`, `checkSweepTipWith`) asks whether every unit commit of the branch is reachable from the published main (`branch.EndpointTip` fetches origin's main, `internal/goal/branch/park.go:75-93`), or is named by the `Goal-Source` provenance of a landing on main (`sweep.go:264`; the lane's landing records the original unit and the commits folded into it, `internal/goal/branch/land.go:397`), or is an exact concluded drop. A unit landed by HAND without that provenance (tonight's stack rebased the units onto one tree and pushed them under new ids with no `Goal-Source`) is "a commit that never landed" and the person is sent to `metasystem work land`, which would try to land again what is on main.
3. The public concluded-goal shortcut skips branch cleanup (`cmd/metasystem/intent_goals.go:1001`; `goal.Done` itself sweeps after a confirmed publication, `internal/goal/verbs.go:2431`, but a repeated conclusion returns AlreadyHolds at `verbs.go:2823`/`txn.go:1048` before reaching it); the existing disk pass retries registered goal worktrees (`internal/steward/disk_goal_worktrees.go:80`) but does not discover every remaining goal-branch reference, so a branch that escaped its `goal done` stays on origin.

## Decisions

D1. **Repeating `goal done` on a concluded goal reconciles its branch cleanup.** `runIntentDone` (`cmd/metasystem/intent_goals.go:1001`) bypasses the owner call when the goal is already concluded and its impact recorded, and today retries only the review cleanup (`:1015`); from here it also reconciles that goal's branch references through the existing guarded sweep (`steward.SweepGoalWorktrees` around `goalbranch.Sweep`), checking origin, transport and local references even when `ShouldSweep` (`internal/goal/branch/status.go:187-217`, true only for a local branch or a locally readable named unit) finds nothing local, for conclusions that predate this change and carry no pending marker, without publishing another conclusion or changing the conclusion text, and reports "swept goal/X" or the sweep's refusal with its one act. The sentence "Repeat goal done if cleanup is pending" becomes true. A generic replay of recorded follow-ups is deferred (not in this design).

D2. **Provenance first; equivalence only exact; inconclusive keeps the branch.** The landed test preserves range validation, `Goal-Source` recognition, exact concluded-drop declarations and the abandonment semantics as they are (`TestSweepLocalTipExemptions`, `sweep_policy_test.go:686`, keeps passing; a landing containing folded commits whose individual patches do not match main stays sweepable). Only for a commit those rules do not resolve does the test try a rebase-equivalence proof, and that proof is exact: the commit's change (its diff against its parent: paths, file modes, binary content and every byte of content, meaningful whitespace included) equals the change of one commit on main since the merge base; normalized patch-id equality (`git cherry`, which drops whitespace) never authorises deletion by itself; equivalence WITNESSES are distinct commits of main taken in branch order (an apply–revert–reapply branch whose main holds only the apply and the revert has no assignment); when no such assignment exists, every reference and worktree is retained. An inconclusive comparison reports "cleanup could not prove this commit landed", preserves the conclusion and all references, and names `metasystem work status G` to inspect the retained work; it never prescribes another landing (R-126-m1e: recovery follows intent; a hand landing needs a live approval, `cmd/metasystem/goal_branch.go:457`, and an already-landed goal would be sent back to `goal done`, `intent_delivery.go:2115`). The HAND ROUTE carries the same `Goal-Source` provenance the lane's landing writes, so the equivalence proof is the exception, not the rule.

D3. **Done goals' branches are swept by observation.** The existing disk-pass registration of the branch sweep (`cmd/metasystem/goalsync_mutations.go:3550`) is the retry owner: its discovery extends to every uncovered reference of a done goal, on origin, on the transport remote and locally (leftovers after a partial deletion included, `sweep_policy_test.go:722`), and reuses the existing guarded sweep with D2's test; the observation reports them ("3 branches of done goals wait for their sweep: …"); the apply pass deletes one per pass under the critical section, with a sweep row in the records. A reference with an unresolved commit is reported, never deleted. No person is ever sent to `git branch -D` or `git push --delete` (the worktree design's rule, D2 of a-closed-delegates-objects-live-in-the-repository, extended to branches).

D4. **A dirty hand worktree refuses with one act and keeps the rest.** When a worktree on the goal branch has uncommitted work, the sweep refuses with "goal X's worktree P has uncommitted work: …; run: metasystem work status X" (today's wording, kept) and still deletes nothing; after the person cleans it, D1's repeat or D3's pass completes the sweep.
