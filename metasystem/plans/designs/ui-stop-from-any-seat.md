## 1. What happens today (verified)

**One record per seat, read by that seat only.** A seat's interface writes `server.json` under `<stateRoot>/artifacts/agents/ui/` (`internal/ui/lifecycle/state.go:21-23`): process ref, address, checkout, installation (`:26-34`). For the nested-template seats on this computer the state root is the installation itself (`internal/stateroot/stateroot.go:133-141`), so ui's record is `agentic-tools-ui/metasystem/artifacts/agents/ui/server.json` (pid 91362, `127.0.0.1:7878`, mode 0600); m1e and landing have no `artifacts/agents/ui/` directory at all. The verbs resolve one seat: `uiTarget` (`cmd/metasystem/intent_process.go:2038-2078`) takes `--repo` or the working directory (`selectInstallation`, `:493-540`), derives the roots (`:2055`; `internal/ui/lifecycle/roots.go:37-75`) and calls the `ui` seam (`:438`, wired to `uiLifecycleFor` at `:468`), which runs `uiLifecycleRunWith` (`cmd/metasystem/ui.go:1115-1143`): `StartOnce`, `StatusReport` or `StopReport` on `roots.StateRoot` and nothing else. `Stop` reads that root's record (`stop.go:27`; `state.go:119-131`); `Stopped` is worded "interface not running" (`result.go:173-176`), counted as a repeat (`:87-91`) and rendered `intentUnchanged` "the interface is already stopped" (`intent_process.go:2065-2071`). That is the line Wido saw in m1e. Restart goes through `runUIVerb` (`:1637-1685`) to the same seam.

**The engine knows this computer's machines, read-only.** `machine list` is `runIntentMachineList` (`cmd/metasystem/intent_machine.go:522-551`): the fleet's presence from the `fleet` seam (`seatFleetReport`, `cmd/metasystem/seat_verbs.go:22`; without `--refresh` it reads the local copy), then `readHostMachines(fleetNames(report))` (`:244-299`). Discovery is `discoverHostMachines` (`:156-239`): candidates are this checkout (`:161-163`), every checkout of the host registry `registry.HostCheckouts(registry.DefaultPath())` (`:164-179`; `internal/registry/selection.go:14-26`, `~/.metasystem/armed-checkouts.jsonl`; `armed.go:19`) and the landing lane's record (`:180-188`; `internal/landing/lane/lane.go:98`); each is resolved to its Git root by `resolver.ResolveLayout` (`:192-195`), named by `seat.Machine` (`:216-220`; `internal/seat/ledger.go:59-65`), and kept when it is the lane, or has a nickname and is armed or in the fleet (`:221-225`); the other 3273 registrations are only counted. Each machine's checkout is then read as `system status` reads it through `checkoutInvocation(checkout)`, "as if --repo named it" (`:131-136`, `:251-257`). It reads files (registry, lane record, `metasystem.conf`, presence refs); the only processes are git reads, `git rev-parse --show-toplevel` per candidate (`stateroot.go:170`, `:82-90`) and the presence transport's local refs; no MetaSystem process is started. Today it names ui (this checkout), landing, m1e.

**Starting in a second seat collides, after the spawn.** Every seat defaults to `127.0.0.1:7878` (`internal/config/defaults.go:78`; `config.UIListen` through `uiListen`, `ui.go:1079-1088`). `StartOnce` finds no record in the second seat (`result.go:98-105`) and spawns `ui serve`; `Serve` takes that seat's own lock, then `net.Listen` fails: "cannot listen at 127.0.0.1:7878; choose another address with --listen or ui.listen: … address already in use" (`serve.go:151-154`); the child writes `failed …` on the ready pipe (`cmd/metasystem/ui.go:70-78`), `Launch` returns it (`launch.go:71-73`), and the verb prints "the interface did not start; its report is below" (`intent_process.go:2076-2077`). Nothing names the seat that holds the port.

**Stopping is identity-checked.** `Read` proves the record's pid by exact identity (`state.go:119-131`; `identity.AliveRef`, `internal/identity/identity.go:193-197`): Alive is Running, Unknown is Uninspectable; a dead pid is repaired under the lock to Stale (`:133-157`); a held lock with an unreadable record is Unreadable, else Busy. `Stop` re-proves immediately before SIGTERM through `identity.SignalExact` (`stop.go:48-56`; `internal/identity/ref.go:132-150`: Dead is ErrGone, Unknown is ErrUninspectable, only Alive is signalled), then waits for the lock (`:60-71`). Every non-Running state stops nothing (`:44-46`) and is worded by `stateLine` (`result.go:173-186`).

**Authority.** `ui stop`, `ui start` and `ui status` are audience `both` and prove no person (`intent_process.go:232-253`; `uiTarget` checks options only, `:2038-2047`); `ui restart` says "An agent may do this within its authorization" (`:244`). Whether an interface acts as a person is observed once, at its own start, from the launcher's ancestry, and written into its record as evidence (`internal/ui/act/act.go:119-131`, `:893-894`; `Record.Authority`, `state.go:35-42`); 91362's record says "not proven". Stopping reads none of it.

## 2. Step 1: what exists after the slice

`ui stop`, `ui status`, `ui start` and `ui restart` know the other seats of this computer, and `ui start` and `ui restart` launch the target seat's own engine (D-engine, D-restart). Nothing in `internal/ui/lifecycle` changes: `Read`, `StopReport`, `RestartReportFor`, `Record` and `State` are already exported.

- **D-seats: the seats are what `machine list` lists, and the inventory says whether it is complete.** `uiTarget` and `runUIVerb` set `uiIntentOptions.seats`, a closure `func() uiSeatInventory` over a new `inv.uiOtherSeats(layout)` beside `discoverHostMachines`, invoked only when a verb needs the other seats (D-stop, D-status and D-start all ask after this seat's own state first), so a running seat's `ui status` reads nothing more than today. It runs the fleet read as `machine list` reads it (fetch false), then `discoverHostMachines(fleetNames(report))` minus `This`. Each other seat's roots are derived exactly as its own verb derives them: `checkoutInvocation(machine.Checkout).selectInstallation()` then `lifecycle.ResolveRootsWith(…)` (the pair at `intent_process.go:2051-2055`). `uiSeatInventory{Seats []uiSeat{Name, Checkout, Roots}, Problems []string}`: a problem is a registry that cannot be read (`RegistryProblem`, `intent_machine.go:165`, `:170`), a lane that cannot (`LaneProblem`, `:182-184`), a fleet read that fails (which drops every unarmed machine only the fleet names, `:221-225`), or a listed machine whose layout (`:199-201`) or roots do not resolve. (Astra US-01.) A fleet read fails in three shapes, and all three are problems: the seam's returned error, which is the only one `machine list` checks (`intent_machine.go:526-529`); a non-empty `report.CopyProblem`, which `seatFleetReport` sets with a nil error and an empty copy when the presence cannot be read (`cmd/metasystem/seat_verbs.go:56-59`); and `report.ClaimsUnavailable`, set with a nil error (`:63-64`). Both the copy and the claims feed the fleet's names (`:80-83`), so either field silently loses machines. (Astra US-05.) The invoking seat's own name follows the same rule as a machine's (`:216-220`: nickname, else the checkout's base name).
- **D-stop.** After the seat's own `StopReport` answers a repeat (Stopped or Stale, `result.go:89`), `uiLifecycleRunWith` reads each seat of the inventory with `lifecycle.Read(other.Roots.StateRoot, prober)` (`state.go:119`), the read `ui status` makes there, stale records repaired as there. Candidates are the seats whose state is neither Stopped nor Stale. **An inventory with a problem stops nothing across seats** (Astra US-01: uniqueness needs a complete inventory, and "already stopped" cannot be asserted for the computer from a partial one): the lines are this seat's own, then "the machines of this computer could not all be read: <problem>; nothing was stopped" and one line per known candidate with its `--repo` command (as for several below); Refused, exit 1; the JSON data carries `seatsProblems` and `seats`. Otherwise: none: today's line, unchanged, exit 0. Exactly one: `lifecycle.StopReport(candidate.Roots.StateRoot, stop)`, the same function with the same prober and `--wait-seconds` on that seat's record; Running gives "no interface for m1e; stopped the interface of machine ui (pid 91362, :7878)", exit 0, Confirmed, Targets `{ui, <ui checkout>}`, Summary that line; every other outcome (Uninspectable, Unreadable, Busy, Timeout) gives "no interface for m1e; machine ui: " + `StopReport`'s own line and its code. Several: nothing is stopped; "no interface for m1e; 2 machines of this computer run one; nothing was done", one line per seat "machine ui: pid 91362 at 127.0.0.1:7878: metasystem ui stop --repo /Users/wido/LocalStorage/GitHub/agentic-tools-ui", exit 1, Refused.
- **D-status.** After the seat's own `StatusReport` answers Stopped or Stale (its lines, state and code 1 unchanged), the same read; each candidate adds a line, "machine ui runs one (pid 91362 at 127.0.0.1:7878): metasystem ui status --repo <checkout>" for Running, "machine ui: <state>" otherwise; an inventory problem adds "the machines of this computer could not all be read: <problem>" after them; the JSON data gains `seats` and `seatsProblems`. A seat that runs its own interface lists nothing more.
- **D-start.** In the `start` closure (`ui.go:1118-1129`), before anything is spawned, this seat's own record is read first (`lifecycle.Read(roots.StateRoot, prober)`), and only when it answers Stopped or Stale does the check run (Astra US-02: `StartOnce` calls the closure also when this seat runs at another address, `result.go:98-105`, and that case keeps today's path whole, the child's own refusal included, `serve.go:109-113`). The check: for each seat of the inventory `Read`; a Running record whose `Address` equals the validated listen (both canonical, `serve.go:53-78` and `:160`; a port-0 listen equals none) answers `Result{Lines: {"no interface for m1e; machine ui runs one at 127.0.0.1:7878 (pid 91362); stop it with: metasystem ui stop --repo <checkout>, or start this seat's at another address with --listen"}, Code: 1}` and no child is launched; `uiTarget` renders it Refused as today (`:2076`) with `next` that `ui stop --repo` argv. Another address, or an inventory with a problem and no known collision, starts as today: the bind failure (`serve.go:151-154`) stays the backstop. The closure is parameterized by the roots it starts for (its own seat, or the seat D-restart selects), and its inventory read excludes that target.
- **D-engine: the engine is the target installation's, never the binary typed.** Today the closure launches `effects.executable`, which is `os.Executable` (`ui.go:1112`, `:1119-1125`): the binary the person typed, told to serve the target with `--repo` and `--metasystem-root` (`launch.go:25-33`), and the child stamps the record with its own build (`ui.go:389`).
