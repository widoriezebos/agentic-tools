## 1. What happens today (verified)

**One record per seat, read by that seat only.** A seat's interface writes `server.json` under `<stateRoot>/artifacts/agents/ui/` (`internal/ui/lifecycle/state.go:21-23`): process ref, address, checkout, installation (`:26-34`). For the nested-template seats on this computer the state root is the installation itself (`internal/stateroot/stateroot.go:133-141`), so ui's record is `agentic-tools-ui/metasystem/artifacts/agents/ui/server.json` (pid 91362, `127.0.0.1:7878`, mode 0600); m1e and landing have no `artifacts/agents/ui/` directory at all. The verbs resolve one seat: `uiTarget` (`cmd/metasystem/intent_process.go:2038-2078`) takes `--repo` or the working directory (`selectInstallation`, `:493-540`), derives the roots (`:2055`; `internal/ui/lifecycle/roots.go:37-75`) and calls the `ui` seam (`:438`, wired to `uiLifecycleFor` at `:468`), which runs `uiLifecycleRunWith` (`cmd/metasystem/ui.go:1115-1143`): `StartOnce`, `StatusReport` or `StopReport` on `roots.StateRoot` and nothing else. `Stop` reads that root's record (`stop.go:27`; `state.go:119-131`); `Stopped` is worded "interface not running" (`result.go:173-176`), counted as a repeat (`:87-91`) and rendered `intentUnchanged` "the interface is already stopped" (`intent_process.go:2065-2071`). That is the line Wido saw in m1e. Restart goes through `runUIVerb` (`:1637-1685`) to the same seam.

**The engine knows this computer's machines, read-only.** `machine list` is `runIntentMachineList` (`cmd/metasystem/intent_machine.go:522-551`): the fleet's presence from the `fleet` seam (`seatFleetReport`, `cmd/metasystem/seat_verbs.go:22`; without `--refresh` it reads the local copy), then `readHostMachines(fleetNames(report))` (`:244-299`). Discovery is `discoverHostMachines` (`:156-239`): candidates are this checkout (`:161-163`), every checkout of the host registry `registry.HostCheckouts(registry.DefaultPath())` (`:164-179`; `internal/registry/selection.go:14-26`, `~/.metasystem/armed-checkouts.jsonl`; `armed.go:19`) and the landing lane's record (`:180-188`; `internal/landing/lane/lane.go:98`); each is resolved to its Git root by `resolver.ResolveLayout` (`:192-195`), named by `seat.Machine` (`:216-220`; `internal/seat/ledger.go:59-65`), and kept when it is the lane, or has a nickname and is armed or in the fleet (`:221-225`); the other 3273 registrations are only counted. Each machine's checkout is then read as `system status` reads it through `checkoutInvocation(checkout)`, "as if --repo named it" (`:131-136`, `:251-257`). It reads files (registry, lane record, `metasystem.conf`, presence refs); the only processes are git reads, `git rev-parse --show-toplevel` per candidate (`stateroot.go:170`, `:82-90`) and the presence transport's local refs; no MetaSystem process is started. Today it names ui (this checkout), landing, m1e.

**Starting in a second seat collides, after the spawn.** Every seat defaults to `127.0.0.1:7878` (`internal/config/defaults.go:78`; `config.UIListen` through `uiListen`, `ui.go:1079-1088`). `StartOnce` finds no record in the second seat (`result.go:98-105`) and spawns `ui serve`; `Serve` takes that seat's own lock, then `net.Listen` fails: "cannot listen at 127.0.0.1:7878; choose another address with --listen or ui.listen: … address already in use" (`serve.go:151-154`); the child writes `failed …` on the ready pipe (`cmd/metasystem/ui.go:70-78`), `Launch` returns it (`launch.go:71-73`), and the verb prints "the interface did not start; its report is below" (`intent_process.go:2076-2077`). Nothing names the seat that holds the port.

**Stopping is identity-checked.** `Read` proves the record's pid by exact identity (`state.go:119-131`; `identity.AliveRef`, `internal/identity/identity.go:193-197`): Alive is Running, Unknown is Uninspectable; a dead pid is repaired under the lock to Stale (`:133-157`); a held lock with an unreadable record is Unreadable, else Busy. `Stop` re-proves immediately before SIGTERM through `identity.SignalExact` (`stop.go:48-56`; `internal/identity/ref.go:132-150`: Dead is ErrGone, Unknown is ErrUninspectable, only Alive is signalled), then waits for the lock (`:60-71`). Every non-Running state stops nothing (`:44-46`) and is worded by `stateLine` (`result.go:173-186`).

**Authority.** `ui stop`, `ui start` and `ui status` are audience `both` and prove no person (`intent_process.go:232-253`; `uiTarget` checks options only, `:2038-2047`); `ui restart` says "An agent may do this within its authorization" (`:244`). Whether an interface acts as a person is observed once, at its own start, from the launcher's ancestry, and written into its record as evidence (`internal/ui/act/act.go:119-131`, `:893-894`; `Record.Authority`, `state.go:35-42`); 91362's record says "not proven". Stopping reads none of it.

## 2. Step 1: what exists after the slice

`ui stop`, `ui status` and `ui start` know the other seats of this computer; `ui restart` gains the start pointer for free (D-start). Nothing in `internal/ui/lifecycle` changes: `Read`, `StopReport`, `Record` and `State` are already exported.

- **D-seats: the seats are what `machine list` lists.** `uiTarget` and `runUIVerb` call a new `inv.uiOtherSeats(layout)` beside `discoverHostMachines`: the fleet read as `machine list` reads it (fetch false; a failed read names no machine, the problem goes into the JSON data only), then `discoverHostMachines(fleetNames(report))` minus `This`. Each other seat's roots are derived exactly as its own verb derives them: `checkoutInvocation(machine.Checkout).selectInstallation()` then `lifecycle.ResolveRootsWith(…)` (the pair at `intent_process.go:2051-2055`); a seat whose roots do not resolve is skipped, with its problem in the JSON data. The result, `[]uiSeat{Name, Checkout, Roots}`, travels in `uiIntentOptions.others`; the invoking seat's own name follows the same rule as a machine's (`intent_machine.go:216-220`: nickname, else the checkout's base name).
- **D-stop.** After the seat's own `StopReport` answers a repeat (Stopped or Stale, `result.go:89`), `uiLifecycleRunWith` reads each other seat with `lifecycle.Read(other.Roots.StateRoot, prober)` (`state.go:119`), the read `ui status` makes there, stale records repaired as there. Candidates are the seats whose state is neither Stopped nor Stale. None: today's line, unchanged, exit 0. Exactly one: `lifecycle.StopReport(candidate.Roots.StateRoot, stop)`, the same function with the same prober and `--wait-seconds` on that seat's record; Running gives "no interface for m1e; stopped the interface of machine ui (pid 91362, :7878)", exit 0, Confirmed, Targets `{ui, <ui checkout>}`, Summary that line; every other outcome (Uninspectable, Unreadable, Busy, Timeout) gives "no interface for m1e; machine ui: " + `StopReport`'s own line and its code. Several: nothing is stopped; "no interface for m1e; 2 machines of this computer run one; nothing was done", one line per seat "machine ui: pid 91362 at 127.0.0.1:7878: metasystem ui stop --repo /Users/wido/LocalStorage/GitHub/agentic-tools-ui", exit 1, Refused.
- **D-status.** After the seat's own `StatusReport` answers Stopped or Stale (its lines, state and code 1 unchanged), the same read; each candidate adds a line, "machine ui runs one (pid 91362 at 127.0.0.1:7878): metasystem ui status --repo <checkout>" for Running, "machine ui: <state>" otherwise; the JSON data gains `seats`. A seat that runs its own interface lists nothing more.
- **D-start.** In the `start` closure (`ui.go:1118-1129`), before anything is spawned: for each other seat `Read`; a Running record whose `Address` equals the validated listen (both canonical, `serve.go:53-78` and `:160`; a port-0 listen equals none) answers `Result{Lines: {"no interface for m1e; machine ui runs one at 127.0.0.1:7878 (pid 91362); stop it with: metasystem ui stop --repo <checkout>, or start this seat's at another address with --listen"}, Code: 1}` and no child is launched; `uiTarget` renders it Refused as today (`:2076`) with `next` that `ui stop --repo` argv. Another address starts as today. Restart gets this for free: `RestartReportFor` runs the same closure after its own stop (`result.go:130-153`; a Stopped own seat takes the start's lines and code, `:146-150`), so `ui restart` in m1e points at ui and stops only its own seat's interface, as `Restart` does (`stop.go:74-80`). Restart never stops another seat's interface: that would start m1e's in ui's place, a different act (later list).
- **D-proof: no second path.** Another seat's interface is stopped only by `Stop` on that seat's record (`stop.go:26-72`): `Read`'s exact-identity proof, `SignalExact`'s re-proof before SIGTERM, the lock wait after it, all with the invoking verb's prober (`identity.KernelProber{}`, `ui.go:1112`) and wait (`:1117`). `uiLifecycleEffects` gains `send identity.SignalFunc` (nil is `syscall.Kill`) and sets `StopOptions.Send`, so a test proves the signal without receiving one.
- **D-authority: nothing more than today.** Stopping one's own interface proves no person and is open to agents (`intent_process.go:237-239`, `:2038-2047`). What is stopped is the same kind of thing, one process of this user on this computer whose authority is observed afresh at its next start (`act.go:119`) and never inherited; who may stop it is unchanged; only the record read differs. So the cross-seat stop keeps audience `both` and proves nothing (open question 2 if Wido wants otherwise).
- **D-words.** `ui stop` gains a details line: "When this seat runs no interface and exactly one other machine of this computer does, stop stops that one and says which; when several do, it lists each with its --repo command and stops none." `ui status` and `ui start` gain: "When this seat runs no interface, names the machine of this computer that does." Usage lines and the pair table are unchanged.
- **Seams.** `uiIntentOptions` gains `others []uiSeat`; `uiLifecycleResult` gains `Seat *uiSeat` (the seat acted on) and `Seats []uiSeatView` (the JSON lines); `uiTarget` takes Summary and Targets from `Seat` when set. The `ui` seam's signature (`intent_process.go:438`), `machine list` and `internal/ui/lifecycle` are untouched.

## 4. Later, when it hurts

- One interface per computer (Wido's "later"): `ui start` refuses whenever any seat runs one, whatever the address; D-start's per-seat `Read` becomes that rule.
- Seats that are not machines: a scratch clone with a running interface is invisible to D-seats; searching means reading 3273 registered checkouts' records.
- `ui restart` from another seat replacing that seat's interface: a ruling first, then D-stop's candidate plus its `start`.
- Naming a seat (`ui stop --seat ui`): the `--repo` command in the listing is the pointer until typing it hurts.
