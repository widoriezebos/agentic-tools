# At the helm, the person just acts

> As you can see above, trying to commit something and push something while at the helm is not easy at all. But I really want this to be as easy as possible, even from a tool like GitHub Desktop. While at the helm, it should just do what the human wants to do. [...] figure out what the easiest, most elegant, and intuitive non restricting way that is still safe is for all commands like this. What happened: on another machine a person held the helm and could not land a change; nine blockers surfaced one per round trip, and the route that worked was `git commit` + `git push` on main by hand in a terminal. GitHub Desktop could never have done it.

## 1. The proposal: taking the helm is the only authorization

After it, the seat behaves as a plain git repository.

1. `metasystem helm take --reason "…"` once, at a terminal. Unchanged: it is the one moment the person is proven (`cmd/metasystem/intent_helm.go:119-127` refuses an agent anywhere in the chain), and it writes the signature with the checkout it was taken in (`:128`; `internal/helm/helm.go:143-155`).
2. Then the person works however they like: commit and push from GitHub Desktop, VS Code, the terminal, or ask the agent next to them. No flags, tokens or particular terminal. Each such act is recorded as done at the helm, with which process did it.
3. `metasystem helm return`: the machinery catches up after, not before. It already prints "yields since the take: N" (`intent_helm.go:287-288`, counted from `helm-yields.log` at `:311-328`); later slices offer the follow-ups (conclude a goal, an after-the-fact review) as plain questions.

Safety moves from "ask permission before each act" to "trust the person at the helm, record everything": only a proven person can take it; it covers one seat, one checkout plus its linked worktrees, named by the git common dir (`helm.go:1-6`, `:52-80`); every act is logged and shown again at return. Kept at the helm because they are damage checks, not identity checks: hand edits to the goal ledger (`plans/goals/`, `plans/channel/`; the pattern at `internal/landing/landpath/precommit.go:42`) and `.orig` patch backups. Yielded: the agent-commit wrapper fence and the new-plan acknowledgment. Background delegates and machinery that keep running under the helm gain none of the person's power.

**GitHub Desktop, after slice 1.** The person ran `helm take` this morning. They edit two files in the checkout, write a summary in Desktop, press Commit to main. Desktop runs `git commit`; the enrolled hook (`.git/hooks/pre-commit`, composed by `internal/ledgerfence/fence.go:244`) runs `metasystem internal pre-commit`; the guard sees the helm, admits, writes one yield line; the commit exists. Push origin: there is no pre-push hook (`.git/hooks/` holds `pre-commit` only), so it goes. Nothing was typed, nothing exported. `helm return` later says "yields since the take: 1". Today the same press fails with "an agent commit goes through metasystem work land; the live wrapper ancestry token is missing" (`precommit.go:79-80`): Desktop's git has no controlling terminal, so the classifier answers UNTRUSTED (`internal/lease/classify.go:453-455`, `:476`), and main is the published line (`precommit.go:167-168`).

**What still refuses, and why.** A staged `plans/goals/` or `plans/channel/` path: the ledger changes only through goal verbs, and a hand edit corrupts the record every seat reads (`precommit.go:84-101`). A staged `.orig`: never tracked (`:102-111`). Both keep today's messages. Any commit from a linked worktree of the seat: that is where jobs and goal work run (`cmd/metasystem/intent_worktree.go:237-243`; `internal/gittree/detached.go:250`), and the helm does not reach them (D-scope).

## 2. Step 1: what exists and works after slice 1

**Behavior.** In the pre-commit guard, when the seat is at the helm AND the commit's work tree is the seat's primary checkout, the two identity refusals do not refuse: each records one yield, prints one line, and the guard goes on. Everything else in the guard is today's, byte for byte.

- **D-scope: the helm is the checkout the person sits in.** The guard admits when `helm.Active(workTree).Active` holds and the commit's work tree is the seat's primary worktree, not a linked one: `git rev-parse --path-format=absolute --git-dir` and `--git-common-dir` resolve (`filepath.EvalSymlinks`) to the same directory. A linked worktree has its own administrative directory under the common dir's `worktrees/`, so it fails the test; a primary checkout and a submodule's primary worktree (whose git dir is `.git/modules/<name>`, also its common dir) pass. `helm.Active(workTree)` reads the signature of the seat that common dir names (`helm.go:52-80`, `:82-102`), so the helm read and the checkout test agree on the seat. `workTree` is the hook's working directory, which git sets to the work tree's top (`cmd/metasystem/precommit_entry.go:21`). Linked worktrees keep the guard exactly as today, which keeps background jobs fenced without asking process ancestry anything, and covers GitHub Desktop, the terminal and the agent working in the checkout alike. (Revision 2, Astra HA-01: revision 1 compared the toplevel with `Seat.Checkout`, which names the metadata directory for a submodule, `helm.go:68-70`.)
- **D-yield.** Under that condition the wrapper fence (`precommit.go:78-82`) and the new-plan acknowledgment (`:130-137`) each record one `helm.RecordYield(workTree, helm.Yield{Boundary: "pre-commit", Gate: g, Would: "refuse", Subject: s})`, `g` one of `wrapper-fence` and `new-plan-acknowledgment`, `s` = `branch=<symbolic-ref HEAD> tree=<git write-tree> class=<the classifier's class, or unavailable>`. `RecordYield` fills By from the signature and PID from the guard process, and never refuses (`internal/helm/yield.go:46-63`). The helm is consulted only at those two points: a commit that passes anyway leaves no yield and no line, and the classifier still runs first (`precommit.go:62`), so its class is in the record. The ledger fence and the `.orig` refusal stay with their messages; the classifier-unavailable observation (`:63-73`) stays as it is, since it refuses nothing.
- **D-words.** `helmYielding` (`intent_helm.go:23`) gains `the pre-commit guard admits your commits in the checkout you sit in`, which `helm take --help` joins into its first paragraph (`:68-69`). Nothing else in `helm take`/`return` changes in this slice; return's yield count is the account. No test pins that help text.
- **D-malformed: the guard follows `helm.Active`'s contract.** A present signature that cannot be read or decoded is active with By "unknown" (`helm.go:118-124`). Every other yielding boundary reads the same bool (`internal/adapter/toolgate_run.go:96`, `internal/hooks/runtime_hook_start.go:442`, `runtime_hook_stop.go:109`; status says "the signature is unreadable", `intent_helm.go:368-370`). The file is the person's own, mode 0600 under the seat's git dir (`helm.go:151`); an agent able to corrupt it could as well write a valid one, so parsing buys no safety; and a guard that refused here would be the tenth blocker, invisible in Desktop. The yield carries By "unknown", the stderr line says the signature is unreadable, and `helm return` reports the same (`intent_helm.go:266-273`).

**What the guard prints.** One stderr line per yield, at most two per commit: `pre-commit guard: HUMAN AT THE HELM (<by>): the <gate> yields; recorded in <common-dir>/metasystem/helm-yields.log`, with `(signature unreadable)` in place of the name under D-malformed. GitHub Desktop shows hook stderr only when the hook fails, so there it is harmless; at a terminal it is the one visible trace of the yield. Exit status 0.

**Seams in code.**
- `landpath.GuardOwners` (`precommit.go:15-35`) gains two owner fields, so tests fake the helm as they fake the classifier: `Helm func(workTree string) helm.State` and `HelmYield func(workTree string, y helm.Yield)`. A nil `Helm` means no helm, so every existing bed (`port_guard_test.go:81-95`) runs today's guard unchanged. `landpath` imports `internal/helm` (standard library plus `atomicfile`; no cycle).
- `Guard` (`precommit.go:51-138`): one memoized local `helmAdmits() (helm.State, bool)` (the helm read plus the git-dir test of D-scope) evaluated inside the two refusal branches, which become "yield, print, continue" when it answers true. `wrapperFenced` (`:152-198`) is untouched.
- `landingGuardOwners` (`cmd/metasystem/landing_path.go:537`) wires `Helm` to `helm.Active` and `HelmYield` to `helm.RecordYield`. `precommit_entry.go`, the hook script and `internal/helm` do not change.

## 4. Later

**Slice 2: the identity chokepoints answer "the person at the helm".** The goal verbs' person proofs go through `humanauthority.Prove` (enrolled terminal, no agent in the chain: `cmd/metasystem/goalsync_mutations.go:2208`, `:3148`, `delegate_host.go:46`, `intent_disk.go:359`, `internal/ui/act/act.go:123`) and `lease.ClassifyVerbAt` (`internal/lease/verbs.go:369`). Both refuse the agent working next to the person. The open problem: process class cannot tell that agent from a background job. `ClassifyAt` walks up from the caller and returns DELEGATE at the first ancestor whose command is an agent runtime (`classify.go:423-426`); an interactive Claude or Devin session with no announced main is that ancestor, exactly as a dispatched job's runtime is; HUMAN is only a caller with a controlling terminal (`:453-455`). The lead: checkout scope, as in slice 1. Under the helm, an act from the seat's primary checkout is the person's act; acts from linked worktrees, where jobs and goal work run, stay what they are. The chokepoints gain one owner (the same `helm.Active` read and git-dir test) and record one yield per admitted act. Premise to keep true: no dispatched job runs in the primary checkout.

**Slice 3: `helm return` asks the follow-ups.** Return already lists the yield count, running jobs and batches (`intent_helm.go:287-309`). It gains a readback of the pre-commit yields (branch, tree, class, when) and one plain question per follow-up: conclude the goal this work belongs to, or ask for an after-the-fact review of the commits made at the helm. It still starts, stops and claims nothing (`:80`).

## 5. Later, when it hurts

- Name the committing program in the yield (GitHub Desktop, zsh, claude): two parent hops above the guard, `identity.ExecutablePath` (`internal/identity/terminal.go:25-27`).
- The parity check counting git-ignored files.
- The goal-branch token.
- A `work land --check` preflight that names every blocker at once instead of one per round trip.

## 6. Not in it

No change to `helm take`'s proof, to `helm return` beyond the help clause, to the hook script, to `wrapperFenced`, to the ledger and `.orig` refusals, to `work land` or to any goal verb. No pre-push hook and no push-side check: a push after an admitted commit is a plain `git push` today and stays one. No new flag, token or environment variable. No admission in linked worktrees or in other clones, whoever holds the helm. No yield for a commit the guard admits anyway.
