## 2. Decisions

- D1 The owner lock is held by the holder's native process identity, never by argv text. `lock.Identity` (`metasystem/internal/lock/lock.go:31-36`) gains `Process identity.Ref` (`json:"process,omitzero"`); a binding that leaves it zero keeps its bytes and its equality (the generic lock users).
  - The record is canonical. The claim probes the pid it is given (its own for arming, park, recertification and evidence; the caller's for the delegation, `metasystem/internal/delegation/infra.go:239`) and stores one native form of `Exact.Ref()` (`metasystem/internal/identity/identity.go:55-64`): on Linux pid, ticks and boot id, with the start second cleared, because a clock step moves it (`metasystem/internal/identity/identity_linux.go:71-84`); on darwin pid and the kernel's microseconds. A probe that is not Alive claims nothing and says so.
  - Release matches by pid and tag. `ReleaseNamed` and `TransferNamed` (`lock.go:263-293`) compare with `Process` cleared on both sides, so a release succeeds after any clock step and for a `CallerPid` that has ended (the delegation releases for it, `infra.go:251`). Nothing else compares `Process` structurally; the canonical form keeps any later comparer stable.
  - The holder probe (`metasystem/internal/dispatch/ownerlock.go:60-84`): a holder recorded with a ref is `identity.LiveRef`, so a clock step keeps it alive and a reused pid is dead; a holder without one (an older engine's file) is busy while its pid is Alive or Unknown, whatever its argv, and dead only when its pid is gone; the argv is never read. The workspace reclamation reads the same probe (`metasystem/internal/dispatch/delegate_workspace.go:240-262`) and inherits it.
  - Injection. `OwnerLockClaimWith(directory, pid, tag, OwnerLockOptions{Now, Sleep, Prober})` carries a clock, a sleep and a prober into `lock.Acquire` (`lock.go:92-107`) and into the codec's `acquiredAt`; `OwnerLockClaim` and `OwnerLockRelease` keep their signatures with the production defaults. `acquireCapAuthorityLock` (`metasystem/internal/supervise/arming.go:294-316`) passes `armingNow`, `armingSleep` and a new `armingLockProber`, so a supervision test drives the whole schedule on its own clock (R-104-m1e).
  - The holder is kept and shown. A busy claim returns `ErrOwnerLockBusy` wrapped with the holder's pid, tag and liveness (`errors.Is` still holds for every caller); the cap wait's refusal reads "repository cap-authority lock remained busy: held by pid N (...)" (`arming.go:309-311`).
  - Callers, all unchanged in their calls and all run (R-18): `arming.go:301`, `:304`; `infra.go:239`, `:251` (the delegation's owner locks, among them the same `cap-authority.lock.d`, `infra.go:477-505`); `metasystem/internal/landing/park.go:227-228`; `metasystem/internal/validate/recertification.go:610-612`; `metasystem/internal/evidence/lifecycle.go:40`, `:50`; and the probe's reader `delegate_workspace.go:240-262`.
  - The mixed-version boundary: serialization holds between engines that carry this unit. An older engine reads pid and tag only and keeps its tag rule, so it can still take a lock a newer start holds; the window closes when a person's start runs every helper of the checkout on the new engine. A legacy file whose pid was recycled stays busy until the cap wait refuses with that holder named; the person's act is the fail-safe.
  Rejected: "metasystem up" in the public verbs' argv (the same defect with a new string); the start second alone (a clock step frees a live lock); the ref in the release comparison (a release after a clock step, or for an ended caller, would fail, and `arming.go:1250-1255` turns that into a failed start).
- D2 Every row of the remedy table has one class, machine or person, and the table is its only owner. `Remedy` gains `Machine bool` (`remedy.go:7-12`); an unmarked row is a person's, so a new row fails closed. Machine rows are the rows a machine clears with no act of a person: breach-stop-open (`:62`), observation-pending (`:82`), clock-regressed (`:86`), ledger-attention (`:99`), trunk-red (`:101`), capability-snapshots (`:103`), proof-attempts (`:107`), proof-admission without an owner instruction (`:112`). Every other row is a person's, the supervision owner's included. A row keeps the conditional person act the table already gives it ("a person corrects an inaccurate clock", "metasystem system start arms it"): the class says who clears it first, not that no person ever acts. `remedyCauseNeedsAPerson` and its comment go (`health.go:177-197`); its test reads the table. Rejected: keep the cause map (a second owner, already wrong for budget-breach).
- D3 The final wording is projected once, after the breaker, onto the role. At the end of `standingRoles` (`health.go:1019-1050`) every role that is not alive gets `Remedy` from `PublicRemedy` for the human audience. So the tick's line (`tick.go:814`), the stored verdict, the alert episode and the standing-defect message (`health.go:1090`) show the same words. `PublicRemedy` keeps its ledger and capability case (`remedy.go:39-41`) and gains one rule: a person's row on a lawful role at AUTO_HEAL_ELIGIBLE reads "nothing to do yet: the machine is healing it (failure n/5); if healing ends: " and then the row's own words. The alert episode follows: when a tick reuses an existing episode, `updateAlertEpisodesWith` sets its `Message` to the current line (`alert_episode.go:493-512`) and changes nothing else, not its id, digest, attempts, transport result or acknowledgement; so the words at 5/5 are the words shown, in the alert list and in the situation. An unknown role keeps the row's words, conditional act included; it never stands. Agent lines still re-render through `PublicRemedy("agent")` (`health.go:381-389`), so the hook preview keeps its audience's commands. Rejected: change `PublicRemedy` only (the tick's line and the standing defect keep the cached words); a new episode per wording (a new id re-notifies and loses the acknowledgement).
- D4 Hook-freshness no longer names system start. Its row (a new case before `remedy.go:91`) is a person's row whose first words name the evidence producer: "nothing to do while a session runs: its next completed turn records a fresh hook completion; a person repairs the Stop hook when it stands". The role stays not lawful (`health.go:1130`), so it stands at five as today. Rejected: a machine row (Astra round 2: the next turn produces evidence, it repairs nothing, and the person's act stays necessary); keeping `system start` (both standing episodes of today cleared with no start).
- D5 The readers say who decided. The decision list (`intent_operations.go:709-716`) keeps "Decisions in a person's name" for lines with a `By`, and lists every other line (an agent's disposition today, any machine-written line later) under "Decisions by agents and the machine" with its actor. The detail view (`:751`) shows "actor" beside "by", and "by: none, decided by <actor>" when `By` is empty. Rejected: leave the reader for a later machine writer (today's agent dispositions are already shown as a person's).
- D6 Escalation goes through the existing paths. An ended or standing role alerts (`healthSummary`, `health.go:1052-1071`; `fileStandingDefects`, `:1075-1099`) with D3's words; getting it to a person is the-steward-acts' (G2b D3). Rejected: a channel of this page's own.
