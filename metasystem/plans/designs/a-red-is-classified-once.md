## Step 1

After U1: a unit check that goes red only because some tests flaked no longer stops the round, and nobody is asked anything. Each failed test is rerun alone on the unit's own tree; if every one passes, the round goes on to its read, and the check step names the tests that flaked. A test that fails again alone and passes on the unit's base stops the round as the unit's own, as today, also when it is registered as flaky. That stop now names the test, the rerun and the base run, and a registered test's registration. A test that fails on main too stops as main's red: it names main's incident and offers Retry, not a correction, and that Retry runs. After U2, the unit check's flake is a sighting in main's register, like a lane sighting, and a person's retry works on every stop without a fake change. After U3, the lane decides with the same table: a batch red that passes alone on the batch tree is a flake, not the last goal's own.

## 3. Decisions

- **D1 One cause table, in `loopstop`, with no side effects.** `metasystem/internal/loopstop/red.go` (new) adds `ClassifyRed(RedEvidence) RedVerdict`. The evidence holds: whether the check's report is complete (and why not); the failed units, each with its named tests and its section (check or audits); the registered identity of each test from the judge (for naming only); the rerun alone on the subject tree (absent if not run); and the replays, oldest first, each with its role (main, goal merge with goal and SHA, or base) and its outcome (absent if not run). The verdict is either the next run to make (rerun these selectors on the subject tree, or replay them on tree *i*) or a `Cause` (kind, goal, SHA, name, tests, evidence), plus the tests that flaked and one line of words. Each owner runs the executions: the lane with its proof trees and lock, the unit check with launches through its manager. The table and its words are shared. First match wins:
  1. The report, a rerun or a replay did not complete (no report, lost process, deadline) → **environment**.
  2. Failed units that name tests, and no rerun yet → next: rerun the named tests alone on the subject tree, once (the lane's form: `LANDING_ONLY` and `LANDING_ONLY_TESTS`, `metasystem/internal/landing/plain/prove.go:1225-1227`).
  3. The rerun passed every named test and no failure was unnamed → **flake**.
  4. Tests still red after the rerun, and unnamed failures (a build failure, an audit section, a group) → replays oldest first. An unnamed failure has no rerun, so for it the replays decide alone. Each replay uses the named tests, falling back to the whole failed package when the named run is green or incomplete (the lane's form, `metasystem/internal/landing/plain/replay.go:463-477`); an unnamed failure replays its failed package or section. The first tree where the red reproduces names the cause: main's tree → **main**; a goal's merge → **own** of that goal; a base that is not main's tree → **other**.
  5. The red reproduces on no replayed tree → **own** of the subject's goal (the unit's goal; on a batch, the last goal). For an unnamed failure this is own of the subject as today (`metasystem/internal/launch/unit_attribution.go:234-257` answers own for a passing base), and the words say that no rerun is possible for an unnamed failure.
  6. A step that cannot run (no base, a git error, an unreadable log) → **unclassified**, with what could not run. The table never answers own for a named test without both a red rerun alone on the subject tree and a green replay.

  A test that passed its rerun is a flake sighting whatever the class of the rest. The judge's `Affected` is no longer a classification input; it stays as evidence (the surfaces recorded with a sighting). Rejected: lifting the lane's `classifyRed`/`continueRed`/`classifyReplay` whole into a shared package. They are about 600 lines bound to the lane's lock, results file, running slot, proof trees and batch merges, none of which the unit check has. Also rejected: a new package. `loopstop` already owns the vocabulary and both sides import it.
- **D2 The unit check's decision table.** `compareProof` gathers the evidence and calls `ClassifyRed` until it returns a cause. The rerun is a proof launch in the unit's worktree with the frozen full declaration (`plan.FullArgv`) and the selector environment. Its launch id is appended to the step's launch list (`step.LaunchIDs`) exactly as `metasystem/internal/launch/read_sequence.go:59-75` does for a step's launches, so collection (`metasystem/internal/launch/unit_run.go:773-777`), accounting (`metasystem/internal/launch/unit_accounting.go:11-16`) and the execution reconciliation (`metasystem/cmd/metasystem/intent_work.go:607-608`) count it with no change of their own; the run's tree reservation (`metasystem/internal/launch/tree_reservation.go:181`) and the process measure (`metasystem/cmd/metasystem/intent_process_measure.go:65`) read the same list and see it too. `step.LaunchID` stays the check's launch, so the verdict's cause books the check and the stop's evidence names it (D5). `step.Alone` (launch id, selectors, outcome) is the retained record for resume, so a restart resumes the rerun rather than repeating it; it is not a second accounting path. It is not named `Rerun` because `UnitStep.Rerun` (`metasystem/internal/launch/unit_run.go:118`) already marks a read's rerun step. The existing `step.FlakeRepeat` flag bounds the rerun to one per check step per round. A started rerun is the step's second launch, so the machine's one deadline retry, which needs fewer than two launches (`metasystem/internal/launch/unit_step_failure.go:95`), does not follow it, as it does not follow today's whole-step repeat: a rerun that reaches the deadline is environment, with Retry for a person. The base run keeps today's isolated export and retained comparison (`metasystem/internal/launch/unit_attribution.go:108-230`) but runs the named selectors. The whole-step `KnownFlake` repeat is removed; the cmd seam becomes a facts seam (registered identities and surfaces).

- **D3 One writer and one reader for the register.** The writer is `goal.RecordFlake` through `landingFlakeRecorder`, which now takes the actor's lineage (the lane passes its own; the unit check passes the seat's). There is one function and two callers. A unit sighting has location `tip`, tree = the unit's tree, base commit = the unit's base, attempt = the check's launch id, rerun = the rerun's launch and log, repeat `alone`, and the judge's surfaces. That is the register's existing shape, so no validator changes. The reader is `goal.FlakeFacts` over main's register, used by the judge on both sides and by the lane's health. A unit sighting counts toward confirmation like a lane sighting: at two sightings with no fix goal, the lane steward opens it. The steward needs no change. The sighting is evidence, not a gate: if the write fails, the round goes on, and the step records the error, which shows as a warning on the status line. Rejected: recording unit sightings that do not count. A flake that only bites seats would never get its fix goal, against "flaky tests we should fix immediately"; and lane sightings at a batch tip already include goal changes, so a seat sighting adds no new risk. Also rejected: a new `unit` location. It would change two validators for a distinction no reader acts on.
- **D4 No change made up for a flake.** The flake path stays inside the round: no new round, so the build-gap rule never sees it. A person's retry is accepted for every class. `RetryFailedStep`'s cause gate (`metasystem/internal/launch/unit_step_failure.go:192-194`) and `work review`'s retry gate (`metasystem/cmd/metasystem/intent_unit_review.go:48`) accept any `unit-build` stop when a person gives a reason (U2; main joins environment and deadline in both gates already in U1, D5). The retained check reruns in the same round, with no builder turn, recorded as the person's act. That is the one generic fail-safe for a wrong class. The question still offers only the class's act (D2); the land refusal and the continuation name it too. Rejected: an exception in the build-gap rule for a round with no change after a flake. It would rebuild nothing, rerun the whole check (about 50 minutes) and key the gap rule on a class.
- **D5 The stop names its class and its evidence.** `holdFailedStep` takes `Class` from the table's words. `Cause` carries kind, tests, name (main's incident; for a registered test, its identity) and evidence (the check's launch). `Stop.Replay` (already in `loopstop.Stop` and in `Words`) carries the rerun and the replay with their launch ids. Every reader takes the words from the record unchanged: the question (`metasystem/cmd/metasystem/intent_unit_questions.go:200`, `metasystem/cmd/metasystem/intent_unit_questions.go:265`, `metasystem/cmd/metasystem/intent_unit_questions.go:285`), the correction brief (`metasystem/cmd/metasystem/intent_unit_questions.go:295`), the status line, the land refusal and the board card. In U1, main joins environment and deadline wherever the act is chosen and wherever the retry is admitted: the question's act (`metasystem/cmd/metasystem/intent_unit_questions.go:178`), the continuation (`metasystem/cmd/metasystem/intent_selection.go:465`), `work review`'s gate (`metasystem/cmd/metasystem/intent_unit_review.go:48`) and `RetryFailedStep`'s gate (`metasystem/internal/launch/unit_step_failure.go:192-194`). So the Retry U1 offers on a main stop runs in U1, and no person's decision reaches a refusal (ruling R-142-m1e). The question about a flake goes away because no stop is written; T2 pins it.
- **D6 The lane uses the same table (U3).** In `continueExecutedRed`, a batch red is rerun alone on the batch tree when every failed unit names tests, not only when the judge says known and not affected. The rerun uses the existing `repeatRed` and its per-tree allowance. `classifyReplay` no longer names the subject's goal own unless that rerun was red, and each cause the red path writes comes from `ClassifyRed`. What changes in the lane: a batch red with named tests costs one rerun alone before the main replay (the failed packages only); a red that passes that rerun is a flake on a batch tip, recorded as trunk reds are today, not own. The lane's case of 10:26 (gap 7) would have been rerun alone on the batch tree and named a flake there, not returned as own. What stays: the trunk path (it already reruns first), main recording, the repeat allowance, the proof budget, the person's classification act. Rejected: leaving the lane alone. That keeps two tables, and the same flake would be own at the lane and flake at the seat, which is the defect this page removes.
- **D7 a-unit-check-runs-the-audits: sequence, not fold.** That goal changes which tests the unit check selects (queued, priority 1, pinned m1e, one unit, no design). This page changes what a red means. It lands first or alongside. An audit red with no named tests takes the table's unnamed row: no rerun is possible for an unnamed failure, so the base replay of the failed section decides, as today; a red that reproduces nowhere is own of the subject, and the words say that no rerun is possible for an unnamed failure. Once it names tests, it gets the rerun like any test. Rejected: folding it in, which would hold a ready one-unit selection change behind a design it does not need.

## 4. Risks

- A change that makes a test intermittent passes the unit check as a flake. It is recorded with the unit's tree, the second sighting opens the fix goal, and the lane sees the same test. Accepted ("not a nuclear reactor").
- A test that fails only inside its package and passes alone is a flake, as the lane already treats it ("alone").
- A registered flaky test that fails twice in a row on one tree by chance stops as own (about one in a hundred at a 10% flake rate). The words name its registration, and a person's Retry (D4) reruns the check in the same round. Accepted with Q1's answer (section 7).
- A unit sighting is a records-only move of main. Main's green inherits it (`metasystem/internal/landing/plain/trunk_recovery.go:181`), and a proving batch folds it in at push (`metasystem/internal/landing/plain/push.go:188`). No batch is re-proved for it.
- Cost: one named rerun per unit-check red and per named lane batch red, in place of a whole-check rerun (unit) or nothing (lane batch).
