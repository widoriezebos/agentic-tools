## Problem

A test's scratch folder has no owner at the end of its life. The test binary's teardown (`cleanupReporting`, `internal/testenv/testenv.go:938-957`) tries to remove the folder, finds its custodian still holding a shared lock (the custodian is a child that must outlive the test to clean up after a kill) and leaves the folder "for a later sweep". The custodian inherits the folder's path (`testenv.go:423`, `:555`) but its completion branch (`:250-259`) only removes its own quiet log; it never calls the folder's cleanup, so the folder stays. Removal falls to a stranger: the next test binary's start-up sweep (`removeDeadRegistryHomes`, `:989-1012`), which must guess from outside whether the folder is still in use. When the custodian's six-second self-destruct fires (it times a whole pass, so under load it fires while the custodian is still working, E4), its records stay too and the stranger can never decide; the folder stays forever. 26,000 such entries in two days made every test start slower, and the fixture-bed tests' waits ran out: most of this week's flakes. Rounds 1-8 of this page hardened the stranger's guessing; every round found another case it could not decide (unreadable processes, zombies, untagged children, macOS hiding Apple binaries' environments). The cause is the missing owner, not the guess.

The rest of this section's facts stand as Evidence E1-E14 above. The lane's cadence (E10), the wrong words (E11, E12) and the deploy (E13, now its own goal) are unchanged by the reset.

## Invariant after the goals

1. The last process of a test's custody removes the test's scratch folder: the teardown when no custodian is left, else the custodian when it finishes, whether the test ended normally or was killed.
2. A custodian's self-destruct fires only when one process check is stuck past the bound; a slow but progressing custodian is never halted.
3. A folder whose custodian halted is kept, as today, and counted after the build; nothing new is judged from outside.
4. The fixture-bed tests whose failures this page names observe what they inject: an injected clock and prober for every time-bound assertion.
5. A flake record does not schedule a full proof of main; `proof.trunk-every` is the cadence when no code moves.
6. What a person reads is true: a flake is called a flake; a seat card is retired on accepted `StateDone` evidence (retirement on unenrolment stays deferred); the automatic deploy is the next goal (D7).
7. Joining flake identities by cause stays deferred (D9).

## Decisions

### D1. The self-destruct times one stuck check, not a slow pass (goal 1)

- The injected six-second timer is armed immediately before each inner `Probe` (and `ReadStart`, which `AliveRef` calls, `internal/identity/identity.go:224-231`) and disarmed when it returns, through one wrapping prober that every probe of the custodian goes through. The pass-level arming sites are removed (the brief draft of 11:40 counted five: `fixture_custodian.go:281`, `:451`, `:467`, `:553`, `:628`). No timer runs during census enumeration, file reads, bookkeeping or logging (R-35-m3: kill on stalled, not on slow). The timer runs on the injected clock (R-104); the bound stays 5 s + 1 s.
- Unchanged: what a halt does (it exits 2 and leaves its records), and every rule of how the custodian decides that a helper is dead. This decision touches only when the timer runs.

### D2. The last one out removes the folder (goal 1)

- The custodian's completion branch in `testenv.Main` (`testenv.go:250-259`) gains one step after its existing `removeQuietFixtureCustodianLog`: when its log was quiet and is now removed, it calls the existing guarded `RemoveSettledHome` (`testenv.go:1171`) for the folder its own log names (the home in its environment, `testenv.go:558`, checked against its log's name). The custodian holds no owner-lock descriptor (the owner file is close-on-exec, `:804`, `:898`; the custodian gets fds 0-4 only, `:442-443`); what made the teardown back off is the custodian's exclusive lock on its own log (`:414-443`, `:1231-1233`), which removing the quiet log ends (brief premise P1, 12:40). A report of another custodian's non-quiet log is refused, not written into this custodian's own removed log, so that log waits for the next start-up sweep, which shows it to a person (P2). Every guard is the existing one: the folder's owner lock taken exclusively without waiting (so a live test, or another custodian still holding its inherited lock, keeps the folder, and that one is then the last one out), and every sidecar settled by the existing rules (records absent, each custodian log's lock free, a non-quiet log reported before removal).
- Nothing new decides settlement (QH-R9-02): the start-up sweep already removes the same folder on the same evidence once the custodian has removed its records; this step makes the removal happen at the custodian's exit instead of at a stranger's next start. A non-quiet log keeps its existing report-before-removal path (QH-R9-03).
- The teardown (`cleanupReporting`) is unchanged and stays the remover when no custodian outlives the test.
- A custodian that halts leaves its folder, records and log, as today. Automatic disposal of halted folders is deferred (QH-R9-01): with D1 a halt means a probe was truly stuck, which should be rare; the full proof after the build measures how many folders remain (A1's guarded listing counts them) before any rule is written for them.
- The proofrun inventory test (`TestTestEnvironmentStandardInventoryMatchesObserved`) stops doubling every testenv red: its nested whole-package run reports inventory only, not pass/fail (finding 410).

### D3. Tests observe what they inject (goal 1)

- launch `TestUnitCheckFindsRunningEngineWithoutCallerPath`: the fixture engine is a script that prints the expected line, not a `testenv.Main` binary; the one-minute bound stays.
- cmd `TestProofRunLegacyPublicLaunchUsesAndClearsHostPhase`: the test injects an empty census process file (`METASYSTEM_CENSUS_PROCESS_FILE`) as the governed test already does, so the attempt-less launcher reads the injected table, not the host's.
- cmd `TestProofRunCommandGovernedParentSharesOneCharge`: the governed child and its engine run on the fixture's semantic clock through the authorized goal-clock path (`METASYSTEM_GOAL_NOW`, `cmd/metasystem/goal.go:45,65`), propagated explicitly; `METASYSTEM_WAIT_BINARY`/`_SOURCE` (binary reuse, `ambient_controls_test.go:62`) are only an optimisation and are passed too. A mutation that drops the clock propagation fails a deterministic assertion (QH-06).
- proofrun `TestResourceCustodyStreamsLiveCapNoteAndRetainsSpools`: the launcher's verdict (`public.err`) joins the `Fatalf`, and the fixture sets the existing authorised `METASYSTEM_CENSUS_PROCESS_FILE` fixture in the launcher's parent environment and supplies a counting `LaunchOptions.Signal` transport (`launcher.go:31`; no new production census seam, QH-R4-04), so the launcher's post-suite enumeration (`launcher.go:633`, attempt-less through `fixture_reap.go:29`) reads the injected table, not unrelated host processes. The cap transition and the single-notice assertion (`resource_custody_output_test.go:48`, `:68`) move into an injected-clock, injected-prober watchdog test over the existing seams (`internal/proofrun/watchdog.go:47`) with counting output, where mutations that suppress or repeat the notice fail; the subprocess test keeps only synchronised stream and spool wiring (R-104, rounds 3 and 5).
- testenv `TestSetupChildIsEndedWhenTheBinaryIsKilled`: the custodian's pause, progress and expiry regression moves into `internal/identity`, driven through `runCustodian` with its injected runtime (clock and prober; `fixture_custodian.go:94`, `:167`), where a mutation that drops the progress reset fails deterministically. The testenv subprocess test keeps only the wiring proof (the custodian is started and ends the setup child), synchronised on the custodian the test started, not a glob, with no time-bound assertion (R-104, round 2). No new production seam: `runCustodian` and `custodianRuntime` are package-internal and the regression lives beside them.
- cmd `TestProviderRecoveryAskPublicLifecycle` (added in revision 13; analysis/provider-recovery-test-2026-10-21.md): the parent re-executes the test binary as a child with a fixed `-test.timeout=30m` and no `-test.parallel` (`cmd/metasystem/provider_recovery_test.go:76`); the child inherits the lane's `GOMAXPROCS=1` (`internal/proofrun/test_go.go:153`, `:354`), so its 21 `t.Parallel()` scenarios run one at a time and, on a loaded host, reach the child's own 30-minute alarm (both of today's failures were `panic: test timed out after 30m0s`, never an assertion; passes took 858-1679 s, 58 s alone). The child inherits the parent's remaining timeout (`t.Deadline()`), explicitly `-test.timeout=0` when the parent has none, which removes its private 30-minute alarm; an explicit `-test.parallel` equal to the scenario count lets the scenarios overlap their process waits under `GOMAXPROCS=1` (it adds no processors); cancellation under an unlimited parent stays the enclosing runner's responsibility (QH13-05). Dropping the re-exec for an injected git seam is the durable fix and is not in this goal.
- Test lines, plus the clock plumbing D1 already adds; zero further production lines.

### D8. A flake record is not a reason to prove main (goal 2)

- What is exempt (QH-R4-03): a records-only move whose changes are the flake register (`plans/goals/trunk-red.json`) plus the appended sighting, the appended history entry and the matching `Revision` increment that `record-flake` writes to the incident's linked FixGoal record (`recordflake.go:177`, `verbs.go:479`), whatever that goal is named (`internal/goal/recordflake.go:40-166`; today's register links `tests-observe-only-what-they-inject-2` and others). The classifier reads the change, not the file name: any other edit to a goal record, including a design edit to a `flake-fix-*` goal, keeps the hour rule.
- One no-launch admission path (QH-R4-02): moved-main recovery and `Start` share an admission step that, for an exempt move, validates the complete diff from the executed full-green tree, records or reuses the target tree's inherited result keeping the original `FullTree`, `FullAt` and environment (`prove.go:132`), and launches nothing; `applicableMainProof` (`trunk_recovery.go:125`) accepts that inherited result for the new tree instead of skipping it for its tree, and the existing later-red and executable-input guards stay. Because the result carries the inheritance, it survives a restart without the scope decision's path list.
- The exemption holds in every place that imposes the hour (QH-08): scope selection (`scope.go:112`, `:137`, `:153`), inherited-result reuse (`scope.go:476`) the hourly debt (`scopedProofDue`, `wake.go:153`, honoured by `KeeperClock` before the cadence, `keeper_clock.go:83`), and moved-main recovery (`applicableMainProof`, `trunk_recovery.go:140`, which rejects an inherited proof at one hour before `reusableGreen`; called by `RecoverMovedMain` from the keeper's Observe composition, `cmd/metasystem/landing_agent.go:344`) (QH-13). It inherits the last full green, keeps that green's original timestamp, and runs nothing. Code moves and other records keep today's rule; `proof.trunk-every` (4 h) remains the clock.
- Question Q2 for Wido: keep the one-hour rule for other records moves, or make `proof.trunk-every` the only cadence? Recommendation: keep the hour rule for non-flake records (a goal record move can carry a design that changes test inputs); drop it only for flake records.

### D10. A test that passes its repeat is a flake, whatever else is red (goal 2)

- Today a trunk proof's repeat verdict covers the whole proof. `repeatRed` (`internal/landing/plain/replay.go:153-273`) repeats each failed unit once with only its failed tests; if any unit's repeat fails, the proof becomes unclassified and then `main` (`replay.go:123-124`, `:390-397`), and `landingIncidentRecorder` (`cmd/metasystem/intent_landing_incident.go:52-64`) writes every first-pass failure as a `red:` incident, also the tests that passed on repeat. On 2026-10-21 one real red (proof 20261021T153912) so turned four repeat-passing tests into four red incidents that held landing until the next green full proof cleared all five (`intent_landing_incident.go:83-132`). The results row's `flakes` list names every failed unit, the real red included (`report.go:100-129`).
- Decision (revision 14, after Astra round 10): D10 changes only which first-pass failures of a red trunk proof are recorded as red incidents. It adds no green path and changes no cause.
  - When every unit's repeat passes, nothing changes (today's rule, `replay.go:258-272`, including `RepeatComplete` and its green recovery, `replay.go:107-113`, `:192-195`, `prove.go:441-445`) (QH13-01, QH13-06).
  - When at least one unit's repeat fails, the proof's result and cause are exactly as today: `environment` for an incomplete or interrupted repeat (`replay.go:237`), otherwise `unclassified` and the caller's existing main-versus-goal attribution (`continueExecutedRed:115-124`, `classifyReplay:488-514`) (QH13-02).
  - In that red case, a first-pass failed test whose own terminal event in its unit's complete repeat report is `pass` is a flake: it is left out of the tests handed to `recordMainFailures` and the incident recorder, and it is recorded through `RecordFlake` (`report.go:131-134`).
