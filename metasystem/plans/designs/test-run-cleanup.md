# Automatic test-run cleanup

- Kind: design
- Id: 01M3BPVZBZEAHF3KR7QC7B20ZG
- Status: draft

Revision 3 on Main 32d1b143d, source read only, folding the six accepted final-review findings (R2-D2-1, R2-D3-1, R2-D5-1, R2-D6-1, R2-D6-2, R2-D7-1) into revision 2 (D1–D8). None is accepted risk. This page is the build contract: code proves every obligation through §5 under independent code critique. The queued janitor goal is context; no goal record is claimed.

**The consequential decision:** one `test run` invocation owns exactly one scratch root inside the control root's scratch store. It is recorded before it receives bytes, every runner-managed disposable byte lands inside it, one inherited writer lock plus the existing custodian and attempt records name every writer, the launcher removes the root only after proving its children drained, and a crashed run's root is recovered only after every recorded writer is proven dead and the lock is taken exclusively.

## 1. Classification

Retained: attempt records and `proof-runs/<attempt>/testing/<plan-digest>/`; bounded `suite-failures` bundles; inherited `GOMODCACHE`, `GOPATH`, user `GOCACHE`, user HOME, any checkout the runner did not create; legacy `candidate-engines/<identity>/` entries, never evicted. Retained, bounded here: `candidate-engines/v2/<identity>/`.

Disposable, all inside the run root: candidate build worktree, engine copy and publication stage; group worktrees, temp, home and XDG trees; run-private compiler caches and Go env snapshots.

Bound: a value a group declares explicitly (its own `HOME`, say) is honoured literally and lies outside cleanup; no filesystem sandbox is promised beyond launcher-generated paths.

## 2. Machinery

**Run root and record** (`internal/proofrun/scratch.go`, new). Root `<control>/artifacts/agents/proof-runs/scratch/<run-ulid>/`; record `<control>/artifacts/agents/proof-runs/scratch/<run-ulid>.json`. The store sits beside `candidate-engines` (`cmd/metasystem/test.go:1177`), so publication is a same-store rename (R2-D6-1), and lies under gitignored `artifacts/`. Runner-owned candidate materialization, compiler indexes and test environments use this root. Existing test fixture socket registries retain their separately authenticated short temporary namespaces. Creation order: write record; `Mkdir` root 0700; open `<root>/.writer-lock` (0600) and `flock(LOCK_EX|LOCK_NB)`; write marker `<root>/.metasystem-scratch` naming run and root; write a stub `go.mod` (`module metasystem.scratch`) so neither the outer module's `./...` nor a Go command run inside scratch reaches the outer module; create `engine/`, `groups/`, `gocache/`, `staticcheck/`, `goenv/`, `freeze/`, `no-hooks/`. Record fields: `schema`, `run`, `root`, `launcher` (`identity.EncodeRef`), `attempt` once admitted, `custodians` appended before each workload starts, `worktrees` tuples. Rewrites use unique temporary files, sync and atomic rename under a cross-process `<run>.record-lock`, with reload before each mutation. The process mutex protects each handle; there is no per-directory ledger.

**Writer lock (R2-D3-1).** The lock belongs to the open file description, so it lives while any process holds a descriptor to it. The launcher passes the `*os.File` after existing host descriptors in `ExtraFiles` to every root-writing child: Git children through a new `RawRequest.InheritFiles []*os.File` that `runRaw` (`internal/gittree/gittree.go:176-195`, the only native Git site) copies to `cmd.ExtraFiles`; the compiler and every suite command through the `exec.Cmd` handed to `RunResourceCommand` (`internal/proofrun/resource_custody.go:677`), with `startResourceCommand` preserving `ExtraFiles`. The custodian retains the writer descriptor until it has drained the workload, including a workload that closes its inherited copy. Go clears close-on-exec on `ExtraFiles` and Git keeps inherited descriptors, so Git's internal subcommands hold the lock too. Materialization Git children run with `-c core.hooksPath=<root>/no-hooks` (empty), since a repository hook is the one child that could daemonise and drop the descriptor. `flock` needs a local control root, as the identity lock already assumes.

Normal removal proves drainage: after custodians report clean and the last Git child was waited, the launcher closes its descriptor without `LOCK_UN` (an unlock would also release every inheritor), reopens the file and takes `LOCK_EX|LOCK_NB`. Failure means a child still holds it: stderr reports `cleanup.incomplete`, the record stays, and exit is nonzero. The result schema is unchanged. Success is followed by the revision-2 preconditions (`EvalSymlinks(root)` equals the record, `Lstat` is a directory, marker decodes to the same run and path), `RemoveAll(root)`, record deletion. Cancellation through `CancelStopProof` takes the same path once `RunResourceCommand` has waited for its custodian.

**Recovery predicate (R2-D2-1).** `ReconcileAttempts` (`internal/proofrun/reconcile.go:57-98`) gains a scratch phase after its attempt loop that reads `scratch/*.json`, skipping the calling run's own record; `test run` calls the scratch reconciliation phase once at start, before admission. The existing standing reaper calls `ReconcileAttempts`, so it also retries cleanup without another test invocation. A new `scratchWritersDead(record)` is written apart from `allRecordedEnded` (`reconcile.go:239-249`), which skips `StatusDone` and checks neither launcher refs nor groups. Any read failure or `Unknown` yields pending. It requires:
- launcher ref `Dead`;
- if `attempt` is recorded: every process record for that attempt, including `StatusDone`, has suite, watchdog and launcher refs `Dead` and its suite pgid empty (`GroupMembers`, `reconcile.go:185-206`); a missing process record set is pending;
- for every recorded custodian: ref `Dead` and pgid empty;
- then the writer lock: open `<root>/.writer-lock`, `LOCK_EX|LOCK_NB`; `EWOULDBLOCK` is pending with reason `writer-lock-held`; lock file absent with marker present is refused (creation order puts the lock before the marker).

Holding the lock, recovery removes recorded worktrees, then `RemoveAll(root)`, then the record. Root absent: delete record. Root without marker: remove only an empty directory at the exact recorded path, else refuse (D8). Each root reports removed, refused or pending with a reason. No prefix sweep, no `worktree prune`.

**Recorded worktree tuples (R2-D7-1).** `gittree.PlanDetachedWorktreeIn(parent, control)` allocates the ULID parent and derives `Top`, `Control` and `Common` (`git rev-parse --git-common-dir`, absolute) without touching Git state. The launcher appends `{group, parent, top, control, common, state: reserved}` to the durable record under its cross-process lock and only then calls `plan.Create(...)`, which runs `worktree add` and `read-tree` as `NewDetachedWorktreeIn` does (`internal/gittree/detached.go:104-157`). `DetachedWorktree.Close` (`:394-418`) flips the tuple to `closed` after removal. `request.candidateWorkspace()` (`internal/proofrun/test_build.go:1668`) and the candidate build's `io.open` go through the plan. Recovery removes only recorded tuples via `gittree.RemoveRecordedWorktree(tuple)`, which takes the admin lock (`detached.go:313-330`) and classifies with the reciprocal checks of `RegisteredDetachedWorktreeOf` (`:27-86`, HEAD omitted) against the exact entry `<common>/worktrees/<basename(top)>`: links intact, `worktree remove --force --force` then `RemoveAll(parent)`; `top/.git` absent and no entry, `RemoveAll(parent)`; entry present whose `gitdir` is absent or names the recorded top (interrupted add), remove that entry then the parent; `top/.git` or the entry naming any other path, refuse and retain. Unreadable tuples are pending.

**Compiler caches (D1).** Unchanged: `GOCACHE=<root>/gocache` and `STATICCHECK_CACHE=<root>/staticcheck` on every group environment and on `candidateEngineBuildEnvironment`, shared within the run; `digestEnvironment` (`test_build.go:2771`) already excludes both, so proof identity holds; cross-run compilation is cold, disclosed. Effective `GOMODCACHE` and `GOPATH` retain their pre-managed dependency locations, including Go defaults derived from the effective group home and configuration. The candidate build already runs `GOENV=off` (`test.go:1131`), untouched below.

**Managed homes for every adapter (R2-D5-1).** `groupTestEnvironment` (`test_build.go:2684`) overlays, for every group including `go`: `HOME=<root>/groups/<g>/home`, the five `XDG_*` variables beneath it, `TMPDIR`, `TMP`, `TEMP` and `GOTMPDIR` at `<root>/groups/<g>/tmp`, and `GOENV=<root>/goenv/env`. Before metadata preparation, the launcher snapshots effective Go configuration once and carries the immutable descriptor through admission and the authenticated worker. Group overrides determine their pre-managed default config and dependency paths; unset or empty `GOENV` means the Go platform default, and `off` disables config. Owned snapshots are read without following symlinks and validated rather than recreated. Their SHA-256 digests bind content without placing configuration values in logs or reports. Identity: a launcher-generated value digests as the token `managed:<NAME>:v1` in `digestEnvironment` and explicit-mode `digestGroupEnvironment`; `GOENV` also contributes `goenv-sha256=<hex>`, so a changed toolchain configuration changes identity and a relocated root does not. A group-declared value wins over the overlay and digests literally. Changing the managed layout bumps `v1`.

**Failure evidence (D4).** As revision 2: `PreserveDetachedSuiteFailures` (`internal/proofrun/evidence.go:89-151`) returns `Dropped` in `EvidenceResult` and the note, not as an error; the walk skips `.git`, symlinks and files over 1 MiB; default `EvidenceMaxBytes` (`test_build.go:1672`) is 16 MiB; the group closer (`test_build.go:1668-1690`) always calls `detached.Close()` and joins errors; `invalid` only on an IO or close error; shell beds that `mv "$tmp"` need no edit.

**Candidate engine cache v2 (R2-D6-1, R2-D6-2).** `prepareCandidateEngine` (`test.go:1171-1254`) targets the namespace `candidate-engines/v2/<identity>/` with the same `record.json` and `.lock` layout. Legacy `candidate-engines/<identity>/` entries are neither read nor evicted; no owner can prove pre-revision consumers ended (§4). Cold build: compile into `<root>/engine/build/`, validate, `os.Rename(<root>/engine/stage-<ulid>, v2/<identity>)` under the identity lock, same-filesystem because both sit under `artifacts/agents`. On `EXDEV` the run continues on its private copy and reports `engine.unpublished`; no stage outside the root is ever created. Warm or cold, the runner copies the validated executable to `<root>/engine/metasystem`, revalidates the copy's digest against `record.json`, returns that path, touches the entry's `record.json` mtime, and evicts v2 entries beyond the newest 8 by mtime, excluding its own identity, each only after `LOCK_EX|LOCK_NB` on its `.lock` succeeds. Lock files are never removed. The compiler runs under the existing custodian (`buildCandidateEngine`, `test.go:1329-1333`); `runResourceCommand` (`resource_custody.go:693`) gains `started(custodian identity.Ref)` on `resourceCommandEvents` and the launcher records that ref before the compiler can write bytes.

**Freeze.** The `test run` path does not call the gate's frozen-export functions. Their existing lifecycle is unchanged; no unused cleanup integration is introduced.

**Testenv sidecars.** The registry cleanup owner authenticates the exact home and takes its exclusive owner lock. Its custodian log has an inherited lock; cleanup waits for that lock and for the custodian to remove settled records. Remaining records or unknown ownership stay pending. Under the log lock, cleanup reads its final size and emits at most its last 64 KiB before removing exact sidecars. A later registry pass retries; age alone never authorizes removal.

## 3. Lifecycle ordering

1. Record; root; writer lock; marker; stub `go.mod`; subdirectories.
2. Candidate worktree tuple reserved, then created with the lock inherited and hooks off.
3. Candidate build: identity lock, lease, custodian `started` ref recorded, compile with the lock inherited, copy out, same-store publish, v2 eviction.
4. Admission; attempt ID recorded; carry the environment snapshot already prepared before metadata, without replacing it.
5. Per group: tuple reserved, created, run under custodian with the lock inherited; on return bounded preservation, `Close`, tuple `closed`, errors joined.
6. Terminal commit; custodians drained; launcher re-takes the lock; preconditions; root removed; record deleted.
7. Recovery: refs and groups dead, lock taken, recorded worktrees, root, record; anything Unknown reported and left.

## 4. Deferred

Legacy `candidate-engines/<identity>/` retirement (needs proof that pre-revision consumers ended); size-aware trimming; a shared cross-run compiler cache; machine-wide temp inventory; per-application cleanup catalogues; goal record edits; the custodian quiet-log protocol.

## 5. Acceptance

Focused Go tests, `t.TempDir()`, synthetic fixtures; readiness from pipes and `wait_for_exact_death`, never sleeps.

- A1 (D1): two synthetic groups share one `GOCACHE`; a second identical run reports `reused` after the root is gone; inherited `GOCACHE` untouched.
- A2 (D2, R2-D2-1): a `StatusDone` process record with one live suite-pgid member, an `Unknown` prober, and a missing process record each stay pending; all `Dead` with the lock free removes.
- A3 (D3, R2-D3-1): launcher `Dead` but custodian alive refuses; custodian `Dead` with empty group removes. Killed parent, live Git child: a fake `git` on `PATH` signals readiness on a pipe and blocks holding descriptor 3; the launcher is SIGKILLed after recording; one reconcile pass reports `writer-lock-held`; a later pass after the child exits removes the root. Normal path: a child outliving the run yields `cleanup.incomplete` and a retained record.
- A4 (D4): a failing group with a `.log` and a 20 MiB blob yields the log, a truncation note, no blob, a removed worktree, a non-invalid status; an IO error turns it invalid and still calls `Close`.
- A5 (D5, R2-D5-1): a generic group and an arbitrary Go package test each write under `HOME`, an XDG cache dir and `TMPDIR`; all land under the root; the digest equals a second run's on a different root; a changed inherited Go env file changes the digest; a declared explicit `HOME` digests literally and is not removed; no env content appears in output.
- A6 (D6, R2-D6-1, R2-D6-2): nine identities publish to v2; the oldest is evicted, a locked one skipped, a running consumer keeps its copied engine; a legacy `candidate-engines/<identity>/` sentinel is untouched; an injected `EXDEV` rename leaves a completed run with `engine.unpublished` and no stage outside the root.
- A7 (D7, R2-D7-1): reciprocal, unregistered, interrupted-add and foreign-`.git` recorded tuples produce remove, remove, remove-entry-then-parent, refuse; an add killed after the admin entry exists but before the caller receives the worktree is recovered only through its recorded tuple; an unrecorded sibling entry is untouched.
- A8 (D8): absent root deletes the record; empty unmarked root removes; nonempty unmarked refuses; symlinked root refuses; marker without lock file refuses.

End-to-end (one small real `test run`): after success and after `CancelStopProof`: no scratch records, none of the run's worktrees in `git worktree list`, root gone and retained evidence valid. A killed worker may leave no result document: cancellation then requires the durable cancelled terminal and no delivery receipt; any result present must identify the same cancelled attempt and be insufficient for delivery. Kill path: the public launcher is killed after workload readiness while a live peer and foreign sentinels remain. Recovery must retain the live child's files; after the child ends, `ReconcileAttempts` removes the drained run and preserves the peer, its record lock, the foreign symlink and unrecorded same-prefix directory.

## 6. Implementation units

Disjoint: U1 root, record, writer lock, recovery predicate and phase (A2, A3 lock cases, A8); U2 `gittree` plan and tuple API, `InheritFiles`, hooks-off materialization, `RemoveRecordedWorktree` (A7); U3 engine v2 namespace, custodian `started` ref, copy-out, same-store publish, eviction (A3 custodian cases, A6); U4 group environment, Go env snapshot, digest tokens and caches (A1, A5); U5 evidence truncation and always-Close (A4); U6 testenv sidecars. U1 lands first; the others depend only on its record type and lock handle. Every unit ships its fixtures and receives independent code critique against this page.

## Built and remaining limits

The first slice owns runner-generated scratch and bounded engine cache entries, uses existing process custody and reaper scheduling, and preserves retained proof. It does not scan arbitrary application writes or historical caches. Ownership, missing process records or process liveness that cannot be proven remain visible and pending; deletion is never based on elapsed time alone. In particular, an interrupted admission with no process record cannot currently be reclaimed automatically. That startup shape remains for later recovery refinement rather than guessing that no child exists.

The existing periodic reaper becomes active for this change only after the landed engine is installed and rearmed. Runtime acceptance includes public success/reuse/verify, failure, cancellation and surviving-child recovery, plus native Linux checks of the changed descriptor, filesystem and process behavior.

Worker compatibility uses the existing capability handshake: protocol 2 identifies the optional scratch request fields, so a new frontend refuses a strict protocol-1 worker before preparation. The release is validated with the existing trusted frontend and worker against the new candidate, then installed and rearmed together. A small installed-engine run checks the activated cleanup path; no worker authority is transferred to an untrusted candidate.
