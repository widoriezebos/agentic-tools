## What it delivers

A registered host has one current mark per provider. The existing failure/success paths feed it, the registered steward probes at reset or every two minutes when reset is unknown or distant, provider-dependent clocks stop spending during the evidenced wait, and stale marks clear with an alert. Every seat emits a completed-unit boundary; headless seats also hand off and end; abnormal restarts are bounded. Build starts use current load and the host's declared policy. The old suite-ratio feedback rule, new full-suite lease and comparison consumer are removed.

**Step 1 is P1:** `machine list` exposes fresh load, cores, registered owner and active builds, including unknown coverage. It is useful on its own. Its provider section becomes populated by P2; it must say unavailable before then. P2 supplies the shared condition, P3 its clock consumers, P4 the minimal boundary, and P5 restart/build limits. No new scheduler, account service, model roster, periodic sampler or context ceiling is part of these units. The threat model is ordinary concurrent work, crashes, stale state and mistakes by trusted agents/operators.

### P2 — One provider mark in the registered owner's state

Extend the existing `internal/outage` owner, retaining its bounded lock and atomic writer (`internal/outage/outage.go:57`, `:65`, `:165`), to keep one provider-keyed current mark and closed wait intervals under the registered owner's state, fenced by P1's registration; identity comes from the actual runtime adapter, never from the checkout name. Keep source execution, observation time, reset time and last probe, with a success watermark so replayed/older failures cannot resurrect a cleared mark; a success closes only its provider's interval. Move the production writers/readers together: `internal/steward/seat_start.go:300`, `:663`, `internal/missionrunner/loop.go:2104`, `:2163`, `:2196`, `internal/steward/runner.go:497`, `internal/steward/revive.go:169`, plus delegate results at `internal/adapter/adjudicate.go:135`–`:191`, the landing-agent result writer `cmd/metasystem/landing_agent.go:183` (`outage.Record`) and its start-hold reader at `:307` (`outage.StandingAt`); readers routed through `standingProviderOutage` inherit the provider selection. Only the registered steward uses the existing probe path (`runner.go:454`, `:497`): probe at an observed reset within `outage.Horizon`; when reset is unknown or more than that 30-minute horizon ahead, keep probing every two minutes rather than waiting for reset, and retain the two-minute retry cadence after a failed probe. Record each probe, but only genuine provider evidence refreshes the observation; never parse an old reset line against today's date. First success clears immediately; a failed reset probe leaves the mark for P3's bounded stale expiry. Missing reset uses the existing outage horizon, with unknown reset shown. Old per-checkout hints without provider identity are reported as legacy unknown and do not become fresh shared evidence. Name the person's recovery act as the proposed `metasystem machine clear-provider PROVIDER`, owned by the existing machine command and P2's outage owner: after the existing person-actor check, atomically close only that provider's interval at the act's time and retain a clear watermark so older results cannot restore it. Explain and record that this removes an advisory hold, not that the provider answered; no outage, reset or load hold may refuse this act, and an already absent mark is a successful no-op. A mark never pauses or refuses any explicit person's act, including start; only automatic acts wait. Unreadable ownership/state is explicit unknown and cannot silently prove recovery; a failed clear reports its actual persistence error without claiming success. This unit adds no new recovery authorization or account-usage mechanism. Estimate: 250 production lines including landing callers, the person remedy and P1 provider rendering.

### P3 — Dependent clocks pause and stale marks clear visibly

Use P2's provider intervals in the sole budget projection at `internal/dispatch/budget.go:271`, its consumption entry at `:277` and wait projection at `:867`, and in the steward's age/decision sample at `internal/steward/tick.go:515`: subtract only the union of evidenced waiting intervals intersecting that clock's lifetime and provider dependency, unioned with existing excluded waits, so overlap is never subtracted twice and unrelated local work, another provider's execution and actual billable job minutes remain charged. Provider identity/dependency comes from the retained launch/step; missing dependency is unknown rather than a guessed pause. Progress still resets the steward's age while a mark stands. Extend the same outage owner with expiry at reset plus one existing probe interval (two minutes, the draft grace chosen from `runner.go:454`), or the existing 30-minute `outage.Horizon` from the last genuine observation when no reset exists; expiry closes the interval at that bound, clears the current mark and retains a once-per-mark stale alert for the registered steward to deliver through its existing notification owner. A late tick never charges or pauses past the bound, and a replay does not duplicate the alert; stale expiry is not evidence of provider success. Expiry does not replace P2's two-minute probes for unknown resets or resets beyond `outage.Horizon`; a scheduled probe alone never extends an interval. The person's clear closes only the chosen interval at the clear time, and a mark never pauses a person's act. Preserve unknown accounting on corrupt history, with the source error visible and the existing explicit person remedy available. No clock store, budget derivation, outage retry round or unrecovered-seat ask is added. Estimate: 200 production lines.

### P4 — Minimal completed-unit event and existing session handoff

Have the steward retain a minimal boundary identity `(seat, session, goal, unit, completed outcome)` beside its existing handoff state for every seat, including `seat.driver=person`, reading real unit/step outcomes (`internal/launch/read_sequence.go:37`) and existing open-work checks before emission: running or starting work, pending proof, undecided read, revision, ask or capacity-held step means no completed boundary. Only a headless seat binds that event to a handoff: its generated session instruction (`internal/steward/seat_start.go:517`, `seatBrief`) tells it to stop advancing at the completed boundary, capture `session handoff` with its configured note and no-delegates declaration, then end its turn once the binding is durable. Reuse the existing verb (`cmd/metasystem/context_verbs.go:217`, `:347`, calling `internal/steward/handoff_capture.go:1063`; `:75` parses status). The steward's handoff owner persists the event-to-nonce binding and, once it is durable, revalidates the recorded predecessor identity and sends SIGTERM to that headless predecessor through the existing process signalling path; normal turn exit may have ended it already. Unknown identity or a signal failure is visible and holds replacement; never signal a reused process id. Re-entry reuses the boundary, capture and binding, including a capture persisted before binding, rather than creating another event or successor. Failed capture/binding leaves the session alive with the exact error and no signal. The existing predecessor check (`internal/steward/handoff.go:65`) admits the successor only after the exact predecessor is observed dead. A person's session emits the same boundary for goal 4 but gets no automatic handoff binding, stop instruction or signal; its own explicit handoff remains available. This unit creates no next-step queue, driver, generic consumer-acknowledgement bus, settings activation or engine-rearm mechanism. Preserve the shared mechanism's ordering contract for those future consumers: handoff/end when headless, settings, engine, budget admission, driver. Estimate: 250 production lines including the instruction, boundary emission and steward signalling.

### P5 — Bounded abnormal revival and current-load build admission

In `internal/steward/revive.go:109`, `:169` and `:218`, extend existing arbitration/evidence so a stable seat retains at most two automatic abnormal restart attempts per rolling hour, stopping earlier on the same death class twice or no retained work progress after revival; count before irreversible launch, preserve history across steward re-arm, and use existing stop/ask and explicit person start/resume owners. Provider-limit holds from P2 and planned P4 handoffs consume no abnormal attempt; unknown launch outcome cannot create another allowance. This is about 110 lines. In about 140 further lines add `host.builds=auto|N|person` and positive declared `host.load-max` through the existing configuration/policy owners (`internal/config/policy.go:59`, `internal/config/defaults.go:66`), checked in `Manager.Start` (`internal/launch/launch.go:105`, `:238`) immediately before creating the Starting reservation, only when `StartSpec.Kind == "build"`; reads, design launches and the landing agent through the same manager never encounter the load/cap check. Add `StartSpec.Actor` (`launch.go:50`) for the validated actor of this exact invocation: `work build` fills it after its existing actor check and carries it through its invocation-local `UnitRunner` to each build start (`cmd/metasystem/intent_work.go:438`, `internal/launch/unit_run.go:253`, `:392`). It is not a persisted person grant: a later automatic continuation supplies its own actor, and an absent actor gives no person bypass. Auto admits when current one-minute load is below the declared maximum; N also caps distinct active build goals, counting an unassigned build as its own identity and including Starting reservations. Read/count/create share a host admission lock; the current store's per-launch lock (`internal/launch/record.go:159`) alone is insufficient. Person policy requires the existing proof of an explicit person's exact act; that act bypasses advisory load/cap holds without changing settings or fabricating authority from flags. An absent/invalid load declaration or unknown host state returns an explained capacity admission result to agents before supervisor start, with the original command as the person's remedy; no core-count default or suite ratio is invented. Keep that result distinct from an executed failure, with no correction round spent; `read_sequence.go:37` already retains a starting step with no launch when start returns an error. Its durable queue, retry and recovery belong to goal 4. Running work is unchanged by later policy/load samples. Total: 250 production lines including actor propagation.
