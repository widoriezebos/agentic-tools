## Problem (measured, lane test findings 46-91)

Nine integration reds and four interventions on 2026-10-10 sat on the boundary between the units' synthetic beds and the real system: the real contract's canary groups, the real ledger shapes, two installs with their own config and artifacts, real git state (a pending merge under a redeploy). The unit tests and the Opus reads were green; the live lane found each defect on its first run. The lane's own end-to-end tests (landing_pipeline_test.go, landing_batch_test.go) use real git but substitute the proof command, the impact plan and the builder, so they cannot see the real contract, the real proof runner or the real adapters.

## Decisions

D1. **A rehearsal is the real engine on a real clone, and the engine IS the candidate.** `metasystem landing rehearse` builds the engine from the pinned candidate snapshot itself (a `git archive` of the candidate commit, never the working tree, never a supplied binary), stamps it with that commit, and refuses to issue a pass when the engine's build identity differs from the candidate commit recorded (critique round 3 F1: a pass must never certify a tree with another engine; `--engine PATH` is deferred and, when it comes, must carry a matching build identity). It creates a scratch bare origin and a scratch clone of THIS repository at the candidate commit (so the real testing.json, canaries, skills, audits and adapters are in play), registers a scratch lane install on it under an ISOLATED supervision registry (`METASYSTEM_SUPERVISION_REGISTRY_HOME` set to a scratch directory for the rehearsal and every child it starts, so `landing set` touches no host registration or hook, lane.go ~290) with the lane's deploy-after-push disabled by a scratch setting (intent_landing_push.go ~233 starts a detached deploy: the rehearsal suppresses it and waits for every child it started before cleanup; machine nickname `rehearsal`), and generates the fixture goal set into the scratch ledger: a green goal, a red goal (one failing test in its own package), a conflict pair (two goals changing the same line), a goal held by a pause. The fixtures live in the repository as templates (plans/rehearsal/*) and are regenerated per rehearsal, never reused (the original lane-check goals decayed to done/abandoned and could not be reused).

D2. **The driver is the skill as a program.** The rehearsal drives the lane's verbs exactly as skills/landing-agent/SKILL.md tells the agent: hand the fixtures in with `work land`, select, merge, `landing prove --gate`, `landing prove`, `landing push`, `landing return`, `landing resolve --as-seat` with a scripted resolution (the resolution job is the fixture builder that applies the known resolution and runs `test impact --check`), the pause and resume. It asserts the outcomes the skill promises: the green goal lands on the scratch origin with one proof at the decided depth; the red goal returns with cause own and the lane stays green; the conflict pair resolves and lands with a lane-merge commit, the merge read checkout being the merge commit; the paused lane admits nothing; the collection reuses the job's check; the gate is skipped when the change is not cheap; status lines read as designed. The agent's judgement is not rehearsed (that is the skill's own test); the engine beneath it is.

D3. **Cost is bounded by a scratch proof contract, committed first.** `proof.full` and `proof.cheap` are committed-only declarations read from the commit under proof (intent_landing_prove.go ~50, `git show COMMIT:metasystem.conf`), so the rehearsal COMMITS its overrides onto the scratch main and PUSHES `candidate + harness commit` to the scratch origin before anything else (`landing prove --trunk` fetches and proves origin/main and reads the declarations from that commit, intent_landing_prove.go ~246/~50; critique round 4): the scratch base is that pushed commit, the candidate commit's identity is recorded separately as the engine under test. It then runs one bootstrap trunk proof of the scratch origin's main and asserts that the bootstrap's commit and later the batch base equal the pushed harness commit; so the lane's full-proof clock is paid (a fresh lane declares `full-due`, wake.go ~99, and `proofScope` returns full before the cheapness policy, proof_admission.go ~115); only after that does the green scenario exercise the decided depth. The scratch clone's `metasystem.conf` overrides `proof.full` and `proof.cheap` with the repository's fast-static-build group plus the fixture goals' own packages (the contract's groups and canaries stay as they are, so the cheapness measure, the audits and the layering rules see the real shapes); a rehearsal runs in minutes. The rehearsal never pushes to the real origin, never touches the real lane install, and removes its scratch on success (kept on failure, path printed).

D4. **The rehearsal is the gate.** A change that touches the lane (skills/landing-agent/, internal/landing/, cmd/metasystem/landing_*.go, cmd/metasystem/intent_landing*.go, cmd/metasystem/test_impact.go, internal/repoproof/, internal/proofrun/, the landing-agent skill tests) lands only with a fresh rehearsal pass recorded for its tree hash in records/rehearsals/<tree>.json (candidate engine commit, scenarios, durations, outcome). `work land` on such a change and the hand push both refuse without it (code LANE_REHEARSAL_MISSING, remedy `metasystem landing rehearse`); the lane's own proof of a batch containing such a change runs the rehearsal as its first group. A person may run the rehearsal from any checkout; the record is a ledger record, not an install artifact.

D5. **A rehearsal red is a unit red.** The rehearsal's failure names the scenario, the verb and the status text that differed, so the unit's correction brief can quote it; a rehearsal that cannot set itself up (scratch, engine build) is an environment red, retried once.

## Threats and nets

- A pass certifies a tree with a different engine: the engine is built from the candidate snapshot and its build identity is checked against the record before a pass is issued (D1).
- The rehearsal passes but the live lane differs (roster, enrollment, two installs): D1 registers a real scratch lane with its own install and conf.local layer written from the seat's roster, so the roster path is exercised; enrollment is exercised by the driver acting as the person through the real verbs; what remains different is named in the record.
- The scratch proof contract hides a real proof red: the rehearsal is a gate for lane mechanics, not a proof of the change; the batch proof still runs in full in the lane.
- Cost creep: the rehearsal is bounded to the fixture set and the scratch contract; a scenario over 10 minutes is a finding.

## Step 1: the smallest thing that works first

`metasystem landing rehearse` with ONE scenario, the green goal (tier 1, so the decided depth is impact; the scenario asserts depth `impact`, the recorded reason, and that no full proof ran for the batch): the scratch origin and clone of this repository at the candidate commit, the scratch lane install with the seat's roster and the scratch proof contract, one generated green fixture goal (a one-line change with its own test), the driver running hand-in, selection, merge, gate, proof at the decided depth and push to the scratch origin, asserting the status lines and the decided depth, and the rehearsal record in records/rehearsals/<tree>.json. This alone catches the class of defect the day found most (a measure or policy that misreads the real contract: canaries, cheapness, depth), because the green goal must land at the decided depth within the scratch contract's minutes, and it runs on the real testing.json, real skills and real adapters. Acceptance of step 1: on main today it passes in under 10 minutes including the bootstrap trunk proof; with the cheapness measure deliberately counting the canaries, it fails naming the decided depth.

Deferred to later units, in this order: the red goal's return (U3 second half), the pause (U3), the conflict pair with the scripted resolution and check reuse (U4), the admission refusal LANE_REHEARSAL_MISSING at work land and the hand push and the lane proof running the rehearsal first (U5). Until U5 lands, the rehearsal is run by hand before every lane change (the steward's rule of 2026-10-10 23:35) and its record is the evidence.

## Acceptance

The next lane change lands only after `landing rehearse` passed on its tree; a rehearsal of main today takes under 10 minutes and passes; a deliberate break of the cheapness measure (count canaries) fails the rehearsal's green scenario before it reaches the live lane. Stop rule for the design: Astra critique to material zero, at most three rounds; one unit at a time, Opus read each, each unit rehearsed before landing once U1-U4 exist.
