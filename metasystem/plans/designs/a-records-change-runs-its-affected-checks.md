## Problem

The steward's `unproven-incidents` row fires when main moved by commit (`health.go:318, 336-337, 486-488`) with no `codeMoved` filter and calls `stewardTrunk` (`steward.go:115, 166-170`): the path of finding 320. `RecoverMovedMain` (`trunk_recovery.go:67-74, 83-130`) does filter records-only moves. Two classifiers disagree about what a record is: `ledgerPath` (`main_move.go:10-13`, goals and records ledgers only) treats a design page as code, `recordsOnlyPaths` (`scope.go:200-220`, pathclass Record/Ledger) may not. The checks that declare `metasystem/plans/**` as inputs are `fast-static-build` (`testing.json:47`: `go run ./cmd/devgate static`, phase admission), `shipped-installation-standard`, `agent-protocol-standard` and `batch-buildcd-standard`. ## Decisions

D1. A changed-main check of a move that changes only records runs the checks whose declared inputs changed and inherits the rest from a qualifying full green. The trunk subject is `origin/main` itself (`prove.go:457-466`), so `decideScope`'s batch logic cannot serve it as it stands (it returns full when `rev-list running.Commit ^origin/main` is empty, `scope.go:57-59`, and its records fallback compares against the same tree, `scope.go:74-76`): for a changed-main check the baseline is a qualifying full-green ancestor of the pinned main commit, selected without the batch-membership prerequisite; that proof's tree is compared with the target tree; the affected groups come from `testpolicy.Affected` over the paths between them; the decision is pinned through admission and execution; the fallback stays full when no fresh baseline exists, when a later applicable red remains unresolved for any group that would be inherited (the selector skips non-green results, `scope.go:80`: an older full green must not conceal a newer red in an unrelated package; Astra RS8), when facts are unreadable, when a code path, the testing contract or the environment changed, or when an input is uncovered. The scope decision is pinned so that execution (`Run`, detached) does not overwrite it with the trunk default. The cadence proof (`keeper_clock.go:184-187` sets `Trunk` like the steward does) and an explicitly fresh request carry a full-depth marker and stay full. The scope reason names what changed ("records changed: 2 design pages; 4 checks run; the rest holds from the 02:50 full check" — the count describes the executed checks: the affected selection plus its existing prerequisite closure (`RunNamedGroups` expands prerequisites, `internal/proofrun/groups.go:42`; `fast-static-build` requires `refusal-register-standard`); an ordinary design page selects fast-static-build, shipped-installation-standard and agent-protocol-standard (`testing.json:47, 100, 102`) and executes four) (Astra RS2, RS11, R3-3).

D1a. Credit (amends lane-clock-prefers-work D1a, which credits any trunk result): `fullProofClock` advances only on a full-scope trunk result that satisfies the execution predicate of lane-proof-finds-its-own-engine — a green that ran, or a red with `CountedFull` (full scope alone does not establish execution: a worktree can fail to be created before any check starts, `prove.go:1321`) — and on qualifying full-proof pushes; scoped results and non-runs never advance the four-hour clock (RS3, RS10) (`wake.go:123-128` examines no scope today; the full-scope restriction at `:142-145` applies only to pushes) (RS3). The hourly debt applies to a scoped trunk result even when no lane push record exists (`scopedProofDue` starts from `LastPush`, `wake.go:153-165`: a hand records push followed by a scoped trunk check leaves none), and every inherited result preserves the ORIGINAL full execution's tree and completion time — an inherited result's newer timestamp never renews the allowance (`inheritScope` keeps `Scope=="full"` with an older `FullAt`, `scope.go:421-426`; the records fallback overwrites `FullTree/FullAt` with the candidate's, `scope.go:82-91`) (RS4).

D2. At the keeper's main observation, main is refreshed through the existing bounded fetch independently of queued work and incidents (today `RecoverMovedMain` returns before fetching when the queue is empty, `trunk_recovery.go:79-91`, batch selection returns before fetching without a batch or queue, `batch.go:338-355`, and trunk admission reads the local `origin/main`, `prove.go:461`: a remote records push can stay unseen while the old local commit still holds applicable proof); a refresh failure stays visible and establishes no proof (Astra R3-1). The observation then requests the applicable check for the fetched commit whenever it lacks applicable proof — independently of open incidents and queued work (today both named paths depend on incidents: the health row is generated only inside its incident loop, `health.go:319`, and recovery returns without queued work or open incidents, `trunk_recovery.go:79`; the wake calculation has no independent changed-main reason) (RS9). A changed-main request stays pending while a candidate repair obligation owns its checkpoint (the protection of lane-clock-prefers-work D1a lives in `keeper_clock.go:110-124` and is absent from trunk `Start`: checkpoints count as not running, `prove.go:342-343`, trunk bypasses repair readiness, `fix.go:358-360`, and admission writes the replacement `running.json`, `prove.go:586`); it starts after that obligation settles, through the keeper's shared arbitration; observation, recovery and steward triggers never replace the checkpoint (R3-2). Every other trigger preserves eligible work and delegates depth to that same admission: the steward's `unproven-incidents` row (`health.go:318, 336-337, 486-488`) and `RecoverMovedMain` (`trunk_recovery.go:67-73, 102-110`, whose `codeMoved` filter returns without starting anything for a records-only move) start the check of D1 for a records-only move with open incidents or a moved main; the check is scoped when a fresh baseline exists and full when it does not (RS5). A records-only commit does not by itself require another FULL proof, but its changed inputs are checked, and the fallback, environment and hourly-debt requirements still apply (this sentence replaces one-person-one-truth U5's blanket exemption).

D3. One notion of a record for classification (pathclass, shared by `ledgerPath` at `main_move.go:10-13` and `recordsOnlyPaths` at `scope.go:200-220`; a design page is a record that IS an input to checks) — but classification never authorises reuse: inherited settlement (`prove.go:1070-1109` into `proof_admission.go:116-129`) and record folding (`main_move.go:115-141`, published by `push.go:183-219`) each run every group whose declared inputs changed before the resulting tree is recorded green; the in-flight result carry (`prove.go:1039-1046`) is removed rather than extended, and a changed folded tree is returned through proof admission instead of being checked inside the folding lock (`push.go:167`) (RS1; Astra round 2 note).

D4. Every controlled publisher of records validates the complete candidate commit, including its goal references, before each publication attempt and after every rebuild — at the transaction's own boundary (goal transactions build commits from an isolated index seeded from the fetched tip, `internal/goal/txn.go:344-408`, and already validate each rebuilt candidate at `:900-939`; the caller's checkout need not hold those bytes, so `project.Read` on the checkout can approve a different tree; `internal/project/goals.go:11` imports `goal`, so the checker is composed above `internal/goal` and invoked through the publication boundary) (RS6). Covered publishers: goal publication, the lane's own records commits, and the existing hand records route `work land G --records PATH...` (`cmd/metasystem/intent_delivery.go:165,187`; its project check at `intent_records.go:219-226` and publication at `:246-251`), which the hand route uses from now on instead of raw pushes; raw Git pushes stay outside this guarantee (enforcing them needs a separately agreed remote publication control) (RS7). A refused publication says why in intent words ("the design page X names goal Y, which is not in the ledger; the push waits").

D5. UX: the person reads "main moved by records only; 4 checks run (2 min), the rest holds from the 02:50 check" — no scope words, group ids or paths.

D6. **A completed red is standing evidence, kept apart from reusable green coverage.** Two things are determined separately at every changed-main admission (D2): the reusable green coverage (D1's baseline: a qualifying full-green ancestor; absent, no green coverage is inherited) and the standing failure evidence: a completed classified red, full or scoped, whose matching incidents remain open (the incident match is the existing identity-based one, `prove.go:1525-1539`; an incident closed by a person, `internal/goal/trunkred.go:1078`, no longer stands). Standing failure evidence suppresses automatic repetition of its unchanged failing inputs: a move whose changed inputs do not touch a standing red's failing groups does not execute those groups again; main stays red with the same incidents; the lack of a qualifying green baseline does not by itself authorise repeating those failures (today it does: the fallback is full).

- Required checks. A records-only move still runs every check its changed inputs affect (plans and ledgers are check inputs, `testing.json:47, 100, 102`; the goal's intent at `plans/goals/a-records-change-runs-its-affected-checks.md:8`) TOGETHER WITH the prerequisite closure of that selection (`internal/proofrun/groups.go:42` expands prerequisites, `:106-116` executes them before the dependent group; e.g. a design-page change selects `fast-static-build`, which requires `refusal-register-standard`, `testing.json:47`, whose own inputs exclude design pages, `:56`). A standing failing group inside that closure may repeat, with the reason "required prerequisite of an affected check"; suppression applies outside the closure. A passing affected check never erases an unrelated standing failure and never establishes coverage that was not executed; a failing affected check adds its own incident.
- Execution contract. The admission pins a partial-red plan and carries it through detached execution (`Run`): the suppressed groups are resolved from the source attempt's retained group evidence and the matching open incidents (failures are stored as units and tests, `prove.go:141-144`, and a group id can be replaced by its package identity, `cmd/metasystem/test.go:171-184`: the mapping from standing failures to concrete group ids is explicit and tested); the plan's execution identity is checked independently of any green baseline; unexecuted groups receive no green coverage and no full-execution credit (today `scope.go:254-269` labels unexecuted groups "kept" from a green source, and `prove.go:1383-1409` widens to full when the source environment is absent: missing green provenance alone never triggers environment invalidation under D6; a changed execution environment still does).
- Same code. The code is unchanged between two commits when their tree diff is empty or every changed path resolves to Record or Ledger through the shared pathclass classifier (`internal/pathclass`; `codeMoved` at `trunk_recovery.go:67-73` and the records fallback at `scope.go:200-220` already compute this and are reused, not duplicated); unchanged code does not establish unchanged check inputs, which D1's affected-group computation decides.
- Routes. The health row `unproven-incidents` (`health.go:318, 336-337`), moved-main recovery (`trunk_recovery.go:41-62`) and the steward's other routes into trunk admission (`steward.go:115-171`, stale questions and suspected contention) all go through this one admission and therefore never repeat a standing red on their own; the row's "prove main before asking anything" is satisfied for a commit whose code is unchanged against the incident's commit.
- Debt. An executed full trunk check that completes green or red with `CountedFull` discharges earlier scoped debt for the covered main history (today `wake.go:174-181` clears scoped debt only after a later full green, while `wake.go:97-99` returns that debt before the cadence clock: a debt-triggered full red would otherwise keep authorising the same red); inherited results and non-runs discharge nothing.

What still starts a proof of a tree whose red stands, each with its own reason, through the keeper's shared arbitration with the candidate-repair protection (`keeper_clock.go:110-124`), none of which this amendment weakens: the independent trunk clock when it is due (`keeper_clock.go:83-89, 184-187`); the hourly debt of a scoped result until a full check discharges it (`wake.go:95-102, 153-181`; D1a extends the debt to scoped trunk results); a proof invalidated by changed execution inputs or environment (`prove.go:1383-1409`, D1's environment fallback); a required prerequisite of an affected check (above); an explicitly fresh request from a person (`landing prove --trunk --fresh`, `intent_landing_prove.go:152-154, 219-220`); the automatic isolated flake confirmation (`replay.go:103-111, 136-148`) within its allowance; and the person-authorised classification continuation (`red.go:200`, exact-commit and one-use checks at `:212-227`). Inheritance of a standing red earns no credit (D1a: unrun and scoped results do not advance the clock).

D7. **An unattended trunk request is idempotent at admission.**

- Rule: when `Start` runs with `Trunk`, no `Person` and not `Fresh`, it re-evaluates applicable proof under the lane lock. If a completed result applies to the fetched commit, `Start` answers `already = true` with that result and starts nothing. An effect that already holds is success (R-129).
- Applicable means exactly the callers' predicate: `applicableMainProof(install, checkout, commit, tree, seams, true)`. A green of the same commit, or of the same tree with current full coverage (`trunk_recovery.go:147`; this includes a same-tree non-trunk batch green, `Trunk` false), or a standing classified red of that trunk commit (`:135`).
- Place: inside the lock, after `checkState` and the busy branch (`prove.go:510-530`), in the trunk block before the NoRepeat check (`:557`), so before `proofAdmission` (`:566`).
- Answer: a `Running` built from the result, as the non-trunk reuse does at `:548` (attempt, tree, commit, log, `Since` = result `at`, `Trunk` true), plus a new field `Reused *Result` tagged `json:"-"`, set only here, never in the running record. A joined live attempt has `Reused == nil`. `Start`'s signature stays.
- Reused mechanism and callers. Reused: `applicableMainProof` (`trunk_recovery.go:104-152`), the lane lock (`withLock`, `queue.go:125-135`) and the non-trunk reuse shape (`prove.go:548`). Callers of `Start`: `trunk_recovery.go:95`, `steward.go:229`, `keeper_clock.go:192`, `deploy.go:250`, `resume.go:209` (carries `Person`, so outside D7), `cmd/metasystem/intent_landing_prove.go:344, 365`.
- `stewardTrunk` returns `stewardAlreadyProven` only for reuse of a completed result (`already && running.Reused != nil`); joining a live attempt retains the running outcome, so `steward.go:173` keeps `proofRunning` true.
- The non-wait CLI (`cmd/metasystem/intent_landing_prove.go:344-353`) renders every `already` as "already proving … since …"; `Settled` returns false for unattended trunk (`prove.go:698`). U4 makes it report completed reuse (the retained result, its time, nothing started) apart from joining a live attempt.
- `Wait` stays unchanged: it finds the reused attempt's result (`wait.go:12-31`); the reused `Running` has no `Process`, so `alive` reads false (`prove.go:300-303`). But the wait CLI (`intent_landing_prove.go:365`, rendering `:396-418`) also consumes `running.Reused`. Today a reused non-trunk batch green renders "landing push may put it on main" (`:411`), though main already holds that tree. U4 reports completed reuse against the requested main commit and keeps the original result's provenance.
- Unchanged: a person's request and every fresh request admit as today. A person's non-fresh CLI request keeps its green settlement (`prove.go:713` → `intent_landing_prove.go:328`).
- D7 relies on the record order. Successful finalisation appends the result before removing the running record under the same lock (`prove.go:1050`, `:1053-1061`). `checkState` can remove a dead, non-checkpoint record with a matching result (`:391-393`): live records return first (`:353`) and checkpoints are retained (`:359`), so completed-red checkpoints stay protected.
