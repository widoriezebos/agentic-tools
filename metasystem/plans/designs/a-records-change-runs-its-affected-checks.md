# Design: a records change runs its affected checks

- Id: 01M4Z4RECORDSCHECK0000000A1
- Kind: design
- Status: accepted
- Goals: a-records-change-runs-its-affected-checks
- Evidence: lane test findings 320 (a records-only push started a full 233-unit proof 47 minutes after the clock proof), 321 (a design page's Goals line turned main red: records ARE inputs to fast-static-build; records pushes bypass the project check); the 24-hour analysis of 2026-10-15 (L2) and Astra's rounds on it (round 1 finding 2: "no code, no proof" would conceal the records defect that actually happened; the rule is reuse for unchanged inputs, affected checks for changed ones, every publisher validates).

## Problem

Every trunk proof is forced to full scope: `proofScope` returns `full`, "fresh full check of main", whenever the proof is a trunk proof (`internal/landing/plain/proof_admission.go:71-72`; set again at `prove.go:978-979`), before `decideScope` (`scope.go:51-197`) can narrow it; scoping exists only for batch proofs, where a records-only batch borrows main's newest full green under an hour old (`scope.go:72-98`) and `testpolicy.Affected` (`internal/testpolicy/affected.go:27`) maps changed paths to the groups that declare them as inputs. The steward's `unproven-incidents` row fires when main moved by commit (`health.go:318, 336-337, 486-488`) with no `codeMoved` filter and calls `stewardTrunk` (`steward.go:115, 166-170`): the path of finding 320. `RecoverMovedMain` (`trunk_recovery.go:67-74, 83-130`) does filter records-only moves. Two classifiers disagree about what a record is: `ledgerPath` (`main_move.go:10-13`, goals and records ledgers only) treats a design page as code, `recordsOnlyPaths` (`scope.go:200-220`, pathclass Record/Ledger) may not. The checks that declare `metasystem/plans/**` as inputs are `fast-static-build` (`testing.json:47`: `go run ./cmd/devgate static`, phase admission), `shipped-installation-standard`, `agent-protocol-standard` and `batch-buildcd-standard`. A design page committed by hand with a comma in its Goals line (2026-10-14 21:02) turned main red for five hours; nothing checked it before the push (finding 321); the project check lives in `internal/project/answers.go:198`.

## Decisions

D1. A changed-main check of a move that changes only records runs the checks whose declared inputs changed and inherits the rest from a qualifying full green. The trunk subject is `origin/main` itself (`prove.go:457-466`), so `decideScope`'s batch logic cannot serve it as it stands (it returns full when `rev-list running.Commit ^origin/main` is empty, `scope.go:57-59`, and its records fallback compares against the same tree, `scope.go:74-76`): for a changed-main check the baseline is a qualifying full-green ancestor of the pinned main commit, selected without the batch-membership prerequisite; that proof's tree is compared with the target tree; the affected groups come from `testpolicy.Affected` over the paths between them; the decision is pinned through admission and execution; the fallback stays full when no fresh baseline exists, when a later applicable red remains unresolved for any group that would be inherited (the selector skips non-green results, `scope.go:80`: an older full green must not conceal a newer red in an unrelated package; Astra RS8), when facts are unreadable, when a code path, the testing contract or the environment changed, or when an input is uncovered. The scope decision is pinned so that execution (`Run`, detached) does not overwrite it with the trunk default. The cadence proof (`keeper_clock.go:184-187` sets `Trunk` like the steward does) and an explicitly fresh request carry a full-depth marker and stay full. The scope reason names what changed ("records changed: 2 design pages; 4 checks run; the rest holds from the 02:50 full check" — the count describes the executed checks: the affected selection plus its existing prerequisite closure (`RunNamedGroups` expands prerequisites, `internal/proofrun/groups.go:42`; `fast-static-build` requires `refusal-register-standard`); an ordinary design page selects fast-static-build, shipped-installation-standard and agent-protocol-standard (`testing.json:47, 100, 102`) and executes four) (Astra RS2, RS11, R3-3).

D1a. Credit (amends lane-clock-prefers-work D1a, which credits any trunk result): `fullProofClock` advances only on a full-scope trunk result that satisfies the execution predicate of lane-proof-finds-its-own-engine — a green that ran, or a red with `CountedFull` (full scope alone does not establish execution: a worktree can fail to be created before any check starts, `prove.go:1321`) — and on qualifying full-proof pushes; scoped results and non-runs never advance the four-hour clock (RS3, RS10) (`wake.go:123-128` examines no scope today; the full-scope restriction at `:142-145` applies only to pushes) (RS3). The hourly debt applies to a scoped trunk result even when no lane push record exists (`scopedProofDue` starts from `LastPush`, `wake.go:153-165`: a hand records push followed by a scoped trunk check leaves none), and every inherited result preserves the ORIGINAL full execution's tree and completion time — an inherited result's newer timestamp never renews the allowance (`inheritScope` keeps `Scope=="full"` with an older `FullAt`, `scope.go:421-426`; the records fallback overwrites `FullTree/FullAt` with the candidate's, `scope.go:82-91`) (RS4).

D2. At the keeper's main observation, main is refreshed through the existing bounded fetch independently of queued work and incidents (today `RecoverMovedMain` returns before fetching when the queue is empty, `trunk_recovery.go:79-91`, batch selection returns before fetching without a batch or queue, `batch.go:338-355`, and trunk admission reads the local `origin/main`, `prove.go:461`: a remote records push can stay unseen while the old local commit still holds applicable proof); a refresh failure stays visible and establishes no proof (Astra R3-1). The observation then requests the applicable check for the fetched commit whenever it lacks applicable proof — independently of open incidents and queued work (today both named paths depend on incidents: the health row is generated only inside its incident loop, `health.go:319`, and recovery returns without queued work or open incidents, `trunk_recovery.go:79`; the wake calculation has no independent changed-main reason) (RS9). A changed-main request stays pending while a candidate repair obligation owns its checkpoint (the protection of lane-clock-prefers-work D1a lives in `keeper_clock.go:110-124` and is absent from trunk `Start`: checkpoints count as not running, `prove.go:342-343`, trunk bypasses repair readiness, `fix.go:358-360`, and admission writes the replacement `running.json`, `prove.go:586`); it starts after that obligation settles, through the keeper's shared arbitration; observation, recovery and steward triggers never replace the checkpoint (R3-2). Every other trigger preserves eligible work and delegates depth to that same admission: the steward's `unproven-incidents` row (`health.go:318, 336-337, 486-488`) and `RecoverMovedMain` (`trunk_recovery.go:67-73, 102-110`, whose `codeMoved` filter returns without starting anything for a records-only move) start the check of D1 for a records-only move with open incidents or a moved main; the check is scoped when a fresh baseline exists and full when it does not (RS5). A records-only commit does not by itself require another FULL proof, but its changed inputs are checked, and the fallback, environment and hourly-debt requirements still apply (this sentence replaces one-person-one-truth U5's blanket exemption).

D3. One notion of a record for classification (pathclass, shared by `ledgerPath` at `main_move.go:10-13` and `recordsOnlyPaths` at `scope.go:200-220`; a design page is a record that IS an input to checks) — but classification never authorises reuse: inherited settlement (`prove.go:1070-1109` into `proof_admission.go:116-129`) and record folding (`main_move.go:115-141`, published by `push.go:183-219`) each run every group whose declared inputs changed before the resulting tree is recorded green; the in-flight result carry (`prove.go:1039-1046`) is removed rather than extended, and a changed folded tree is returned through proof admission instead of being checked inside the folding lock (`push.go:167`) (RS1; Astra round 2 note).

D4. Every controlled publisher of records validates the complete candidate commit, including its goal references, before each publication attempt and after every rebuild — at the transaction's own boundary (goal transactions build commits from an isolated index seeded from the fetched tip, `internal/goal/txn.go:344-408`, and already validate each rebuilt candidate at `:900-939`; the caller's checkout need not hold those bytes, so `project.Read` on the checkout can approve a different tree; `internal/project/goals.go:11` imports `goal`, so the checker is composed above `internal/goal` and invoked through the publication boundary) (RS6). Covered publishers: goal publication, the lane's own records commits, and the existing hand records route `work land G --records PATH...` (`cmd/metasystem/intent_delivery.go:165,187`; its project check at `intent_records.go:219-226` and publication at `:246-251`), which the hand route uses from now on instead of raw pushes; raw Git pushes stay outside this guarantee (enforcing them needs a separately agreed remote publication control) (RS7). A refused publication says why in intent words ("the design page X names goal Y, which is not in the ledger; the push waits").

D5. UX: the person reads "main moved by records only; 4 checks run (2 min), the rest holds from the 02:50 check" — no scope words, group ids or paths.
