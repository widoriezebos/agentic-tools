# A person's test plan and test run are admitted, and every proof launch shares the host's admission

- Id: 01M4ZD0000000000000000TRA1

## Problem

1. A person is refused (R-142/143). On 2026-10-16 12:44 the steward ran `metasystem test plan --mode standard --repo W` on a hand worktree and was answered "machine m1e holds no claimed goal to charge this test run to; name one with --goal GOAL" (`internal/testrun/contract.go:290`), then with `--goal` "this checkout has no enrolled engine to choose the tests with" (`internal/testrun/refusal.go:124`) (S289; the invocation's human authority was unverified: it came from an agent-started shell). Planning and execution share `testrun.Prepare` (`cmd/metasystem/test.go:238, 491, 676`): accounting depends on purpose and an explicit goal (`prepare.go:495-502`; an explicit `--goal` bypasses automatic claim selection, `contract.go:152-155`), linked worktrees can borrow enrolment (`prepare.go:678-688`), and selection combines the protected base and the candidate contracts (`prepare.go:345-386`). The missing boundary is the supported, authenticated HUMAN invocation: a person's checkout has neither a claimed goal nor an enrolment, and there is no form in which that is fine.
2. Two heavy jobs on one host. The hand gate (today a script running test binaries directly) and the lane's proof never share admission: the executor's host resource admission (`internal/proofrun/host_resources.go:658, 771-835`, used by `test run` at `cmd/metasystem/test.go:770`) is bypassed by the hand gate, AND by the lane's own proof launch (`launchCheck` starts its shell directly, `internal/landing/plain/restart.go:90`; `proof/full.sh:6` builds the reporter before registration; `repoproof/full.go:127`). On 2026-10-16 16:44–16:59 a hand gate and the lane's hourly check ran together: load 62–77, the gate killed (S309). A forecast of the lane's next check cannot prevent this (a job overruns, main moves, queued work wakes the lane, `wake.go:60`); only shared admission can.

## Decisions

D1. **A person's `test plan` and `test run` are admitted on any checkout.** The authority decision sits at the shared preparation boundary (`testrun.Prepare`) and is CARRIED through execution reservation, retained-attempt validation and result reading (execution refuses an empty goal today, `cmd/metasystem/proof_run.go:1014`; reservation requires positive accounting and retained attempts require goal identities and revisions, `internal/proofrun/attempt.go:713, :508`): an uncharged human run is represented explicitly in the records (no goal is invented; the existing accounting requirements for agent runs are not weakened), so both public commands with no goal produce a readable retained result without changing any goal budget. An authenticated human invocation (the enrolled terminal, or the helm's grant lineage: the same notion the goal verbs use with `--by`) of `test plan` or `test run` on a checkout without a claimed goal or an enrolment is admitted through the EXISTING executor: it runs uncharged unless the person names a goal; for an authenticated human, naming an existing goal preserves attribution WITHOUT requiring a live claim (today an approved unclaimed goal needs another live claim, `cmd/metasystem/proof_run.go:856`, queued and parked goals are rejected, `:754`, and an exhausted goal stops a cold candidate build before execution reservation, `test_cold_budget.go:72`): the run charges an existing accounting episode where one is available, otherwise records explicitly uncharged human attribution, and explains and records any budget override BEFORE both the cold-build preflight and the reservation, creating no claim and weakening no agent admission; an authenticated person may RERUN a candidate with retained failed evidence without supplying a retry-decision file (today the executor calls `NoChildDecisionLocked` before budget admission, `proof_run.go:1207`, and a retained failure on the same candidate yields `retry-required`, `internal/proofrun/test_ownership.go:488`, returned by the public command, `test.go:878`): before execution the override and the prior attempt are explained and recorded, the failed evidence preserved, the retry requirement kept for ordinary agents; it chooses the tests with the protected base contract plus the candidate's contract, exactly as today (a candidate that removes a required check is still caught; the person's run never weakens the gate); it records the exact tree, the engine that chose the tests and the selected contract, and it explains and records every accounting or policy override it made for the person. An ordinary agent on the same route is refused or charged exactly as today. Trust and engine for an UNENROLLED target: the target uses its OWNING installation (the linked-worktree owner, or the installation selected by the project's declared engine-delivery policy) for human authentication (`internal/humanauthority/authority.go:876` needs an enrolment before its helm fallback) and for enrolled-engine resolution (`internal/testrun/prepare.go:678` tries the target and its linked owner only; the pinned planning child receives the target installation again without a separate owner binding, `prepare.go:726`); that owner binding follows the pinned planning child and the executor, while the destination and the candidate selection stay bound to the target; unresolved ownership produces a specific refusal naming the one act; checkout shapes this resolution cannot support are deferred explicitly. A refusal of a person's run that remains (an unreadable checkout, a missing engine anywhere) names the one act.
D2. **Every proof launch on the host shares one admission.** The hand gate is a person's `test run` (sharded by the executor as the lane's proof is, under host resource admission with the configured capacity), and it writes the proof record the hand route's preflight cites instead of a script marker. The lane's own proof launch enters the SAME admission before its heavy phases (reporter compilation, shard fan-out): acquiring capacity under the admission guard, waiting when the host is full, never killing completed work; custody of the host lease is retained through reporter compilation, execution and descendant cleanup with the EXISTING resource-custody mechanism (`LaunchDetached` constructs another command without inherited resource descriptors and returns at once, `internal/gaterun/launchdetached.go:58`; a bare acquisition creates a cleared marker that inspection ignores, `host_resources.go:905`, `host_lease_inspect.go:136`; the accepted `landing-takes-an-hour.md:50` names this distinction), nested work sharing that lease and status observing its active state; and, before replacing a running-proof record or removing proof worktrees (`internal/landing/plain/prove.go:1266` removes old proof worktrees before launching; `:1409` uses forced removal), the previous execution's custody is settled with the lane installation's configuration identity and its files preserved while custody is live or unknown (a retry after launcher death cannot remove a surviving worker's worktree), as the accepted landing-takes-an-hour design specifies. The configured capacity expresses Wido's "one heavy job at a time" (the default for this host: one proof-class job); admission is observable (`landing status`/`test status` say "waiting for the host: a proof of main runs").
D3. **Acceptance.** Reproduce S289 through the human-authority route, with and without an explicit goal, for both commands; both commands with no goal produce a readable retained result without changing any goal budget, with admission and record validation REAL in the fixture (restoring either unconditional goal requirement fails this test; bypassing authentication fails the ordinary-agent case); a person without a claimed goal or enrolment (admitted, uncharged, recorded); an ordinary agent on the same route (refused or charged as today); a candidate that removes a required check (still caught); a seeded failed native producer for the same candidate on the human and the ordinary-agent routes (restoring the unconditional retry refusal fails the human case; removing authentication fails the agent case); an approved but unclaimed NAMED goal and an exhausted named goal with a cold build, at the real boundaries (restoring either refusal fails the human case while the agent refusal stays); a distinct pinned planning process with an unenrolled target, including the removal of a protected check (dropping the owner binding fails the successful case; substituting the candidate's policy fails the protected-check case); hand-first, lane-first and simultaneous starts of a hand run and a lane proof under the configured capacity: the second contender waits without killing completed work; the lane's reporter compilation inside the admission; launcher-exit and surviving-child fixtures for lease custody (removing descriptor retention or releasing before descendant cleanup fails them). Artificial clocks and injected process observations only (R-104).
