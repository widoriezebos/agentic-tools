## Problem, measured on 2026-10-11

Merge plus gate costs about 4 minutes; the full proof costs 40 to 67 minutes (results.jsonl: 38.8, 67.5, and 40+ min today). The batch seals on the first hand-in and, by the standing policy, holds one member. Two goals handed in 20 s apart (22:12, finding 150) therefore cost two full proofs. A proof reruns every package (`-count=1` on every go group, internal/proofrun/test_go.go:352) even when a restart or the next batch changes a handful of files. A detached proof cannot be cancelled on purpose: a killed child is recorded as a lost-process red (lane-housekeeping-2 U1).

## Decisions

- D1 Admission window. The `auto` policy prepares a batch of EVERY waiting goal that is admissible (not held by a conflict record, not returned; a records-only hand-in is a member as before — it rides the batch and never starts or restarts a proof by itself, D7) and the batch stays OPEN while the agent merges and gates; a goal handed in during that phase joins it (the agent re-reads status before each step, merges the newcomer and re-gates; the gate is minutes). The batch SEALS when the FULL proof starts: its own `sealed_at` stamp (BatchRunning is already set during gate admission, batch.go ~758, so it is not the seal). The window is not a timer: it is "until the expensive step starts".
- D2 Restart rule. A goal handed in while a sealed batch's full proof runs restarts the batch when (a) the proof's elapsed time is under half of the expected full-proof time — the median of the lane's last five green full proofs, 45 minutes when there are none — and (b) this batch has not restarted before. The lane records the decision on the batch ("restarted at 12 min for ssil; expected 45") and in status; otherwise the newcomer waits for the next batch, as today, and status says why ("ssil waits: proof at 31 of 45 min, past the restart point"). One restart per batch: a trickle of newcomers cannot starve the first goal.
- D3 Clean cancel. A restart (or a person's `landing restart`) writes a cancel record for the running attempt BEFORE ending it, then ends the WHOLE proof process tree — the detached wrapper AND the proof command it launched in its own session (record that command's process identity at launch; LB-02) — and confirms every process is gone before the worktree is touched or a replacement proof starts; the attempt is recorded "cancelled: restart for G" and never as a lost-process red or an incident; the agent is woken to re-merge, re-gate and prove the reopened batch. A cancel is the only way the lane ends its own proof.
- D4 Preemption. When main is red (the trunk-red register has an open incident) a newcomer that IS an incident's fix — the goal the incident names, as hold.go already identifies it (LB-04) — restarts the batch at once, whatever the elapsed time and even after the batch's one restart: a fix for main outranks every landing; the restart record says so. Any other newcomer follows D2 and never interrupts the proof of a fix already repairing main. No other priorities (no queue ordering by tier).
- D5 Green-package reuse — PARKED on 2026-10-12 05:30 after two corrections and a measured read: the only SOUND rule (a package whose tests, non-test files or directly imported module packages start a child process is never reused) clears NOTHING in this repository, because all 167 test packages import internal/testenv, which starts processes (the fixture custodian, testenv.Go); and the scan that decides it costs about 8 minutes per full proof (27 cmd/metasystem partitions × 25 declared groups × 1.3 s). The smallest safe thing yields no speed. Reuse returns when groups DECLARE their inputs (a design of its own: per-group input sets, or a custodian proven to read no tree input), not through a scan. What lands from this decision: `landing prove --fresh` — a person's or the agent's way to force a complete re-run past the lane's saved, inherited and gate-baseline reuse (prove.go ~472, ~761, ~864) — because a safety escape is worth having before any reuse exists.
- D6 Verbs and status (a verb for every situation, Wido 08:00). `landing batch` prints the batch, its state (open / sealed since / restarted …), members and the pending newcomers with the reason they wait; `landing batch seal` closes the window by hand; `landing batch reopen --with G` admits a waiting goal (restart if a proof runs); `landing restart` cancels the running proof cleanly and reopens the batch with every waiting goal. Status headline while a detached proof runs says "proving (N of M units, t min); agent waits for the keeper", never "idle"; the unit count says "counting" until the plan is known.
- D8 Reds found outside a batch proof get the flake repeat. A red test from a TRUNK proof of main or from a classification REPLAY is re-run by name on the same tree (the repeat the batch proof already has) before it becomes an incident or attributes a cause; a red that is green on repeat is recorded as a flake (the flake register of 2026-10-04), never as an incident, and never blocks a landing or asks the person. Measured 2026-10-12: three false main reds in one night, every one a timing-sensitive test red only while the host carried builds (findings 153c, 168, 174); each cost an hour of lane time and a person's answer.
- D7 Unchanged: conflicting members are held for the next batch by their `after` record; records-only hand-ins never start or restart a proof; a red proof attributes by the named replay and returns the culprit.

## Threat model

(1) Starvation by newcomers: one restart per batch (D2 b). (2) A cancelled proof mistaken for a red: the cancel record precedes the kill (D3); the lost-process detection reads it. (3) A cached green hides a real red: the reuse policy clears a package only when no test of it, no non-test file of it and no module package its tests import directly starts a child process, and only when its declared inputs and the changed paths since its last green on this host are known; when it cannot tell, the package runs; the proof's own failures always re-run (flake repeats and replays keep -count=1); a person can force a full rerun with `landing prove --fresh`. ACCEPTED RISK (for Wido): a child process started by a helper that is reached only through a SECOND module-package import is not seen by the scan, so such a package may reuse a cached green after an input that only the child reads has changed; today no package of this repository has that shape (the critic found nine with the one-import shape, which the scan covers). (4) Restart churn: the restart point is half the expected time, measured, not a constant. (5) Two agents acting on one batch: the agent reads status before each step (skill) and the batch record carries the restart generation; a stale agent step ends its turn.

## Units (each at most 250 production lines, independent files, built in parallel)

- U1 (D1) multi-member open batch: `auto` selects all admissible waiting goals; `BatchOpen`/sealed-at on the record; newcomers join an open batch; the skill's loop re-reads and merges newcomers before the gate. - U2 (D2, D3, D4) restart with a clean cancel: expected time from results.jsonl; the rule; the cancel record; recording the proof command's process identity at launch and ending the whole tree with confirmation; the wake; preemption only by an incident's fix. Tests with injected clocks: newcomer at 12 of 45 → restart, recorded; at 31 → waits with reason; second newcomer after one restart → waits; red main → restart at 40; a cancelled attempt is never red or an incident.
- U3 (D5, reduced) `landing prove --fresh` only: the flag carried through admission (Settled, Start, acceptsGreen, proofScope full, inherited and impact reuse, the gate baseline, the detached --attempt path, the retry argv) and recorded on the result; the reuse machinery (scan, run-groups environment, policy changes) is removed. ~60 lines. Files: internal/proofrun/test_go.go, internal/repoproof/full.go, cmd/metasystem/intent_landing_prove.go. Tests: a second proof of an unchanged tree reports cached units and the same result; a changed package re-runs; a replay never caches.
- U4 (D6) verbs and status: `landing batch [seal|reopen --with G]`, `landing restart`, the status headline and unit count wording. Files: cmd/metasystem/intent_landing_batch.go (new), internal/landing/plain/status.go. Tests: each verb against a fixture batch; the headline while proving.

- U5 (D8) flake repeat for trunk and replay reds: internal/landing/plain red.go / replay.go / trunkred recording — reuse the batch proof's repeat; the flake register receives repeat-green reds; status names them. Tests: a trunk red that is green on repeat → flake recorded, no incident, no question (mutation: skip the repeat → incident → test fails); a red that stays red → incident as today; a replay-side red on main that is green on repeat → the goal's own tests still attribute own (finding 169).
