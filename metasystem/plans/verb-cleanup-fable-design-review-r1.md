## Material findings

### VC-D1 · HIGH · material · deleted descriptors have exposed forms with no current route
**Evidence (read).** The compatibility inventory in source is exactly the ten the design names: fold, close (intent_delivery.go:129,147), ready, decide, resolve, recover, red (intent_planning.go:163,190,345,390,474), fleet, doctor, ui (intent_process.go:174,193,202). The design's inventory and `replacedBy` map are per descriptor, but two exposed forms are not covered by the named replacement:
- `fold unit U --brief FILE` (usage at intent_delivery.go:130). Its replacement names only `revise G ... --brief FILE` and `revise job R --dispositions FILE --brief FILE` (intent_delivery.go:105); `revise` has no unit form. The work owner still emits it as a Decision: intent_work.go:1030 prints `metasystem fold unit RUN --brief FILE`.
- `close J --reconcile-evidence JOB` (intent_delivery.go:148,156,1265). The `review ... --dispositions FILE` replacements carry no `--reconcile-evidence`; the only remaining route is the private shell continuation `dispatch.sh close --job … --reconcile-evidence …` emitted by internal/dispatch/read_admission.go:253, which the design's own rule ("normal results never instruct a caller to use [the private protocol]") forbids.
- Unverified in budget: `resolve G --review R --finding F --implementation-chain J --artifact PATH --result RUN --critic ROOT` (intent_planning.go:346) against `review --finding`.
**Failure.** Step 1 deletes `fold` and `close`; an agent that folds a unit round or reconciles evidence has no public spelling, and one continuation names a refused spelling. That is capability loss under the design's own preservation contract.
**Smallest amendment.** Replace the per-descriptor inventory with a per-exposed-form table (every usage line and advanced option of the ten), each row naming its current public route, or "private, left open" with the private owner. For the two confirmed rows: give `revise` a unit form (or state the exact `--work/--after` equivalence) and retarget intent_work.go:1030; add `--reconcile-evidence` to `review job` or explicitly leave evidence reconciliation private and open. Add a refusal test per deleted form and a capability test per row.

### VC-D2 · HIGH · material · shell fixture beds still call `goal engine-floor`
**Evidence (read).** The design removes the engine-floor mutation, `settings compatibility --minimum-engine`, the abandon prerequisite (abandon.go:126,255-280) and the supervisor checker. The checker claim holds: `supervise.EngineFloorProblems` has one caller, goalsync_mutations.go:2381. Shell sections are not run by `go test` or the trunk-red register.
**Failure.** After step 1 the verb is unknown; both beds exit red at the floor line and the dependent-safety and landing assertions behind it never run. Certification is damaged while the Go suite is green.
**Smallest amendment.** Name both beds as VC-3 owners: delete the floor-setting lines, keep every abandon assertion after them, and list the two beds in the Runtime proof column next to the unrelated-repository adapter.

### VC-D3 · MEDIUM · material · continuation migration misses the UI owner and the review-evidence owner
**Evidence (read).** `ui` is both a deleted compatibility descriptor and a registered family (main.go:33 list; dispatch falls through to `dispatchInternal` at main.go:813). After deletion `metasystem ui restart` still executes through the family while public help on `ui` refuses. Three normal results instruct exactly that spelling: internal/ui/lifecycle/result.go:68 (`metasystem ui restart`), internal/ui/lifecycle/serve.go:48 (`metasystem ui stop`), internal/ui/act/act.go:45 (`bin/metasystem ui restart`). **Smallest amendment.** Add internal/ui/lifecycle, internal/ui/act and internal/dispatch/read_admission.go to VC-1's owners, and add one test that sweeps every emitted message constant and fixture output for the ten deleted spellings and for bare family syntax in a normal result.

## Challenged and holding (not material)
- **Engine-floor retirement.** The guard protected engines predating the abandoned state; all seats build from one main and stale engines are already a doctor class. Authority is not lost (the floor's human proof was the mutation's own; abandon keeps its proof, dependency dispositions and locks). Records are not lost: root.go:380 and recover.go:480 keep reading and classifying historical `engine-floor` lines; the design's text preserves them. Two clarifications worth one line each: name root.go and recover.go as preserved owners, and say whether the read form `settings compatibility` (no flag) goes with the write form (recommend yes; history stays readable through the ledger).
- **Retaining private raw dispatch is coherent.** Public intents resolve first, then the one dispatcher (main.go:810-813); the raw protocol has real consumers (808 non-test call sites in scripts, .claude, skills, internal and cmd, 324 of them `goal`). The design's "thousands" is an order of magnitude high but the argument stands: renaming their argv buys no user anything and risks process identity and permission checks. Keeping them behind `internal` for discovery while execution still accepts bare family names is a help boundary, not an execution boundary; the design says so. One build note: `internal FAMILY --help` and `FAMILY --help` share the code path at main.go:817-823, so the implementer must thread the entry prefix through `writeFamilyHelp` to render the `internal` prefix and refuse the bare form.
- **Administration model.** enroll (today group goals), settings and restart (today group operations) are honestly about the work system, not the application. Mixed commands keep their names with per-usage scope at the descriptor; the design forbids a policy, registry, evaluator or parser, so no premature generality. The count checks: 54 descriptors today = 44 public + 10 compatibility.
- **Public task discovery versus argv rename.** The design already draws this line (Deferred section) and it is the right one.
