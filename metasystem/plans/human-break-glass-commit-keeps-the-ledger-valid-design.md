## The mechanism, in seven facts

1. A goal record's Integrity line is sha256 over the bytes above it, LF-normalised for hashing only (internal/goal/
   file.go:1751-1755); ParseFile reports "missing Integrity line" or "Integrity mismatch: recorded %s, computed %s"
   (:483-488). Channel files are JSON plus one newline (channel.go:110-116), validated by decoding (ValidateChannelTree
   channel.go:139-197; it takes any commit, :140).
2. ReadCommitGoals lists plans/goals/ and records/goals/ of one commit and reads the blobs (validate.go:553-566): only
   paths present there. ParseTreeFiles reports "%sbacklog.md: the root record is missing" (:138); ValidateTree reports
   "blockedBy names a goal that does not exist" (:309), a rank gap (:264), a pathless cycle (:337). ValidateCommit
   returns ReadCommitGoals' error first, then flattens []Problem into one error (:623-642).
3. Goal verbs load the tip through loadTree and refuse a tree that does not parse (verbs.go:281-308); Publish runs
   acceptance gates, sync-mode gate, captured-tip validation, Mutate, BuildCommit and Validate before the CAS
   (txn.go:630-690). No verb repairs a tip.
4. BuildCommit seeds a temporary index with `read-tree tip^{tree}`, stages `--cacheinfo 100644` under the state root's
   prefix, then write-tree and commit-tree (txn.go:238-291); goalGit runs git with environWithoutGitSteering()
   (txn.go:71-98; genesis.go:125-144 strips GIT_DIR, GIT_WORK_TREE, GIT_COMMON_DIR, GIT_INDEX_FILE, GIT_CONFIG* and
   only those). PublishCAS: `update-ref <ref> <new> <old>` locally, `push --force-with-lease` remotely (:349-374).
5. Arm's human proof is requireHumanTerminalAt (cmd/metasystem/process_verbs.go:331-363) through the package variable
   classifyProcessVerbCaller (:29); only lease.ClassHuman passes; FixtureGranted comes from a caller-supplied table
   whenever the root's tracked metasystem.conf says metasystem.runtimes=fake (fixtureauth.go:57-71, 291-293).
6. The installer resolves the hooks directory with `git rev-parse --path-format=absolute --git-path hooks` in the
   scrubbed environment, because core.hooksPath and a linked worktree's common directory move it (goalsync_verbs.go:
   67-73, :172-175); the primary hook is `<dir>/pre-commit`, a foreign hook is preserved as `<dir>/pre-commit.local`
   (:112, :160-167); our composer runs the guard then `exec "$here/pre-commit.local"` (:211-217); isOurComposer
   recognises it (:238). The probe runs a hook under a 30 s context timeout and a 5 s WaitDelay (:130-136).
7. The guard emits no structured caller verdict: HUMAN, a non-HUMAN with a valid wrapper token and an unavailable
   classifier all continue silently (pre-commit-guard.sh:44-68; unavailability appends to artifacts/agents/
   landing-observe.log, :29-42); only the invalid-wrapper branch prints and exits 1 (:63-66). Its index rules are
   `(^|/)plans/(goals|channel)/` (:80), `\.orig$` over added or modified paths (:88-89) and `(^|/)plans/[^/]+\.md$`
   over added paths (:104-105), the last skipped under METASYSTEM_ALLOW_NEW_PLAN=1 (:97) or an unborn HEAD (:102).
   Its git calls are unqualified and read the inherited environment (:27, :80, :88, :104).

## BG-PRINCIPLE-01: a human verb; it refuses only identity, and it asks

For the human the verb has exactly the three shapes of plans/human-carried-landing-design.md HCL-PRINCIPLE-01: (a) an
identity check (BG-PROOF-01); (b) a warning, printed and recorded, after which it does what was asked (the hook
chain's words, BG-GUARD-05); (c) a question, when the commit would leave the ledger invalid, could not be validated,
or a repair would discard bytes (BG-ANNOUNCE-06, BG-REPAIR-08), answered by `--proceed <payload-tree>`. No path is
excluded: guarded paths, `.orig` files, new plan files and repo-root paths all commit (the human path
repo-root-paths-ride-agent-commits-unjudged says the docs must name). It runs nothing but git and the installed hook
chain: no tests, no Opus read, no landing evaluator, no push; it is not seat-landings-run-the-selected-sections' lane.

Witnesses. BG-01-ANY-PATH: one commit names a plans/goals record, a repo-root file, an `x.orig` and a new plans/y.md;
all four are in HEAD's tree; fails when any class is excluded. BG-01-ONLY-GIT-AND-HOOKS: the Exec seam records every
argv; the set is git commands plus the hook files of BG-GUARD-05; fails when a lane command (land.sh, commit.sh, go
test, the evaluator) is added. BG-01-THREE-SHAPES: every register row under Owner "breakglass" has Shape Identity or
Question (BG-REGISTER-09); fails on a Warning or Agent row.

## BG-SCOPE-02: three roots, two path grammars, containment without dereferencing the entry

The verb resolves its scope with resolveProcessScope (process_verbs.go:50-76): Checkout is the git toplevel of
`--repo`; Root is the installation holding the engine and the ledger (:76); Prefix is `git -C Root rev-parse
--show-prefix` (txn.go:253-258), empty when Root is the toplevel. A git path is toplevel-relative and addresses the
index and trees; a ledger path is Root-relative and is what the goal package reads (ValidateCommit(Root, c) lists
with `-C Root`, validate.go:554). git path = Prefix + ledger path.

Fold of BGCR2-05. Every `-- <path>` argument is made absolute against the invoking directory and lexically cleaned; a
`..` that leaves Checkout is a Question. Containment resolves symlinks in the PARENT directory only
(filepath.EvalSymlinks on filepath.Dir, and on Checkout) and requires the resolved parent inside the resolved
Checkout by filepath.Rel + IsLocal, the installer's `within` shape (goalsync_verbs.go:95-107). The final component is
never dereferenced: a named symlink is the index entry `c`, whatever it points at. When the lexical parent and its
resolved form differ (the path lies beyond a symlinked directory) the verb asks: "<path> lies beyond the symlink
<link>; name the link itself" (git's own refusal, A11). canonicalPath (cmd/metasystem/up.go:14-22) is NOT used for
entries: it dereferences whenever the path exists. git path = rel(Checkout, resolved parent)/base; a ledger path only
when it starts with Prefix.

Witnesses. BG-02-INSTALLED-LAYOUT: toplevel T holds development/x.md and an installation T/metasystem with
bin/metasystem, plans/goals and memory; one operation names T/development/x.md and T/metasystem/plans/goals/<id>.md;
HEAD's tree differs from the parent in exactly those two paths plus the record and the receipt;
ValidateCommit(T/metasystem, HEAD) passes; fails when Prefix is dropped. BG-02-OUTSIDE: a `..` argument and a
directory symlink pointing out of Checkout are Questions, HEAD unchanged; fails when containment is removed.
BG-02-SYMLINK-ENTRY (command level): the human names symlink `c` whose target lies outside Checkout, then repoints it;
`ls-tree HEAD c` shows mode 120000 with the new link text and the target is byte-identical; fails when the final
component is dereferenced (rejected as outside, or committed as a blob). BG-02-BEYOND-SYMLINK: a path through a
symlinked directory inside Checkout is the Question above; fails when the parent check is lexical.

## BG-TREE-03: one general candidate builder with a kept index, shared with the doctor

internal/goal gains the primitive the doctor's page calls RestoreAndPublish, split so a verb can validate, observe
and ask between the halves (fold of BGCR2-01 and BGCR2-03):

```text
type RepairEntry struct { GitPath string; Content []byte; FromWorktree, Delete bool }
type RepairRequest struct { Parent string; Entries []RepairEntry; Message, Author string; Now func() time.Time }
type Candidate struct { Commit, Tree, Index string }                 // Index: the kept temporary index file
func RepairBuild(checkout string, req RepairRequest, exec Exec) (*Candidate, error)
func (c *Candidate) Add(entries []RepairEntry, message string, exec Exec) (*Candidate, error) // same index, parent
func (c *Candidate) Close() error                                    // removes the index directory
type LandMode interface{}; type LandRef struct{ Ref, Expected string }; type LandCanonical struct{}
func RepairLand(e Endpoint, checkout string, c *Candidate, mode LandMode, exec Exec) error
func AdvanceIndex(checkout, parent, commit string, exec Exec) error
type Exec interface { Run(RunSpec) RunResult }   // RunSpec{Argv, Dir, Env, Stdin, Timeout}; RunResult{Stdout,
                                                 // Stderr, ExitCode, Outcome: exited|timeout|signal|spawn-error}
```

RepairBuild: a temporary index in the scrubbed environment goalGit uses (fact 4) with GIT_AUTHOR_*/GIT_COMMITTER_*
from Author and GIT_AUTHOR_DATE/GIT_COMMITTER_DATE from Now (the commit oid is a function of its inputs), every git run
`-C Checkout -c core.logAllRefUpdates=false` through Exec (nil is os/exec); `read-tree <Parent>^{tree}` seeds it (as
txn.go:251), so unnamed entries survive; per entry: Content: `hash-object -w --stdin` then `update-index --add
--replace --cacheinfo 100644,<oid>,<GitPath>`; FromWorktree: `update-index --add --replace -- <GitPath>`, so mode and
type come from the worktree entry (100644, 100755, 120000, 160000; a mode-only change is a change; A8); Delete:
`update-index --force-remove -- <GitPath>`. Then write-tree and `commit-tree <tree> -p <Parent> -m <Message>`; the
commit is unreachable (A9); nothing runs a hook (A1). The index is KEPT and returned: the observer needs it and Add
continues on it, staging more entries, write-tree, commit-tree with the same Parent and the given message. Close
removes the directory; the verb defers it. Path expansion, by the verb: a named directory expands to `git -C Checkout
ls-files --cached --others --exclude-standard -- <dir>` (the set `git add <dir>` takes; A8); a named file present in
the worktree is FromWorktree; present in Parent but missing from the worktree is Delete; in neither is a Question
("<path> names nothing in the worktree or HEAD"). A rename is the deletion plus the addition, both named.

RepairLand: LandRef runs `update-ref <Ref> <commit> <Expected>` (the old-value assertion is the CAS, PublishCAS's
local leg, txn.go:359-364); LandCanonical runs PublishCAS (txn.go:349) for the doctor. This verb uses LandRef with Ref
from `symbolic-ref HEAD` and Expected = the HEAD read at start; a detached HEAD is a Question ("HEAD is detached;
check out the branch to commit to"); a refused CAS is a Question ("HEAD moved from <a> to <b> while you typed;
rerun"). Never a push, fetch or remote argument (ruling 2). AdvanceIndex (fold of BGCR2-03): after LandRef moved the
checked-out branch, the ordinary index (GIT_INDEX_FILE unset, scrubbed environment) is advanced for exactly the paths
of `git diff-tree -r <parent> <commit>`: an added or modified entry gets `update-index --add --replace --cacheinfo
<mode>,<oid>,<path>` from the commit's tree, a deleted one `update-index --force-remove`. Every other index entry,
staged or not, is untouched, which is what `git commit -- <paths>` leaves behind. LandCanonical callers decide on
their own page whether the landed ref is checked out.

Witnesses. BG-03-WHOLE-TREE: Parent holds unnamed a.txt, executable b.sh, symlink c, d.txt, e.txt; named: b.sh with
its bit cleared, c repointed, d.txt deleted, e.txt edited, a directory f/ with two new files, one record as Content;
`ls-tree -r HEAD` equals the tree `git add -A` plus write-tree builds in a scratch index; fails when the seed is
dropped, when FromWorktree uses --cacheinfo 100644, or when Delete is skipped. BG-03-SCRUBBED: GIT_DIR and
GIT_INDEX_FILE pointing at a decoy change nothing; fails when the environment is inherited. BG-03-CAS: Exec advances
the branch between read and update-ref; no ref move, the Question printed; fails when Expected is omitted.
BG-03-DETACHED and BG-03-NOTHING-NAMED: the two Questions above; each fails when its check is removed.
BG-03-KEPT-INDEX: after RepairBuild the Index file exists and `write-tree` on it equals Tree; after Add it yields the
new Tree; after Close it is gone; fails when the builder removes the index before returning. BG-03-NO-REMOTE: a
fixture with `origin` configured; after a landed commit the Exec argv set contains no `push`, `fetch` or `remote` and
origin's branch is unchanged; fails when a push is added (fold of BGCR2-07). BG-03-INDEX-AFTER-LAND (command level):
z.txt staged with content differing from the worktree; the verb lands named edits, a deletion, the record and the
receipt; afterwards `git diff --cached --name-only` is exactly `z.txt`, `git status --porcelain` shows no entry for
any named path or the audit files, and HEAD's tree matches; fails when the ordinary index stays at the parent (named
paths appear reverse-staged) or when advancing resets z.txt.

## BG-RESTAMP-04: goal records are restamped by their owner, bytes untouched

internal/goal exports (U1) `LedgerPathKind(ledgerPath) Kind`: GoalRecord for `plans/goals/<id>.md`,
`plans/goals/backlog.md`, `plans/goals/done/<id>.md` and `records/goals/<id>.md` (what ParseTreeFiles parses,
validate.go:99-134); Channel for anything under plans/channel/ (channel.go ChannelPrefix); Other for everything else,
including a deeper file under plans/goals/, which ParseTreeFiles refuses by name (:134) and which reaches
BG-ANNOUNCE-06 unchanged. `Restamp(data []byte) (out []byte, outcome RestampOutcome)`, byte-preserving: it finds the
terminal Integrity line, the last line of data, starting at offset 0 or after "\n", beginning with "Integrity:
sha256=" and followed by nothing but its terminator ("\n", "\r\n" or none). body is data up to that line's start,
original bytes, CRLF kept. Outcomes: Unchanged (the token equals IntegrityDigest(body), file.go:1751); Restamped (only
the digest token is replaced; the terminator kept); Appended (no terminal Integrity line: body is all of data plus one
"\n" when data does not end in a terminator, then "Integrity: sha256=<digest>\n"; reported as "appended Integrity
line to <path>"). A non-terminal Integrity line is body: its bytes survive and the parser's verdict reaches
BG-ANNOUNCE-06. ParseFile agrees with Restamp on every output: splitIntegrity (file.go:1758-1766) normalises, then
takes the last prefix, which is the line Restamp wrote, over the normalised body Restamp hashed.

The verb applies Restamp to every named GoalRecord path and stages the result as Content; Channel and Other paths are
FromWorktree, byte-for-byte. Revision and History stay as the human left them; the verb synthesises nothing.
Everything Restamp cannot cure survives to BG-ANNOUNCE-06. Write-back: committed bytes are written to the worktree
only after RepairLand and AdvanceIndex succeeded, only for Content entries, and only when the worktree file still
holds the bytes read at start; otherwise "<path>: the worktree changed during the commit; not rewritten". After a
landed commit the goal files equal HEAD's and MaintainBase (reconcile.go:245-271, exact match) advances the base on
the next reconcile (ruling 3); the verb never touches artifacts/agents/goal-base/materialized.json.

Witnesses, each failing when its branch alone is removed: BG-04-RESTAMP (an edited line under the old digest; HEAD
validates and the bytes above the line equal the bytes read), BG-04-NO-ROUNDTRIP (a line RenderFile never emits
survives), BG-04-CRLF (every CRLF survives), BG-04-NONL (exactly one "\n" added), BG-04-TRAILING (three lines after a
misplaced line survive and the verb asks), BG-04-APPEND (a missing line is appended and validates), BG-04-CHANNEL (a
valid channel edit is byte-identical; restamping would stop decoding, channel.go:170-175), BG-04-ARCHIVE
(records/goals and plans/goals/done with stale digests validate), BG-04-BACKLOG (a stale root record validates),
BG-04-UNTOUCHED (a path outside the ledger is byte-identical), BG-04-WRITEBACK-AFTER-LAND (with the CAS refused the
worktree keeps the old digest), BG-04-WRITEBACK-GUARDED (a file changed between read and landing is not rewritten and
the line is printed), BG-04-BASE (MaintainBase advances the base to HEAD after a landed commit).

## BG-ANNOUNCE-06: the payload tree is the consent token; audit bytes are added after consent

         <each Problem, verbatim>
