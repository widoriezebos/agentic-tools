## Build
1. The resolution-only read (lane-speed S1, the read the lane requests after a resolution's merge check is green) runs only when the resolution diff (the diff against the automatic merge, already computed for the read brief) touches production code: a Go file that is not `_test.go`, or any file outside `testdata/`, `plans/`, `memory/`, `records/`, `skills/`. A test-only or records-only resolution is not read: the fix record moves straight on with a line "resolution of G reviewed by its check only: N test/records files, no production code" and the batch continues. The rule is one function `resolutionNeedsRead(paths []string) bool` with its reason string, used by the path that launches the read.
2. The read bound (`landing.read-minutes`, default 20) stops being a finding line: when a resolution read runs past the bound, the lane ends the read's job (the job stop path the keeper uses for its own jobs), and returns the goal to its seat with the merge attached (the existing return path with reason "the resolution read of G ran M min past the bound of B min; the automatic merge and the resolution are on the goal branch's lane merge <sha>; review and hand in again"). A person's read (started by a person) is never ended.
3. The landing agent's skill (`skills/landing-agent/SKILL.md`): the first step after reading status is the first job the batch needs (the resolution job for a member with conflicts, else the merge), launched before any other reading; the step record is written at launch. One sentence; keep the skill audit's word budget.
4. A `--read-minutes` is not added; the setting stays. Status prints "reading the resolution of G: M of B min" while the read runs.
