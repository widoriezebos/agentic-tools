## 4. Proof and landing rule

A batch of k units in original join order has prefix trees T1..Tk on `baseTree`, tip Tk, and sealed union U. Each joined entry binds its post-handover Revision and AccountingRevision. A receipt covers its candidate by exact tree, workspace exclusions, or identical selected-group execution identities; reused groups may come from any terminal attempt; a zero-execution prefix receipt creates no attempt. Existing observe and held checks still require the actor to own the goal at the chain revision.

The sequence is: P1, BA8 acquires the lock, re-arms `baseTree`, and re-derives the prefixes. P2, BA11 plans Tk, checks U and both sealed revisions inside admission, and requires two attempts plus twice its reserved minutes before one charged tip proof. P3, BA13 creates receipts for i < k, executing and charging only identity differences. P4, BA14 builds every commit locally in original join order. P5, one held check precedes one push of the complete series. P6, BA14 and BA6b recognize each landed trailer, re-arm, release, edit Next, return or release the claim, and clean worktrees exactly once.

The failing set F is a subset of U, so P2's second-attempt and doubled-minutes check bounds the mandatory diagnostic without a reservation object. Only a human budget edit can remove that headroom while the owner holds Gk. If that happens, the refusal is durable `held-unclassified`; no unit is blamed, ejected, or retried. A moved revision refuses before runner or charge. A moved trunk creates a new tree: disjoint selected inputs permit rebase plus verify-only receipt checks; otherwise the batch returns to P1. A local commit refusal pushes nothing. A crash after push recovers units from their individual origin trailers, never tip equality.

## 5. Red, eject, trunk red

Every red P2 or P3 attempt first runs `test run --purpose diagnostic --no-reuse --mode canary --groups <F> --tree <baseTree> --goal <Gk>` outside the batch lock and charged to Gk. A red base creates `held-trunk-red`; nobody is ejected. The production hook creates the idempotent ledger owner and exists only when BA17's capability is present. Tagged tests may use the file hook. The hold is narrow to batches whose U meets F, and reopening requires a new tree.

A green base computes the named set N from failing-group input manifests and selecting surfaces. N empty is also trunk red. One named unit becomes `return-pending` with attempt, group, log, and failing names; tick prepends the failure and fix round to Next and returns or releases its claim. With two or more named units, diagnostics run the unnamed tree and each named unit alone in join order. This diagnostic order never changes final landing order. Survivors reassemble in original join order as a new tree, so another proof is a new candidate rather than a retry. A P3 red names its prefix unit by construction. A refused diagnostic creates `held-unclassified`. The bounded schedule, no `t.Skip`, injected clocks, and no raised bound or lowered floor remain unchanged.
