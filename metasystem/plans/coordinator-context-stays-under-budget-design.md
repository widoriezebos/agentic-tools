## 0. The contract this revision builds to

Wido's reading of the DONE sentence (2026-09-13): the bound is by construction where the engine owns the surface, and by instruction and measurement where the harness owns it, with the week of section 7 failing the goal on any recorded call over the ceiling. The engine owns its verbs' output, the packets it composes, the continuation it stages and the handoff it records; a hosted session's own file reads and provider invocations belong to the harness on every runtime the roster has, and no engine seam stands in front of them. The words below say which of the two each mechanism is.

## 1. What the measurements say

On m1e on 2026-09-12, `metasystem goal list` printed 19.3 MB of JSON for 645 goals: approved 11, claimed 3, done 311, open 167, parked 4, queued 149. `History`, containing every ledger entry for every goal, occupied 18.3 MB; `NextStep` occupied 0.58 MB and `Intent` 0.51 MB. These are rounded byte measurements supplied for this design. They supersede the goal page's earlier 9 MB observation. `goal show --id` printed 32 KB; `supervise status` printed 196 bytes.

Across today's three seats' Claude transcripts, a fix-forward day with no delegate rounds, tool results totalled 6.7 MB. The seats' own reads dominated: `sed` 1.34 MB over 495 calls, `grep` 0.65 MB, and `Read` 0.42 MB, with single reads reaching 58 KB. Engine output was small: one `goal show` result was 30 KB and one `goal claim` result 29 KB. Nineteen `goal list` calls contributed only 0.07 MB because the seats already piped them through `jq`. The unfiltered 19.3 MB measurement and the filtered transcript measurement describe different surfaces.

The audit days had a different mix: the coordinator loop repeatedly read `goal list`, watch results, test logs, and landing output, while the conversation accumulated toward the million-token ceiling. `artifacts/reports/delivery-deep-dive-2026-09-11/claude-sessions.md` section 1a reports coordinator means of 386 to 507 thousand prompt tokens per call, versus 76 to 126 thousand for delegates. Section 4b records automatic compactions around 967 thousand tokens, each dropping about a million, roughly one per active seat per day. Its exact count is 19 compactions across the cohort, including manual compactions at smaller sizes; the daily description is approximate.

That audit file is retained local evidence in the m1e source checkout, outside tracked source. The 2026-09-12 measurements above were taken on m1e by the seat that owns this page (goal list piped through a byte count, the three seats' transcripts summed by tool result). Both belong in the retained baseline for the implementation proof.

The decision follows both observations: remove accidental bulk at the verb, then bound conversation accumulation across all reads. A small status result is no reason to remove it; a shell filter is no protection against the next unfiltered invocation. Smaller individual responses alone cannot prevent hundreds of useful file reads from accumulating.

## 3. Briefs and evidence travel by path (by construction in the packet, by instruction in the reading)

Today the composition owner embeds the whole brief and every continuation body into the delegate packet (internal/dispatch/composition.go) and records source and delivered digests. The contract of this revision:

- A typed reference: `{"path":"<control-root-relative>","digest":"sha256:...","bytes":N,"lifetime":"immutable|staged","purpose":"brief|design|critique|return|diff|log|evidence"}`. The path is relative to the control root of the chain (the installation's artifacts store or a tracked file), never absolute and never outside the root (`..` and symlinks refused as ComposeRolePacket refuses sources today).
- The packet: `references[]` carries the typed references; the directive text (the task sentence and the section list) stays inline up to `MaxInlineBytes`; a brief, a design page, a critique body, a return, a diff, a log is never copied into the packet, a notification, a follow-up or the handoff state file.
- Lifetime: `immutable` names a file under the control root that no writer changes after composition (the chain's rounds, the tracked plans and records at a commit); `staged` names a verified copy the composition owner made under `artifacts/agents/<job>/staged/` for a recipient on another host, with the same digest.
- Verification: immediately before the model invocation, the runtime adapter (the one place every rostered runtime passes through, scripts/agents/hosts/<runtime>.sh calling `job verify-references --job <id>`) re-reads every referenced file and compares digest and byte count; a mismatch or an unreadable file refuses the launch with `REFERENCE_MISMATCH path=... expected=... found=...` and the job record carries the refusal; nothing is dereferenced by prose.
- Instruction: the brief template (scripts/agents/templates/brief.md), the three role contracts (design-critic, code-critic, implementer) and docs/orchestration.md say: request the smallest section you need, read a large file through a bounded view, and open a reference only through its path.
- Tests, to be added: a composed packet with a 60 KB brief carries a reference and no body; a reference whose file changed between composition and launch refuses the launch by name; a staged copy verifies on a second host root; a path outside the control root refuses at composition.

## 4. Account for the context of each call (by measurement)

Per-call context means the whole prompt presented to one provider invocation, not a sum over invocations, and the engine reads what the harness recorded after the fact. One package owns the reading: `internal/spend` gains the typed API `LatestCall(root, seat) (CallSample, error)` and `Calls(root, seat, since) ([]CallSample, error)`, where `CallSample{Runtime, SessionID, InvocationID, PromptTokens, CacheCreation, CacheRead, At, Source}`.

- Claude: the seat's session is the announced main (artifacts/agents/mains/<session>-<pid>.json carries the sessionId); the transcript is `~/.claude/projects/<slug>/<sessionId>.jsonl`; a sample is one assistant record keyed by `requestId` (input plus cache creation plus cache read, the formula already in spend/transcript.go), deduplicated by requestId. Codex: the announced session names the rollout; a sample is one `event_msg.token_count` record's `info.last_token_usage` (input tokens, cached input a subset), keyed by the record's ordinal in the rollout because the rollout carries no request id (verified on this box on 2026-09-12). Devin and the ACP outcome report per adapter invocation and give `unknown` per call with the reason `per-invocation usage only`; they are outside the proof cohort until their adapters expose call-resolved usage.
- Cursor: `artifacts/agents/context/<seat>/cursor.json` holds, per runtime, the file identity (path, inode, size) and the byte offset last read; a read tails from the offset; a rotated or truncated file (identity or size below the offset) restarts from zero and says so in the sample's `Source`. Cost bound: one Stop-hook attempt reads at most the bytes appended since the last attempt; a first read of a whole transcript is bounded by the harness's own file size and happens once.
- Capability per runtime, declared on the adapter (`scripts/agents/hosts/<runtime>.sh` gains `context-sample: per-call|per-invocation|none`): a runtime without a stream answers `unknown` and the reason; an unreadable home or a missing transcript answers `unknown` with the path.
- `RoleContext` joins the steward's health roles (internal/steward/health.go) and calls `LatestCall`; `ContextBoundTokens = 150000` and `ContextCeilingTokens = 200000` live in internal/steward/context.go. The role renders one line, `context: N thousand tokens this call, bound 150, ceiling 200`, or `context: unknown (<reason>)`. The Stop hook prints the line on each Stop-hook attempt as one accelerator; `metasystem context status --root <installation>` prints it on any runtime with no hook.
- There is no admission in front of a provider invocation: a call above the ceiling is a recorded breach that fails the week (section 7), not a prevented call. This is the measured half of Wido's reading.
- Tests, to be added: `LatestCall` reads a synthetic Claude transcript and a synthetic Codex rollout to the exact figure; a rotated file restarts the cursor and says so; a per-invocation adapter answers `unknown` with the reason; the second read of an unchanged file reads nothing.

## 5. Hand the seat to a fresh session (by construction, on the runtimes whose main the engine can see die)

At the bound the seat hands off to itself; at the ceiling the turn verdict says so in one command. Exclusivity is Wido's decision (2): the successor launches only after the engine has observed the predecessor's death.

- `metasystem context handoff --root <installation>` writes an immutable, nonce-bound state file `artifacts/agents/context/<seat>/<nonce>/state.json` (schema 1): the held goal (id, accepted revision, claimant), its next step (text, source page path and digest), the open items (stable ids, status, evidence paths), the last landings (commit ids, goal ids, receipt paths), the scratch pointers (purpose, path, digest, required or optional) and the messages owed (recipient, subject, draft path, delivery status); every path is a typed reference of section 3 and is verified at write; the file stays under 32 KB by pointing at manifests. The verb refuses on a runtime whose main it cannot observe (`HANDOFF_UNOBSERVABLE runtime=<r>`), refuses when a required reference does not verify, and refuses when the seat holds no goal (a seat with nothing to hand off just stops).
- The verb then stages the continuation intent through the existing staging (internal/steward/stage.go StageIntent) with a new kind `seatHandoff`, carrying the nonce, the state file's digest, and the predecessor's exact process identity (pid, start time, the announced main). Then it returns; it ends no harness. The predecessor's own end is the harness's act: a headless continuation session exits at the end of its turn; an interactive session ends when the person closes it or the Stop hook allows the stop under the recorded handoff (the hook reads the intent and prints `handoff recorded: <nonce>; end this session` as the stop condition, an allowance, not a refusal).
- `decideForRevival` (internal/steward/revive.go) treats `seatHandoff` unlike `seatIdle`: it launches only when the predecessor identity in the intent is provably dead (internal/identity, the same prover the reaper uses: pid gone or start time changed); a live or unknown predecessor keeps the intent staged and the tick says so; the `seatIdle` exemption that launches beside a live main stays what it is for its own kind. The continuation brief names the nonce and the state file's digest; the continuation contract (scripts/agents/roles/steward-continuation.md) gains the rule to read the state file first, verify its digest, and hold the same goal; a state file whose digest differs from the intent's is refused and the tick names it.
- Two handoffs cannot cross: each writes its own nonce directory; a later handoff never overwrites an earlier state file; a delayed continuation of an earlier intent finds its own file. A predecessor that comes back to life after the successor launched is impossible by construction on Claude and Codex (a dead pid is dead); on a runtime without an observable main the verb refused at step one.
- Quiescence: the handoff happens at a harness turn boundary with no tool call in flight; the verb checks the seat's own records (every authorised message delivered, every required result on disk) and refuses otherwise; what the harness holds only in memory is disposable by declaration and the state file says so.
- Tests, to be added: the handoff verb refuses an in-flight required result, a mismatched reference and an unobservable runtime, and writes a valid nonce-bound state file otherwise; two handoffs in a row leave two state files; `decideForRevival` refuses a `seatHandoff` intent while the predecessor pid lives and launches it once the pid is gone; a continuation refuses a state file whose digest differs from its intent.

## 9. Risks, self-grade, reject condition

Risks: a runtime that reports per adapter invocation, read as per call, would fabricate a figure (refused: `unknown`); path references can hide a missing file (verification before every launch and at the handoff write); a fresh session loses cache warmth and orients again (the week's report records handoffs beside the prompt sizes); the engine cannot see a call the harness does not record (the cohort is the recorded samples and the report says so); an interactive predecessor that never exits keeps its handoff staged forever (the tick says so each round and the turn verdict prints the allowance; the seat is not two coordinators, it is one that has not left). Self-grade: every mechanism is labelled by construction or by measurement per Wido's reading; the six round-2 findings each have a mechanism in sections 2 to 5 and 7; the reject condition: reject this revision if a mechanism is claimed by construction where the engine does not own the surface, if a per-invocation figure is presented as a call, if a `seatHandoff` intent can launch beside a live predecessor, if a reference can be dereferenced without verification before a launch, or if the week's pass can be met by samples the report does not cover.

**D2-11. The cursor commits a prefix of the samples log.**

Decision: add `SamplesBytes int64` with JSON name `samplesBytes` to `CursorState`. Bytes `[0, SamplesBytes)` in the samples file are committed evidence. A byte boundary uses the existing cursor and lock without a second transaction file.

The commit and recovery rules are:

1. Load and validate the cursor under its existing lock. Inspect the samples file before reading the transcript. With a trusted cursor, truncate any suffix beyond `SamplesBytes`, sync and close the file. A missing samples file means size zero. A file shorter than `SamplesBytes` is an error. Preserve it and the cursor. Never pad a lost committed prefix or silently restart it.
2. Without a trusted cursor, a missing or empty samples file permits fresh state. A nonempty samples file refuses with an error naming both paths and the missing trusted boundary. Preserve both files. Cursor read errors other than nonexistence are errors, rather than fresh state. This narrows the old unconditional fresh-state rule at `artifacts/reports/codex-ccb-slice2-brief.md:115`.

A failed first final-cursor write therefore still leaves an authoritative zero-byte boundary. A read producing no rows may publish its final cursor directly.

Only then atomically publish the new cursor with the new `SamplesBytes`, transcript position, counters and latest values. A scan, append, sync, close or pre-publication cursor error returns an error. No candidate reading is returned as committed. Leave any unfinished suffix for the next locked recovery.

The agent `<note>` states that the same task id may notify more than once after a resume. Only `completed` was observed.

### 2. The shape in one paragraph

Two configuration keys give the trigger, and the margin is chosen so the DONE's numbers hold by a construction on the largest observed per-call step, with the working room disclosed as a cost (D1). The health line, `context status` and a new Stop-time CONTEXT line read the configured budget; the proof keeps the DONE's numbers as constants (D1). A PreToolUse hook whose branch runs before anything else in the script execs one engine process under a 100 ms deadline counted from the shell's birth; it classifies the call before any read, never denies a landing, a wait, a job watch, the Agent tool or a task tool at any size, and, until the successor design's launch unit lands, runs in observe mode: it allows every call and records the decision it would have made (D3, SR14). The handoff verb records every in-flight task by a state machine over the observed record types, refuses without a fresh memory note under the seat's memory directory that names every declared output, records the engine identity under schema 2 with a dual reader, and keeps refusing while a wait is in flight; the function that ends and records waits is built now and called only by the successor's launching path (D4). The successor itself, the over-trigger block, the claim leg and the fence are the successor design's (section 7).

#### D3. The in-turn bound: a PreToolUse hook in observe mode (U3e-1, U3e-2a, U3e-2b; R-114-m1e item 5; CC8D-209, 210; RN-1; SR6, SR14)

- D3.1 Installation (RN-1). scripts/enforcement/claude-code-hooks.json gains `PreToolUse` (no matcher) whose command is `(bash scripts/agents/supervision-hook.sh claude tool) || true`, timeout 5: the fallback turns any non-zero exit, 2 included, into exit 0 with no decision, the same shape as the Stop's fallback (excerpt 5), and it passes `hooks.CheckSettings` (hooks.go:40-75) because the script stands in command position and enters the vendored directory. Host setup merges it into .claude/settings.json (setup.go:172-185), `hooks check` reports it when missing, and U3e-2b re-derives the checkout's live file through `metasystem up`, never by hand. Job settings (adapter/claude.go:122-131) are unchanged: no job receives the gate. The entry and the script's `claude tool` case land in the same unit, U3e-2b, so no interval exists in which every tool call meets the dispatcher's `exit 2` (excerpt 4).
- D3.2 The path and the bound (CC8D-209, RN-1). The `claude tool` case is placed right after `event=${2-}` (supervision-hook.sh:4), before the builtin-only start block (:391), before `set -euo pipefail` (:399) and before every `exit 2` (:1067-1068); it uses builtins only and one `exec`. In order: (1) when `METASYSTEM_HOOK_DELEGATE_JOB` is set (a job-bound adapter, :1461-1480) it exits 0 with no output, cause `delegate`, no engine call (a job's calls are bounded by its turns, and job settings carry no gate anyway); (2) it reads two lines, the engine path and the installation root, from `${BASH_SOURCE[0]%/*}/../../artifacts/agents/context/engine-path`, which `claude start` writes after resolving `ms` (:907, :1484); a missing or unreadable cache, or a non-executable engine, exits 0 with no output (cause `engine-unresolved`, counted nowhere: the cache's absence is the first Stop's notice); (3) it `exec`s `<engine> adapter claude-tool-gate --root <installation>` with the payload (`session_id`, `transcript_path`, `tool_name`, `tool_input`, `cwd`) on inherited stdin. Because of the exec, the verb's pid and process birth are the shell's, so the deadline counts from shell entry (SR6): `identity.ProcessBirth(pid) (time.Time, bool)` reads `Proc.P_starttime` of `SysctlKinfoProc` on darwin (microseconds) and `/proc/<pid>/stat` field 22 with `/proc/stat` btime on linux (ticks, 10 ms); the deadline is birth plus 100 ms; when the birth is unreadable the deadline is entry plus 100 ms minus `ShellEntryAllowanceMs = 25`, noted in the row. The verb's runner takes `ToolGateOptions{ShellStartedAt time.Time, Clock func() time.Time, MemoryDir string, Mode string}`; `main` wires the prober and `time.Now`; every focused witness injects both, so no witness asserts wall time (Wido 2026-09-12). Order inside the verb: classify the call against the table of D3.3 first, before any file is opened, so an allowlisted or never-denied call returns at once with no sample and never meets the deadline; then the budget (D1.1); then the sample through `usage.LatestCall` with `Transcript` set and two new `ReadOptions` fields, `MaxBytes` (262144) and `Deadline` with a `Clock func() time.Time` (nil is `time.Now`): the reader seeks to max(cursor, size minus MaxBytes), drops a partial first line, skips any line longer than the window, returns `Reading{Reason: "deadline"}` when the clock passes the deadline between lines, and never writes the cursor (the Stop-time reader keeps that). Under the trigger, no sample in the window, any read error or the deadline passed: no decision. Every decision the verb reaches is a row in `artifacts/agents/context/tool-gate.jsonl` under the state root (`session`, `at`, `tokens`, `tool`, `mode`, `decision`, `wouldDeny`, `cause`, `elapsedMs`, `birth`), except the two trivial allows (`under-trigger`, `allowlisted`). The harness's behaviour on a hook timeout (no decision, the call proceeds) is recorded as dated integration evidence under docs/design/turn-verdict-delivery-contract.md's rule (excerpt 8) by the bed leg of U3e-2b and is never the only guard: every slow path inside the verb ends in no decision by the deadline.
- D3.3 The grammar and the table. An allow is no output and exit 0, so the harness's ordinary permission flow runs unchanged (an explicit `permissionDecision: allow` would bypass it, which the gate never does); a deny is `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"CONTEXT AT <N>K (trigger <T>K): this call is denied; run metasystem context handoff --root <installation> alone, or launch a delegate"}}`. The `Bash` command is split into simple commands on `&&`, `||`, `;`, `|` and newlines; each is shell-split; a leading `cd <path>`, `K=V` assignments and a `bash` or `sh` wrapper are stripped; the command word is matched by its basename after any path prefix; a trailing output filter (`head`, `tail`, `grep`, `tee`, `wc`, `cut`, `sed`) is neutral. The table in internal/adapter/toolgate.go has one row per pattern with the columns `trigger` and `ceiling`. Never denied at any size (SR6, SR14): the tools `Agent`, `SendMessage`, `Monitor`, `TaskStop` and any tool whose name begins `Task`; the commands `metasystem landing <verb>`, `metasystem goal land-ready`, `metasystem wait`, `metasystem job watch`, `<path>scripts/agents/land.sh`. Allowed at the trigger: `metasystem context handoff|resume|status|verify`, `metasystem delegate`, `metasystem steward revive|status`; `Write` and `Edit` whose path lies under the seat's memory directory (`MemoryDir`, resolved by D4.4's resolver; unresolvable: those two are allowed with cause `memory-unresolved`). A compound command with any other simple command, and every other call, is a deny in deny mode.
- D3.4 The ceiling column (CC8D-210, SR14). Until the successor design's launch unit lands, the ceiling column equals the trigger column row for row, so delegate launches and the Agent tool are allowed at every size and every landed prefix of the cap group leaves the lawful continuation S1 uses (delegates); `TestToolGateCeilingColumnEqualsTrigger` pins the equality, and the successor's launch unit is the one that switches rows and rewrites that witness (section 7.3).
- D3.5 Observe mode (SR14). The key `context.toolgate.mode` takes `observe` or `deny` (any other value is refused at load); the shipped metasystem.conf carries the line `context.toolgate.mode=observe`, and the code default for an absent key is `observe`. In observe mode the verb computes the decision exactly as deny mode would, writes the row with `mode: observe`, `decision: allow`, `wouldDeny: true|false` and the deny reason, and emits no output. Turning deny on is the successor's launch unit changing that one shipped line to `deny` and rewriting `TestShippedToolGateModeIsObserve`, which pins the shipped line today. Every deny witness of section 5 runs the verb with `Mode: "deny"` injected, so the deny table and its witnesses are built and proven now and no witness is removed; `TestToolGateObserveModeAllowsAndRecordsTheDenyDecision` runs the same inputs with `observe` and asserts no output plus the row.
- D3.6 What DONE's "under a stated context size" means after the cap group: in deny mode D1.4's construction; in observe mode the seat's discipline against the health, status and CONTEXT lines, with every would-deny row counted for the proof week. The proof's maximum rule (D1.3) reports any call over 200K in either mode.

- D4.1 Waits (CC8D-210). - D4.2 Engine jobs stay as today: running jobs of the held goal under `openJobs`; a pending one refuses `HANDOFF_LAUNCH_IN_FLIGHT`.
- D4.3 In-flight tasks (CC8D-206, SR13). `usage.InFlightTasks(transcript string, opts ReadOptions) ([]Task, []Notice, error)` in internal/usage/tasks.go walks the records in file order with one state per task, keyed by the launching tool-use id. Launch: an `assistant` record with a `tool_use` item named `Agent` or `Bash` whose `input.run_in_background` is true; its result is the next `user` record holding a `tool_result` with that `tool_use_id`, and the identity comes from the record's top-level `toolUseResult`: for `Agent`, `status == "async_launched"` and `agentId` (the task id), `description` (what it was asked) and the `output_file:` line of the result text (the output path); for `Bash`, `backgroundTaskId` (the task id), the path after `Output is being written to:` and `input.description`. A result without those fields (a synchronous agent, `isAsync` false) is no task. Completion: a record `type == "queue-operation"` and `operation == "enqueue"` whose `content` begins `<task-notification>`, joined by `<tool-use-id>` to the launch; a `<task-id>` that differs from the launch's task id is a notice (`notification for tool-use <x> names task <b>, not <a>`) and joins nothing. Delivery records, a `user` record whose `message.content` is the notification text, or an `attachment` record with `attachment.type == "queued_command"` and `attachment.commandMode == "task-notification"`, are recognised by the same tags; one task's completion is counted once across enqueue, dequeue, remove and delivery, and a delivery with no enqueue seen (a transcript cut by a resume) is still a completion. `queue-operation` records without a notification are not task events. Resume: a later `tool_use` named `SendMessage` whose `input.to` equals a known task id, or a later `tool_result` whose `toolUseResult.agentId` equals a known id, puts the task back in flight (the `<note>` says the id notifies again). Terminal status set: `{completed}` in one table `terminalTaskStatus`; every other `<status>` word is classified non-terminal: the task stays in flight and the notice `task <id> status <word>: treated as in flight` is printed by the verb; adding a word is one table row with a dated fixture. A task is in flight iff its last event is a launch or a resume. The verb: `--no-delegates` refuses `HANDOFF_TASKS_IN_FLIGHT ids=<...>` when any task is in flight; `--delegate id=<a>[,asked=<text or path>][,output=<path>]` takes `asked` and `output` from the transcript when omitted and refuses `HANDOFF_DELEGATE_OUTPUT_MISMATCH id=<a>` when a supplied output differs from the transcript's; an id the transcript never launched refuses `HANDOFF_DELEGATE_UNKNOWN id=<a>`; an in-flight id not declared refuses `HANDOFF_DELEGATE_UNDECLARED id=<a>`; a declared terminal id is recorded with `terminal: true`; neither flag refuses `HANDOFF_DELEGATES_UNDECLARED`. Each declaration is recorded under `delegates` (id, toolUseId, kind agent|bash, asked, output, declaredAt, terminal). A runtime with no transcript takes the declaration as the record. S1's quiet point reads: no task in flight, or every in-flight task declared. Fixtures, sanitized from the observed shapes (prompts and results cut), under internal/usage/testdata/tasks/: agent-running, agent-completed-user-delivery, agent-completed-attachment-delivery, notification-without-enqueue, repeated-notification-one-id, resumed-then-completed (the resume shape is unobserved here and stated so in the fixture; a builder replaces it with an observed one), unknown-status, bash-running, bash-completed, sync-agent-not-a-task.
- D4.4 S7 mechanically and the memory directory (CC8D-212). `usage.MemoryDirectory(opts ReadOptions) (path, reason string)` resolves `filepath.Join(home, ".claude", "projects", claudeSlug(cwd), "memory")` for `cwd` in `Toplevel` then `Installation`, exactly as `claudeTranscript` (excerpt 3) resolves a transcript: `pathWithin(projects, candidate)`, `os.Lstat` a directory that is not a symlink; a caller-supplied transcript path is never an input. `--note <path>` is required (`HANDOFF_NOTE_MISSING`); the note must be a regular file, not a symlink, within that directory (else `HANDOFF_NOTE_OUTSIDE_MEMORY path=<p>`); it is read once before anything is written and must contain every declared delegate's `output` path (else `HANDOFF_NOTE_LACKS_OUTPUT path=<p>`); its modification time must follow `Announcement.PidStartedAt` in whole seconds: a later second passes; the same second passes only when the note's sha256 differs from the `lessonsNote.sha256` of the seat's previous handoff state (none: passes); earlier refuses `HANDOFF_NOTE_STALE note=<p> modified=<t> session=<t0>`. The state records `lessonsNote {path, modifiedAt, sha256}` and `VerifyHandoffState` checks `lessonsNote.modifiedAt < writtenAt` (S7's check, excerpt 1, unchanged). No machine judgement of the text. Path witnesses accept the project memory directory and refuse a transcript path, another slug and a symlink that escapes it.
- D4.5 Engine identity and the schema (SR8). The state records `engine {path, sha256, installGen}` from `os.Executable()`. `HandoffSchemaVersion = 2`; the state adds `openWork []HandoffOpenWork` (empty on the record-only path), `delegates []HandoffDelegate`, `lessonsNote *HandoffNote`, `engine *HandoffEngine`.
