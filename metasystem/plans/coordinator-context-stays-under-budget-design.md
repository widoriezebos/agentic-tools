## 1. What the measurements say

On m1e on 2026-09-12, `metasystem goal list` printed 19.3 MB of JSON for 645 goals: approved 11, claimed 3, done 311, open 167, parked 4, queued 149. `History`, containing every ledger entry for every goal, occupied 18.3 MB; `NextStep` occupied 0.58 MB and `Intent` 0.51 MB. These are rounded byte measurements supplied for this design. They supersede the goal page's earlier 9 MB observation. `goal show --id` printed 32 KB; `supervise status` printed 196 bytes.

Across today's three seats' Claude transcripts, a fix-forward day with no delegate rounds, tool results totalled 6.7 MB. The seats' own reads dominated: `sed` 1.34 MB over 495 calls, `grep` 0.65 MB, and `Read` 0.42 MB, with single reads reaching 58 KB. Engine output was small: one `goal show` result was 30 KB and one `goal claim` result 29 KB. Nineteen `goal list` calls contributed only 0.07 MB because the seats already piped them through `jq`. The unfiltered 19.3 MB measurement and the filtered transcript measurement describe different surfaces.

The audit days had a different mix: the coordinator loop repeatedly read `goal list`, watch results, test logs, and landing output, while the conversation accumulated toward the million-token ceiling. `artifacts/reports/delivery-deep-dive-2026-09-11/claude-sessions.md` section 1a reports coordinator means of 386 to 507 thousand prompt tokens per call, versus 76 to 126 thousand for delegates. Section 4b records automatic compactions around 967 thousand tokens, each dropping about a million, roughly one per active seat per day. Its exact count is 19 compactions across the cohort, including manual compactions at smaller sizes; the daily description is approximate.

That audit file is retained local evidence in the m1e source checkout, outside tracked source. The 2026-09-12 measurements above were taken on m1e by the seat that owns this page (goal list piped through a byte count, the three seats' transcripts summed by tool result). Both belong in the retained baseline for the implementation proof.

The decision follows both observations: remove accidental bulk at the verb, then bound conversation accumulation across all reads. A small status result is no reason to remove it; a shell filter is no protection against the next unfiltered invocation. Smaller individual responses alone cannot prevent hundreds of useful file reads from accumulating.

## 2. Bound output where each verb produces it

Slice 1 landed the measured offender: `goal list` prints one line per live goal in rank order under 64 KB (27 KB for 167 goals on 2026-09-12), `--json` the records without history, `--json --history` the old bytes, `--done` the archived bucket; `goal show` prints the page without history unless `--history`; a record flag on the summary is refused, never ignored (cmd/metasystem/goal.go runGoalList and runGoalShow, cmd/metasystem/goal_list.go).

Slice 1b adds the spill contract for the verbs that can still print more than a seat should read: `internal/output` owns `MaxInlineBytes = 32 * 1024`; a verb that would print more writes the full bytes to `artifacts/agents/output/<verb>-<timestamp>.<ext>` under the control root and prints one line naming the path, the size and the format (as JSON when JSON was asked for: `{"outputMode":"file","verb":...,"path":...,"bytes":...,"format":...}`). Its callers in that slice: the retained test result a `test run` prints when no result path is given (cmd/metasystem/test.go publishTestingResult, which prints the whole TestResult with every group), the landing script's failed-step output (scripts/agents/land.sh prints forty-line tails of a failed step and the full coverage failure), and `goal claim`, `goal next` and the other ledger mutations that print a goal record (29 KB for one claim on 2026-09-12). Progress lines (TEST-GROUP, PROOF-RESULT, the landing's step lines) are already bounded and stay. Long-lived verbs (watch, test run) keep their bounded progress lines and spill only their final result. The shell landing script owns its temporary combined step file and deletes it on exit; the spill for its failure output is written by the script itself under the same path rule, so the Go owner is not made to retain a file the script deletes.

Native reads a seat makes with its own tools (a file read, a grep) are not the engine's to bound: they are the instruction of section 3 and the measurement of section 7.

## 3. Briefs and evidence travel by path

The composition owner embeds the full brief into a delegate packet and appends continuation bodies (internal/dispatch/composition.go, the brief at line 231 and the continuation bodies after it); the role contracts (scripts/agents/roles/design-critic.md:14, code-critic.md:14, implementer.md:11) and the brief template (scripts/agents/templates/brief.md) carry no size contract. The rule: briefs, designs, critique bodies, delegate returns, diffs, logs and evidence are referenced by repository path and digest, never copied into a packet, a notification, a follow-up or a handoff state file; the packet carries the path and the digest of the referenced bytes, and the recipient opens what it needs. The composition records the digest of the delivered reference text separately from the digest of the referenced bytes. Referenced files must be readable from the successor's workspace and runtime: immutable files stay in the control root; a file for another host is staged as a verified copy. The instruction change lives in the brief template, the three role contracts, the continuation contract and docs/orchestration.md: request the smallest section you need, and read a large file through a bounded view.

## 4. Account for the context of each call

Per-call context means the whole prompt presented to one model invocation, not a sum over invocations. The reader is the existing transcript owner in internal/spend (internal/spend/transcript.go: assistant records keyed by requestId, creation tokens normalised into input, cache-read kept apart): one call's context is its input plus cache creation plus cache read, deduplicated by requestId. A Codex session's rollout carries the same figure directly (`event_msg.token_count.info.last_token_usage.input_tokens`, cached input a subset of it, verified on this box on 2026-09-12); a reader for that shape joins the usage owner. Devin's usage and the ACP outcome are per adapter invocation (internal/usage/devin.go, acp.go): one invocation can hold several calls, so those runtimes report `unknown` per call and stay out of the proof cohort of section 7 until their adapters expose call-resolved usage; nothing is inferred from a per-turn total.

`RoleContext` joins the steward's health roles (internal/steward/health.go) and reads the seat's newest call sample; `ContextBoundTokens = 150000` and `ContextCeilingTokens = 200000` live in internal/steward/context.go. The role renders one line, `context: N thousand tokens this call, bound 150, ceiling 200`, or `context: unknown` with the reason. The Stop hook prints that line each turn as one accelerator of the same reading (scripts/agents/supervision-hook.sh already prints the health preview); `metasystem context status --root <installation>` prints it on any runtime with no hook. There is no admission in front of every model call: a harness makes its calls, the engine reads what the harness recorded, and a call above the ceiling is a recorded breach that fails the week (section 7), not a prevented call.

## 5. Hand the seat to a fresh session

At the bound the seat hands off to itself; at the ceiling the turn verdict says so in one command. `metasystem context handoff --root <installation>` writes `artifacts/agents/context/<seat>/state.json` (schema 1): the held goal (id, accepted revision, claimant), its next step (text, source page path and digest), the open items (stable ids, status, evidence paths), the last landings (commit ids, goal ids, receipt paths), the scratch pointers (purpose, path, digest, required or optional) and the messages owed (recipient, subject, draft path, delivery status). The engine fills the ledger and session facts and validates the paths; the state stays under 32 KB by pointing at manifests. The verb then ends the session the way `session stop` does, with the handoff as its reason, so the seat's main exits. The steward's idle watchdog sees held work and no live worker and launches its continuation from a staged brief (internal/steward/stage.go StageIntent, internal/steward/revive.go CompleteRevival), the brief naming the state file; the continuation contract (scripts/agents/roles/steward-continuation.md) gains the rule to read the state file first and to hold the same goal. The successor launches only once the predecessor's main is gone, which the continuation already requires, so two coordinators are never live and no transfer protocol is needed. The handoff happens at a quiescent point: a turn boundary with no tool call in flight; every required result and every authorised message is on disk before the verb runs, and the harness's own state (a pending tool result, an unsent draft only in memory) is disposable by declaration.

## 6. Runtime independence

The verbs, the spill owner, the usage readers, the health role, the state file and the handoff live in the Go engine and the adapter records; a Claude hook and a Codex plugin are accelerators of the same verbs. Claude and Codex prove the whole path with real coordinator work; Devin proves its reading per adapter invocation and its `unknown` per call; the handoff verb runs on every runtime because it reads and writes files and ends a session.

## 9. Risks, self-grade, reject condition

Risks: a runtime that reports per adapter invocation, read as per call, would fabricate a figure (refused: `unknown`); path references can hide a missing file (the handoff validates every required path before it ends the session); a fresh session loses cache warmth and orients again (the week's report records handoffs and orientation calls beside the prompt sizes, so the price is measured); the engine cannot see a call the harness does not record (the inventory is the harness's own stream, and a runtime without one is out of the cohort). Self-grade: the DONE sentence's four mechanisms have owners in sections 2 to 5, the runtime clause in section 6, the proof in section 7, against the code read for this page and the round-1 read; the one open question is the reading of "by construction", asked above. Reject this revision if a mechanism is claimed by construction where the engine does not own the surface, if any per-invocation figure is presented as a call, if two coordinators can be live after a handoff, or if the week's pass can be met without an enumerable call inventory.
