R5 has 10 material findings, all structural. The launch placement now conforms to architecture doctrine, but the lifecycle built around it is not yet implementable safely.

1. **CRITICAL — STRUCTURAL — PID/start identity is not actually reuse-safe.**

   R5 relies on exact `pid + start` identity for abandoned-open recovery, child proof, signaling, and custodian authentication ([design:140](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/plans/acp-transport-design.md:140), [design:164](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/plans/acp-transport-design.md:164), [design:180](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/plans/acp-transport-design.md:180), [design:208](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/plans/acp-transport-design.md:208)). Shipped records retain only the start second, discarding Darwin microseconds and Linux start ticks ([identity.go:28](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/internal/identity/identity.go:28), [identity.go:49](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/internal/identity/identity.go:49), [identity_darwin.go:48](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/internal/identity/identity_darwin.go:48), [identity_linux.go:56](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/internal/identity/identity_linux.go:56)). The test explicitly treats any process with the same PID and start second as alive ([identity_test.go:91](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/internal/identity/identity_test.go:91)). A same-second PID reuse can therefore impersonate the abandoned spawner or live custodian.

   The design should require a kernel-resolution process birth token in new custody generations and in adapter authentication. Legacy second-resolution identities must defer rather than claim reuse safety when collision cannot be excluded. Add `internal/identity`, record migration, and cross-platform fixtures to the blast radius.

2. **CRITICAL — STRUCTURAL — `except-live-custodian` cannot literally prove its stated group predicate when invoked as a verb.**

   The proof owner is a shell-callable Go verb, while the still-live adapter subsequently commits ([design:175](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/plans/acp-transport-design.md:175), [design:180](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/plans/acp-transport-design.md:180)). That invocation creates at least the verifier process inside the adapter’s group, so “only the adapter may remain” is false during proof. The existing group-members verb already excludes its own invocation ancestry for exactly this reason ([identity_probes.go:70](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/cmd/metasystem/identity_probes.go:70)).

   The design should make proof and terminal compare-and-swap one operation. It must authenticate the actual invoking ancestry against the recorded high-resolution adapter identity, exclude only the authenticated verifier chain as instrumentation, prove the remaining group/custody set, and commit against the same generation/revision snapshot. Untrusted PID/start flags must not constitute authentication.

3. **CRITICAL — STRUCTURAL — The FIFO launch, registration, sealing, and cleanup sequence is incomplete.**

   R5 says the script launches the server, registers custody, then launches the client, while both children must be registered and the generation sealed after spawning ([design:117](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/plans/acp-transport-design.md:117), [design:140](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/plans/acp-transport-design.md:140), [design:149](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/plans/acp-transport-design.md:149)). It does not say how FIFO opens avoid blocking before the second endpoint exists, how the client is backgrounded so the script can register it, or how a partial launch is abort-sealed. Shipped registration fails if a short-lived child exits before its identity is captured ([runtime-common.sh:81](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/scripts/agents/adapters/runtime-common.sh:81)); the existing lifecycle waits and reaps only one child ([runtime-common.sh:277](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/scripts/agents/adapters/runtime-common.sh:277)).

   “Cleanup on every exit path” is also impossible through a shell trap after `SIGKILL`. Retained bootstrap write descriptors can suppress EOF/SIGPIPE indefinitely, while a peer close can terminate or strand the client; P2 has blocked-write fixtures but no peer-close/EPIPE fixture ([design:461](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/plans/acp-transport-design.md:461)).

   The design should prescribe the descriptor-level sequence: install traps before creation; use per-attempt paths; start both children behind gates; capture and register both birth identities; abort-seal partial generations; seal before releasing protocol execution; close every shell/bootstrap descriptor; wait and reap both children; map EOF/EPIPE/SIGPIPE to typed outcomes; and assign stale-FIFO recovery after untrappable adapter death to an external owner. Add peer-close-before-write, peer-close-during-write, partial-spawn, registration-failure, and crash-cleanup fixtures.

4. **CRITICAL — STRUCTURAL — The patch refusal omits proof-critical identity fields.**

   R5 protects only the custody list, generation, seal, and revision ([design:172](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/plans/acp-transport-design.md:172)). Today `pid`, `pidStartedAt`, `pgid`, `instanceTag`, `ownershipProof`, and `custodyProcesses` are absent from the immutable-field set ([record.go:53](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/internal/dispatch/record.go:53)), and `RecordCAS` copies every non-prohibited patch field directly into the record ([record.go:278](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/internal/dispatch/record.go:278)). These fields determine custodian authentication, group ownership, signaling, and abandoned-open recovery.

   The design should make every proof input immutable through generic CAS after its named trusted transition: top-level PID/birth token/PGID/tag/ownership proof, generation owner identity, custody entries, generation, seal, and revision. Only dedicated launch, open, register, seal, and recovery verbs may mutate them under the record lock.

5. **CRITICAL — STRUCTURAL — The r4 “every terminal writer” fold remains non-total.**

   The committer column still contains `adapter → external` and `adapter or external`, so it does not uniquely select a proof mode ([design:393](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/plans/acp-transport-design.md:393), [design:395](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/plans/acp-transport-design.md:395)). It also omits the dispatcher’s handshake-timeout writer, which currently terminalizes before cleanup ([dispatch.sh:1407](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/scripts/agents/dispatch.sh:1407), [dispatch.sh:1434](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/scripts/agents/dispatch.sh:1434), [dispatch.sh:1460](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/scripts/agents/dispatch.sh:1460)).

   More importantly, the dedicated `RecordProtocolError` verb writes `failed` directly under the lock and never traverses `RecordCAS` or the proposed proof owner ([record.go:200](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/internal/dispatch/record.go:200), [record.go:225](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/internal/dispatch/record.go:225), [record.go:229](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/internal/dispatch/record.go:229)).

   The design should retire or route `RecordProtocolError` through the proof-aware terminal operation; add the handshake-timeout backstop as an explicit external/full-set row; split top-level launch failure from adapter child-launch failure; and specify teardown handoff as “adapter makes no terminal write, exits, named external finalizer proves full-set and commits.”

6. **HIGH — STRUCTURAL — The admission type erases shipped evidence states and cannot certify all five fields as defined.**

   `unproven|proven` collapses “no registration,” “constructed successfully,” “one direction observed,” and “behaviorally certified” ([design:92](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/plans/acp-transport-design.md:92)). The shipped self-test deliberately distinguishes behavioral proof from constructed-only evidence ([selftest.go:100](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/internal/adapter/selftest.go:100), [selftest.go:128](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/internal/adapter/selftest.go:128), [selftest.go:139](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/internal/adapter/selftest.go:139)); the fake producer makes the same distinction ([fake.go:270](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/internal/adapter/fake.go:270), [fake.go:281](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/internal/adapter/fake.go:281)).

   The generic “both directions per field” rule is also undefined for `approvals`: ACP preflight fixes approvals to `deny`, and `Decide` never consumes that field ([design:248](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/plans/acp-transport-design.md:248), [design:261](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/plans/acp-transport-design.md:261)).

   The design should distinguish absent registration, constructed-only, partial behavioral evidence, and behaviorally certified evidence. Pair presence must be separate from field state. It must define a per-field certification matrix over supported envelope values; `approvals` remains uncertified unless a concrete governed behavior and two-sided test are specified.

7. **HIGH — STRUCTURAL — ACP settlement does not reproduce the shipped settlement refusals.**

   R5 makes effective-model evidence the decisive prerequisite and merely names the ACP session ID, wire journal, and candidate snapshot ([design:326](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/plans/acp-transport-design.md:326)). Shipped settlement instead refuses an absent repair transcript and a missing or mismatched exported session; an absent model becomes `unobserved` and does not itself refuse certification ([devin.go:226](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/internal/adapter/devin.go:226), [devin.go:238](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/internal/adapter/devin.go:238), [devin.go:264](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/internal/adapter/devin.go:264), [devin.go:274](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/internal/adapter/devin.go:274)). The official `LoadSessionResponse` does not echo a session ID, so request and replay correlation must carry that proof ([ACP v1 schema, lines 3153–3186](https://github.com/agentclientprotocol/agent-client-protocol/blob/main/schema/v1/schema.json#L3153-L3186)).

   The design should define settlement as an evidence join: the repair load request names the initial session; replay and prompt frames correlate to it; the candidate is derived from the repair window in that journal; model evidence meets an explicit observed/unobserved/mismatch policy; and journal/candidate artifacts are present, bounded, and immutable. Missing or contradictory session evidence must disable repair or fail settlement just as decisively as missing model evidence. List each refusal and its terminal outcome.

8. **HIGH — STRUCTURAL — The usage completeness predicate accepts potentially stale updates.**

   A matched `PromptResponse` plus clean wind-down only proves that no later frame arrived; it does not prove that the last `usage_update` included the final model operation ([design:347](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/plans/acp-transport-design.md:347)). ACP defines `used` as current context tokens and only optional `cost` as cumulative session spend; there is no final marker or required final emission ([ACP v1 schema, lines 4149–4184](https://github.com/agentclientprotocol/agent-client-protocol/blob/main/schema/v1/schema.json#L4149-L4184)). The shipped cumulative implementation recomputes from a post-attempt transcript and explicitly publishes unavailable when the repair transcript is absent ([devin.go:24](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/internal/usage/devin.go:24), [devin.sh:170](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/scripts/agents/adapters/devin.sh:170)).

   Under r5’s own boundary, a cumulative wire source can never be complete for a failed attempt lacking `PromptResponse`; nevertheless claimed repair says both attempts are accounted and leaves “when complete” open ([design:319](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/plans/acp-transport-design.md:319), [design:359](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/plans/acp-transport-design.md:359)).

   The design should require a version-pinned Devin emission guarantee that the final update covers all attempt spend; otherwise wire usage is unavailable even on success. For failed attempts, cumulative wire usage must be declared always unavailable unless a post-exit authoritative export/query supplies a final total. State that consequence separately for cumulative and per-attempt branches.

9. **HIGH — STRUCTURAL — P1 cannot produce the admission evidence r5 requires.**

   Admission `proven` requires both an admitted in-envelope request and a refused out-of-envelope request ([design:96](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/plans/acp-transport-design.md:96)). P1 provokes effects but sends only `reject_once` and `cancelled`; it never selects `allow_once` or verifies that an allowed effect actually executes ([design:439](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/plans/acp-transport-design.md:439)). ACP’s selected outcome must carry an exact offered option ID ([ACP v1 schema, lines 5302–5379](https://github.com/agentclientprotocol/agent-client-protocol/blob/main/schema/v1/schema.json#L5302-L5379)).

   P1 should exercise `allow_once` for each supported in-envelope effect, verify the intended effect and useful turn completion, then exercise the corresponding out-of-envelope refusal under separately pinned envelopes. It must cover read roots, write roots, network allow/deny, and tools runtime-default/read-only; approvals follows whatever certification contract finding 6 establishes.

10. **HIGH — STRUCTURAL — “Devin delegate transport only” understates a system-wide supervision cutover.**

    The stated scope is Devin ACP only ([design:31](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/plans/acp-transport-design.md:31)), but r5 changes the custody schema and terminalization rules for legacy records and every runtime’s reaper, drain, lease takeover, cancellation, deadline, adapter lifecycle, census, and record CAS ([design:168](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/plans/acp-transport-design.md:168), [design:196](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/plans/acp-transport-design.md:196), [design:479](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/plans/acp-transport-design.md:479)). These currently are generic cross-runtime owners ([reaper.go:107](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/internal/supervise/reaper.go:107), [drain.go:208](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/internal/missionrunner/drain.go:208), [sweep.go:80](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/internal/lease/sweep.go:80)).

    The design should either declare a system-wide delegate-custody migration—with legacy compatibility, rollout, rollback, and all-runtime tests—or gate the new generation/proof protocol to ACP-tagged records and leave existing terminal behavior explicitly unchanged. The present scope statement and blast radius cannot both be true.
