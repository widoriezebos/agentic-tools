# Draft: law-becomes-software (Wido's order, 2026-08-31 late evening)

His words, verbatim: "I don't like the ease at which you introduce new
laws. That can only lead to a 1000 laws soon that are impossible to
adhere to and maintain. We need to apply the metasystem way; which is:
everything is a feature and needs to follow that route and end up as
software."

The failure specimen: on 2026-08-31 one seat minted three
conduct-prose register rows in a single evening (the no-reservations
rule, the policy-critique rule, a supersession note). Each records a
real human word; none ends as software; each adds to a register a
human must remember and a seat must re-read forever. The repository
contract already forbids this shape ("machine-verifiable requirements
in schemas, tests, linters, permissions, or scripts, never in repeated
prose") and the register's own growth shows the contract is not
mechanical.

The feature this draft proposes (for the design route, per the
critique-first rule — not adopted by this draft):

- A ruling row becomes a WAYPOINT, never a destination: it carries the
  human's verbatim word and a link to the feature that will make the
  word mechanical. A conduct-bearing row without a software link is
  debt the existing ruling-review sweep surfaces (the sweep landed
  2026-08-31 and already reads every row — the check is one more
  column discipline, not a new mechanism).
- The two rows minted tonight get software homes as the first
  application: the load-tolerance rule lands as the re-aimed
  machine-concurrency goal's machinery (progress-based caps); the
  policy-critique rule lands as the change gate the agent contract
  already names — a policy change enters as a draft, takes the
  critique chain, and activates only on the human's word, mechanically
  refused otherwise.
- The register stops growing as law: new human words either fit an
  existing mechanism's configuration, or open a feature, or are
  explicitly marked memory-only by the human.

Paper authority (read 2026-08-31, docs/paper/12-learning-systems.md):
the chapter prescribes exactly this route — "an enforced rule is a
feature like any other," with per-rule governance (owner, review date,
appeal route, known-bad fixture that must keep failing) and marking-
mode trials before refusal power; it also warns that checks born from
incidents "pile up into ceremonies again, rebuilding Chapter 4's
problem in machinery," so the design must carry rule-retirement as
seriously as rule-creation. Its second branch bounds the register's
end-state: a lesson no reliable check can discriminate becomes a
question for human judgment, never a rule — such words stay as
verbatim memory, and the count of conduct-binding prose rows trends to
zero. The landed ruling-review sweep is the chapter's dated-records
watch already; the design should extend it, not duplicate it.

Status: draft awaiting the route — independent critique, then Wido's
word (his own critique-first direction applies to this proposal too).
