## 7. Amendment: how clause 5 is measured

Appended for the m1b seat on 2026-09-16 by a Fable design delegate, after three builds stopped at the same gap. It settles the wire behind lines 228 to 231 of this page, and it changes nothing that members one to three landed.

Clause 5 says: for each event, measure durable publication to the first resumed model turn consuming its wait result; every sample under 60 seconds; notification time, command return time and averages are not substitutes (`metasystem/plans/coordinator-wakes-on-events-not-polls-design.md:228`). Line 216 already fixes the source of inference starts: adapters supply them through `metasystem/internal/usage`, and missing native data is unavailable, never estimated. Line 219 says a "turn" here is one inference request. This section joins those two ends.

### 7.1 What exists, and the one gap

- A wait is a version-2 row (`metasystem/internal/run/waiter.go:134`). Since members A to C landed (commits c4e7d0f31, ba073f5ef, de01a54b2, 53c6d2ee7) the row carries the authenticated runtime session in `runtimeSession` (`metasystem/internal/run/waiter.go:150`), registration refuses without one (`metasystem/internal/run/waiter.go:445`), and the wait verb takes it from the announcement's effective runtime session (`metasystem/cmd/metasystem/wait_verb.go:157`, `metasystem/internal/lease/classify.go:48`). The row also records the adapter's delivery answer (`metasystem/internal/run/waiter.go:169`) and the accelerator state (`metasystem/internal/run/waiter.go:170`).
- A finished wait carries `WaitResult` (`metasystem/internal/run/waiter.go:90`) with `observedAt`, `returnedAt` (`metasystem/internal/run/waiter.go:101`, `:102`), `sourceEvidence`, `ledgerTip` and `terminalStamp` (`:98`, `:103`, `:104`). The row's `lastObservedAt` (`metasystem/internal/run/waiter.go:162`) is rewritten after every successful pending observation (`metasystem/internal/run/waiter.go:765`), so at the moment of the ready transition it still holds the previous observation. The ready transition is `finishV2` (`metasystem/internal/run/waiter.go:643`), which writes the result by compare-and-write on the nonce before anything else sees it.
- Every publication owner already calls `NotifyWaiters` (`metasystem/internal/run/wait_hint.go:137`) right after its durable write: the job transition (`metasystem/internal/dispatch/record.go:37`), the attempt terminal after `FinalizeAttempt` (`metasystem/internal/proofrun/launcher.go:492` and `:497`), the confirmed ledger publication (`metasystem/internal/goal/txn.go:500` and `:505`) and the landing script through the verb (`metasystem/scripts/agents/land.sh:66`, `metasystem/cmd/metasystem/wait_verb.go:234`).
- A usage sample is `CallSample` (`metasystem/internal/usage/calls.go:21`): runtime, session, invocationId, tokens, `at`, ordinal, source. Claude samples come from assistant transcript records (`metasystem/internal/usage/calls_claude.go:52`), sidechain records are skipped (`metasystem/internal/usage/calls_claude.go:75`, `metasystem/internal/usage/cursor.go:151`) and compaction boundaries become markers (`metasystem/internal/usage/calls_claude.go:60`). Codex samples come from rollout token counts (`metasystem/internal/usage/calls_codex.go:107`), with their own compaction marker (`metasystem/internal/usage/calls_codex.go:115`). `Calls(stateRoot, runtime, session, since)` (`metasystem/internal/usage/cursor.go:222`) returns the samples and markers of one session from a time. The steward registers each session's cursor (`metasystem/internal/steward/context.go:108`).
- The event recorder is `Emit` (`metasystem/internal/events/emit.go:43`). It stamps `ts` from the process's UTC wall clock (`metasystem/internal/events/emit.go:79`), refuses any event the registry does not declare (`metasystem/internal/events/emit.go:72`), promotes only six id fields (`metasystem/internal/events/emit.go:22`) and appends to `artifacts/agents/events.jsonl` under the state root (`metasystem/internal/events/emit.go:124`). The registry declares events under `events` (`metasystem/scripts/agents/event-registry.json:42`), each with `emitters`, `ids` and `payload`, as `job-created` shows (`metasystem/scripts/agents/event-registry.json:271`). `run` is an allowed component (`metasystem/scripts/agents/event-registry.json:10`), already used by the run verbs (`metasystem/cmd/metasystem/run.go:494`).

The gap is exactly one thing: nothing names the inference request that consumed a given wait's result. Nothing needs to be added to `CallSample`. The wait identity already reaches the consuming side through `runtimeSession`, because the usage store is keyed by the same runtime session. The join is made on that key plus time order, and 7.3 explains why that is a definition and not an estimate.

One key must be made identical before the join is trustworthy. The steward registers the usage cursor under the announcement's `SessionID` (`metasystem/internal/steward/context.go:217`), while the wait row stores `EffectiveRuntimeSession()`. Those are the same string on Claude today only because the hook writes the payload session at both places (`metasystem/scripts/agents/supervision-hook.sh:1552`, `:1568`, `:1075`; `metasystem/internal/lease/verbs.go:226`). The decision: the usage cursor is registered under `EffectiveRuntimeSession()` when it is set, and under `SessionID` only when it is not; `wait measure` (7.5) refuses to join when the two differ, with reason `session-key-mismatch`. This is one line at `metasystem/internal/steward/context.go:217` and it is in the builder list.

### 7.2 The events

Payload values are clipped at 256 bytes, which every field below fits. Emission is best-effort by design (`metasystem/internal/events/emit.go:43`): a dropped event never changes a wait's result, it only makes a measurement sample unavailable (7.4).

### 7.3 The carrier: the engine defines the consuming request from its own records

Decision: no adapter supplies a wait identity to the consuming side, no new verb asks the model to acknowledge a result, and no transcript text is matched. The consuming request is defined as:

> the first inference request of the wait's `runtimeSession` whose sample `at` is at or after the wait's `returnedAt`, ordinal-minimal among equal stamps, sidechain records excluded.

This is a definition, not an estimate, because two engine-recorded facts fix it:

1. One route (`metasystem/plans/coordinator-wakes-on-events-not-polls-design.md:122`): the seat runs one foreground `metasystem wait`, the runtime keeps that tool call open until the command returns, and the row records the adapter's answer `blocking` (`metasystem/internal/run/waiter.go:169`). While the call is open the runtime cannot start the next request of that session; when the call returns, the runtime cannot omit its result from the next request. So "the next request of this session after `returnedAt`" and "the request that consumes this result" are the same request by construction of the route, not by proximity in time.
2. The session key is authenticated at both ends: the row's `runtimeSession` comes from the same association the hook wrote (`metasystem/internal/lease/verbs.go:226`), and the usage cursor is keyed by that string (7.1's one-line change). The join never searches across sessions.

An estimate would be any of: choosing the nearest request in time, matching the printed result against transcript text, taking the notification's stamp, or averaging. None of those appears here. Where the two facts above do not hold, the sample is unavailable and says why (7.4); it is never filled in.

What each side supplies:

- The adapter supplies, through its existing seams only: the runtime session at session start and Stop (`metasystem/scripts/agents/supervision-hook.sh:1552`), the `blocking` answer to wait-delivery, and the usage stream its reader already parses. Nothing new is asked of any adapter.
- The engine records, without adapter help: the row, `wait-registered`, `wait-returned`, `seat-turn-ended`, and the publication owners' `wait-published`.
- A runtime that supplies neither a usage stream nor a hook gets the same wait guarantee from the rows (line 122 and section 4 already say so) and gets a measurement from records alone: its consumption witness is `seat-turn-ended`, emitted when its turn end reaches the gate through the plain `report turn-verdict` the delivery contract requires (`metasystem/docs/design/turn-verdict-delivery-contract.md`). That witness is an upper edge (the consuming request began somewhere between `returnedAt` and the turn end), so such a runtime can only pass clause 5 when its resumed turn ends within the bound. If its turn end never reaches the gate, the sample is unavailable and clause 5 is unproven for that runtime. That is the honest result: correctness of the wake is proven from the rows; the latency figure is bounded from the rows; nothing is invented.

A usage stream is the accelerator here: it tightens the upper edge from the turn end to the request itself. It is used only when the runtime's reader reports per-call capability (`metasystem/internal/usage/calls.go:16`); readers reporting `per-invocation` or `none` (`metasystem/internal/steward/context.go:340`) give no usage witness and fall to the turn-end witness.

### 7.4 The join, the clocks and the failure modes

The join runs over one state root's `events.jsonl` (`metasystem/internal/events/emit.go:124`) and the usage store (`metasystem/internal/usage/cursor.go:222`). The rows are not the retained input, because a terminal row lives only until the same key is registered again (`metasystem/plans/coordinator-wakes-on-events-not-polls-design.md:74`), which a seat does inside one turn when it waits twice on the same goal.

Which returns are events. A sample is made for every `wait-returned` with `state` ready and `atEntry` false: source outcomes with exit 0, 1, 2 (target timeout) and 3, and exit 6 actionable-work, which is a published human act on another goal. Deadline, interrupted and failed returns are not events; they are counted and listed but never sampled. An `atEntry` return is a publication that was durable before the seat waited, so there was nothing to wake; it is classed `already-published`, counted, listed, and excluded from the 60-second rule. Late registration as a way to hide latency is caught by clause 5's own polling proof over the full event stream (`metasystem/plans/coordinator-wakes-on-events-not-polls-design.md:231`).

Clocks. Every engine stamp is the seat host's UTC wall clock (`metasystem/internal/events/emit.go:79`; the waiter's `options.Now`), paired with the boot clock the waiter already samples (`metasystem/internal/run/waiter.go:163`). Each stamp is classed:

- `same-host`: written on the seat host by this installation. Job records and attempt terminals are same-host because dispatch and the proof launcher run there. The `wait-published` `ts` is same-host when `publisherHost` equals the seat's installation identity.
- `cross-host`: the ledger commit's own dates and a `wait-published` from another installation. These are recorded in the report and never used as an edge.
- `same-host-harness`: Claude's transcript and Codex's rollout are written by a process on the seat host from the same OS clock, so the harness stamp and the engine stamp differ by zero unless the clock stepped. The harness stamps its record at or after the request began, so a sample's `at` is at or after the true request start.
- `remote-harness`: a runtime whose usage stream is stamped elsewhere. Its usage witness is not clock-comparable and is not used as an edge; only the turn-end witness applies.

Edges. For one sample, with every stamp in the seat's clock:

- `publishedLower` = the later of `terminalStamp` when its writer is same-host, and `prevObservedAt`. The previous observation did not see the event, so the event was not yet durable at that read; the record's own stamp was written before the durable write completed. Both are true lower edges; the later is tighter. For a ledger event only `prevObservedAt` applies, which is why cross-host clocks never enter the arithmetic: the seat's own read cadence brackets the publication (ten-second rereads plus the fetch ceiling, or one hint-triggered reread).
- `publishedUpper` = the earlier of `observedAt` and, when same-host, the `wait-published` `ts` for that kind and target. If `wait-published` was dropped, `observedAt` alone stands; the sample is still available.
- `consumedLower` = `returnedAt`. A result cannot be consumed before it was returned.
- `consumedUpper` = the usage sample's `at` (witness `usage`), else the first `seat-turn-ended` for that `runtimeSession` with `endedAt` at or after `returnedAt` (witness `turn-end`).
- `latencyUpper` = `consumedUpper` minus `publishedLower`; `latencyLower` = max(0, `consumedLower` minus `publishedUpper`). The uncertainty recorded is `latencyUpper` minus `latencyLower`, and the report names which edge contributed it.

The rule. A sample passes when `latencyUpper` is below 60 seconds. It fails otherwise, and the reason names the loose edge: `witnessed-above-60` when the usage witness itself is beyond the bound, `turn-end-bound-above-60` when only the turn-end witness exists. There is no mean anywhere in the verdict; the report prints the raw samples and the maximum per runtime (`metasystem/plans/coordinator-wakes-on-events-not-polls-design.md:230`).

Clock steps. The waiter already fails a pending wait whose wall clock moved backwards (`metasystem/internal/run/waiter.go:701`). For the window after the return, `wait-returned` and `seat-turn-ended` both carry wall and boot stamps; if the wall delta and the boot delta between them disagree by more than one second, or their `bootId` differ, every sample whose window overlaps is `unavailable: clock-drift`. In the two-clone bed both clones run under one observer clock (`metasystem/plans/coordinator-wakes-on-events-not-polls-design.md:229`), so every stamp there is same-host by construction.

Unavailable, never estimated. A sample is `unavailable` with one of these reasons, and clause 5 is then unproven for that runtime until the reason is removed:

- `no-wait-returned`: the event was dropped; no row survives to stand in for it.
- `delivery-not-blocking`: the row's recorded answer is anything but `blocking`; fact 1 of 7.3 does not hold.
- `session-key-mismatch`: the announcement's `SessionID` and `EffectiveRuntimeSession()` differ for that main (7.1).
- `no-usage-cursor` combined with `no-turn-end`: no cursor is registered for (runtime, `runtimeSession`) and no `seat-turn-ended` for that session follows `returnedAt` before the stream ends.
- `no-witness-before-stream-end`: the stream ended (session end, or the measurement's cut) before either witness appeared.
- `clock-drift`, as above.
- `usage-reason-unknown`: the reader returned no sample and a reason string (`metasystem/internal/steward/context.go:344` lists them); the turn-end witness is then tried, and only if it is absent does the sample stay unavailable.

Recorded but not disqualifying: a compaction marker between `returnedAt` and the sample (`compactionBetween` true; the compaction request also carried the result, and the latency is the honest cost of it); sidechain records in between (they are not main-chain requests and are skipped by the reader); a `wait-published` that arrived after `observedAt` (a late hint; the edge takes `observedAt`).
