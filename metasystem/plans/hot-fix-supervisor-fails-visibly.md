# Hot-fix hf11: the proof supervisor fails visibly — every reading, verdict and signal result is a line in the unit's output, and no silent path lasts

Working Mode: Implement. Hand-landed hot-fix under the broken-machine rule (lane test findings 240-242, 2026-10-12). Worktree on main. One commit; never push. Production code ≤ 150 lines. No new timeout: ruling R-35-m3 forbids a watchdog that kills on slow; the supervisor's zero-consumption rule stays the only judge. No test may read ../../testing.json or plans/goals; no "witness" or "certification" tests.

## The defect
`internal/proofrun/supervisor.go` `superviseCommand` judged nothing for 36 minutes over a unit of internal/deploy whose tree had no CPU rise and no output (the window is 30 minutes). Three paths stay silent for ever and leave no trace: (1) line ~316 `identity.AliveRef(prober, rootRef) != Alive → continue` skips sampling with no reading, no counter, no reason; (2) line ~356 a `Stopped` or `Waiting` member records a reading only through `OnReading`, which the production launches (groups.go:182, test_build.go:1506, test_rerun.go:83) do not set; (3) line ~369 after the `dead` verdict the custody signal's result is discarded (which pids were signalled, which failed) and an idle tree gets ANOTHER full window before "killed while writing" — a signal that reached nobody is indistinguishable from a dump in progress. The group output (the proof log) therefore holds nothing of what the supervisor saw.

## Build
1. Every production launch passes `OnReading` and `OnVerdict` that append one line to the group's output through the same `activityWriter` tee the command writes to, WITHOUT marking activity (add a `note(line string)` to `outputActivity`/`activityWriter` that writes but does not Mark, so a supervisor line never counts as the unit's progress): `supervisor: reading <reading> at <RFC3339>`, `supervisor: verdict <verdict>: <reason> at <time>`. One helper `supervisorNotes(tee) (OnReading, OnVerdict)` used by the three launch sites.
2. Path (1): a non-alive root is counted; the first skip writes `supervisor: root <pid> not alive (<state>) at <time>`; after three consecutive non-alive samples the outcome records verdict `invalid` with reason `root identity <state> for three samples` and supervision ends through `stopAndWait` — never a silent forever.
3. Path (3): `signalCustody` returns the refs it signalled and the per-ref errors; the supervisor writes `supervisor: signalled <n> processes (<pids>); failed: <errors>`; when it signalled nobody alive, the dump wait is skipped and custody finishes at once (`dump: nothing to signal`). The dump wait that remains is bounded by the window as today.
4. `supervisorOutcome` carries `Readings []string` (the lines written) so the group result and the proof log keep them; `assignSupervisorOutcome` copies them into the GroupResult's Reasons when the verdict is not empty.

## Tests (scripted tree reader and prober, injected clock, as the existing supervisor tests do)
(a) a root the prober reports replaced for three samples → `invalid` verdict, three note lines in the output, the activity's Last() unchanged by the notes; (b) a `Waiting` member for one window → the reading line appears once, the verdict stays empty, the activity unchanged; (c) a dead verdict whose signal reaches no live member → the output holds the verdict line and `signalled 0 processes`, custody finishes within one sample interval, no second window; (d) a dead verdict whose signal reaches the members → unchanged behaviour (dump: complete) plus the lines; (e) the three launch sites pass the notes (a test launches a sleeping command through `runGoGroup`/the partition launcher with a 1-second window and finds the verdict line in the group output).
