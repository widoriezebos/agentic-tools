The R-35-m0 exception's cross-family examination: Sol held both pens;
Fable examined three times. Round 1: 7 findings (4 material, incl. the
critical both-pens specimen F-A - bar (a) narrowed to a shape check).
Round 2: 7 findings (3 material, incl. F2-1 catching the SEAT's own

## Round 1 (two-bars-joint-critique)

- F-A [critical|material=True]: Bar (a), the charter's closed-chain binding, was narrowed to fit the implementation: the evaluator verifies only the named chain record's shape (job-id grammar, self-naming, no parent, implementer role, design-bearing reach, chainClosed true) and never relates the landed change to that chain — the change digest is recorded beside the chain id but compared against nothing the chain produced, even though the chain's conformance reviewedTree and certified diff sit in the same artifacts directory. Design section 2.2 then defines the charter bar as exactly this shape check ('nothing broader'), and section 3 item 6 commits the future enforcement check to accept the wrapper-stamped bar (a) result without recomputation. An honest agent who names a stale or wrong closed chain under pressure — the D90 threat and the human's stated worry verbatim — gets a durable pass that the designed enforcement will also accept. This is the exception's known failure mode: a guarantee rewritten to say what the code happens to do. Remedy: bind bar (a) to the chain's conformance record (compare the candidate tree or change digest against the chain's reviewedTree or certified diff digest), or make the remote check recompute the binding and delete section 3 item 6's acceptance.
- F-B [high|material=True]: The certifying obligation matrix overclaims its test proof: row TB-OBS-02 (severity CRITICAL, status DONE) requires 'a closed design-bearing implementer root evaluates as bar (a) and other root shapes do not' and names TestObserveChainBoundLandingEvaluatesBarA as proof, but that test contains no open-chain, non-implementer, non-design-bearing, parented-record, or unreadable-record case — the five refusal branches of observeChain, including the implementer-only restriction that is the recorded fold of finding TB-LP-R3-09, have zero test coverage. A future edit could delete the role or closure check without any red. This is false verification evidence in the artifact that certifies the slice. Remedy: add the negative root-shape cases to the named test.
- F-C [high|material=True]: The never-direct-fix floor omits bin/, and on adopted non-Go checkouts the committed bin/metasystem binary is the landing-policy owner: commit.sh falls back to the checkout's bundled engine as the policy engine when no source builds. An exact-revert of a commit that updated that binary rolls the policy engine back to its previous committed version and receives pass bar=b, and the designed enforcement recomputation (section 3 item 5) passes it too, because the floor is the same. This contradicts section 2.3's own rationale that anything able to change the landing policy itself takes bar (a), and it is a fresh instance of the floor-omits-the-live-policy-owner class that finding TB-LP-R3-07 was accepted for. The metasystem source repository is unaffected (bin/ is gitignored there). Remedy: add bin/ and the committed engine filename to the floor.
- F-D [high|material=True]: Finding TB-LP-R3-09 is marked resolved by redefinition, but its surviving case is unaddressed: under the designed enforcement, an intermediate design-loop revision landed for cross-machine critique before any implementation exists — this goal's own practice, with design r2 landed at e0bd071c and r3 at 2ac5c546 — has no lawful bar at all: records/ is on the never-direct-fix floor (no bar b), and no closed implementer chain exists yet (no bar a), so the required check would refuse the design loop's own working rhythm. The design says 'design output is input to that implementation chain' without stating how multi-round in-flight design records land under enforcement. The disposition row closes the carried finding while this hole stands, which is the shape ruling R-25b exists to catch. Remedy: name the mechanism (design revisions ride the fold's implementer chain, or a recorded exception) in the enforcement design before promotion is offered to the human.
- F-E [low|material=False]: The code stamps a fourth provenance trailer form, 'Landing-Provenance: invalid change=<digest>', for conflicting or malformed declarations, but section 0's trailer grammar lists only the chain, direct-fix, and none forms — a design-code mismatch written by the same pen in the same round. No consumer exists yet and enforcement requires a pass verdict regardless, so nothing ships wrong. Remedy: document the invalid form in section 0.
- F-F [low|material=False]: The guard's durable fallback observation is best-effort and machine-local: mkdir failure returns silently and the printf is followed by '|| true', and the log lives under gitignored artifacts/, so section 1's 'the failure is no longer invisible' holds only when the local write succeeds and only on the machine where it happened; the promotion-range review reads commit trailers, never these per-machine logs. Acceptable for a non-refusing secondary record, but the design should state the bound. Remedy: one sentence in section 2.4 bounding the guard event's durability.
- F-G [low|material=False]: No test executes the real wrapper-to-evaluator contract end to end: TestObserveVerdictSurvivesLanding greps commit.sh for invocation strings and stamps the trailers itself, while the static-reproof fixture that does run commit.sh stubs both the 'landing observe' verb and 'json get'. The union of tests covers each piece separately and the field tags and verbs were verified by reading, so no defect is demonstrated — but a future drift in the JSON field names or verb dispatch would silently degrade every commit to the evaluator-unavailable fallback with no red anywhere. Remedy: one fixture leg running the real commit.sh against the real proof-built engine.

## Round 2 (two-bars-joint-critique-2)

- F2-1 [critical|material=True]: The tree staged to land is not the certified tree: the orchestrator's main checkout carries the uncorrected round-1 implementation and design record while the conformance certification and the round-3 return describe the corrected version. Landing from this checkout ships the predecessor's critical finding F-A unfixed (bar (a) passes on chain-record shape alone with no binding to the chain's reviewed output), the F-C floor gap (bin/ and the committed engine binary absent from the never-direct-fix floor), the F-B test gap (no negative chain-record cases), and the F-D design gap — all four accepted material findings — under a certification that claims them corrected.
- F2-2 [high|material=True]: The corrected bar (a) binding — the fix for critical finding F-A — locates the chain's conformance output where the real conformance tool does not write it: chainReviewedTree requires review.json in the greatest numeric round directory, but validate conformance writes review.json into the round directory named by the invoked job record's round, which is rounds/1 whenever it is invoked with the root job id, the practice actually used on the chain under review. Every real multi-round chain reviewed that way is refused as chain-output-unreadable — including this very certified chain, which its own bar (a) would refuse. The named test proves nothing because its fixture hand-writes review.json into rounds/2, a layout only the optional -rN invocation style produces. This is the both-pens failure mode the exception warned of: design section 2.2 states the code's locator as if it were the conformance seam, and matrix row TB-OBS-02's DONE status certifies behavior real chains cannot exhibit.
- F2-3 [medium|material=True]: Bar (a) requires the landing candidate tree to exactly equal the chain's conformance reviewedTree, which cannot hold under this repository's own landing practice: landings bundle orchestrator bookkeeping (rulings, narrator digest, goal and job records) with the implementation fold, and any base movement between review and commit also breaks equality. Honest, certified chain landings will therefore systematically record would-refuse chain-output-mismatch, filling the durable observation record the human must review at promotion with false refusals and making the observe slice's central obligation unmeetable in practice. The design itself advertises the change digest's stability under unrelated tree movement (sections 0 and 1) and offers a digest comparison for enforcement (section 3 item 6), but the implemented bar (a) never consults the digest.
- F2-4 [low|material=False]: The predecessor's non-material finding F-E persists: the code stamps a fourth provenance trailer form, Landing-Provenance: invalid change=<digest>, on reachable honest-mistake paths (conflicting --chain and --direct-fix, an orphaned --revert-of, a malformed chain id), while section 0 of the corrected design still promises exactly one of three forms — and the round-3 return claimed this was clarified. A small rule-R-11 truthfulness gap in the one-page explanation.
- F2-5 [low|material=False]: The predecessor's non-material finding F-F persists unchanged: the guard's classifier-unavailable observation is best-effort and machine-local (mkdir failure returns silently, the printf is followed by || true, and the log lives under gitignored artifacts/), while design section 2.4 still presents it as the durable secondary record without stating that bound.
- F2-6 [low|material=False]: The predecessor's non-material finding F-G persists: no test executes the real wrapper-to-evaluator contract end to end. TestObserveVerdictSurvivesLanding greps commit.sh for strings and stamps the trailers itself, and the static-reproof fixture that does run commit.sh stubs both the landing observe verb and json get, so a drift in JSON field names or verb dispatch would silently degrade every commit to the evaluator-unavailable fallback with no red anywhere.
- F2-7 [low|material=False]: Re-running conformance with the root job id after correction rounds overwrites rounds/1/review.json and rounds/1/diff.patch, destroying the earlier round's certified evidence: the round-1 review the predecessor critique cited (reviewedTree 50c47cc...) no longer exists anywhere, and the brief's round-3 artifact paths were never created.
