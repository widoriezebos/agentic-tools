3. **MF-R1-03 — CRITICAL — The proposed launch topology cannot both capture exit status and provide census custody.** A wrapper that waits and writes the exit line has a different PID from the suite and its agent-shaped descendants. The census does no ownership ancestry walk: it joins exact PID/start pairs, with existing multi-process custody explicitly enumerated through `custodyProcesses` and `instanceTag`. The run schema has neither. Registering the wrapper leaves the real agent children UNTRACKED; registering the command leaves the design without a stated process that waits for and records its exit. The implementer must invent the monitor/child topology and process-group or child-custody protocol. 4. **MF-R1-04 — CRITICAL — `run launch` has an unclosed launch-before-register race.** The proposed order is setsid → register, but strict registration correctly fails if identity has already disappeared. A fast command can therefore complete before registration, leaving no record or verdict; any later setup failure can leave launched work untracked. The existing delegate-job design solves the analogous problem with a pre-launch reservation, launch fence, and handshake. This design needs a starting state/start gate plus explicit rollback or cleanup behavior. 5. **MF-R1-05 — CRITICAL — The record cannot represent its promised lifecycle.** `verdictPattern`, evidence mode/source, acknowledgment, and “ended with unknown verdict” are described but absent from the schema; `run register` exposes no verdict-pattern flag. More seriously, an alive process becomes `hung`, which the design later calls terminal, while census ownership applies only to `running` records. It would immediately lose custody while still executing, and no transition back to running or onward to green/red is defined. Green continuations are never projected by the turn verdict, while vanished/unknown outcomes have no continuation or acknowledgment rule. A complete legal transition table and matching schema are required.

6. **MF-R1-06 — CRITICAL — Runs escape the checkout lease’s epoch and lineage rules.** Records contain only `sessionId` and informational `goalId`; they omit `mainId`, `ownerLineage`, and `claimEpoch`. A foreign takeover therefore cannot sweep, fence, or even identify a predecessor’s long-running process, while census continues labelling it owned inside the successor’s checkout. The design must decide same-lineage succession versus foreign takeover, stamp ownership coordinates, include runs in takeover handling, and recheck the epoch around launch/adopt mutations. Current ownership doctrine requires every ownership-related record to compare `claimEpoch`. 7. **MF-R1-07 — CRITICAL — The turn-verdict rule is both unrepresentable and unreachable under its stated precedence.** `ScanResult.Busy` items contain only kind, ID, and a 200-byte display detail—no owner session, watcher state, status, acknowledgment, or continuation. Because Busy is first, an unwatched running run placed in Busy produces “STILL WORKING” and never reaches the required block. 8. **MF-R1-08 — HIGH — Atomic replacement is not lifecycle serialization.** `conclude`, `adopt`, acknowledgment, and `prune` can race on the same file. A stale conclusion can overwrite an adopted successor; acknowledgment can be lost; prune can remove a record being adopted; two registrations can both pass uniqueness checks. Existing delegate-job records use a bounded per-record flock, compare-and-swap, and a lawful transition graph. The design must name the run record’s lock/CAS owner, expected-state behavior, ID collision rule, and which fields `adopt` resets. [Existing record serialization](</Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/internal/dispatch/record.go:102>)

9. **MF-R1-09 — HIGH — The authority statement conflates two different modes and proves identity, not custody.** `holder-only` and `record-writer` are not synonyms: record-writer also permits supervision, while adapter-supervisor access requires a matching job; HUMAN is deliberately unrestricted. Each verb needs a matrix row—especially watcher conclusion versus holder launch/adopt/ack/prune—and holder operations need operation-spanning lease fencing. Separately, probing a supplied PID proves only that a live process owns that PID; it does not prove the caller launched or owns it. As written, registration can convert an arbitrary live agent process from UNTRACKED to CUSTODY. A custody tag, launch token, ancestry/group proof, or explicitly restricted adoption contract is missing. [Authority implementation](</Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/internal/authority/authority.go:24>)

10. **MF-R1-10 — HIGH — Exit evidence has no trustworthy wire contract.** An unnamespaced line in the workload log can be produced accidentally, forged by the command, displaced by rotation, or followed by output from descendants retaining the file descriptor. The design also omits the tail byte bound, matcher grammar, duplicate-marker behavior, signal-exit mapping, and the outcomes for missing or unreadable logs. “Green iff matched” does not say whether a clean non-match is red or unknown. A separate run-ID/nonce-bound exit sidecar, or an equally precise protocol, plus a complete liveness × evidence outcome table is needed.

11. **MF-R1-11 — HIGH — “Unknown surfaces” is not wired end to end.** The current census custody loader silently skips unreadable and malformed custody records; copying that pattern for runs would quietly turn registered work into UNTRACKED without failing the census. At turn end, unreadable inputs can also be hidden by Busy because the hook renders `Display`, not the verdict’s diagnostics array. Finally, the unacknowledged rule covers only red/hung, omitting vanished and ended-unknown—the exact evidence failures that most need surfacing. Every run reader needs defined absent/unreadable/corrupt behavior and an unavoidable human-visible projection. 12. **MF-R1-12 — MEDIUM — Several public grammar decisions remain unstated.** The claim that every projected field is bounded is false for `log`, while `verdictPattern` is absent entirely. The design also leaves the prune age, `run status` collection shape, stale-threshold range, log path resolution/symlink policy, and conversion of launch argv into the persisted display command undefined. Naively joining argv risks persisting secrets. These choices change validation, output, and tests rather than being prose polish.

The flight recorder may narrate terminal transitions, but it cannot close these gaps: its contract explicitly allows lost final events and forbids machinery from treating the stream as authority. It therefore cannot be the reliable wake signal; a blocking waiter must decide from the authoritative record and kernel state.
