1. **MF-R3-01 — CRITICAL — Non-job runs still have no waiter-to-wake mechanism.** The new blocking command watches only delegate jobs. For runs, exchangeability says sessions read `run status` and receive the verdict through the hook, but neither operation can wake a session after its turn has ended. The real hook runs only when a Stop event invokes `report turn-verdict` ([supervision-hook.sh](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/scripts/agents/supervision-hook.sh:111)); the standing watcher only performs periodic work ([supervise_component.go](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/cmd/metasystem/supervise_component.go:117)). Recorder events cannot fill the gap because they are deliberately not messages. An implementer would build run tracking and eventual warnings, not the requested terminal-state monitor that resumes the session.

2. **MF-R3-02 — CRITICAL — The custody proof cannot survive the lifecycle it is meant to protect.** A wrapped run is owned only while the leader verifies through PID, start time, and the nonce in its argv. But the wrapper writes the sidecar as its last act and exits; during `draining`, surviving descendants remain in the process group while the leader is dead, so the stated proof fails and they become `UNTRACKED`. The shipped group-proof precedent instead looks for a tag on a live group member ([sweep.go](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/internal/lease/sweep.go:147)). Adopted processes have the complementary defect: an already-running process cannot acquire an engine-minted argv nonce, so neither `adopted-verified` nor `adopted-unverified` can satisfy the universal census rule. Adoption also lacks a precondition requiring the old generation to be dead or drained, allowing a live old group to be discarded. An implementer must either weaken the third factor or lose custody.

3. **MF-R3-03 — CRITICAL — `lease run-held` is not a fence for HUMAN callers.** The real implementation returns immediately to `runProcess` for HUMAN before acquiring the lease lock ([verbs.go](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/internal/lease/verbs.go:303)). Therefore wrapping HUMAN launch/register/adopt/ack/prune in the existing verb does not serialize them against takeover or other lease-held mutations, despite r3 calling it an operation-spanning fence. Closing this requires an explicit change to the lease contract or a run-specific lock order; merely wiring the verbs as designed ships the same race.

4. **MF-R3-04 — CRITICAL — The attestation cannot prove that current work is watched.** `{completedAt, ok, scanned}` carries no exact run IDs, generations, nonce digest, watcher identity, or supervision generation. A successful empty pass followed by immediate registration yields a fresh attestation for a run that was never scanned. Moreover, the real standalone `supervise watcher-pass` calls the same `WatcherPass` as the standing component ([supervise_watcherpass.go](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/cmd/metasystem/supervise_watcherpass.go:54)); placing attestation inside `WatcherPass` lets a one-shot invocation refresh it without leaving a watcher alive. An implementer could therefore mark a current run `Watched` from an unrelated or obsolete pass.

5. **MF-R3-05 — HIGH — The turn-verdict state table remains incomplete and internally inconsistent.** The unwatched rule covers only `running`, excluding the in-flight `launching` and `draining` states. `launch-failed` is terminal but absent from the warning list and has no continuation mapping; a fence-detected launch failure may never be acknowledged, so the ack-required prune cannot age it out. Run-reader errors are also assigned to the common `Unreadable` slice, while r3 simultaneously says Busy suppresses that ladder and requires Busy+Unreadable to display both. The current input has only one untyped unreadable collection ([turnverdict.go](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/internal/goal/turnverdict.go:28)), and Busy currently suppresses it ([turnverdict.go](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/internal/goal/turnverdict.go:167)). An implementer must guess whether to expose every unreadable outside the ladder or accidentally hide run-reader failures.

6. **MF-R3-06 — HIGH — Once-only digests confuse legally reused run IDs with old lifecycles.** R3 explicitly permits ID reuse after prune, yet the unwatched key is exactly the hash of the sorted ID set. A later run with the same ID produces the same digest and may never block that session. `greenDigests` likewise has no lifecycle-token definition. The facts handed to the verdict omit generation and nonce, so the verdict cannot repair this itself. The key must include a lifecycle identity, not only the public run ID.

7. **MF-R3-07 — HIGH — The promised event-registry rows are still only names.** The real registry contract requires each event’s component emitters, required identifiers, and every payload field with type and requiredness ([flight-recorder.md](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/docs/design/flight-recorder.md:74)). R3 does not specify those rows for `run-launched`, `run-transition`, or `run-swept`, nor whether the watcher emits as existing component `census` or new component `run`. The emitter authorizes literal component strings ([emit.go](/Users/wido/LocalStorage/GitHub/agentic-tools/metasystem/internal/events/emit.go:170)). An implementer could produce events that the catalogue silently drops or tests cannot validate consistently.

8. **MF-R3-08 — MEDIUM — The public grammar is not complete.** `windDownMin` has a default but no accepted range, although it directly determines how long live descendants retain custody. The log rule still does not decide absolute versus repository-relative paths, containment, symlinks, or revalidation after bind; “exists-or-creatable” does not answer the symlink-replacement issue raised in round 2. These choices change validation, what files may be read for verdict evidence, and timeout behavior.

The generation-scoped sidecar, single dead-without-evidence outcome, never-delete launch rollback, and explicit draining state are genuine improvements. They are not enough to stop: findings 1–4 require new interfaces or identity/fencing invariants, so this is not a round of contract polish. Because this is round 3, the first critique budget is exhausted; any focused successor should enumerate MF-R3-01 through MF-R3-08 as its carried worklist.
