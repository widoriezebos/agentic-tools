**2. The fit algorithm.**

Saving is measured as the rendered inline section minus the rendered reference section, so the heading, both newlines, the whole stanza and the final `OpenPath` bytes are all counted (`composition.go:414`, stanza built at `:362` from `canonicalReference`, never from the stage directory). Ties break by packet order because the scan runs in index order and the comparison is strictly greater (`:415`). It terminates: each pass marks exactly one previously-unreferenced eligible section, so at most five passes. It is deterministic across reruns: nothing in the decision depends on the stage directory, on map iteration, or on the filesystem; `TestComposeRolePacketFitsCombinedContinuations` recomposes with a different stage directory under the same root and requires byte-identical packets and records (`composition_test.go:443-457`). It cannot stop one replacement early: the loop condition is re-evaluated after each re-render (`:404`, `:434`). It cannot stop one replacement late: `bestSaving` starts at 0 and the comparison is strict, so zero and negative substitutions stay inline. Section savings are independent of one another, so the greedy reaches the true minimum candidate before refusing.

**3. Publication atomicity.**

On an impossible fit the function returns at `:428` with no `MkdirAll`, no `atomicfile.WriteText` and no directory creation anywhere earlier; `planReference` only computes paths. `TestComposeRolePacketRefusesWhenFixedPartsCannotFit` asserts `os.IsNotExist` for the packet, record, stage directory and both staged body paths, then repeats the same refusal against pre-existing sentinel files and requires `bytes.Equal` for each (`composition_test.go:800-828`). **5. `InlineInputLimitBytes`.**

Resolution goes through `capGet` and the existing `config.Get` owner, so flag, environment, `.local` overlay, base file and default are all the shell's own order (`composition.go:169`, `internal/dispatch/cap.go:25`, `internal/config/resolve.go:60-116`). Spelling is `capMinPattern`, `^[1-9][0-9]*$`, the same regular expression the shell uses; Go's `$` is end-of-text, so a trailing newline does not slip through. Whitespace from the environment is not trimmed by the resolver and is rejected by the pattern, matching the shell, and the test covers `" 64"` and `"64 "` (`composition_test.go:501`). Overflow is rejected before multiplying: `ParseInt` catches 9223372036854775808 and the explicit `limitKiB > math.MaxInt64/1024` catches 9007199254740992, with the maximum accepted product asserted as 9223372036854774784 (`composition.go:179-183`, `composition_test.go:496-499`).
