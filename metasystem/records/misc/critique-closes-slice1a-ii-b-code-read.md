## The seat's six questions

**1. Fold 1: is the promotion now exactly right?** No. The *promotion* is right; the *failure* is not. Everything the first read's F-1 asked for is delivered on the incomplete-root side: an absent, unreadable, failed, cancelled or still-running second root now yields no `hardBeforeStale`, its diagnostics land in `staleDiagnostics`, and they are dropped once another root matches the final tree. The new subtests are genuine red cases — I reconstructed the pre-fold verdict logic in an overlay and `TestMergeCritiqueIgnoresIncompleteStaleRootsWhenCurrentRootMatches` fails on it for both `running` and `cancelled`, with the exact "reported count None" failure the first read described. But the same edit also moved `len(materialIDs) > 0` behind `verdictReadable`, which is G-1: an older root with genuinely open findings no longer blocks when its count field is absent or the wrong JSON type. `exhaustionDiscipline` appends nothing when there are no `critiqueExhaustions` entries, and the register branch is not taken for a registerless root, so nothing else catches it. `verdictZero`'s value is unchanged in every case, so `exhaustionDiscipline` behaviour did not drift. No other caller wedges: `verifyOriginalCritic` and both recertification entry points call the same function and inherit both the fix and G-1.

A candidate correction that I ran green: keep the failure on the old condition and gate only the promotion, e.g.

```go
verdictCount, verdictReadable := jsonInteger(result["verdictMaterialCount"])
verdictZero := verdictReadable && verdictCount == 0
if len(materialIDs) > 0 || verdictCount > 0 {
        detail := "reported count " + quoted(verdictCount)
        if len(materialIDs) > 0 {
                detail = strings.Join(materialIDs, ", ")
        }
        failures = append(failures, "final round still has material findings despite any dispositions: "+detail)
        if verdictReadable || len(materialIDs) > 0 {
                hardBeforeStale = true
        }
}
```

With that in an overlay, the whole of `internal/validate` is green, `TestMergeCritiqueIgnoresIncompleteStaleRootsWhenCurrentRootMatches` still passes, and both material probes refuse again with `F-OPEN`. A nil verdict with no findings now also stops emitting the misleading "reported count None" line, which is a bonus the fold was reaching for. Whatever shape the builder picks, the fold needs a regression case for "material finding present, verdictMaterialCount absent" added to `TestMergeCritiqueClosureAndUnion`.

- Step 3: the ancestry walk covers P and every intermediate (loop index `len(ancestry)-2` down to `0`, so R is only ever a parent and keeps its own root-level checks), and enforces role, non-empty non-implementation session, `parentJob` naming the preceding member, `round == parent.round + 1`, `dispatchMode: follow-up`, equal `runtime` and `resumedSessionId == parent.sessionId`.
