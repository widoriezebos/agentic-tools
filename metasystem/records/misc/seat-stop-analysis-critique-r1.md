# Seat-stop analysis — Sol critique, round 1

Critic: codex gpt-5.6-sol (job ssa-crit-retry-1788332075, DESIGN-BEARING, fresh context) over records/misc/seat-stop-analysis.md as landed in 7c7bdb82. Persisted verbatim by the m0b seat, 2026-09-02.

## SSA-R1-EXISTING-VERDICT-OWNER — high
CLAIM: The design is founded on a false implementation premise: the engine and Stop hook already have one authoritative turn-verdict path, but the design asks an implementer to create a second command and also collapses two distinct identities. metasystem/scripts/agents/supervision-hook.sh already calls report turn-verdict, passing the runtime session identifier through --session and the authenticated main-process identifier separately through --main-id. The proposed metasystem turn verdict --session <mainId> would either duplicate the decision owner or erase that separation. The backlog item must be framed as changing the existing verdict contract and state machine, including migration of its current consumers and persisted state, rather than adding an independent verb.
EVIDENCE: metasystem/records/misc/seat-stop-analysis.md calls the command new. metasystem/scripts/agents/supervision-hook.sh lines 267-297 already invoke report turn-verdict and honor shouldBlock. metasystem/internal/goal/turnverdict.go owns the verdict state and precedence ladder, and metasystem/docs/design/turn-verdict-delivery-contract.md declares it the single engine decision.
MATERIAL: True

## SSA-R1-BLOCK-ONCE-BYPASS — critical
CLAIM: The shipped decision owner contains a deterministic second-attempt escape that directly defeats the proposed invariant. Open work, a current goal revision, a queued frontier, and unwatched work block only once for an unchanged signature; metasystem/internal/report/stopblock.go even promises that the refusal will not repeat. A seat can therefore answer the continuation with a hollow explanation and stop again without changing READY, starting relevant flight, or presenting HUMANSTOP. Unless the design explicitly removes or replaces block-once semantics, extending the existing verdict will preserve the exact conduct-based bypass that this mechanism is meant to close.
EVIDENCE: metasystem/internal/goal/turnverdict.go lines 363-425 persist previously blocked signatures and allow later unchanged attempts. metasystem/internal/report/stopblock.go lines 8-13 states that the refusal does not repeat for the same work. That conflicts with the proposed table in metasystem/records/misc/seat-stop-analysis.md, where only INFLIGHT or HUMANSTOP should make READY work exit-lawful.
MATERIAL: True

## SSA-R1-READY-HAS-NO-EXISTING-ADMISSION — high
CLAIM: READY cannot be computed as written by reusing one existing admission verdict. The canonical frontier only filters state, labels, blockers, and foreign machine pins. A queued goal may lack the human-chosen budget required to claim it, and final dispatch admission depends on an exact goal revision plus a concrete proposed job-minute cap. The current side-effect-free admission function evaluates already claimed goals owned by a machine-lineage pair; it does not answer whether a queued candidate can lawfully be claimed and advanced. Implementing the proposed predicate therefore requires either a new canonical, side-effect-free candidate-action admission interface shared with claim and dispatch, or a narrower READY definition. Copying the claim and dispatch checks into turn verdict would create the reimplementation and drift that the design says is grounds for rejection.
EVIDENCE: metasystem/internal/goal/project.go defines Next without budget or admission. metasystem/internal/goal/verbs.go refuses a claim with no complete stored or supplied budget. metasystem/internal/dispatch/admission.go evaluates claimed goals and later binds dispatch to revision and proposedCap. metasystem/docs/backlog-mechanism.md says queued work need not carry a machine budget because selecting limits is human judgment.
MATERIAL: True

## SSA-R1-READY-OWNERSHIP-SCOPE — high
CLAIM: READY is machine-scoped while the required verdict is seat-scoped, producing a deterministic two-seat false-refusal loop. The design counts a goal claimed by this machine, but actual claim authority is the pair of machine and owner lineage. Seat B on the same machine can therefore be told that Seat A's claimed goal is ready while Seat B cannot lawfully advance it; Seat A's flight does not excuse Seat B because INFLIGHT is separately per-session. The design must use the same ownership pair as claim admission and prove the two-seat outcomes with fixtures.
EVIDENCE: metasystem/records/misc/seat-stop-analysis.md defines claimed READY by machine but demands per-session coexistence. metasystem/internal/goal/verbs.go defines ownPair as machine and lineage and explicitly calls another lineage on the same machine a stranger. metasystem/internal/goal/project.go selects claimed frontier entries by machine alone.
MATERIAL: True

## SSA-R1-UNRELATED-INFLIGHT-LAUNDERS-IDLENESS — critical
CLAIM: The verdict recreates the incident's local-to-global reasoning error in code: any same-session INFLIGHT makes every READY goal exit-lawful. One unrelated long-running job, monitor, or ceremonial watch can therefore launder idleness on another ready goal indefinitely. This is worse than a nagging gate because the seat can satisfy it mechanically without advancing the frontier. INFLIGHT must be relevant to the ready frontier—normally joined by goal and revision or by another explicit capacity invariant—not merely existential within the session.
EVIDENCE: The table in metasystem/records/misc/seat-stop-analysis.md allows exit whenever INFLIGHT is true, with no relation between the ready goal and the flight. Job records inspected through metasystem/internal/dispatch/jobrecord.go and metasystem/internal/dispatch/record.go already carry goal identity, so a relevance join is representable rather than hypothetical.
MATERIAL: True

## SSA-R1-INFLIGHT-PROOF-MISSING — high
CLAIM: The stated INFLIGHT proof is not available from the cited records for the full lineage semantics, and nonterminal status is not liveness. A job record has mainId and a worker sessionId but no immutable ownerLineage. The live announcement can join a current mainId to ownerLineage, but metasystem/internal/lease/verbs.go deletes that announcement at retirement, so it cannot prove that a predecessor's surviving job belongs to a resumed lineage. Independently, a pending or running lifecycle value can outlive its waiter or process and therefore cannot prove that anything is progressing. The implementation must either narrow ownership to the exact current main-process identifier or stamp lineage durably into job records, and it must require a live waiter or equivalent process proof rather than status alone.
EVIDENCE: metasystem/internal/dispatch/record.go lists mainId, sessionId, parentJob, and status but not ownerLineage. metasystem/internal/lease/classify.go puts ownerLineage on process announcements, and metasystem/internal/lease/verbs.go Retire removes them. metasystem/internal/run/run.go records ownerLineage durably for monitored runs, while metasystem/internal/run/waiter.go implements a separate LiveWaiter check. The existing verdict in metasystem/internal/goal/turnverdict.go treats nonterminal work without a live waiter as unwatched, confirming that lifecycle status alone is not its liveness proof.
MATERIAL: True

## SSA-R1-HUMANSTOP-RELAY-LAUNDERING — critical
CLAIM: HUMANSTOP-by-relay is the authority-laundering escape the gate is supposed to eliminate. Existing temporary relay machinery explicitly cannot verify who supplied the words; any agent able to invoke that path can present three words and a review date. Treating such a record as equivalent to a human-classified stop lets the seat mint its own sole bypass while leaving an audit-looking artifact. HUMANSTOP must require proven human authority, or a separate human-ratified ruling must explicitly accept that unverified agents can stop work; the current relay path cannot be called an actual human word.
EVIDENCE: metasystem/internal/humanauthority/authority.go says ValidateTemporaryWordPair checks transport shape, the three-word requirement is not proof of provenance, TemporaryGoalProof carries no ancestry facts, and the package cannot verify who supplied the words. The proposal in metasystem/records/misc/seat-stop-analysis.md nevertheless authorizes HUMANSTOP from recorded relayed words and calls the result an actual human word.
MATERIAL: True

## SSA-R1-HUMANSTOP-CONSUMPTION-RACE — high
CLAIM: HUMANSTOP's lifecycle is not soundly specified. Consuming it at the next turn start does not bind consumption to the Stop decision it authorizes: a marker present before a turn could disappear before the relevant exit, while one created during a turn could survive its intended exit. Codex Stop continuation creates another prompt within the same turn flow and reports stop_hook_active; it does not imply a SessionStart event. The design also omits the marker's world, machine, lineage, runtime session, human directive or revision, expiry, and atomic compare-and-consume rule, so another seat or concurrent Stop attempt can steal or reuse it. Consumption must occur atomically with the allowed Stop verdict and be scoped to the authenticated human directive and intended seat or world.
EVIDENCE: metasystem/records/misc/seat-stop-analysis.md specifies only durable, single-use, and consumed by the next turn start. metasystem/scripts/enforcement/codex-hooks.json wires SessionStart only for startup, resume, or clear and wires Stop separately. The official Codex protocol supplies turn_id and stop_hook_active and says a blocking Stop creates a continuation prompt, showing that session start is not the relevant consumption boundary.
MATERIAL: True

## SSA-R1-FAIL-OPEN-IS-A-BYPASS — critical
CLAIM: Explicit fail-open on unreadable state makes the guarantee bypassable and omits the larger operational failure surface. The current hook also exits benignly or emits only a nonblocking system message when the engine is missing, runtime environment lookup fails, no Git root resolves, or turn-verdict returns an input/output error; the Codex Stop command has only five seconds. Corrupting or withholding any required state can therefore turn READY into quiet allowance. The design needs a complete outcome table for missing, unreadable, stale, timeout, identity-unknown, wrong-root, lock, and emission failures, with a machinery-owned recovery escape. An unknown decision cannot be treated as evidence that exit is lawful if the stated goal is to make unattended stops nearly impossible.
EVIDENCE: metasystem/records/misc/seat-stop-analysis.md failure mode 6 explicitly allows exit when the ledger is unreadable. metasystem/scripts/agents/supervision-hook.sh lines 26-30 and 60-65 exits successfully on missing engine or unresolved operational context, and lines 306-320 turns a failed verdict into a systemMessage without decision:block. metasystem/scripts/enforcement/codex-hooks.json gives Stop five seconds.
MATERIAL: True

## SSA-R1-STALE-BOARD-ALLOWS-EXIT — high
CLAIM: The proposed synced-ledger READY fact can be stale at the enforcement point. The existing accepted-tree projection used by the turn verdict reads offline with fetch disabled; older state merely receives a banner after thirty minutes. A remote machine can publish ready work after the local accepted reference, and this seat can then compute no READY and exit quietly. The contract must define a freshness proof or durable synchronization cursor and a non-allow outcome when freshness cannot be established; a diagnostic banner is not a correctness witness.
EVIDENCE: metasystem/internal/goal/project.go documents offline reads and only banners accepted commits older than StaleThreshold. metasystem/internal/goal/turnverdict.go convertedGoalFacts calls Project with fetchFirst set to false. The design calls the input a synced ledger without specifying a freshness boundary or mapping stale knowledge in its verdict table.
MATERIAL: True

## SSA-R1-STOP-HOOK-NOT-MANDATORY-OR-EXCLUSIVE — high
CLAIM: Codex Stop is a valid re-prompting enforcement point, so the design's rejection condition does not fire, but a repository-declared Stop hook is not an exclusive or mandatory gate. Official protocol says project hooks are skipped until their exact definition is trusted, non-managed hooks can be disabled, all matching hook sources run, and any matching Stop hook returning continue:false overrides continuation decisions. The repository itself records Codex as declared rather than live-observed. To claim nearly-impossible exit, the backlog item must own enrollment, trust, version compatibility, conflicting-hook composition, and runtime conformance—most robustly through a managed, non-disableable hook policy that excludes competing unmanaged hooks, or through an equivalent harness-integrated turn-finalization gate.
EVIDENCE: metasystem/docs/design/turn-verdict-delivery-contract.md marks Codex live observation pending. metasystem/scripts/enforcement/codex-hooks.json is only a shipped declaration. The official Codex Hooks documentation confirms both the continuation behavior and the trust, disabling, multi-source composition, and continue:false precedence rules. [Official Codex Hooks documentation](https://developers.openai.com/codex/hooks)
MATERIAL: True
