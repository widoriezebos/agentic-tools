## The seven checks, answered

**1. The liveness decision.** The prober is the package-local `handoffProber`, default `identity.KernelProber{}` (`internal/steward/handoff.go:14`), swapped only in tests. `AliveRef` is used without a tag, `AliveTaggedRef` with one (`internal/steward/handoff.go:86-89`). Unknown correctly holds and never launches, with `VerdictUnknown` on the decision, and this is well proven — mutation M8 (treat Unknown as dead) and M9 (drop the Unknown verdict) are both killed. A **slow** seat reads Alive (a stopped or busy process still exists to the kernel). A seat **on another host** reads Dead if no local process holds the pid, but this path only ever runs against a predecessor the same installation recorded, so I do not treat it as a live hazard. A seat that is merely **mis-tagged or whose argv read is short** reads Dead and launches — F-1, confirmed by probe.

**2. Exactly-once.** Sound for the paths that exist. "Held" is not a persisted state at all: it is the absence of a transition, re-decided from scratch inside the arbitration lock on every tick, so there is no stale decision to act on. The single atomic point is `ConsumeIntent` under arbitration (`internal/steward/revive.go:172`), and `decideForRevival` — including the liveness probe — runs inside the same critical section (`internal/steward/revive.go:78-118`). Two competing revivers produce one consume and one launch (`internal/steward/revive_test.go`, `TestCompleteRevivalHoldsThenLaunchesAHandoff`), though note that the test serialises them on the lock rather than racing the consume itself. A tick and a human `steward revive` both enter the same function under the same lock, and the verb resumes `live[0]` rather than minting a second intent (`cmd/metasystem/steward_verbs.go:446-455`). Death between deciding and launching errs toward stranding, never doubling: crash before consume changes nothing and the next tick re-decides; crash after consume leaves a consumed-unstamped record that `ConsumedActive` protects and no second launch can occur. Clearing the hold notice before consume (`internal/steward/revive.go:167-171`) is the right order — mutation M23, which moves it after, is killed — and a crash in that window self-heals because the next hold re-queues the notice.

**3. Supersession and cancellation.** A second handoff for the same seat is unit C, and in this tree it mutually deadlocks (F-11). A predecessor that is alive again is handled correctly: liveness is re-probed inside the arbitration section on every tick, so the decision cannot go stale, and the final outage recheck also holds rather than cancels (`internal/steward/revive.go:137-142`, mutation M14 killed). State-file verification failure at launch time is the weak spot: `decideForHandoff` only shape-checks the binding, so the byte-level digest, schema, manifest and staged-reference checks happen later in `authorize-dispatch` (`cmd/metasystem/steward_verbs.go:402`), i.e. after consumption — which fails closed (escalate, no launch) but costs the handoff permanently. A durably **absent** state file never even reaches that point and wedges revival instead (F-3).

**4. Expiry — confirmed, with one caveat.** `handoffExpired` ignores both of its arguments and returns false (`internal/steward/handoff.go:48-50`); the only other reference is through the single `handoffExpiryRule` indirection (`internal/steward/handoff.go:19`, `:82`). Mutation M7 (replace the default with a one-hour clock rule) is killed by `TestHandoffDefaultHasNoExpiry`, and mutation M6 (skip the consult) is killed, so both halves of the rule are proven. Nothing else reads a clock for this purpose: `revivalNow()` is sampled once and threaded (`internal/steward/revive.go:266`, mutation M20 killed), and it feeds only `outage.StandingAt` and `goal.ReadClaimableBudgetedWork`. `LiveIntents` has no age filter (`internal/steward/intervene.go:289-316`) and there is no intent sweeper, so a hold can persist indefinitely. The dry-revival cap and the outage guard sit **after** the liveness branch and are unreachable while the predecessor is alive or unknown, so they cannot decay a hold either (mutation-proven: `alive predecessor dominates later guards`). The caveat is consequential rather than a code defect: while a handoff is held, the tick reads it as an active continuation and `ResumableIntent` returns it every tick, so an indefinitely held handoff also suppresses ordinary dead-worker revival for that checkout, forever. That is the cost of the no-limit default and belongs in front of Wido with F-8.

**5. State-root containment — clean.** Every path in the unit is derived from the caller's root: `pendingDir`, `intentsDir`, `cancelledDir` from `repoRoot`, and `HandoffDir` canonicalises with `filepath.Abs` + `EvalSymlinks` before joining (`internal/steward/handoff.go:36-44`). `validateHandoffBinding` pins the state path to the exact canonical owned path and refuses a symlink escape (`internal/steward/handoff_state.go:372-386`). No environment variable, no OS temp directory, no absolute literal, nothing touching the diagnostic root. Two notes only, neither reachable: F-13 (unvalidated nonce on the cancel path) and F-16 (root-resolution convention differs from unit D's).

## Verdict

**Not fit to land as it stands.** Five material findings, two of them high and both landing on the same failure the unit exists to prevent — one seat with two live sessions on one goal.

What must change before this lands:

1. **F-1** — stop using `identity.AliveTaggedRef` as a launch authority. A readable argv without the recorded tag on a process whose pid and start time still match the binding is `stale`, not dead; it must **hold**, the way `identity.TagState` and `CustodianLiveness` already classify it. Change `internal/steward/handoff.go:87-89` and invert the assertion in `internal/steward/revive_test.go:456-468`, which currently locks the unsafe outcome in.
2. **F-2** — admit the worker census to the handoff decision. A live worker on this machine, an incomplete census, or any untracked or unprovable record must hold, not launch; the predecessor's death proof answers "is the predecessor gone", not "is the seat free". Add a live-main and an incomplete-census case to `TestDecideForRevivalHoldsUntilThePredecessorIsDead`, which today passes `deadCensus()` in every subtest.
3. **F-3** — give a durably absent or invalid state target the terminal path the brief specifies, distinguishing it from a transient read error, so a lost snapshot cannot wedge every future revival on the checkout.
4. **F-4** — do not hold the steward arbitration lock across the external notifier. Decide authorization under the lock, release, then deliver.
5. **F-5** — either drop the unlocked-snapshot re-read or add a test that fails without it; a rule whose own named test passes with the rule removed is not proven.

F-9, F-11 and F-16 are not B2 defects but should be settled before unit C lands. F-8 and the note under check 4 are the concrete cost of the unanswered expiry decision and belong in Wido's hands with that question.

## The six checks, answered

**1. The five folds, individually.**

- **F-1, tag miss.** Correct and complete. `handoffPredecessorLiveness` (`internal/steward/handoff.go:130-147`) joins one probe to the recorded ref and returns `Unknown` for a matched identity whose expected tag is missing or unreadable, `Dead` only for a kernel-proven death or a genuinely reused pid, and `Alive` without an argv read when no tag was recorded. A tag miss holds on every path that can launch, because there is exactly one such path: `CompleteRevival` -> `decideForRevival` -> `decideForHandoff`, and `authorize-dispatch` refuses anything that is not an already-consumed, unstamped intent from a steward-classified caller (`cmd/metasystem/steward_verbs.go:393-400`), so `delegate --revive` cannot bypass the decision. The identity package is untouched: `git status` lists only the six steward files plus the untracked test, and `identity.AliveTaggedRef` keeps its signal-side callers in `internal/supervise/arming.go:271,583` with unchanged semantics. One deliberate difference from `identity.Custodian` is safe in direction: the new helper uses exact-token matching only, so a composite argv element such as `--instance-tag=foo` reads as `Unknown` and holds where `Custodian` would substring-match it alive.
- **F-2, worker census.** Consulted, but not in the same way the ordinary ladder consults it, and that is G-1. The ordinary ladder reads `Workers` only when `Work == WorkOwned`; when a live delegate makes the backlog in-flight it returns `healthy/none` without reading `Workers` at all (`internal/steward/verdict.go:96-129`). The handoff path reads the census unconditionally and holds on any of `Live > 0`, incomplete, untracked or unprovable. That is strictly safer against displacement and strictly stricter than the brief. No live or doubtful worker can be displaced by any route: the single launch route is the one above, a census error becomes `Workers{Unprovable: 1}` (`internal/steward/revive.go:242-245`), and a census that cannot prove a scan holds.
- **F-3, missing state file.** Folded for the named case and proven (M8). A structurally valid binding whose target returns `ENOENT` returns `ActNotify`, `CompleteRevival` cancels through the existing terminal path, `CancelIntent` writes the tombstone carrying "state file is missing" and clears the hold notice, and `TestMissingHandoffStateFileCancelsThroughTheTerminalPath` proves the whole transition including the empty pending queue and the tombstone cause. Two residues: G-2 (the classification also catches a root-resolution ENOENT and mislabels it) and G-3 (non-ENOENT durable failures still wedge).
- **F-4, arbitration around delivery.** Removed and proven (M9). `DeliverPending` and `deliverPendingHandoff` take no lock; `TestHandoffNoticeDeliveryDoesNotReacquireArbitration` calls delivery from a caller holding arbitration and completes inside a one-second guard. Nothing the author thought it was protecting came back: what the lock was protecting is the "no stale notice after a terminal transition" rule, and that is now carried by the authorization recheck, proven by `TestHandoffNoticeAuthorizationIsRecheckedBeforeDelivery`, which drives the exact interleaving (snapshot, then launch, then resume) and observes zero deliveries and an empty queue. The residual window — authorized, then launched, then delivered — emits one stale informational notice, which the brief explicitly declines to exclude ("do not claim once-ever notification delivery"). The one new edge it opens is G-7.
- **F-5, the arbitration re-read.** Removed, and the removal itself is proven in reverse (M10): reintroducing a second queue read fails `TestHandoffNoticeDeliveryUsesTheInitialQueueSnapshot`. The authorization half is proven three ways (M11, M12, M13).

**3. Terminal cancellation for a missing state file.** It can cancel something that should have been kept only through G-2's root-resolution path, which is near-unreachable mid-tick. One ENOENT observation is taken as durable with no confirming second look, which is the right call for a file the installation itself owns. It is recorded in the tombstone under `cancelledDir(root)/<nonce>.json` with the exact cause and in `ReviveOutcome.Reason`; it is not announced to the operator (G-4), and the work itself is picked up by the next ordinary revival without the captured state.

## Verdict

**One material finding: not yet fit to land.** Four of the five folds (F-1, F-3 for its named case, F-4, F-5) are correct, complete and proven by named tests, and nothing the first read verified was disturbed. The fifth, F-2, is folded in a way that is safe against displacement but contradicts the brief's explicit rule that a running goal job belongs to the successor's work snapshot, and the subtest that carries that rule in its name cannot detect the contradiction. The seat must adjudicate G-1 one way or the other: narrow the census term at `internal/steward/handoff.go:99` so a delegate job or monitored run does not hold a successor, or accept the stricter rule and change the brief sentence together with the name and fixture of `internal/steward/revive_test.go:658`. Either disposition changes an artifact; leaving both as they are ships a handoff that refuses to launch in the case the handoff state schema was designed for.
