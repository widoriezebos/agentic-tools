### HCL-C-75 (medium, material)

Claim: Mandate 3 does not hold. The crash-local leg's checks cannot tell a recovery that keeps the local commit from one that resets it and commits again (a restamp), and the leg never moves origin, so it does not drive the rebase HCL-19-RECOVERY-KEEPS-REBASED-COMMIT is named for. In this leg origin stays where it was between the kill and the rerun. SIGKILL means the exit trap writes no abandon row. The rerun's steps before the push are only fetches, the read-only 'landing carry-status' and a local journal entry (land.sh:868-924, 780-816). So the rebase in the local: branch (land.sh:910-916) does nothing, and the rerun pushes the first run's commit unchanged. The leg's five checks (land-fixtures.sh:807-822) are: one commit on origin with the Carry trailer, an equal workspace projection, one open carrying row, one landed carried row, one counselor line. A recovery that ran 'git reset --soft origin/main' and committed the same index again would pass all five. The new commit would carry the same trailer and the same payload, keep the same open reservation, and write one carried row and one counselor line. Nothing else in the path would stop it: 'goal carrying --commit' (internal/goal/verbs.go, func Carrying, commit branch) marks a dead owner's carried intent entry terminal ('superseded by rebuilt carried intent') and creates a fresh entry for whatever commit it is given. The design's HCL-06-CRASH-BEFORE-PUSH-RESUMES oracle says the rerun 'pushes <sha> (origin unmoved)' (design 1236-1239). HCL-19's setup is 'origin moved by a ledger commit' (design 941-945). The fold's 'not the sha' guarded against comparing origin's tip, which ledger commits follow. The code commit found by its trailer is a different thing. What changes if it stands: in this leg, assert that the code commit found by git log --grep '^Carry: <word>$' equals local_commit. That holds because origin does not move here, and it is not a comparison with origin's tip. To prove HCL-19 as named, move origin with a ledger commit (for example a goal note) before the rerun. Then assert that the found commit's parent is the moved tip and that its author line and full message equal local_commit's. A rebase keeps both; a restamp does not.

Evidence: Read land.sh:236-261 (the exit trap abandons only when armed), 615-630 (the new SIGKILL seam), 762-778 (ensure_recovery_reservation keeps an open row), 780-822 (create_carried_intent calls goal carrying --commit), 848-866 (finish_carried_publication), 868-924 (run_carried_landing and the local: branch). Read land-fixtures.sh:753-824. Read design lines 800-815, 941-945 and 1236-1239. Not driven as a mutant through the bed, which needs the host.

The admission rebuilds the expected line from that stored reason (internal/landing/observe.go:270) and requires the staged line to match exactly (internal/counselor/register.go:149). So '--why "paid "' writes a register line that no ledger row matches, and the next carried landing refuses record-not-owned. Rerunning accept-risk does not help, because the replayed line gets a new recordedAt that the stored row does not have. Nothing refuses the accept-risk itself: ValidateCommit parses and validates without re-rendering, and the integrity digest does not object. What changes if it stands: trim or refuse trailing whitespace in --why before either write, or have the admission compare the stored form on both sides.
