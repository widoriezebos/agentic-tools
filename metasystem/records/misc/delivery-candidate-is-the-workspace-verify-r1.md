## Riskiest part, as the verifier wrote it

Step 4 contradicts the brief. After the second clone appended a comment to scripts/agents/coverage-delta.sh and pushed, the first clone's landing was refused (land.sh exit code 1) and origin's main stayed at the peer's commit B. But the refusal came from a different rule than the one the brief expects. land.out contains no "proof-input-moved-after-receipt" line, no test group id and no mention of coverage-delta.sh. Instead, the step "verify shared testing proof after rebase" failed with "metasystem test verify: TEST_POLICY_ENGINE_REQUIRED: retained destination engine does not bind the captured policy base: enrolled source <seed commit> and destination <B> have different ENGINE projections". The cause, read from the source: metasystem/internal/behaviorsurface/policy.v2.json lists "scripts/agents/**" among the engine paths (unchanged between HEAD and the reviewed tree). So any change to that script changes the engine's identity, and the steward's engine-binding check (metasystem/internal/steward/rearm_resolver.go, lines 348-349) refuses before the per-group input comparison ever runs. The chain's own test bed does not catch this. Its equivalent leg (input-move-refuses in metasystem/scripts/agents/land-fixtures.sh of the reviewed tree) edits scripts/application-input.txt, which is a declared test input but not an engine path, instead of the coverage-delta.sh the design (section 8.2) and the brief name. The safety outcome held (nothing reached origin), but the promised diagnostic did not appear for the path the brief names. Per decision D3 I stopped on this step and did not look for a path that would produce the expected text.

That binary (build stamp cbe443a41) refused to take a receipt in the scratch repository because its stamp is not a commit there. - In step 3, land.out itself does not show that site 8 reached test verify (land.sh prints a step's output only when the step fails). That was observed through an argument-logging METASYSTEM_BIN wrapper that execs the same engine binary.
- Each scratch repository arms a steward process with its own registry. Enrolled-engine resolution against a real installation, and the real repository's live landing, were not exercised. Both are outside what this bed can reach.
- Not driven: the drift probes inside the ledger leg (an unstaged or restaged payload after the receipt), and the second half of the bed's receipt-cutover leg (an old engine plus the new land.sh refusing an old receipt after a ledger move).
- My first round of step 2, 3 and 4 runs had a driver bug (the message was passed as text where land.sh expects a file), so those landings stopped before any product logic. I discarded them and reran. The step 6 run from that first round is valid and is the one reported above.
