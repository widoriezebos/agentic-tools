## What checked out clean

- **Arming and disarming boundaries (task item 2).** The boundary is set only immediately before each of the three named calls and cleared immediately after each (`scripts/agents/dispatch.sh:1749`, `:1757/:1759`, `:1862/:1864`); `arm_refused_workspace_cleanup` is a no-op while the tuple is empty (`:182`); `disarm_refused_workspace_cleanup` clears the whole tuple before `claim-launch` (`:1903`); `follow_up()` never sets it. I verified in bash 3.2 that a script's EXIT trap does **not** fire inside a command substitution subshell, so `input_bytes=$(enforce_inline_input_limit ...)` cannot run cleanup twice.
- **Exit code and evidence (task item 3).** Cleanup runs inside the EXIT trap before `release_chain_lock` (`scripts/agents/dispatch.sh:1689`), `cleanup_refused_workspace` always `return 0` and never calls `exit`, so the `die` status survives. On failure it prints the boundary, the retained workspace/ref and the cause to stderr (`:186-198`, with the Go message at `refused_workspace.go:81-86`). The retry legs assert the identical 64-hex evidence token across an unchanged retry (`scripts/agents/dispatch-fixtures.sh:3445-3448`, `:3532-3534`).
- **Serialization against the claim.** `TestCleanupRefusedWorkspaceSerializesWithClaim` (`internal/dispatch/refused_workspace_test.go:216-318`) uses real barriers and a non-blocking flock probe, with no sleeps or liveness guesses, as B-10 requires.
- **No vacuous cleanup assertions (task item 5).** Every leg carrying `assert_refused_workspace_removed` passes `--worktree`, so `git worktree add` runs at `scripts/agents/dispatch.sh:1703` before the refusal; had arming failed, the workspace would remain and the assertion would fail. The gap is coverage of a boundary (F-3), not a vacuous assertion.
- **Scope of trusted state (task item 6).** No coverage floor, `testing.json` or role text change in the working tree. `memory/receipts.log` is the one exception (F-5).
- I ran `go test ./internal/dispatch -run RefusedWorkspace -count=1`: ok, 3.695s.

## Verdict

**Not fit to land.** Five material findings.

Minimum that must change:

1. Stop rewriting the shared alternates file. Implement step 3 as written - publish the quarantine on the fresh `WON` path and keep cleanup out of alternates entirely. That one change closes F-1 and F-2 and removes F-7 and F-8 with them. If the seat instead wants publication to stay at creation, the alternates edit needs a lock keyed on the shared Git common directory, not on the checkout, and the deviation needs to be ruled on explicitly because the amendment forbids it by name.
2. Add the `refused-workspace-subject-mismatch` leg with `--worktree` so the `read-subject` arm has end-to-end proof (F-3).
3. Arm the inline-input boundary for every fresh dispatch that created a worktree in this invocation, not only the two critic roles, or get the narrowing ruled by the seat with B-9's source incident named (F-4).
4. Drop the `memory/receipts.log` row from this change, or give it a `goal=` (F-5).

On the seat's "smallest correct form" question: this is not the smallest form of the amendment, it is a different form. It drops what the amendment requires (the creation token, the ownership marker, the move of publication to `WON`) and adds what the amendment forbids (removing shared alternates entries) plus a new engine verb to serialize that removal. The riskiest single operation in the change - a whole-file rewrite of state shared by twelve checkouts - is one the amendment's own design does not contain.
