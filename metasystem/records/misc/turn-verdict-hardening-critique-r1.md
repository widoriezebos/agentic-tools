# Turn-verdict hardening design — Sol critique, round 1

Critic: codex gpt-5.6-sol (job tvh-crit-2, DESIGN-BEARING, read-only) over plans/turn-verdict-hardening-design.md revision 1. Nine material findings (five critical). Persisted verbatim by the m0b seat, 2026-09-02.

## TVH-R1-CLAIM-ADMISSION-OMITS-AUTHORITY-AND-REPLAY — high
CLAIM: The proposed ClaimAdmission is not the canonical proof that a claim would succeed. The design says it extracts metasystem/internal/goal/verbs.go lines 436-470 and is called first by claimRequest.Mutate, but the real claim also calls bindClaim at line 475, which refuses a non-positive authenticated claim epoch. The proposed signature carries neither the epoch nor lease-holder authority. Consequently an advisor with free machine quota can be classified as R2 READY even though the advertised goal claim command deterministically fails. Calling ClaimAdmission before opidLanded also makes a replay of an already successful operation fail admission before it can return AlreadyApplied. The shared function prevents its internal checks from drifting, but its two call sites still disagree because their request and replay inputs differ.
EVIDENCE: metasystem/plans/turn-verdict-hardening-design.md section 1.2 says R2 is exactly 'would goal claim succeed' and that calling ClaimAdmission first makes disagreement impossible. metasystem/internal/goal/verbs.go lines 440 and 475 respectively implement operation replay and the additional positive-claim-epoch check. metasystem/cmd/metasystem/goalsync_mutations.go lines 59-69 leave ClaimEpoch zero for an advisor. This also refutes fail-closed table row F8's statement that an advisor has no READY 'by construction'.
MATERIAL: True

## TVH-R1-R3-NAMES-ILLEGAL-EXIT — critical
CLAIM: R3 held-releasable names an illegal recovery move for the fenced goals it intentionally includes. The design says a fenced or budget-closed claim becomes READY because the seat can run goal park on the held goal or goal done and then claim the queue. In the current engine, release, park, and done all call clearClaimBinding, which refuses every breach-stopped goal and states that only goal resume may clear its launch fence. Resume is a human-authorized transition. Moreover, the converted command parser does not accept the advertised goal park --then operation. A fenced seat is therefore repeatedly blocked on a move it cannot lawfully perform, exactly matching the design's own two-seat/refusal-loop rejection condition.
EVIDENCE: metasystem/plans/turn-verdict-hardening-design.md line 98 includes fenced claims in R3 and advertises 'goal park <held> --then <g>' or done as the move. metasystem/internal/goal/verbs.go lines 128-136, 653-668, 743-780, and 832-873 show the common fence refusal. metasystem/cmd/metasystem/goalsync_mutations.go lines 104-159 define no --then flag and lines 232-241 route converted park directly to goal.Park.
MATERIAL: True

## TVH-R1-SLICE1-IGNORES-GOAL-BOUND-GOVERNED-RUNS — critical
CLAIM: Slice 1 knowingly ignores a relevant progress record that already has every required join key. The design calls goal-bound governed runs an unread gap and postpones them to slice 2, but run records already contain goalId, governed.goalRevision, ownerLineage, claimEpoch, and live process or waiter evidence. A seat actively advancing its READY goal through such a run will be refused on every Stop in slice 1. This is the false refusal the design explicitly says should reject it, so the run join must be part of the first specimen-refusing slice rather than a residual.
EVIDENCE: metasystem/plans/turn-verdict-hardening-design.md lines 191-194 and 399-401 say the run binding was not read; lines 438-440 make a bound run ignored by slice 1 a rejection condition. metasystem/internal/run/run.go lines 114-130 and 160-181 contain GoalRevision, GoalId, OwnerLineage, and ClaimEpoch. metasystem/internal/report/scan.go lines 192-239 already reads these records and their process/waiter liveness, although the current goal.RunFact projection drops the binding fields.
MATERIAL: True

## TVH-R1-JOB-LIVENESS-DOWNGRADES-EXACT-IDENTITY — high
CLAIM: The relevant-job live process test weakens new records from platform-exact identity to legacy whole-second identity. New job ownership records contain Darwin start microseconds or Linux start ticks plus boot identifier, specifically so a reused process identifier cannot inherit authority. The design reconstructs only Ref{pid, pidStartedAt}. A different process that reuses the same identifier within the recorded second can therefore be reported Alive and make READY exit-lawful. The live-waiter branch is exact and sound; the direct process branch must consume the record's full native identity and treat incomplete exact data as unknown.
EVIDENCE: metasystem/plans/turn-verdict-hardening-design.md line 172 specifies only J.pid and J.pidStartedAt. metasystem/internal/dispatch/ownership.go lines 9-13 and 55-96 write exact platform fields. metasystem/internal/identity/identity.go lines 21-30 and 72-93 explain that seconds-only comparison is the weaker legacy mode; lines 128-135 perform that weaker comparison. metasystem/internal/run/waiter.go lines 195-209 demonstrates the sound exact waiter comparison.
MATERIAL: True

## TVH-R1-FRESH-CURSOR-IS-NOT-A-CURRENTNESS-WITNESS — critical
CLAIM: The ten-minute synchronization cursor is a recent-history banner, not a correctness witness. After a successful fetch writes cursor tip A, another machine can publish READY work at tip B one second later. For the next ten minutes this seat's cursor still matches its accepted projection A, so the design declares FRESH, computes no READY, and allows the Stop without attempting a fetch. The proposed rule therefore preserves a deterministic stale-board allowance for up to ten minutes.
EVIDENCE: metasystem/plans/turn-verdict-hardening-design.md lines 273-284 accept a cursor solely because checkedAt is within ten minutes and its tip equals the local projection. metasystem/internal/goal/fetchadvance.go lines 26-81 proves only the fetched canonical tip at the instant FetchAdvance runs. metasystem/internal/goal/project.go lines 28-46 confirms subsequent offline projections keep reading the accepted ref. No cursor fact proves that the remote did not advance after checkedAt.
MATERIAL: True

## TVH-R1-HUMANSTOP-CANNOT-RESCUE-DECISION-OWNER-FAILURES — high
CLAIM: The fail-closed contract promises a HUMANSTOP escape in states where the decision machinery cannot observe or consume one. With a missing engine, unknown world root, unavailable or unparsable turn verdict, or failed goal flock, the hook never completes the compare-and-consume path. Even a marker set in advance cannot authorize that Stop. The offline F16 case has a functioning HUMANSTOP path, but its only offline exit remains a fresh human directive, contrary to the earlier requirement for a machinery-owned recovery escape. The table must distinguish failures recoverable by HUMANSTOP from failures that require repairing the decision owner; its present universal 'unless HUMANSTOP' precedence is false.
EVIDENCE: metasystem/plans/turn-verdict-hardening-design.md lines 207-210 promise every block reason the one lawful human exit, rows F1, F2, F10, and F11 cover states in which the engine, root, verdict, or lock is unavailable, and precedence lines 372-375 says any unknown blocks 'unless' HUMANSTOP. HUMANSTOP consumption is specified only inside TurnVerdict's flock at lines 330-347. Lines 286-290 explicitly make a human word the only offline exit for F16.
MATERIAL: True

## TVH-R1-FAIL-CLOSED-TABLE-OMITS-PREVERDICT-SHELL-EXITS — critical
CLAIM: The twenty-one-row fail-closed table does not cover all shell paths that can terminate before a block is emitted. The shipped hook runs with set -e and has unguarded directory resolution, payload mktemp, payload cat, supervision-directory creation, and response construction operations. Several occur before world identification or verdict handling, and an error exits without decision:block. None maps to F1-F17 or the two admitted emission/runtime residuals. An implementer following the table can leave deterministic fail-open exits in place.
EVIDENCE: metasystem/scripts/agents/supervision-hook.sh lines 2, 23-24, 42-44, 263-265, and 273-321 show unguarded operations before final emission. metasystem/plans/turn-verdict-hardening-design.md lines 201-203 claim every outcome the hook cannot vouch for becomes a block, but rows F1-F21 do not assign these failures an outcome.
MATERIAL: True

## TVH-R1-STOP-DEADLINE-DOES-NOT-BOUND-EMISSION — critical
CLAIM: The Stop-budget mechanism does not guarantee emission before the runtime timeout. Adding context.WithDeadline does not cancel report.Scan, Project, FetchAdvance, or their Git subprocesses because their current interfaces take no context; report.Scan currently runs before TurnVerdict. The proposed date +%s%N clock is not portable to the repository's supported Darwin path. Finally, moving unbounded ceremonies after verdict computation still permits the runtime to kill the hook before emission unless the block is emitted before those ceremonies or every ceremony is independently bounded. The 80-percent skip test only helps before a command starts.
EVIDENCE: metasystem/plans/turn-verdict-hardening-design.md lines 246-260 specifies the clock, context wrapper, and post-verdict ceremonies. metasystem/cmd/metasystem/goal.go lines 530-560 calls report.Scan before TurnVerdict without context. metasystem/internal/goal/fetchadvance.go lines 26-81 and metasystem/internal/goal/project.go lines 28-46 expose no context or deadline. metasystem/scripts/agents/supervision-hook.sh lines 179-215 and 267-321 show that computation and response emission are separate phases. metasystem/internal/identity/identity.go explicitly supports both Linux and Darwin, while the proposed shell clock assumes GNU date behavior.
MATERIAL: True

## TVH-R1-RUNTIME-HOOK-CHECK-OMITS-TWO-SUPPORTED-RUNTIMES — high
CLAIM: The owned hook-enrollment and timeout work is incomplete for the declared runtime universe. The design repeatedly says to update 'both' shipped JSON files, but the registry has three real shipped enforcement configurations: Codex, Devin, and Claude. More fundamentally, its proposed session-start hooks check cannot succeed for Codex or Devin because the existing command requires Declaration.SelfCheck and only Claude has one. Following the design literally leaves Devin's Stop timeout at five seconds and reports permanent hook drift or check failure for two supported runtimes.
EVIDENCE: metasystem/plans/turn-verdict-hardening-design.md lines 248-252 and slice 1 line 414 say both JSON timeouts; lines 354-362 require hooks check for runtime R. metasystem/internal/runtimes/runtimes.go lines 161-226 declares codex-hooks.json, devin-hooks.json, and claude-code-hooks.json, with SelfCheck only on Claude. metasystem/cmd/metasystem/hooks.go lines 28-39 rejects a runtime without SelfCheck. All three enforcement files currently declare a five-second Stop timeout.
MATERIAL: True
