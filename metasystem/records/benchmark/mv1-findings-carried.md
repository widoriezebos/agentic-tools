# MV-1 verification findings, carried for the consolidating rewrite

Chain design-critic-20260807t094616z-ac0a, round 1, fresh eyes over the folded design. All nine OPEN, none dispositioned.

### MV-1-1 (sev=critical)
The generation fence ends before adapter launch, so a predecessor can start stale work after the successor has completed its claim-time sweep and opened dispatch. A holder can create a generation-tagged pending record under the lease lock, release that lock, die, and leave its dispatch subprocess alive. The successor can then claim, sweep the still-unlaunched record, stamp cleanup complete, and dispatch new work while the predecessor proceeds to launch. The design's standing reaper only closes this after a cadence delay, if at all, so the proof that stale-generation runners are killed before dispatch opens is false.
EVIDENCE: Read: W-5 locks only verification and record creation, and the Proof says the sweep kills stale-generation runners before the stamp opens dispatch. In the shipped dispatcher, initial dispatch creates the record at line 1396 and launches at line 1398; follow-up has the same split at lines 1765 and 1767. The launch helper starts the adapter before publishing its process identity to the record, at lines 828 through 861. The design specifies no second generation check or launch authorization spanning this gap.

### MV-1-2 (sev=critical)
Commit authorization is vulnerable to a time-of-check-to-time-of-use race that the accepted identity residual does not cover. A pre-commit check can authenticate the old holder, return, and then lose its holder process before Git updates the index and reference. A successor may claim immediately on that death and begin writing while the already-authorized Git process finishes the old commit. Per-call process-table re-reading does not serialize the action it authorizes, so the promised single writer is not mechanically enforced for commits.
EVIDENCE: Read: W-2 authenticates at each mediated call, W-3 permits an immediate claim on proven holder death, and W-4 promises that non-holder commits refuse. The shipped hook installed by adopt.sh executes scripts/agents/pre-commit-guard.sh as a child of Git. That guard exits after its check; it cannot retain the lease lock through the parent Git process's subsequent commit. The design names no commit wrapper, inherited lock owner, or other fence covering the actual Git mutation.

### MV-1-3 (sev=high)
Placing the lease check only around job-record creation allows a non-holder dispatch to mutate shared state before it is refused. An implementer following W-5 literally would still let a non-holder create a Git branch and worktree, write prompts and payload directories, create capability snapshots, and reserve mission budget before reaching the protected record write. The design needs an early authorization boundary as well as the final locked generation check; otherwise W-4's refusal happens after interference has already occurred.
EVIDENCE: Read: W-5 says dispatch takes the lease lock, verifies the holder and generation, writes the record, and releases. In the shipped initial path, worktree creation occurs at line 1325, payload writes at lines 1345 through 1348, and mission reservation at lines 1392 through 1394, before record creation at line 1396. Follow-up synchronizes a critic worktree, writes prompts, records exhaustion state, and reserves mission capacity before its record creation at line 1765.

### MV-1-4 (sev=high)
The design does not define the complete mediated-write surface or the trusted control-plane exceptions, so implementations can either leave non-holder mutations open or break required background services. The dispatcher includes follow-up, cancel, close, and reap, while the stop hook runs destructive evidence collection and writes supervision state. Announcements and the second-session escape hatch must also write even for a non-holder, and the detached standing reaper must remain authorized. Merely gating the three proof nouns—dispatch, commit, and arming—leaves real mutations available; gating every script uniformly disables mechanisms the design depends on.
EVIDENCE: Read: W-4 and its Proof enumerate only dispatch, commit, and arming. The shipped dispatch command table exposes mutating follow-up, cancel, close, and reap operations at lines 2038 through 2042. Cancel signals a job, close changes its record, and reap signals processes and changes records. The supervision stop hook invokes evidence-gc.sh and appends shared hook state, while W-1 requires every main, including an advisor, to write an announcement. No authority matrix distinguishes holder actions, advisor bookkeeping, detached trusted services, human tools, and the worktree escape hatch.

### MV-1-5 (sev=high)
The caller-classification algorithm contains incompatible process identities and lacks the announcement data needed by its stronger rule. Its ordered walk says a process identifier plus start-time announcement match authenticates immediately, but the same section later requires process identifier, start time, and current command line to match the announcement together. W-1 also says process identifier plus start time is used everywhere. An implementer can therefore build either the unsafe pair comparison or a triple comparison whose stored command representation, matching rule, and schema are left to guesswork.
EVIDENCE: Read: W-2 lines 52 through 56 authenticate on the process identifier and start-time pair, while line 58 requires that pair plus current command line. W-1 says the pair is used everywhere. The shipped strict announcement reader in process-census.py accepts exactly sessionId, pid, pidStartedAt, pgid, runtime, instanceTag, and announcedAt; it has neither mainId nor an announced command line or command hash. The design never defines the added field or whether matching means exact command text, a hash, or an adapter signature.

### MV-1-6 (sev=high)
The per-checkout durable-evidence layout is not specified deeply enough to integrate with the collector or preserve existing evidence. The design does not define a collision-resistant checkout segment, canonicalization rules, the resulting path schema, or how old unsegmented manifests remain collectible. Updating only the mirror path satisfies the stated subtree sentence but makes the shipped collector miss every new manifest; updating only the collector strands existing terminal chains. The proposed audit also detects paths into the primary checkout, not two worktrees resolving to the same external evidence directory.
EVIDENCE: Read: W-4 says only that the segment is derived from the checkout path. The shipped mirror writes evidence.root/agents/root-job in dispatch.sh line 1011. evidence-gc.sh independently looks for evidence.root/agents/chain/manifest.json at lines 58 and 94 rather than using the mirror path stored in each job record. The Proof does not require a legacy-layout case or a two-checkout distinct-path assertion.

### MV-1-7 (sev=high)
Return schema version 2 is not an implementable schema contract. The design requires schemaVersion and says claimed values move under claimed, but never defines the claimed object's fields, requiredness, null rules, runtime-specific values, or the exact version 1/version 2 acceptance and retirement behavior. Implementers will produce different schemas and normalization behavior, and tests cannot know whether an agent's claimed session or model must be retained, rejected, or represented when no observed value exists.
EVIDENCE: Read: W-6 is the complete folded specification for version 2 and supplies no JSON shape beyond two field names. The current role schemas forbid extra properties and contain neither field. runtime-common.sh currently fills a missing session and overwrites model.effective with telemetry, while validate-metasystem.sh asserts the exact existing property set. The Proof delegates to unspecified round-2 fixtures rather than stating versioned assertions.

### MV-1-8 (sev=high)
The keyed protocol-error and cursor mechanism is missing its data and ordering contracts, so it cannot reliably close the silent-error incident it targets. The design does not define the error key, set record location and schema, event ordering, cursor value, atomic relationship between insertion and terminal job transition, or what inherited count is printed after a claim. Different reasonable choices count retries and repeated validation failures differently and can either double-report or suppress errors.
EVIDENCE: Read: W-7 consists only of “add-if-absent set under the record lock at the adapter lifecycle point,” a per-main cursor, and an inherited count. The round-2 disposition adds no schema or key definition. The shipped adapter can enter protocol_error from more than one validation branch, and its terminal transition and return validation are separate operations. The Proof again refers only to unnamed round-2 fixtures.

### MV-1-9 (sev=medium)
The superseded caller-classification paragraph still instructs implementation of the deleted environment-marker mechanism. Because the superseding header says conflicts are ignored rather than removing the obsolete algorithm, one reader can correctly implement kernel-only classification while another can retain marker precedence and contradiction checks. Those implementations authorize and refuse different callers.
EVIDENCE: Read: W-2 explicitly says the environment marker is deleted because a hook cannot install it in its parent. The immediately following superseded paragraph still says classification checks environment markers and refuses when a marker contradicts the ancestor walk. This is the exact surgical-fold seam identified in the review brief.
