- Intent: Retained proof is reused wherever its execution identity still holds, so unchanged groups are skipped instead of re-run. The delivery deep dive (proof-attempts.md section 5) shows reuse fired for 3.6 percent of groups and that identity churn, not the same-goal rule, is the binding constraint: a Go group's input manifest spans the whole module (985 files); a section group's identity carries the candidate engine digest (46 identities in 47 adoption-fixtures runs); every group carries the policy engine's file digest, so a rebuild invalidates everything; and reuse is scoped to the same goal, accounting revision and successful terminal. DONE means: (1) a Go group's execution identity is its test-aware dependency closure (go list -deps -test, including embedded files and testdata) plus its declared runtime inputs, its tools, discovery, environment, contract and behavior-policy digests, and a versioned judge-compatibility key in place of the policy engine's file digest, so a rebuild of an unchanged judge keeps identities and a changed judge invalidates them; section and steward-consuming groups keep the candidate engine digest; (2) a selected group is reused only from the NEWEST retained observation with the same identity on the seat, and only when that observation is a passed, collection-complete group: a newer failed or live observation blocks reuse; the goal, accounting revision and terminal result of the attempt no longer scope it; validateRetainedGroupReuse keeps refusing forged or stale metadata; (3) cadence attempts that establish trust in a changed judge execute every group afresh and record executed-group counts and attempt ids; (4) proven by fixtures: a re-stage that moved only files outside a group's closure and runtime inputs re-runs only the changed groups; an edit to a test's external data file re-runs its group; green then red yields no reuse; test verify refuses when a required group has no matching retained result. Cross-machine reuse is out of scope. Own goal, own battery, three fresh green cadence runs before trust. Goal 10 of plans/delivery-efficiency-plan.md. Wido's word 2026-09-11: I want that added. RUNTIME INDEPENDENCE (plan principle 0; architecture doctrine of 2026-08-16: correctness never depends on an accelerator): this holds for every runtime the roster can host today (claude, codex, devin) and for future adapters such as opencode; the mechanism lives in the Go engine, the ledger verbs and the adapter contract, never in one runtime's hook, harness, CLI or transcript format; a native facility may accelerate it through its adapter, and an agent on any runtime with no accelerator gets the same guarantee from the records and the verb alone; where the goal touches a runtime path, DONE is proven on at least two runtimes.
