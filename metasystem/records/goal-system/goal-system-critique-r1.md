Not ready. All findings below are material and ranked by severity.

1. **G-01 — CRITICAL: A non-blocking goal cannot make an agent continue.** The current hook starts another turn only through the `decision: block` path, and that path is entered solely for `OPEN-WORK` lines ([supervision-hook.sh](</private/tmp/claude-501/-Users-wido-LocalStorage-GitHub-agentic-tools/af965b26-11a5-4d56-b6c2-8f1df989f9f3/scratchpad/wt-quality/metasystem/scripts/agents/supervision-hook.sh:172>)). A goal-only `systemMessage` is merely a post-stop advisory. The central outcome therefore fails exactly when only a goal remains. The design must decide whether a new goal revision blocks once, or provide another causal continuation mechanism.

2. **G-02 — CRITICAL: `goals.md` is accidentally an ordinary plan under the existing scanner.** `planFiles` reads every `plans/*.md` except `README.md`, while `planField` returns the first matching field in the whole file ([openwork.go](</private/tmp/claude-501/-Users-wido-LocalStorage-GitHub-agentic-tools/af965b26-11a5-4d56-b6c2-8f1df989f9f3/scratchpad/wt-quality/metasystem/internal/report/openwork.go:214>)). Consequently, a retained next step from a done or parked goal can produce `OPEN-WORK`; later active goals can disappear behind the first block; and changing that field can re-arm the block-once signature. This contradicts the requirement that goals not block. The scanner must explicitly exclude the ledger or consume its grammar correctly.

3. **G-03 — CRITICAL: The actor scope directly violates backlog item 14.** “Host and delegate alike” is binding context, yet delegates and mission integration are excluded. Avoiding context leakage requires a filtered goal projection into a brief, not removal of an explicitly required audience. This scope reduction needs a human ruling, not a design assertion.

4. **G-04 — CRITICAL: Runtime-neutral storage is being substituted for runtime-equivalent behavior.** Claude gets an effective turn-end mechanism; Codex and Devin get an instruction to remember to run a command. Prompt compliance is not machinery and recreates the exact continuation weakness the stop hook exists to solve. Deferring actual delivery to item 16 means item 14 would ship incomplete.

5. **G-05 — CRITICAL: The original incident remains possible because goal registration is optional.** Nothing creates a goal when a program or backlog is opened, migrates existing intent, or rejects a “nothing left” claim when intent remains only in another document. The incident test pre-seeds the very record whose omission caused the incident, so it proves parsing rather than regression prevention. “There is now a home” is not an invariant.

6. **G-06 — HIGH: Read failures are indistinguishable from no goals.** The current hook suppresses reporter failures with `2>/dev/null || true`. Missing, unreadable, or malformed goal state would therefore collapse into “none,” especially because exit 3 is already assigned to the legitimate empty case. Parse failure needs a distinct outcome that surfaces degraded state and forbids the all-clear verdict.

7. **G-07 — HIGH: The mutation and authority contracts contradict each other.** “Engine owns every mutation” is incompatible with unrestricted direct editing. Direct filesystem writes take neither the goal lock nor the lease lock and can race an atomic rewrite, bypass validation, or clobber a concurrent update. Any repository writer with sufficient filesystem permission can bypass the claimed holder-only gate. Either make the engine the exclusive writer or define a lock/CAS-aware human editing workflow.

8. **G-08 — HIGH: Checkout write custody is being confused with authority over intent.** A lease holder is entitled to mutate the checkout; that does not automatically entitle it to redefine, park, or declare complete a human or program-level goal. Takeover also changes the holder without reconciling stale next steps. Goal ownership, permitted transitions, provenance, expected epoch, and human-reserved decisions need separate rules.

9. **G-09 — HIGH: The advertised “one engine verdict” has no specified owner or interface.** Today the engine separately reports open work and constructs a block object, while shell code assembles messages, computes the session signature, decides block-once, and writes state. If goals are excluded from `open_work`, the current `work_sentence` can literally emit “NOTHING LEFT” followed by “proceed with …”. The design must define one structured decision result—including `shouldBlock`, open-work identity, goal revision, diagnostics, and display text—or explicitly retain shell ownership.

10. **G-10 — HIGH: Item 15 cannot compose as claimed.** A run has three conditional continuations—green, red, and hang—whereas a goal has one unconditional active next step. Activating it before terminal state surfaces work prematurely; activating it afterward requires the supervision writer to mutate holder-only state, which the authority matrix refuses. The conditional continuations must remain on the run record, with a specified terminal projection into goal orientation if one is still useful.

11. **G-11 — HIGH: The proposal creates competing next-step authorities.** Handoff plans already require both “Goal and current status” and “Next step,” and the open-work scanner consumes that next step ([plans/README.md](</private/tmp/claude-501/-Users-wido-LocalStorage-GitHub-agentic-tools/af965b26-11a5-4d56-b6c2-8f1df989f9f3/scratchpad/wt-quality/metasystem/plans/README.md:15>)). A parked goal can disagree with an unblocked handoff, or vice versa. The design must replace one field, derive one view from the other, or define an enforceable reference relationship.

12. **G-12 — HIGH: This is a new standing-ledger contract despite being labelled otherwise.** The routing doctrine says task-local plans are deleted or archived and names exactly five permanent ledgers. A permanent, machine-consumed history of completed goals is a sixth standing ledger. `plans/README.md`, `wow.md`, adoption payload generation, cleanup rules, and audits all require amendments.

13. **G-13 — HIGH: There is no deterministic global “next.”** Multiple active goals produce multiple imperatives while the required wording and behavioral objective are singular. File order is an undeclared priority policy that agents can game by reordering blocks. The design needs either exactly one current goal, an explicit selection rule, or wording and consumer behavior for a bounded set.

14. **G-14 — HIGH: The command surface cannot create or resume the declared records.** `goal set --id --next` lacks the intent required in a new heading, while no create, resume/unpark, or reopen operation exists. Legal transitions, idempotency, invalid source states, metadata preservation, and whether done goals retain actionable next-step text are left for the implementer to invent.

15. **G-15 — HIGH: Repository text is elevated into an imperative system message without a trust contract.** A committed or directly edited next step can contain prompt injection or instructions requiring authority the goal itself does not grant. The grammar needs control-character and size bounds, safe framing, provenance, and an explicit rule that a goal conveys orientation—not authorization to deploy, delete, spend, publish, or cross an envelope.

16. **G-16 — MEDIUM: The proof obligations miss the dangerous seams.** Required coverage includes goal/open-work scanner interaction, unchanged-work block-once after goal edits, malformed-state fail-closed behavior, concurrent human/holder writes, lease takeover, all three terminal run outcomes, startup/resume consumption, delegate projection, and adapter parity. Package-level parser and verdict tables will not prove those behaviors.
