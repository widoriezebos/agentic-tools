# g1-s11 goal detail: Sol's design critique

Run 2026-09-22 against `21c446ff7`, read-only, nothing built or executed.

**Sol’s verdict: 4 DESIGN ERROR findings must be fixed before building.** This was one read-only critique round against commit `21c446ff7`. Evidence below comes from source inspection; the 585-record census was also recomputed.

1. **[1] DESIGN ERROR — the gap categories contradict their own contract.** `Absent` means a missing field or value; `NotProjected` means records potentially held elsewhere. Yet DefinitionRefs and the nonexistent slice-plan owner are classified as `NotProjected`, while editor actions receive that classification with no meaningful reach. These entries would appear under “Not read by this build, and where it lives,” and O4 requires their exact text in fixtures. Put missing record structures under `Absent` and describe future editors separately. The master explicitly treats DefinitionRefs as a future schema extension. Sources: [gap types](plans/user-interface/g1-s11-goal-detail-design.md:76), [Definition entries](plans/user-interface/g1-s11-goal-detail-design.md:173), [Plan entries](plans/user-interface/g1-s11-goal-detail-design.md:175), [O4](plans/user-interface/g1-s11-goal-detail-design.md:291), [master distinction](plans/user-interface-design.md:437), [DefinitionRefs extension](plans/user-interface-design.md:509).

2. **[1] DESIGN ERROR — “no claim; nothing is executing” is unsupported.** The design assigns this reach to job, spend, and session sources whenever the goal is unclaimed. But release clears the claim without consulting job activity, and the engine’s existing activity reader explicitly returns live job activity even when there are no claims. Thus absence of a claim cannot establish absence of execution. Say “no current claim; activity and execution location are unknown from this record.” Sources: [prescribed wording](plans/user-interface/g1-s11-goal-detail-design.md:177), [release transaction](metasystem/internal/goal/verbs.go:1721), [claim clearing](metasystem/internal/goal/verbs.go:1751), [independent job scan](metasystem/internal/goal/project.go:518), [activity without claims](metasystem/internal/goal/project.go:556), [master’s evidence-gap rule](plans/user-interface-design.md:637).

3. **[1] DESIGN ERROR — the journey link names the wrong path in adopted projects and promises the wrong version.** Evidence describes an accepted-tip document, but the page hardcodes `metasystem/docs/journey.md`. State lives beneath the installation in a template checkout and beneath the application repository in an adopted installation; the journey’s canonical relative path is `docs/journey.md`. Moreover, g1-s21’s document reader serves current checkout bytes and expressly makes no HEAD claim. Derive the checkout-relative document ID from resolved roots and label this as a current-checkout link, rather than an accepted-tip document. Sources: [Evidence reach](plans/user-interface/g1-s11-goal-detail-design.md:179), [hardcoded reference](plans/user-interface/g1-s11-goal-detail-design.md:231), [root ownership](metasystem/internal/stateroot/stateroot.go:108), [journey home](metasystem/docs/backlog-mechanism.md:306), [document identity](plans/user-interface/g1-s21-project-thread-design.md:61), [checkout read](plans/user-interface/g1-s21-project-thread-design.md:68).

4. **[2, 5—Q1] DESIGN ERROR — the rank prefix can hide a real goal event; the proposed ownership question is already settled.** A reason such as “priority-ordering was harmful” satisfies the proposed `HasPrefix("priority-order")` classifier, although abandonment copies the human’s reason verbatim into its own History event. That event would be folded as a rank change. Generated reasons instead start with `priority-order subject=` or `priority-order from=`. Also, the pinned source already implements the same broad classifier in `lastVerbOn`, with tests excluding rank changes from `LastVerb`: Q1’s recommended behavior is already built, and the “first reader” claim is false. Specify one shared predicate with a prefix-collision fixture, updating the fenced change boundary as necessary. Sources: [classification contract](plans/user-interface/g1-s11-goal-detail-design.md:181), [Q1](plans/user-interface/g1-s11-goal-detail-design.md:316), [free reason copied](metasystem/internal/goal/abandon.go:403), [generated reasons](metasystem/internal/goal/order.go:145), [compaction reason](metasystem/internal/goal/abandon.go:414), [existing owner](metasystem/internal/backlog/project.go:269), [existing fixtures](metasystem/internal/backlog/project_test.go:298).

Both have concrete owners and paths: the counselor reads accepted-risk and misclassification registers, and landing reads `records/counselor/carried-landings.jsonl`. Add corresponding gap entries, distinguishing committed versions from potentially newer local appends. This fits the existing contract and need not reopen the design: complete evidence joins and scenario 33 are explicitly deferred.
