Confirm the threat model of one trusted human, error-prone agents using every granted capability, and a foreign page in the same browser. Remote fleet observation/control is still product scope and needs its own node boundary.

## All disagreements with the suggested remedies

1. **UID-R1-02: extra browser enrollment and per-action authentication.** The human has chosen successful sign-in as sufficient authority, so terminal/channel pairing and one-time codes for individual actions add requirements the application does not need. Account provisioning and recovery belong to the sign-in system. The server validates human sessions and keeps agent-originated requests under agent authority, including when routed through the UI. Explicit human confirmation of a proposal creates the human-authorized action; the agent's authorship remains recorded. This closes the special enrollment gap without treating an agent response as a human decision.
2. **UID-R1-13: a compulsory core/satellite document split.** Dependency boundaries and deliverable scope are necessary; separate files for every boundary are not. One integrated design with explicit implementation gates better preserves the agreed information architecture and reduces duplicated contracts. Extract a focused owner design only when it helps implement that unit.
3. **UID-R1-14: automatic paid continuation when the sitting's limit is reached.** Replacing the provider or session must not manufacture new authorization. Continue within remaining authorization for context or availability reasons; at budget exhaustion preserve state and wait for an explicit new grant.

No other finding or proposed correction is rejected. Pure preparation rather than running side-effectful code as a dry run, incremental reuse of the ACP driver, and a single server-held presentation reference make the accepted corrections precise without introducing a second execution system.

## Nonmaterial notes and preserved decisions

- Keep the human-command map as a capability-family map and require a routed-operation inventory before claiming completeness. Updated the budget entry to current `goal budget`; the critic's listed omissions remain part of that full audit, not a claim that these browser workflows already exist.
- Delegation scope/expiry come from the owner, not arbitrary form options. No unsupported scope is introduced by the UI.
- Mark `session/load` transcript replay as history; do not reexecute tools or presentation requests. Store the Overview visit marker per human/project in server-local preference state.
- Consolidated the result contract under the shared-interaction section and referenced it from the product narrative. The substantive command-edge requirements have one architectural home.
- Retained fixed navigation, explicit message-time selection, frontend-owned routes, durable operation outcomes, authoritative status, honest evidence gaps, checked drag/drop, and the brain's execution fences.
- Seat inventory, exact phase/lane sources, and complete evidence joins remain investigations with explicit coverage limits. The critique did not establish those owners, and this amendment does not pretend otherwise.
