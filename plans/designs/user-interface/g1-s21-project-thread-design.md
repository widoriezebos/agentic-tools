### Documents: identity and the reading boundary

A document is `{"kind":"document","id":"<checkout-relative path, / separators>","revision":"blob:<40 hex>"}`. The revision is the Git blob object id of the bytes read (SHA-1 over `blob <size>\0` and the content, `crypto/sha1`), equal to `git hash-object <file>`: the repository's own name for the content, which a later `DefinitionRef` can pin. Whether HEAD holds it is not claimed; `sourceHead` is `g1-s7`'s.

The reading route serves any Markdown file in the checkout, not only catalogued ones, because that is how the doctrine's and the master's links open. **The planner has ruled that the route stays this broad** (review, head): links between designs must resolve, which is the thread's point, and the exposure is small once the fixes below land, because a hostile page cannot read the responses (a cross-site fetch is refused and only a top-level navigation passes, `httpd.go:115` to `:118`, `:316` to `:324`) while an agent with filesystem tools already reaches every file the route can. What that exposes, stated so nobody is surprised later: every `.md` beneath the checkout outside the four refused directories, which today includes the human's rulings (`memory/rulings.md`), machine and session handoffs (`plans/handoff-*.md`), spend records (`records/waits/`), and the agent instructions under `.claude/` (the review's "Other dot directory" and "Existing sensitive Markdown" rows). The human may narrow the route to the catalogue plus the documents those link; that is a contained change, an allow-set built from the catalogue and the `document` links of what it lists, tested in `Read` before the open, with the payloads and the frontend unmoved.

The boundary, in Go, in this order; after step 1 nothing looks at a pathname, and nothing is opened twice:

1. **The id, textually.** Refused unless `path.Clean(id) == id` (a trailing `/`, an empty or `.` segment, or a collapsible `..` differs from its Clean), `id` does not start with `/`, is not `.`, and has no `..` segment; refused if any segment equals `.git`, `node_modules`, `artifacts`, or `bin` under `strings.EqualFold`, **case-insensitively**, because APFS is case-insensitive by default and `.GIT/x.md` reaches `.git/x.md` (tested: `os.Stat` of the mixed-case spelling finds the planted file, and `os.Root` does not fold either, so `.GIT/x.md` opens through it; only the fold stops it); refused unless the id ends in `.md` exactly, an allow test, where being stricter than the filesystem is safe.
2. **One anchored open.** `root, err := os.OpenRoot(roots.Checkout)` per request, closed when the request ends; then `f, err := root.Open(id)`, the only call on the route that yields a descriptor. `os.Root` resolves every component from the directory descriptor it holds and restarts there whenever the path it has walked changes under it (`root_openat.go`, `doInRoot`), so a parent or the leaf swapped for a symbolic link between step 1 and this call is refused with `path escapes from parent` instead of followed (tested: the leaf swapped for a link to an outside file, then the parent directory swapped for a link to an outside directory, both refused); an absolute name or a `..` that climbs out is the same error (`root.go:301` to `:307`). Every error from the open is `ErrNotFound`, unconditionally: the escape error is not `fs.ErrNotExist` (tested), so nothing tests for it.
3. **`fstat` the descriptor.** `f.Stat()` is `fstat` on the open descriptor (`os/stat_unix.go:15` to `:25`), never a lookup by name: refused unless `Mode().IsRegular()` (a directory opens, `os.Root` does not refuse one, and is refused here; tested). Its `Size` and `ModTime` are the payload's `bytes` and `modifiedAt`.
4. **A bounded read of the same descriptor.** `io.ReadAll(io.LimitReader(f, 1<<20+1))`: more than 1 MiB read means `too-large`, decided from the read and never from step 3's size, so a file that grows or is replaced after `fstat` cannot make the server allocate beyond 1 MiB plus one byte (tested: a 1,053,576-byte file yields 1,048,577 bytes and `too-large`). A `too-large` document carries step 3's `bytes`, an empty `revision`, because not every byte was read, and no blocks. Otherwise `utf8.Valid`, or `unreadable` with its blob id, since every byte was. A read error after a successful open is the 500.
5. Parse, hash, and classify links from those bytes, and nothing else.

Symbolic links, the policy stated plainly: **a symbolic link that stays in the checkout is served, at the leaf or in the middle of the path; one that leaves the checkout, or is absolute, is refused.** That is `os.Root`'s own rule, verbatim from its documentation ("Methods on Root will follow symbolic links, but symbolic links may not reference a location outside the root. Symbolic links must not be absolute.", `root.go`), so the words and the implementation are one call. Tested: a leaf link to a sibling and a linked middle directory inside the checkout both open; the same links pointing outside, and an absolute link even to an in-checkout file, are refused. Revision 1 said links were refused at the leaf; that was an `Lstat` by name, which cannot see a middle link and can be raced. Refusing in-checkout links would protect nothing the boundary protects, because a **hard link is served**: it is an ordinary directory entry in the checkout, whatever other names the same file has (tested: a hard link to an outside file opens and its contents are served), so the boundary is one of reachable names, not of inodes. And `os.Root` has no switch for it: `rootOpenFileNolog` sets `O_NOFOLLOW` on every `openat` itself and, on the error that produces, reads the link and resolves it within the root (`root_unix.go`), so a caller's `O_NOFOLLOW` is absorbed (tested: both in-checkout links still open with it); refusing would mean a hand-written `openat` walk (darwin's `syscall.openat` is unexported; `x/sys/unix.Openat` would serve), which is the component-by-component code the fix exists to keep us from writing.

Every refusal is a 404 `{"error":"no document at <id>"}` except size and encoding, which are 200 with `state` `too-large` or `unreadable` and no blocks. The trust is the goal reads' (loopback, D2, the human's own checkout); `metasystem.conf.local` is not `.md` and is never served.

**HEAD.** `ServeHTTP` admits HEAD beside GET with no route branch (`httpd.go:106`); on this route it does the GET's work, steps 1 to 5 included, and `net/http` discards the body (`chunkWriter.Write` eats writes for HEAD, `net/http/server.go:381` to `:384`), so the status and headers are the GET's and nothing of the document leaves. The cost is the GET's, bounded by step 4; no short-circuit is added, because no client of this interface sends HEAD and a second path would be a second thing to test.

Title: the first line beginning `# ` in the first 4 KiB, else the file name. Ownership: `stateroot.OwnerForInstallation(I, path)` once per catalogue directory and per single file, about twelve `git rev-parse` subprocesses per thread request, carried as the oracle's strings and labelled "the MetaSystem's", "the application's", "runtime state" (master `:459`); an oracle error is `unknown` with its reason.

### Markdown: D6 settled

**Decision: Go parses, the browser renders a typed tree, and no HTML string exists anywhere.** Dependency: `github.com/yuin/goldmark` **v1.8.6**, MIT, "depends only on standard libraries" (pkg.go.dev, 2026-09-21; the builder confirms the tag). The third module dependency (`go.mod` has two), justified: a CommonMark parser of our own is an open-ended defect surface, and goldmark is the most used Go implementation (Hugo). Only its parser and `ast` package are used, with the `Table`, `Strikethrough`, and `TaskList` extensions; its HTML renderer is never called and `WithUnsafe` never set, so the API carries no HTML.

The alternatives. Source text (the plan's placeholder at `:130`) is risk-free, but the paper and the 910-line master are not readable as raw text, which defeats D31, and D6 returns unchanged at gate 5. A browser renderer: `react-markdown` brings the unified, remark, micromark, and hast graph, roughly fifty packages, into the runtime closure where any advisory of any severity blocks every `npm run bundle` (`g1-s8`, Audit); `marked` with `DOMPurify` makes a browser sanitiser the trusted component behind `dangerouslySetInnerHTML`. Against "no vulnerabilities please", the Go tree has the smallest surface: one pure-Go dependency, React's own escaping, Go tests as the primary proof (plan `:73`). Cost: one `go.mod` line, some binary size (not measured), and a schema of ours that flattens what it does not model.

**Who sanitises: nobody has to, because nothing is interpreted.** Raw HTML in the source (`ast.HTMLBlock`, `ast.RawHTML`) becomes a node of type `html` whose `text` is the source; the browser shows it in a code block captioned "HTML in the source is shown, not run", so a `<script>` tag is visible characters. A link's `href` is carried verbatim and classified in Go: `external` for `http:` and `https:`; `fragment` for `#…`; `document` for a relative `.md` path under the checkout, with its `id`; everything else (`javascript:`, `data:`, `mailto:`, `file:`, paths outside the checkout or to non-Markdown files) is `unresolved`. The browser renders `external` as an anchor with `target="_blank" rel="noopener noreferrer"` and a 12px `ExternalLink` icon, `document` as a `NavLink` to `routeFor`, `fragment` in-page, and `unresolved` as mono text; as a belt it renders text for any `external` not starting with `http://` or `https://`. Images become the text `[image: <alt>] <src>`; no `<img>`. The policy (`httpd.go:54` to `:57`) already blocks inline script, `javascript:` navigation, inline style, external images, forms, and frames; it is the second wall. The first is React elements only: the cut guard gains a rule that `dangerouslySetInnerHTML`, `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `DOMParser`, `createContextualFragment`, and `write` name no identifier under `src/`.

Schema, `internal/ui/markdown`, `Parse(source []byte) Document`, `Document{Headings []Heading; Blocks []Block}`. Blocks: `heading` (`level`, `id`, `inlines`), `paragraph`, `code` (`lang`, `text`), `quote` (`blocks`), `list` (`ordered`, `start`, `items[]` with `checked` null or bool and `blocks`), `table` (`align[]`, `head`, `rows`, cells as inlines), `rule`, `html` (`text`). Inlines: `text`, `emph`, `strong`, `strike`, `code`, `link` (`href`, `target`, `id`, `inlines`), `image` (`src`, `alt`), `break`, `html`. Heading ids are GitHub-style slugs (lower-case, punctuation removed, spaces to `-`, duplicates suffixed `-1`), computed in Go so cross-document `#anchors` resolve. Footnotes and definition lists are not enabled; a mermaid fence is a `code` block with `lang` `mermaid`; CRLF is accepted. The keys are fixed for the brain's tools later (plan `:70`).

## Behaviour

Main flow: `/project` fetches `/api/project` behind skeletons; Go, per request, resolves the layout, walks the catalogue (each entry's checkout-relative id opened through the route's own step 2, `fstat` on that descriptor for `bytes` and `modifiedAt`, a 4 KiB head read for the title; the installation and the state root both lie beneath the checkout, `ui/lifecycle/roots.go:25` to `:40`, `:60`, so every entry has such an id), asks the oracle per directory, reads the covenant and the purpose line; the listing's `too-large` is `fstat`'s size at that moment, advisory, and the route decides again from its own read. A document route fetches `/api/documents/<id>`; Go validates the id, opens once through `os.Root`, `fstat`s and bounded-reads that descriptor, computes the blob id, parses, classifies links.

| Case | Required result |
| --- | --- |
| A catalogued file is absent | Not listed; `lookedFor` names it; every source absent → `not-recorded`, "Not yet recorded" |
| A symlink leaving the checkout, an unreadable, or a non-UTF-8 file | Listed `unreadable` with the reason; no link. A symlink staying in the checkout is listed as the file it reaches, as the route serves it |
