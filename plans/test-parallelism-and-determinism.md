## Contract and evidence

Every selected test must be eligible to execute alongside other tests without sharing mutable process state or external fixture state. The operator can configure the total worker count; its default comes from CPU capacity available to the process. Results must depend on controlled inputs and observable events, including tests of expiry and cancellation. A slower host may take longer; completing inside an arbitrary short interval is not the correctness oracle. Resource exhaustion, cancellation and a genuine hang remain explicit unsuccessful outcomes.

The mechanism serves any application through the existing testing contract and adapters. This application's Go adapter and fixture scripts are consumers. Parallel execution does not mean adding `t.Parallel` to functions that mutate process-wide state. Independent processes provide the required isolation without rewriting production interfaces merely for tests. No assertion, test, race run, coverage floor, native-result completeness check or first-failure verdict is removed. Both native and shell tests are in scope. Performance workload and regression coverage remain: portable correctness checks assert bounded work, while hardware-dependent timing is retained and reported as a measurement.

## Capacity and execution

The supported boundary is an admitted test run and its adapter-controlled workers. It is not an operating-system thread sandbox for arbitrary application processes. The existing host admission cap, named-resource locks, exact-process custody and descendant cleanup remain unchanged. Do not add weighted host CPU leases, descriptor suballocation or a nested reservation broker. That proposed extension was withdrawn after the second critique exposed a conservation hole; no implementation of it ships and no risk is accepted on its behalf. The two-round design chain is closed by this scope correction under Wido's existing implementation authority; independent code critique is mandatory for the retained change.

Keep `testing.concurrency` as the maximum number of active groups. Add `testing.workers` as the positive total adapter-worker allowance for one attempt. Its default is `max(1, runtime.GOMAXPROCS(0) / max(1, resolvedAdmissionMaximum))`, captured once before preparation. This conservatively shares available CPU capacity across the existing admitted-proof limit. An explicit worker value overrides that per-attempt default; report the worker value and admission maximum separately, including an unlimited admission setting, without promising a global OS CPU bound. Do not silently change the host-admission configuration. Validate positive values without an arbitrary 64-core ceiling. Bind resolved worker policy to the authenticated request, prepared component identities and result; changing it prevents reuse across different test conditions.

The existing stage scheduler owns group ordering, prerequisite readiness and performance isolation. One finite, cancellation-aware allocator inside `proofrun` grants native worker shares. It has no discovery, retry or ordering policy. A Go group coordinates partitions without holding a worker while waiting for children; each native partition acquires one worker and runs `GOMAXPROCS=1`, `go test -p=1 -parallel=1`. Failed-test diagnostic reruns use the same path and retain the original red result. A share is released after supervised native cleanup on every success, start failure, output failure and cancellation path. An atomic multi-worker grant never holds a partial grant while waiting. Performance groups run alone and receive the complete allowance.

The measured consumer for leaf allocation is the B7 long tail: two large native groups remained active after 46 fresh passes and 112 reuses. Fixed small group shares assigned while many groups are ready cannot spend the workers freed later. Partition count and native conditions are prepared deterministically from selected test identities and attempt allowance; runtime completion order affects only when a partition starts.

Command and section groups declare `resources.workers`: omitted means one worker, a positive number reserves that number, explicit zero means the whole attempt allowance. Use a pointer-valued integer to preserve omitted versus explicit zero. Refuse a declaration larger than the configured attempt allowance before execution. The launch receives reserved `METASYSTEM_TEST_WORKERS`; contract environment entries cannot override it. The application maps this value to its framework option. MetaSystem-owned fixture, full-gate and focused runners must consume their inherited allowance instead of recomputing machine-wide defaults. A fixture scenario gets one worker; a nested runner used as that scenario's execution engine receives that same one-worker limit. A driver delegating its complete allocation to another runner waits for that runner, rather than executing additional test workers alongside it. These are tested adapter contracts, not authority granted by an environment variable. Arbitrary application code's internal threads/processes remain that application's responsibility, just as with native test-framework worker limits.

A generic command/JUnit acceptance fixture must actually consume the allowance and prove active-worker maxima, cancellation and retained failure. Document this integration for another application's framework. A command that ignores the allowance has not implemented the parallel adapter contract and cannot be presented as evidence that its internal threads were limited. The existing authenticated proof and custody authorities remain the security boundary.

Preserve the existing launcher ordering: all selected live producers resolve before native host resources are acquired. This may delay unrelated work in that attempt but holds no lease needed by its producer. TPD-4 begins after the worker starts, including already-retained prerequisites; it does not add asynchronous live-producer admission.

## Isolation, scheduling and timing

Generalize `runShardedGoGroup` to named selections and whole-package selections. With omitted `shards`, partition the complete prepared top-level test inventory automatically, up to the worker count; an explicit value is a partition ceiling, not permission to exceed capacity. Preserve package identity, duplicate names in different packages, packages with no test functions, build tags, race mode, subtests, expected/observed joins and union coverage. No package may vanish because it has no selected test name. Retain one log per partition and deterministic merged evidence. Use existing `go test -json` and coverage ownership; compiling custom test binaries is unnecessary for this change.

Each worker's test environment owns its mutable home, registry, admission/queue paths, temporary files, ports and executable copies. Reuse current `testenv`/fixture owners and fix concrete external-state collisions found by the audit. Shared Go/module caches stay shared under their existing safe owners. Tests deliberately exercising process-wide state remain serial inside their own process and can run concurrently with other processes. Nested scenarios that dominate the critical path must be partitioned at their independent fixture boundary where their setup currently combines many cases into one top-level test. This is bounded test restructuring with unchanged assertions, not a production-global rewrite. The existing `t.Parallel` ratchet remains a non-regression check; it is not misrepresented as the acceptance measure for process parallelism.

Replace the ready-wave loop with a completion-driven scheduler inside the existing stage owner. Reuse and borrowed evidence satisfy prerequisites immediately. Start a dependent as soon as its own prerequisites pass and group capacity is available; preserve intentional stage boundaries. A failed prerequisite blocks its dependents, while independent groups continue and retain all failures. Cancellation/progress-write failure stops new launches and drains existing children. Performance isolation, deterministic result order and retained-duration priority remain. The launcher resolves live borrowed evidence before this loop and before acquiring native host resources. The loop therefore handles retained results and owned execution, and cannot deadlock while holding capacity needed by a borrowed producer.

Tests of deadlines, timestamps and budgets use injected clocks or explicit recorded time. Readiness uses pipe/channel/state acknowledgements; ordering assertions deliberately hold/release those events. The test's outer hang protection must not become a short success deadline. Audit existing Go time-window assertions and shell waits, not only calls listed in the Go allowance file. Live process observation may poll an exact kernel identity, but success comes from that fact. Replace real 1/3-minute proof work in lifecycle fixtures with controlled accounting and deterministic application evidence; retain public acceptance/refusal of small budgets without requiring a real build to finish inside one minute. Fix fixture descendants that can outlive ownership using existing leashes/custody, without importing the unrelated queued janitor design.

Concurrent suite instances use independent checkouts and runtime namespaces. The guard against two suites mutating the same checkout remains a valid ownership check; removing it is unnecessary to run all tests concurrently in isolated workers. The full validator delegates native parallel execution to the same Go owner instead of maintaining special package names and a second shard scheduler. Shell remains plumbing; scheduling/test logic belongs in Go.

## Implementation map

All builds use private copies, Sol xhigh, focused canaries, and exact-diff independent reads. Root owns integration and publication. Native isolation and fixture corrections are independent of the scheduler and can proceed concurrently. Policy publishes a frozen interface patch first: `TestRunRequest.Workers int`, `GroupResources.Workers *int`, resolved result/identity fields and reserved adapter environment. Root reviews that interface and places the same exact dependency tree in the execution builders' copies. Scheduling then provides a context-scoped finite worker allocator with atomic acquire/release; Go workers builds against that exact API and dependency tree. The existing host-resource acquire/borrow/inherit API does not change. Their shared `test_build.go` ownership is by function: policy owns request/preparation/identity/environment; scheduling owns the stage loop and command/section allocation; Go workers owns shard/native/rerun execution. No builder silently invents the others' types. Any later interface change returns through the coordinator and recompiles all consumers. Focused implementation can proceed in parallel behind these explicit interface handoffs, but certification uses the complete integrated dependency tree. Numeric changed-line estimates are allocations, not reasons to omit necessary tests; a builder reports an ownership or contract gap before inventing another mechanism.

## Implementation findings and release constraints — 21 September, 08:12 CEST

The full baseline reached native tests and failed with eighteen distinct leaves: nine incomplete frozen-project exports, seven timing/custody failures and two test synchronization/identity defects. This is a measured failed baseline, not a passing full-suite duration. The failure inventory and raw run are retained under the evidence root. The Linux baseline engine builds and a native race-toolchain canary passes; the new integrated implementation has not yet been exercised there.

Review exposed three additional boundaries that must be complete before release:

- A frozen test checkout must retain the application's project inputs and Git layout, including an installation at the project root or a nested path. Newly included inputs must participate in fresh **and retained** coverage/witness identity. Copying the files without updating reuse would permit stale proof. The freeze-project unit owns this correction.
- The trusted installed worker rejects unknown request fields. Publication therefore has two ordered stages: first prove, publish and install a compatible backend that still serves the old request/result contract; then activate the frontend's worker fields and capability negotiation. The frontend must refuse an unsupported trusted worker before reservation or native work. It cannot replace that authority with a candidate executable. The policy unit owns compatibility; the coordinator owns the exact two-release projection and installed transition proof.
- Controlled time must reach every relevant writer and reader. A cancelled attempt stamped with fixture time can otherwise appear newer than a subsequent passing group stamped with host time. Admission, proof observation, expiry and terminal accounting must use one authorized semantic clock. Kernel process identity and diagnostic elapsed measurements retain their real clocks. The native-time unit owns that correction; the portable batch publication test remains required.

The existing serial-test ceiling is also being checked before integration. New tests that mutate shared hooks or environment variables need invocation-local dependencies or owned subprocesses; increasing the ceiling or merging test names to hide the increase is not acceptable. Focused proof now needs observed execution of each promised test, because a review found an anchored selector that omitted four intended tests despite reporting a successful package result.

The unit runner's raw Git-index checksum also rejected a successful focused proof after an index-byte change. Such changes can be harmless metadata refreshes, but the old snapshot cannot establish that retrospectively. The tool-repair follow-up will compare meaningful index state while preserving refusal of staged content, flag and conflict changes. The original ambiguous result remains recorded; a separate repeat passed with both raw and staged index identity unchanged.

Additional bounded implementation owners are timing-boundaries, freeze-project, remaining-native, fixture-events and supervision-time. Their briefs, exact dependency snapshots and independent findings are retained under `evidence-root/units`, `coordination` and `reviews`. No additional broad proof runs until these corrections converge. All critical/high obligations above remain open; component existence and a delegate's report do not close them.
